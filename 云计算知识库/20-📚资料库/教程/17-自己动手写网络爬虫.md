# 自己动手写网络爬虫

## 这条教程在解决什么
书的目标很朴素：**从零实现一个能"抓网页—抽内容—挖价值"的网络爬虫**，不依赖现成重型框架，而是把每一层自己写出来、讲透原理。作者把它拆成"三层"：

1. **抓取（Crawling）**——拿到 HTML 源码（第1篇）；
2. **抽取（Extraction）**——把 HTML 解析成结构化数据（第2篇）；
3. **挖掘（Mining）**——对抽取后的数据做分析利用：链接分析、去重、分类、聚类（第3篇）。

这条主线要和"工程师思维"挂钩：拿到需求（比如"每天盯竞品价格"）后，不是直接写代码，而是反推——需要哪些字段 → 数据从哪来 → 用 [[网络爬虫]] 抓取 → 用 [[网页解析]] 抽取 → 落到存储 → 必要时用 [[数据采集]] 管道喂给分析系统。

## 关键内容（按 PDF 章节提纲）

### 第1篇 自己动手抓取数据
- **第1章 全面剖析网络爬虫**
  - URL/URI：爬虫的处理对象就是 URL；URL = 协议 + 主机(IP/端口) + 路径（第1篇第1.1.1 节）。
  - 抓取网页：用 `HttpClient` 模拟浏览器发请求，`GetMethod`/`PostMethod` 取响应；POST 可传不限长度参数、GET 受 URL 长度限制（第1.1.2–1.1.3 节）。
  - **HTTP 状态码处理**（抓取核心易错点）：200 成功取正文；3XX（301/302/303/307）要跟随 `Location` 重定向；4XX（400/401/403/404）直接丢弃；5XX 服务器错误丢弃（第1.1.4 节，表1.1）。
  - **宽度优先爬虫**：把互联网看成超级大"图"——网页是节点，链接是有向边。从"种子 URL"出发，下载页面→用解析器抽出新链接→入 TODO 队列→循环。用 **TODO 表 + Visited 表** 去重，Visited 表用 `HashSet`（O(1) 查找、不重复）。宽度优先最常用，原因：重要网页离种子近、利于多爬虫合作（第1.2 节，图1.5）。
  - 书里给了完整 Java 示例：`Queue`（链表）、`LinkQueue`（已访问/待访问集合）、`DownLoadFile`（带连接超时5s、重试）、`HtmlParserTool`（抽 `<a>`/`<frame>` 链接）、`MyCrawler`（主循环，限抓 1000 页）。
  - **带偏好的爬虫**：宽度优先不够"聪明"，用 PageRank 给待抓链接算重要性、按优先级遍历（第1篇第1章延伸）。
- **第2章 分布式爬虫与云计算**（本书与"云"衔接最紧的一章）
  - 为什么分布式：为抓取**性能与可扩展性**，也可按地域/网络（电信/联通）物理分布节点（第2.1 节）。
  - **云计算**：是分布式/并行/网格计算的发展与商业实现；特点——超大规模、虚拟化、高可靠（多副本容错）、通用、高可扩展、按需服务、廉价（第2.1.1 节）。
  - **Google 三大技术**：GFS（分布式文件系统，存网页）、MapReduce（分布式计算，把大任务拆成子任务并行再合并）、BigTable（半结构化数据分布式存储）（第2.1.2/2.3/2.4 节）。
  - **分布式存储**：海量 URL/页面存哪？从 RDBMS 切到 **key/value 存储**（无 schema、易横向扩展，如 BigTable/SimpleDB）；用 **Consistent Hash（一致性哈希）** 解决"节点增减时数据重新映射"的问题——环形 hash 空间 + 虚拟节点保证单调性、平衡性（第2.2 节，含 Java 实现）。
  - GFS 详解：主服务器(master)+块服务器(chunkserver)，文件切成 64MB chunk、多副本；适合"一次写、多次顺序读"的爬虫场景（网页抓下后基本不改）（第2.3 节）。

### 第2篇 自己动手抽取 web 内容
- 主题：**网页解析**——从抓到的 HTML 里抽出结构化字段。
- 工具链：**正则表达式**（适合规则强的小片段，但对嵌套/不规则 HTML 力不从心）+ **HTML 解析器**（把页面变 DOM 树，按标签/属性/类名提取，如书里用的 HtmlParser）+ XPath/CSS 选择器。
- 易错点：编码（`parser.setEncoding("gb2312")`）、链接过滤（filter 只收符合规则的 URL）、动态渲染页面（JS 生成内容需无头浏览器）。

### 第3篇 自己动手挖掘 Web 数据
- **链接分析（排序）**：PageRank（query-independent，随机冲浪模型）与 HITS（query-dependent，hub/authority 相互增强；及其改进 ARC、Hub 平均、阈值算法）（第8章）。
- **去掉重复文档**：用**语义指纹 / SimHash** 把网页映射成定长指纹，近似指纹归为重复（第9章）。
- **网页分类**：特征选择（TF-IDF、X² 统计量等）+ **支持向量机 SVM** 做二分类/多分类（第10章）。
- **聚类**：如 DBScan 把相似网页聚成簇（第10章）。

## 它背后的原理（别只记操作）
- **爬虫本质 = 图的遍历**：互联网是一张图，爬虫就是 BFS/带偏好遍历；去重是"已访问集合"的经典问题。
- **抓取层本质是 HTTP 客户端**：所有的 magic 都回归到"发请求—读状态码—取响应流"，超时/重试/代理/重定向是工程必需。
- **抽取层本质是"非结构化→结构化"**：HTML 是树，正则/解析器/XPath 是不同的"导航方式"。
- **挖掘层本质是"数据→信息"**：链接分析用图论、去重用指纹哈希、分类聚类用机器学习——爬只是数据入口。
- **分布式爬虫 = 云计算思想的雏形**：Google 正是因为要爬全网才催生了 GFS/MapReduce/BigTable，爬虫与云原生同源。

## 我能复用/改编的点
> 换个需求，这套做法还能怎么用？

- **做"竞品价格看板"**：反推 schema（商品名/价格/库存）→ 用 [[网络爬虫]] 定时抓 → [[网页解析]] 抽字段 → 落库 → BI 展示。采集器做成 [[微服务]]，多实例跑不同站点。
- **做"舆情监控"**：抓新闻/社媒 → 去重（SimHash）→ 分类（SVM 正负面）→ 告警。
- **分布式采集上云**：把单体爬虫包装成 [[微服务]]，用 [[Kubernetes]] 按抓取压力弹性伸缩多个 Pod；URL 队列用 key/value 或消息队列解耦；配合 [[CI-CD]] 做爬虫版本持续交付。
- **带偏好的遍历**思想可迁移到任何"图遍历+优先级"场景（如站点地图生成、死链检测）。
