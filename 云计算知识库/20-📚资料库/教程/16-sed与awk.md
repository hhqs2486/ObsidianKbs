# sed 与 awk（修订第三版）

## 这条教程在解决什么
- 教工程师用两个经典命令行工具处理文本：**sed 做"行级流编辑"（替换 / 删除 / 打印），awk 做"列级结构化处理"（按字段 / 模式提取、统计、报表）**。目标不是背语法，而是建立"从文本处理需求反推该用哪个工具"的工程师直觉。

## 关键内容（按 PDF 章节提纲）
- 第 1 章 起步：sed 与 awk 都是"流处理"——读入、处理、输出，边走边处理，不整文件加载。定位是命令行编辑器 / 文本处理语言，不是 GUI 工具。
- 第 2 章 正则表达式：所有匹配的通用语言。BRE（基础，需转义 `\(` `\{`）与 ERE（扩展，`+` `()` `{}` 直写，grep -E / sed -E / awk 用）。核心元字符 `. * ^ $ [ ] [^ ]`。
- 第 3–4 章 sed 基础与脚本：逐行进"模式空间"，默认打印结果。`s/old/new/flags` 是核心；定址（行号、范围、`/pattern/`）决定命令作用在哪些行。脚本可写成文件用 `sed -f script.sed` 调用。
- 第 5 章 sed 基本命令：`p`(打印) `d`(删) `s`(替换) `y`(字符转换) `=`(行号) `i/a/c`(前插 / 后插 / 整行改) `n`(读下一行)。`-n` 关默认打印，配 `p` 只输出匹配行。
- 第 6 章 sed 高级命令：保持空间(hold space) `h H g G x` 与多行命令 `N D P`，做跨行处理（合并多行、段落重排）。务实场景少，懂概念即可。
- 第 7–8 章 awk 基础与脚本：`pattern { action }` 模型。`$0`=整行，`$1..$NF`=字段，FS 默认空白。`BEGIN` 在首行前、`END` 在末行后执行（汇总圣地）。
- 第 9 章 传参：`-v var=value` 把 Shell 变量传给 awk，避免把变量硬拼进脚本。
- 第 10 章 条件 / 循环 / 数组：`if`/`for`/`while`，`arr[key]` 关联数组（key 可为字符串），用于分组计数。
- 第 11–13 章 字符串 / 数值 / 自定义函数：`sub()` `gsub()` `index()` `split()` `substr()`；`printf` 格式化；`function name(args){...}` 复用逻辑。
- 第 14–19 章 实战：记录与字段、变量运算符、模式与动作、关联数组、函数、实用 awk 程序（统计、报表、数据转换）。
- 附录：sed / awk 速查表；grep 家族；lex/flex、yacc/bison 家族（词法 / 语法分析，进阶）。

### 工程师可直接抄的范例
sed 行级流编辑：
```bash
# 1. 把配置里 listen 8080 改成 443（先预览，不加 -i）
sed 's/listen 8080/listen 443/' nginx.conf

# 2. 原地修改（会改文件！确认无误再用）
sed -i 's/old.example.com/new.example.com/g' *.conf

# 3. 删除空行和注释行
sed -e '/^$/d' -e '/^[[:space:]]*#/d' file.conf

# 4. 打印包含 ERROR 的行号与内容
sed -n '/ERROR/{=;p}' app.log

# 5. 路径含 / 时用 # 当分隔符，避免转义
sed 's#/old/path#/new/path#g' script.sh
```

awk 列级结构化处理：
```bash
# 1. 打印第一列
awk '{print $1}' access.log

# 2. 按 : 切 /etc/passwd 取用户名
awk -F: '{print $1}' /etc/passwd

# 3. 统计每个 IP 的访问次数（关联数组 + END 汇总）
awk '{cnt[$1]++} END{for(ip in cnt) print ip, cnt[ip]}' access.log | sort -k2 -nr

# 4. 第五列（响应码）为 500 的行
awk '$9==500' access.log

# 5. 算平均响应时间（假设第 10 列是耗时）
awk '{sum+=$10; n++} END{print "avg=", sum/n}' access.log

# 6. 跳过首行表头再处理
awk 'NR>1 && $3>100{print $1}' data.csv
```

组合（grep → sed → awk → sort → uniq）：
```bash
# 从 Nginx 日志抽 404 的 URL 并统计 Top10
grep ' 404 ' access.log | awk '{print $7}' | sort | uniq -c | sort -nr | head
```

## 我卡住/没懂的地方
- sed 高级命令（保持空间 `h/H/g/G/x`、多行 `N/D/P`）概念抽象、跨行处理心智负担大——实际工作中多行合并优先用 awk 或 `paste`/`tr`，sed 高级用法留作"知道存在"。
- awk 字符串比较 vs 数字比较的类型陷阱（`"10" < "9"` 为真）需要刻意注意，建议字段用 `+($3)` 强制转数字。
- PDF 为图片扫描版，抽取文本极少，上述命令均来自对 sed / awk 的既有可靠知识，未逐字核对原书排版。

## 它背后的原理（别只记操作）
- 两者都遵循"流 + 模式"范式：数据像水流过过滤器，每个工具只做一件事，靠管道 `|` 串成流水线。这是 Unix 哲学"小而专、可组合"的典范。
- sed 的世界观是"行"：整行进模式空间，命令在行上操作，天然适合替换 / 删除 / 打印整行或行内片段。
- awk 的世界观是"表"：把每行当记录、空白 / 分隔符切成字段，自然适合按列提取、条件过滤、分组聚合。
- 记住分工：**sed 做行级流编辑，awk 做列级结构化处理**。选错工具会事倍功半。

## 我能复用/改编的点
> 换个需求，这套做法还能怎么用？
- 日志告警：把"统计 5xx 次数"改成"统计慢请求（耗时 >1s）"，只改 awk 条件 `$10>1`。
- 配置治理：sed 批量改端口 / 域名可写成 [[CI-CD]] 流水线里的"配置规范化"步骤，提交前自动跑。
- 数据落库：awk 抽取 CSV 列 → 拼成 `INSERT` 语句 → 灌进数据库，省掉写 Python 解析。
- 报表：BEGIN 打印表头、END 打印合计，awk 一行脚本替代 Excel 透视表。
