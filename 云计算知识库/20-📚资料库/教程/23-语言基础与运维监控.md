# 语言基础与运维监控（6 本合集）

## 这条教程在解决什么
- 本批是「编程语言 + 系统运维 + 数据 + 监控」基础，目标不是背语法，而是建立一条**工程师认知线**：
  **Go 是云原生主力语言（K8s / Docker 都用 Go 写，Goroutine 做并发）→ Git 是协作与 [[CI-CD]] 的基石 → [[Linux运维]] 是地基 → 大数据体系用 [[数据中台]] / [[数据仓库]] / [[离线计算]] + [[实时计算]] 分层 → [[运维监控系统]]（Zabbix / Nagios 等）与 [[Prometheus]] 互补构成 [[可观测性]]**。
- 读者是大二学生，重点练「从需求反推架构」：拿到一个需求，先想该用哪块能力，再去翻对应概念卡。

### 一、Go 语言入门与实战（《Go 学习笔记（第四版）》+《Go 语言实战》）
- 《学习笔记》主线：入门 → 结构（类型 / 表达式 / 函数 / 方法）→ Goroutine 与 Channel → 包与 cgo / Reflect → 附录深抠**内存分配器、垃圾回收（GC）、Goroutine 调度器**（G-P-M 模型）。
- 《实战》主线：第 1 章用 Go 解决现代编程难题（开发速度 / 并发 / 类型系统 / 内存管理）；第 2 章快速跑通一个搜索程序（main 包 / search 包 / 匹配器）；第 3 章打包和工具链（**包、导入、init、go vet、依赖管理**）；第 4–5 章数组 / 切片 / 映射、类型系统（方法 / 接口 / 嵌入 / 公开性）；第 6 章并发（goroutine / 竞争状态 / 锁 / 通道）；第 7 章并发模式（runner / pool / work）；第 8 章标准库（log / json / io）；第 9 章测试与基准。
- 关键收获：**Go 单二进制部署 + 原生并发**，这正是它成为云原生母语的原因（见 [[Go语言]] [[Goroutine]] [[Go模块]]）。

```go
// Goroutine：一行 go 启动一个轻量并发任务
package main

import (
	"fmt"
	"time"
)

func worker(id int, ch chan string) {
	ch <- fmt.Sprintf("worker %d done", id) // 通过 channel 通信
}

func main() {
	ch := make(chan string, 3)
	for i := 1; i <= 3; i++ {
		go worker(i, ch) // 起 3 个 goroutine
	}
	for i := 0; i < 3; i++ {
		fmt.Println(<-ch) // 汇总结果
	}
	time.Sleep(time.Millisecond) // 真实程序用 context 控退出
}
```

### 二、Git 协作流（《Git 团队协作》）
- 第一部分「制定工作流」：第 1 章团队作战（成员 / 思维策略 / 会议）；第 2 章命令与控制（项目治理 / 访问模型：分散、并列、共同维护）；第 3 章**分支策略**（主线分支开发 / 功能分支 / 状态分支 / 计划部署）；第 4 章工作流（基本工作流、同行评审、按计划发布）。
- 第二部分「在工作流中使用命令」：单人团队（基于 issue 的版本控制、分支、标签、连接远程）；回滚 / 还原 / 重置 / 变基；多人团队（消费者 / 贡献者 / 维护者角色、评审、合并、冲突解决）；准备评审；用 stash / blame / bisect 找 bug。
- 第三部分「托管平台」：GitHub / Bitbucket / GitLab 的仓库、权限、保护分支、Pull Request。
- 关键收获：Git 工具之上必须套**工作流纪律**，并接 [[CI-CD]]（见 [[Git工作流]] [[Git]]）。

```bash
# 一条可信的功能分支流
git checkout -b feature/login      # 从主干拉功能分支
# ... 写代码、git commit ...
git push -u origin feature/login   # 推到远程
# 提 PR/MR → 同伴评审 + CI 通过 → 合并回 main（主干受保护）
git checkout main && git pull --rebase
```

- 关键收获：代码跑起来之前，先有能托住它的 Linux 地基与架构蓝图（见 [[Linux运维]] [[系统架构]] [[服务器虚拟化]] [[高可用]] [[虚拟机]]）。

### 四、阿里大数据体系（《大数据之路：阿里巴巴大数据实践》）
- 第 1 章总述：**四层架构**——数据采集层（Aplus.JS / UserTrack 日志、TimeTunnel 传输、DataX 同步）→ 数据计算层（[[离线计算]] MaxCompute + [[实时计算]] StreamCompute + OneData 整合）→ 数据服务层（OneService 接口化）→ 数据应用层（搜索 / 推荐 / 广告 / 大屏）。
- 数据模型篇：[[数据仓库]] 分层 ODS（贴源）/ DWD（明细）/ DWS（汇总）/ ADS（应用），实现「数据资产 → 信息资产」。
- 数据管理篇（第 12–15 章）：[[数据治理]]——元数据（技术 / 业务）、计算管理、存储与成本管理、数据质量。
- 核心思想：用 [[数据中台]]（OneData + OneService）统一建模与服务，避免数据烟囱与口径不一致。
- 关键收获：大数据不是「装个 Hadoop」，而是「采集→计算→服务→应用」分层 + 治理的体系（见 [[大数据]]）。

```
阿里大数据体系（反推视角）
数据源 ──采集层(Aplus/UserTrack/TT/DataX)──▶ 计算层(MaxCompute离线 + StreamCompute实时 + OneData)
        │                                          │
        └──────────────── 服务层(OneService) ◀────┘
                              │
                          应用层(搜索/推荐/广告/大屏)
```

### 五、常用运维监控系统概览（《常用的运维监控系统.docx》）
- 文档抽取 17 种监控工具，重点是「传统主机 / 网络 / 应用监控」：
  - **Zabbix**：企业级、自带 Java / VMware / 硬件监控，每分钟 300 万次检查，Server + Agent + Web + 数据库架构，支持自动发现 / 拓扑 / proxy（见 [[Zabbix]]）。
  - **Nagios / Icinga**：状态、日志、告警老牌；Icinga 是 Nagios 分支，分布式 + 多线程、Web UI 配置友好。
  - **Cacti**：RRDtool 前端，图形化强，SNMP 采集。
  - **Open-Falcon（小米开源）**：全 Go 编写、水平扩展，单 graph 撑 200 万 metric/分钟，agent / SNMP / 主动 push 均可。
  - 其余：GroundWork、Hyperic、Observium、NetXMS、Pandora FMS、NetDisco、OpenNMS、RANCID、Xymon、Big Brother / Big Sister、Ntop。
- 关键收获：这类系统管「主机 / 网络 / VM 活没活、慢不慢」，与云原生里的 [[Prometheus]]（容器 / 多维标签 / PromQL）**互补**，共同支撑 [[可观测性]]（见 [[运维监控系统]]）。

| 维度 | Zabbix | Prometheus | Open-Falcon |
|------|--------|-----------|-------------|
| 擅长 | 主机/网络/VM、模板化 | 云原生/容器、多维 | 互联网大规模、水平扩展 |
| 采集 | Agent/SNMP/IPMI/JMX | Pull + Exporter | agent/SNMP/push |
| 告警 | 触发器+动作 | PromQL+Alertmanager | 策略模板 |
| 定位 | 传统基础设施监控 | K8s 内可观测 | 大厂自研风 |

## 它背后的原理（别只记操作）
- **语言选型的工程逻辑**：云原生要「编译快、并发好、单二进制、生态一致」→ Go 胜出；K8s / Docker / etcd / Prometheus 全是 Go，学 Go 等于读懂云原生源码。
- **协作的本质是纪律**：Git 提供原子能力，工作流（分支策略 + 评审 + CI）把纪律固化，否则规模一大必乱。
- **运维的本质是可观测、可复现、可自动化**：Linux 是地基，架构是蓝图，监控是「体温计」。
- **数据的本质是分层与治理**：不做分层 → 冗余与口径乱；只采集不治理 → 数据灾难；OneData / OneService 用「复用」对抗「重复」。
- **可观测性 = 指标（监控）+ 日志 + 链路**：Zabbix 类管指标与主机，Prometheus 管容器指标，二者互补才是完整可观测。
