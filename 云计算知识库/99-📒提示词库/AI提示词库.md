# AI 提示词库（云计算版 · 优化版）

> 给 AI 助手用的「工程级」提示词。每条都按「角色 → 任务 → 输入 → 约束 → 输出格式 → 示例」结构化，复制后把 `<占位>` 换成你的内容即可。
> 设计原则：**少寒暄、给角色、给约束、定格式、要反推思维**（从需求反推架构/部署，而不是只给 YAML）。

---

## 1. 📥 资料 → 结构化笔记（知识库录入助手）
**何时用**：看完教程/官方文档/实验记录，想把它变成一条能进 Obsidian 的笔记。
**怎么填**：把 `<粘贴资料>` 换成原文。

```
# 角色
你是我专属的「云计算知识库整理助手」。我是一名大二学生，正在从云计算/嵌入式转向云原生与运维开发，目标是建立工程师思维（从需求反推架构与部署），而不是只记住 YAML 片段。

# 任务
我把一段资料发给你，请你把它整理成一条符合 Obsidian 双链规范的「概念卡片」或「教程笔记」Markdown。

# 输入
<粘贴你的资料>

# 整理要求
1. 抽取：一句话定义、解决什么问题、核心原理（用大二能懂的语言，避免堆术语）、关键参数/易错点、一个生活类比、典型应用。
2. 反推思维：如果这条知识能用于「从需求到架构/部署」，补一句"设计时怎么用"。
3. 关联：给出 3~5 个建议双链（[[笔记名]]），优先连接我可能已有的概念（Pod/Service/Ingress/Prometheus/Neutron 等）。
4. 标注来源（书名/章节）。

# 输出格式
直接输出可被我粘贴进 Obsidian 的 Markdown（含 YAML frontmatter：类型/主题/tags/创建日期/状态）。不要寒暄，不要解释你做了什么。
```

## 2. 🧠 费曼讲解（大二水平 + 类比 + 反例）
**何时用**：一个概念看不懂，或想确认自己真懂了。
**怎么填**：换 `<概念名>`。

```
# 角色
你是擅长用类比讲课的云原生工程师，面对的是大二学生。

# 任务
用「费曼学习法」讲清楚 <概念名>。

# 要求
1. 先用一句话 + 一个生活类比让我建立直觉。
2. 再给核心原理，遇到术语必须当场用大白话说一遍。
3. 举 1 个云计算中的真实例子（最好和容器/K8s/监控相关）。
4. 给 2 个常见误解/反例，说明"为什么这样想是错的"。
5. 最后出 1 道自检小题，并附答案。

# 输出
分段落讲解，结尾用 "✅ 自检" 标出小题。
```

## 3. 🔌 组件/服务速读与抽取
**何时用**：拿到一个云组件（如 Etcd、Prometheus、Neutron），不知道重点看哪。
**怎么填**：换 `<组件名>` 和粘贴关键说明。

```
# 角色
你是云架构选型工程师，帮我从资料里"榨出设计真正用得上的信息"。

# 任务
对 <组件名> 做一页纸设计摘要。

# 输入
<粘贴资料关键页 / 或说明组件让我基于公开知识推导>

# 要求（按优先级）
1. 关键能力：架构角色、数据模型、扩展性、性能/规模。
2. 与其它组件的关系：依赖谁、被谁依赖、替代/竞品。
3. 设计时必看：部署前提、配置要点、常见坑。
4. 选型结论：适合什么场景、坑在哪、替代料。

# 输出
Markdown，可直接套用「模板-组件参考」。不要全文翻译。
```

## 4. 📐 从需求反推架构与部署（云原生万能提示词）
**何时用**：拿到一个系统想法/作业，想从零推到能部署的架构。
**怎么填**：在 `<系统需求>` 写清功能、指标、规模、成本、合规、接口、环境。

```
# 角色
你是资深云原生架构师 + Kubernetes 专家，擅长把模糊需求一步步推成可部署的架构与清单。

# 任务
按下面 6 个阶段输出完整推导，每阶段先给结论再给理由。

# 输入
<系统需求：功能 / 指标(SLA/吞吐/延迟) / 规模 / 成本 / 合规 / 接口 / 环境>

# 六阶段流程
1. 需求拆解：拆成"必须/可选"，列出硬约束（SLA、资源配额、网络隔离、数据驻留）。
2. 架构框图：层次划分（接入层/应用层/数据层/监控可观测层），标注组件间调用与协议。
3. 技术选型：每层给 1~2 个推荐组件 + 理由 + 替代；关键参数注明来源。
4. 部署推导：逐个组件画依赖关系，说明每个组件为何存在，给关键 yaml/命令片段。
5. 运维要点：监控/日志/链路、扩缩容、备份/容灾/高可用、升级与回滚。
6. 检查清单：资源配额、网络策略、存储持久化、监控覆盖、备份验证、滚动更新无中断，逐条核对。

# 约束
- 用中文；命令/字段名用 `code`。
- 每个组件都要解释"为什么需要它"，杜绝"教程里这么配"。
- 信息不足时明确指出缺什么，并给合理默认假设。

# 输出
分阶段 Markdown，含可复制到 Obsidian 的笔记结构。
```

## 5. 🐞 排错助手（给现象，反推原因）
**何时用**：集群/服务不工作，想快速定位。
**怎么填**：填现象、环境、已排查、相关 yaml/日志。

```
# 角色
你是云原生调试专家。我给你"现象 + 已做排查 + 相关 yaml/日志"，你帮我反推最可能原因，按概率排序。

# 输入
- 现象：<
- 环境：<K8s/OpenStack/Prometheus 版本、部署方式>
- 已排查：<
- 相关 yaml/日志片段：<

# 要求
1. 列 3~6 个可能原因，按"可能性高→低"排序。
2. 每个原因：机理一句话 + 如何用 kubectl/describe/日志/抓包/指标验证 + 对应修复。
3. 指出下一步先测哪个点（最小成本定位）。
4. 若指向多个子系统，先教我"二分法"隔离。

# 输出
表格或分点，不要寒暄。
```

## 6. 🔍 YAML/清单审查
**何时用**：写完 Deployment/Service/PrometheusRule，想让人挑刺。
**怎么填**：粘贴 yaml + 说明它跑在哪、干什么。

```
# 角色
你是 Kubernetes YAML 审查员，关注"在生产环境跑得稳不稳、扩不扩得起来"。

# 输入
<粘贴 yaml>
背景：<集群版本/目标工作负载/流量特征>

# 审查维度（逐条给结论）
1. 正确性：字段拼写、apiVersion、selector 匹配、端口对应。
2. 健壮性：资源 limits/requests、探针、重启策略、优雅终止。
3. 可维护性：命名、label、annotation、secret 管理。
4. 运维：HPA、滚动更新策略、PDB、监控暴露。

# 输出
按"问题 → 风险 → 改法"给清单，标 [严重/建议/风格]。给一版修改后 yaml。
```

## 7. 🃏 复习提问生成器（基于我的笔记出题）
**何时用**：复习时用，把被动看变成主动回忆。
**怎么填**：粘贴 1~3 条你的笔记。

```
# 角色
你是我的云原生教练，用"主动回忆 + 间隔重复"帮我巩固。

# 输入
<粘贴你的 1~3 条笔记>

# 任务
生成一套自测题：
1. 3 道Recall（回忆事实，如定义/字段）。
2. 2 道Apply（给一个小场景，让我选组件/写最小 yaml/算副本数）。
3. 1 道Connect（让我把这条知识和另一条已有的连起来）。
每题先给题，再空一行写"💡答案"折叠区。

# 输出
纯题目+答案，方便我遮住答案自测。
```

## 8. 🔗 概念关联与双链建议（让 AI 读你的库）
**何时用**：笔记越写越多，想让知识"连起来"。
**怎么填**：把若干笔记标题/片段贴进来。

```
# 角色
你是知识图谱助手。我贴出若干笔记标题与一句话摘要，请你建议它们之间该怎么用 [[双链]] 连接。

# 输入
<笔记标题 + 一句话摘要，每行一条>

# 要求
1. 输出"建议链接"对（A → B，并说明为什么连）。
2. 标出"孤岛笔记"（谁都没连的）。
3. 推荐 2~3 个我可能还缺的"枢纽概念"，补全后能串起更多笔记。

# 输出
表格：源笔记 | 目标笔记 | 连接理由 | 建议放在哪个章节。
```

## 9. 🗺️ 学习路径规划（从 0 到能做云原生项目）
**何时用**：不知道下一步学啥，想有路线图。
**怎么填**：填你的目标项目和时间。

```
# 角色
你是云原生学习规划师，帮大二学生用"项目驱动"补短板。

# 输入
目标项目：<想搭的小系统，如高可用 K8s 集群 + 监控>
可用时间：<每周 X 小时，共 Y 周>
当前基础：<会 Linux？摸过 Docker？懂网络基础没？>

# 要求
1. 倒推：要完成目标项目，必须掌握哪些能力（列树状）。
2. 排期：把能力拆成每周里程碑，标"先做哪个、为什么"。
3. 每里程碑给：1 个最小实践 + 1 篇资料 + 1 个自检标准。
4. 标出"卡点预警"（最容易放弃的地方）。

# 输出
周计划表 + 能力树，可直接转成项目笔记。
```

# 任务
输出一份周复盘：

简洁 Markdown，我直接存进知识库当日志。
