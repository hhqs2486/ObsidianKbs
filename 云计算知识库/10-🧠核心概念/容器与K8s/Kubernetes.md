# Kubernetes

## 一句话定义
> Kubernetes（K8s）是开源的**容器编排平台**，负责自动化部署、扩缩容、运维成百上千个容器化应用。

## 它解决什么问题 / 为什么存在
单机用 docker 跑几个容器还行，但当应用拆成几十个微服务、每个要多个副本、还要自愈、滚动更新、服务发现时，人工管不过来。K8s 把"大厂运维最佳实践"沉淀成一套**声明式 API**：你描述"期望状态"，它负责让"实际状态"无限逼近期望。

## 核心原理（大二能懂的水平）
- **声明式**：你写 yaml 说"要 3 个 Nginx 副本"，控制器循环一直把现实掰向这个目标（少了就补，多了就删）。
- **控制平面**：APIServer（入口）、etcd（唯一真相源数据库）、Scheduler（把 Pod 调度到节点）、ControllerManager（一堆控制器）。
- **工作节点**：kubelet（节点管家）、kube-proxy（网络规则）、容器运行时（跑容器）。
- **核心对象**：Pod（最小调度单位）、Deployment（管无状态多副本）、Service（稳定访问入口）、Ingress（对外暴露）。

## 关键参数 / 易错点
- 把 K8s 当"高级 docker"是最大误区——它是编排系统，不是运行时。
- 忽视"声明式 + 控制器调和循环"：改 yaml 才生效，直接改运行中的容器会被覆盖。
- yaml 里 `selector`/`label` 不匹配是新手最常见的 Service 不通原因。

## 类比（帮助理解）
把 K8s 想成**餐厅经理**：你告诉他"要 3 个厨师(Pod)做川菜(镜像)"，经理负责招人、顶替请假的人、生意好就加人——你从不直接指挥某个厨师。

## 设计时怎么用（反推思维）
做微服务后端时，我会用 Deployment 管无状态服务、StatefulSet 管有状态（数据库/中间件）、Service 做服务发现、Ingress 暴露流量，而不是自己写调度和心跳脚本。
