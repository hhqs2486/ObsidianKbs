# 南北向流量

## 一句话定义
南北向流量（North-South Traffic）= 集群"外部"客户端（用户/前端/其他系统）与集群"内部"服务之间的纵向流量（如浏览器→Ingress→服务），因画在架构图上常是上下纵向而得名。

## 它解决什么问题 / 为什么存在
外部请求怎么安全、可控地进集群？需要统一的入口网关做 TLS 终止、认证、限流、路由——对应 [[Ingress入门]] 与 Istio [[Gateway]]。

## 核心原理（大二能懂的水平）
- 南北向入口通常是一个边缘网关（Ingress Controller 或 Istio Gateway / Envoy），把外部请求转成集群内的 [[东西向流量]] 去调服务。
- 网关负责：TLS 终止、域名/路径路由、限流、WAF、对外暴露（NodePort/LB）。
- 与东西向区别：南北向是"边界"，要严控认证与暴露面；东西向是"内部"，要互信加密。

## 关键参数 / 易错点
- 易错：把内部 Service 用 LoadBalancer 直接全暴露公网（暴露面太大）→ 应只暴露网关/Ingress。
- 易错：南北向 TLS 终止在网关后，内部仍明文（除非再开东西向 mTLS）。
- Gateway 与 Ingress 概念易混：K8s [[Ingress入门]] 是标准入口资源，Istio Gateway 是 Mesh 视角的南北向入口。

## 类比（帮助理解）
像"公司大门前台（南北向网关）"：访客（外部请求）从大门进，前台查证件(认证)、登记、指路(路由)后，内部再用分机(东西向)联系各部门。

## 设计时怎么用（反推思维）
> 做系统对外暴露时，我会只用 1 个南北向网关（Ingress/Istio Gateway）收口外部流量，做 TLS+认证+限流，再把请求转成集群内东西向调用，绝不把每个服务直接暴露公网。

## 典型应用 / 我在哪见过
- Ingress Controller、Istio Gateway、API Gateway；本书微服务实践里外部入口与内部服务解耦即南北向/东西向分层思想。
