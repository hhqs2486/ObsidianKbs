# Docker

## 一句话定义
> Docker 是最流行的容器引擎/运行时：它负责把应用打包成镜像、并在节点上创建和运行容器。在 K8s 里，Docker 是底层"搬箱子"的工具之一。

## 它解决什么问题 / 为什么存在
- 让"构建镜像、运行容器"变得简单可用（早年容器技术门槛高，Docker 把它做成人人能用的命令）。
- 提供镜像仓库（DockerHub）生态，方便分发。
- 书里把 Docker 比作"飞机"，K8s 比作"飞机场"——Docker 管单机跑容器，K8s 管多机编排调度。

## 核心原理（大二能懂的水平）
- Dockerfile 是镜像的"配方"：FROM 基础镜像、ADD 拷文件、RUN 执行命令、ENTRYPOINT 启动命令。
- `docker build` 按配方做出镜像；`docker run` 跑出容器。
- 在 K8s 节点上，Docker 引擎负责真正创建容器；[[kubelet]] 告诉它做什么。K8s 也支持其他运行时（如 containerd），不强制 Docker。
- 默认网络：docker0 网桥给同机容器分配 172.17.0.0/16 网段，跨机通信需要 [[CNI网络]]（如 Flannel）。

## 关键参数 / 易错点
- `docker build -t 名称:标签 .`：`-t` 打标签，末尾 `.` 是构建上下文目录。
- `docker exec -it <容器ID> bash`：进容器排错（第11章连 MySQL 就这么干）。
- 易错：K8s 集群里不要用 `docker run` 手动起业务容器（应由 K8s 管理）；docker 仅作底层运行时。
- 易错：镜像没设国内源时拉取慢/失败（书里多处用阿里云/中科大镜像）。

## 类比（帮助理解）
- Docker 是"集装箱工厂 + 吊车"：把货（应用）装成标准集装箱（镜像），吊车（引擎）把箱子搬到船上跑起来；K8s 是调度整支船队的港口调度中心。

## 设计时怎么用（反推思维）
> 做 XX 系统时，我会用它能解决 YY。
- 要把自研应用交付到 K8s，先写好 Dockerfile 产出标准镜像（第11章做法），再交给 [[Deployment]] 调度，而不是手动 docker run。

## 典型应用 / 我在哪见过
- 第2章节点安装 docker-ce；第3章 kubeadm 前置装 Docker；第11章写 Dockerfile 构建 Spring Boot 镜像。
