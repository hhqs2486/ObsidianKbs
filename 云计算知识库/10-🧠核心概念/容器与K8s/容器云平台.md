# 容器云平台

## 一句话定义
> 在 [[Kubernetes]] 等容器编排引擎之上，叠加**多租户、统一门户、网络/存储、日志、监控、DevOps、服务目录**等能力，面向企业提供的"容器即服务"（CaaS）平台。

## 它解决什么问题 / 为什么存在
- [[Kubernetes]] 本身只解决"把容器调度跑起来 + 自愈 + 服务发现"，但企业落地时还要：多租户隔离、统一权限、应用全生命周期管理、对接现有 IT 系统（堡垒机/CMDB/ITSM）、统一运维。
- 书《基于 Kubernetes 的容器云平台实战》第 16 章以金融为例：业务要快速上线、开发测试生产环境一致、缺乏有效的 DevOps 落地手段、运维割裂自动化水平不高——这些都是单机 K8s 不管的，需要"容器云平台"这层来补齐。

## 核心原理（大二能懂的水平）
- 书里原话：Kubernetes "本质上可看作是**基于容器技术的 mini-PaaS 平台**"（第 16 章 16.2.2）。也就是说 K8s 已经是半个平台了，容器云平台是把另一半补上。
- 书的"逻辑架构"（16.3.2）把平台分成三层：① **统一门户**（管理门户=账户/权限/单点登录；用户门户=应用中心/应用拓扑/资源视图）；② **容器云核心平台**（容器引擎层 + 编排调度层 + 管理层）；③ **DevOps**（镜像构建/持续集成/持续部署）。
- 在 K8s 之上加的"管理能力"主要是：租户配额（用 ResourceQuota 实现租户级配额，配合 [[多租户]]）、镜像仓库、配置中心（[[ConfigMap]]）、安全管理、日志/监控、自动化部署。

## 关键参数 / 易错点
- 容器多租户隔离基本靠 [[Namespace]]；但 Namespace 只做**资源**隔离，**网络隔离**还得靠 VxLAN 不同 ID（书 16.4.11）。易错：以为建了 Namespace 就安全隔离了。
- 配额要提升到**租户级**：在对应 Namespace 上加载 ResourceQuota，防止租户间资源抢占（书 12.5.3）。
- 平台对外暴露 API 时，用户安全模块要充当 **API 网关**做 Token 校验与鉴权（书 16.4.6）。
- 易错点：把"我搭了个 K8s 集群"等同于"我有容器云平台"——缺了门户、租户、对接，那只是集群不是平台。

## 类比（帮助理解）
- [[Kubernetes]] 像给一栋楼装了电梯和配电（能住人、能调度）；
- **容器云平台**像整栋写字楼的物业 + 门禁 + 招商 + 报修系统（谁能用、用多少、出了事找谁）。

## 设计时怎么用（反推思维）
> 做企业级应用时，我会用"容器云平台"这条主线：用 [[Kubernetes]] 解决调度与编排，再在此之上补齐**多租户配额、统一门户、对接堡垒机/CMDB、日志监控一体化**，而不是只交付一个裸集群。

## 典型应用 / 我在哪见过
- 书第 16 章完整设计了一套"金融容器云平台"（系统架构/逻辑架构/数据架构/技术架构/部署架构/关键模块）。
- 业内同类：华为云 CCE、红帽 OpenShift、Rancher——都是"K8s + 平台层"的思路。
