# CKA认证

## 一句话定义
> CKA（Certified Kubernetes Administrator，Kubernetes 管理员认证）是由 CNCF 与 Linux 基金会联合推出的**实操型**认证：不是选择题考试，而是在一个真实 Kubernetes 集群上现场完成一堆运维/部署/排错任务，证明你真能"把集群用起来"。

## 它解决什么问题 / 为什么存在
- 企业招人时没法一眼看出"你是不是真会在集群上干活"，CKA 用一个标准化、上机操作的考试把"会背概念"和"会排错部署"的人分开。
- 对学习者来说，它的考纲几乎就是一份**最小可用的 Kubernetes 运维能力清单**：你能用它反推"我到底要会哪些真功夫"。

## 核心原理（大二能懂的水平）
- 普通考试考"你知道什么"，CKA 考"你能做什么"。考试在一个带多个上下文（cluster context）的 live 集群里进行，题目形如"把 foobar 这个 Pod 的报错日志筛出来存到某文件""把节点排空并重新调度上面的 Pod""给 etcd 做个快照"。
- 这一切都建立在你已经理解 [[Kubernetes]] 是"声明式 + 控制器调谐"的系统（见 [[容器编排]]）：你写 YAML 描述"期望状态"，kube 组件负责把它变成现实。CKA 就是逼你亲手把这套流程跑通。
- 考试可以用 `kubectl`、官方文档（`kubernetes.io`）、`etcdctl` 等，但**不能靠记忆力蒙**——任务杂、时间紧，必须靠肌肉记忆和命令拼装能力。

## 关键参数 / 易错点
- **权重（考纲能力占比，约）**：集群架构与安装配置 ~25%、工作负载与调度 ~15%、服务与网络 ~20%、存储 ~10%、故障排查 ~30%。排错占了最大头，印证了"考真功夫"。
- **切换集群上下文是每题第一步**：几乎每题开头都是 `kubectl config use-context <xxx>`，切错 context 等于在别人集群上操作，白干。
- **别手敲长 YAML**：善用 `kubectl create <资源> --dry-run=client -o yaml > x.yaml` 生成骨架再改，比纯手写快且不易错。
- **改完要验证**：每条真题解析里都有"检查"步骤（如 `kubectl get po -o wide`、`kubectl exec ... -- ls /secrets`），考试不验收但现实里必须确认。
- **时间管理**：考试约 2 小时、十几到二十题，单题平均几分钟，卡住的先跳过。

## 类比（帮助理解）
- 把 CKA 想成"厨师资格证的上机实操考"：不是让你写《烹饪原理》论文，而是给你一口锅和食材，限时点几道菜、把糊了的菜救回来。
- 它考的不是"你读过多少 K8s 书"，而是"集群真出问题时你手会不会抖"。

## 设计时怎么用（反推思维）
> 如果这条知识能用于「从需求到架构/部署」，在这里写一句：做一套系统时，我会用 CKA 的能力地图反推——先想"集群怎么搭/怎么高可用"（架构），再想"负载怎么调度、服务怎么暴露、数据怎么存"（工作负载/网络/存储），最后永远留一手"出问题怎么排"（排错），而不是只堆功能。
