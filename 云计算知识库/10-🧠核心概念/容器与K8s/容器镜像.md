# 容器镜像

## 一句话定义
> 容器镜像（Image）是一个**只读的、分层堆叠**的文件系统模板，里面打包了应用运行所需的程序、库、配置；它是 [[容器]] 的「静态定义」，容器是它运行时的实体。

## 它解决什么问题 / 为什么存在
- 以前「在我机器上能跑，在你机器上跑不了」——环境不一致。镜像把「应用 + 它依赖的一切」冻结成一个可移动的单位，到哪都能一致运行。
- 类比面向对象：**镜像 = 类，容器 = 实例**（《Docker实战(图解)》ch01、《Docker从入门到实践》ch05 原话）。

## 核心原理（大二能懂的水平）
- 镜像不是单个 ISO 文件，而是**分层存储**（Union FS / overlay2）：底层是基础 Linux 根文件系统，往上每改一点就加一层；前一层只读，后一层只记「与上一层的差异」。
- **写时复制（Copy-On-Write）**：多个容器共享同一基础层只读数据，只有各自容器层可写，极大省磁盘。
- overlay2 存储驱动下的目录：`LowerDir`（底层只读）、`UpperDir`（容器可写层）、`MergedDir`（合并后的完整视图）、`WorkDir`（临时层），位置在 `/var/lib/docker/overlay2/`。
- 镜像用 `<仓库名>:<标签>` 寻址，默认标签 `latest`，如 `ubuntu:14.04`；[[镜像仓库]]（如 Docker Hub）负责集中存储与分发。
- 「删除前一层文件」其实只在当前层打「已删除」标记，文件仍占空间——所以每层只加需要的，构建结束前清掉临时文件。

## 关键参数 / 易错点
- 选基础镜像优先 alpine / slim 等小镜像（busybox 是「瑞士军刀」，alpine 是安全向极简 Linux）。
- `docker image inspect nginx` 看分层；`docker ps -s` 看容器实际写层大小（size）与虚拟大小（virtual size，含共享只读层，不能直接相加）。
- 别把 `latest` 当稳定版本用——它飘。
- 镜像构建后内容**不可变**；要改只能重新 build。

## 类比（帮助理解）
- 镜像像「量产产品的模具 / 类」，容器像「用模具造出来的一个个实物」；或像「系统安装盘的快照」。

## 设计时怎么用（反推思维）
> 做系统时，我会把「交付单位」定为镜像：先想清楚这个服务需要什么运行时（JRE？nginx？），选最小底包，用 [[Dockerfile]] 声明构建，再推到 [[镜像仓库]] 供 [[Kubernetes]] 拉取调度。

## 典型应用 / 我在哪见过
