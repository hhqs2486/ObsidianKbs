# 云管平台

## 一句话定义
> 云管理平台（CMP, Cloud Management Platform）：统一纳管多种云/多种资源（IaaS、PaaS、容器）的**运营运维平台**，提供统一门户、资源编排、计量计费、运维监控与跨系统对接。

## 它解决什么问题 / 为什么存在
- 企业往往已有 IaaS（如 OpenStack/VMware），容器云只是其中一层。书第 16 章 16.3.5 生产网络容器云平台的"云管理与调度"层，要对接**监控中心、日志中心、自动化平台、ITSM、用户管理、流程管理**——这些"把周边系统串起来"的工作就是云管平台的职责。
- 没有云管平台，各系统各自为政，运维割裂、自动化水平低（书 16.1 痛点 4）。

## 核心原理（大二能懂的水平）
- 书 16.3.2 逻辑架构：容器云平台位于 SaaS 与基础架构资源之间，包含统一门户、容器云核心平台、DevOps；同时容器云要对接堡垒机、CMDB、流程服务平台、自动化平台、监控中心、日志中心（书 16.3.3 数据架构）。
- 云管平台就是把这些"周边系统 + 容器云"用一个**统一管控面**串起来：账号映射、配额计量、CMDB 同步、工单流程、统一监控。
- 典型对接点（书 16.4.6 安全管理）：容器云对接**堡垒机**做用户分组映射、对接 LDAP/SSO 做身份验证、用 Token 做 API 网关鉴权。

## 关键参数 / 易错点
- **单点登录 / 账户映射**：容器云用户要能和堡垒机/AD/LDAP 的组、角色、权限对应（书 16.4.6、16.3.3 用户模型）。
- **配额与计量**：按租户/项目统计资源使用率，生成报表（书 16.4.7 报表管理）。
- **CMDB 同步**：集群节点信息要回写 CMDB（书 16.3.3）。
- 易错：把"云管平台"和"容器云平台"混为一谈——容器云是其中一类被纳管的资源，云管平台是统管多类资源的更高层。

## 类比（帮助理解）
- 云管平台像"物业集团总控中心"：管着楼里的电、水、网、门禁多个子系统，一个面板看全部、一个工单派全部。

## 设计时怎么用（反推思维）
> 设计企业云平台时，我会让容器云**不要孤立建**，而是预留与堡垒机/CMDB/ITSM 对接的接口（书 16.4.6、16.3.3）——这一步集成正是云管平台的价值；否则容器云再强也融不进企业现有运维体系。

## 典型应用 / 我在哪见过
- 书 16.3.2/16.3.3/16.3.5/16.4.6 中反复出现的"云管理与调度""统一门户""对接堡垒机/CMDB"。
- 业内：VMware vRealize、各公有云控制台、混合云 CMP 都是云管平台思路。
