# 企业级Kubernetes

## 一句话定义
> 企业级 Kubernetes 不是另一个编排引擎，而是在原生 [[Kubernetes]] 之上叠加"构建、路由、安全、运维、应用目录"等企业落地所需能力的发行版 / 平台（[[OpenShift]] 是最典型代表）。

## 它解决什么问题 / 为什么存在
- 原生 K8s 只解决"把容器调度到节点并维持期望状态"，但企业真正上线要面对：代码怎么变成镜像、外部流量怎么进来、有状态/复杂应用怎么装和运维、多租户安全与配额、监控日志、权限模型。这些 K8s 都不直接给，企业得自己拼。
- 所以"企业级 K8s" = 原生 K8s + 一整套开箱即用的企业能力，降低自研平台的成本与风险。

## 核心原理（大二能懂的水平）
- 类比：原生 K8s 像一台裸发动机（能转、能驱动），企业级 K8s 像一辆整车（发动机 + 变速箱 + 底盘 + 仪表盘 + 安全气囊），买回去就能上路。
- 组成维度：① 构建自动化（如 [[Source-to-Image]]）；② 流量入口（如 [[Route]] 替代 [[Ingress入门]]）；③ 复杂应用生命周期管理（如 [[OperatorHub]] / [[OLM]] + [[CRD与Operator]]）；④ 安全合规（如 [[SCC安全上下文约束]]、[[安全与认证]]、[[RBAC]]）；⑤ 多租户与配额（Project、ResourceQuota）；⑥ 运维与可观测（度量、日志、[[可观测性]]）。

## 关键参数 / 易错点
- 易错：把"上了 K8s"等同于"有了平台"。K8s 原生没有 S2I、没有 Route、没有 Operator 市场，这些都要平台层补。
- 易错：企业级发行版默认安全更严格（如 OpenShift 默认容器非 root），直接搬 Docker Hub 的 root 镜像会起不来（见 [[SCC安全上下文约束]]）。
- 版本绑定：发行版会锁定一个 K8s 版本并做增强，升级要跟着发行版节奏走。

## 类比（帮助理解）
- 裸 K8s = 毛坯房；企业级 K8s = 精装房（水电、地板、家具都配好，拎包入住）。

## 设计时怎么用（反推思维）
> 做"给多个业务团队用的容器平台"时，我会以企业级 K8s（而非裸 K8s）为底座，因为它把构建流水线、对外路由、安全约束、应用目录一次性打包，避免每个团队各搭一套。

## 典型应用 / 我在哪见过
- [[OpenShift]]（Red Hat）、Rancher、VMware Tanzu、以及各大云厂的托管 K8s 企业增强（如 GKE / 阿里云 ACK 的企业特性）都属于"企业级 Kubernetes"范畴。
