# PaaS平台

## 一句话定义
> 平台即服务（Platform as a Service）：把"运行环境 + 中间件 + 部署运维"打包成平台，开发者只上传代码/镜像，不用管底层服务器与基础设施。

## 它解决什么问题 / 为什么存在
- IaaS 只给你虚拟机，应用怎么部署、依赖怎么装、扩缩容怎么做全得自己来；PaaS 把这套复杂度屏蔽掉，让开发者专注业务代码。
- 书前言："PaaS 平台的出现正是上述问题的最佳解决方案"——传统开发部署复杂、环境不一致、交付慢。

## 核心原理（大二能懂的水平）
- 容器（[[Docker]]/[[Kubernetes]]）是"轻量级 PaaS"的一种实现。书 16.1.3 指出：容器作为轻量级 PaaS 解决方案，解决了**传统 PaaS 复杂、学习周期长、对开发侵入性强**等问题，并以**容器镜像**作为标准交付物。
- 镜像成为交付标准后，开发、测试、准生产、生产都跑同一个镜像 → 环境天然一致（书 16.1.3、第 17 章 DevOps）。
- 书 16.2.2 把 Kubernetes 定性为"基于容器技术的 mini-PaaS 平台"，即 K8s 已具备应用托管能力，平台工程只需在其上增强租户/网络/编排。

## 关键参数 / 易错点
- 交付物是**镜像**（不是可执行文件、不是源码包）：书 17.3.1 "软件交付方式已经由可执行代码交付方式变成 Docker 镜像交付方式"。
- 镜像 tag 必须与版本库标签关联（书 17.3.1），否则无法追溯"线上跑的是哪份代码"。
- 易错：把 PaaS 等同于"给我一个 Tomcat"——真正 PaaS 的卖点是**标准化交付 + 自动部署 + 弹性伸缩 + 自助服务**。

## 类比（帮助理解）
- IaaS = 租毛坯房（水电不通，自己装修）；
- **PaaS** = 租带家具家电的精装房（拎包入住，不能改承重墙）；
- SaaS = 住酒店（连家具都不是你的，直接用服务）。

## 设计时怎么用（反推思维）
> 做应用平台时，我会用"PaaS"思路：以**容器镜像为唯一交付标准**，让开发测试生产环境一致，并用 [[Kubernetes]] 的 Deployment 做滚动发布、用 [[容器云平台]] 做自助门户，从而把"部署"从运维负担变成开发自助。

## 典型应用 / 我在哪见过
- 书 16.1.3 把 Docker 容器平台称为"轻量级 PaaS / Container as a Service (CaaS)"。
- 经典 PaaS：Cloud Foundry、Heroku；容器型 PaaS：以 K8s 为底座的各类容器云。
- 演进方向：Serverless（函数即服务）是更极致的 PaaS 抽象（见 [[容器云平台]] 与 [[平台工程]] 的进一步抽象）。
