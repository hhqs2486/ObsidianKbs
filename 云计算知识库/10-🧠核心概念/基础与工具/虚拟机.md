# 虚拟机（Virtual Machine, VM）

## 一句话定义
通过**虚拟化技术**，在一台物理机上运行多个相互隔离的「虚拟电脑」的资源抽象——每个 VM 都以为自己独占一套硬件。

## 它解决什么问题
- 物理机资源利用率低（一台服务器常只跑一个应用，CPU 闲着）
- 应用之间不隔离，一个崩了拖累全部
- 迁移/扩容难：搬物理机要搬机器

## 核心原理（大二能懂）
中间有一层叫 **Hypervisor（虚拟机监控器）** 的软件，它截获客户机（Guest OS）发出的 CPU/内存/IO 指令，翻译成真实硬件能懂的操作，给每个 Guest 一个「虚拟硬件视图」。
- **Type 1（裸金属）**：Hypervisor 直接跑在硬件上（ESXi、KVM 宿主），性能好 → 云厂商用这个
- **Type 2（宿主型）**：Hypervisor 跑在普通 OS 上（VirtualBox、VMware Workstation），方便个人用

## 关键参数 / 易错点
- **全虚拟化**（二进制翻译/硬件辅助 VT-x）vs **半虚拟化**（Guest 知道自己是虚拟机，如 VirtIO）→ 半虚拟化更快
- **嵌套虚拟化**：在 VM 里再跑 VM，需要 CPU 特性支持
- **KVM** 是 Linux 内核模块，把 Linux 变成 Type 1 Hypervisor；QEMU 负责设备模拟，两者常搭档
- 易错：把「虚拟机」和「容器」混为一谈——VM 虚拟化**硬件**（重量级、含完整 OS），容器虚拟化**OS 层**（轻量、共享内核）

## 一个生活类比
在一栋楼里用隔板隔出多个独立公寓：每套公寓有自己的水电表（虚拟资源），互不影响，但都共用大楼的地基（物理硬件）。

## 设计时怎么用（反推思维）
- 做云/容器平台时，先想**底层资源单元是什么**：OpenStack/K8s 的节点本质就是一台台 VM
- 要隔离强、跑不同 OS → 用 VM；要密度高、启动快 → 用容器
- vSphere with Kubernetes 就是把 K8s 直接跑在 VMware 虚拟化层上

## 典型应用
- IaaS 云服务（AWS EC2、阿里 ECS、华为云 ECS）
- OpenStack / vSphere 私有云
- 开发测试环境隔离
