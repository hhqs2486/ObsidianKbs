# 反爬虫

## 一句话定义
> 网站为防止被自动化程序**批量、高频抓取**而采取的技术与策略集合，是 [[网络爬虫]] 的"对抗面"。

## 它解决什么问题 / 为什么存在
- 保护**服务器资源**（防被爬挂）、**数据安全**与**商业利益**（内容/价格不被低价搬运）。
- 对爬虫方而言，理解 [[反爬虫]] 才能把采集系统"跑通且不被封"，是工程必修的非功能需求。

## 核心原理（大二能懂的水平）
反爬按层次设防：
- **请求层**：校验 User-Agent、Referer、Cookie/Session 登录态；限制单 IP 请求**频率**；出**验证码**拦截脚本。
- **行为层**：检测鼠标轨迹/点击节奏；JS 挑战（如 Cloudflare）要求浏览器执行脚本；**渲染型页面**（内容由 JS 动态生成，直接抓 HTML 拿不到，需无头浏览器）。
- **数据层**：内容**加密/混淆**、**字体反爬**（字符映射乱序）、动态 Token、接口签名。

## 关键参数 / 易错点
- **频率控制**：设合理 delay 与并发，别把别人服务器打挂（既是礼貌也是保命）。
- **遵守 robots.txt**：爬之前先看对方允许什么。
- **IP 轮换 / 代理池**：应对单 IP 限频封禁（呼应第1篇 HttpClient 设置代理）。
- **UA 池 / Cookie 池**：模拟真实浏览器、维持登录态。
- **无头浏览器**：Playwright/Puppeteer 处理 JS 渲染页。
- **法律与道德边界**：不碰隐私、不超授权、不突破付费墙——越界可能违法。

## 类比（帮助理解）
> 像小区门禁：正常住户（浏览器）刷脸进；陌生批量访客（爬虫）会被拦、要登记、频繁进出直接请出去。爬虫要"看起来像住户"才进得去。

## 设计时怎么用（反推思维）
> 设计采集系统时，我会把**反爬对策列为非功能需求**：限流+代理+UA 池打底，JS 页用无头浏览器，并先评估合规风险——先想"对方怎么拦我"，再决定架构（是否需要渲染集群、代理池规模）。

## 典型应用 / 我在哪见过
- 电商价格保护、内容付费墙、搜索引擎反作弊、API 签名校验。
- 本书第1篇涉及代理、状态码、超时等"基础对抗"；现代 JS 挑战/字体反爬需额外补充。
