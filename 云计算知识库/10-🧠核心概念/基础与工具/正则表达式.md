# 正则表达式

## 一句话定义
> 正则表达式（Regular Expression, RE）是用元字符描述"字符串模式"的规则，用来在文本中匹配、查找、提取符合条件的片段——它是 sed、awk、grep 共用的"通用匹配语言"。

## 它解决什么问题 / 为什么存在
- 想"找一段符合某种形状的文字"（如邮箱、IP、以 ERROR 开头的行），光靠固定字符串搜不到。正则把"形状"表达成可复用模式，让查找/替换/提取变得程序化，是 [[文本处理]] 所有工具的地基。

## 核心原理（大二能懂的水平）
- 普通字符匹配自身；元字符表示结构：
  - `.` 任意单个字符；`*` 前一项重复 0 次或多次
  - `^` 行首，`$` 行尾
  - `[...]` 字符集，`[^...]` 取反字符集
  - `\( \)` 分组（基本正则需转义），`\{m,n\}` 重复次数
- 扩展正则(ERE)下 `+`(1 次以上) `?`(0/1 次) `()` `{}` `|`(或) 可直接写，少反斜杠。

## 关键参数 / 易错点
- BRE vs ERE：sed 默认 BRE（分组/次数要转义 `\(` `\{`）；grep -E / sed -E / awk 用 ERE（`+` `()` `{}` 直接写）。
- `*` 是"重复 0 次或多次"，**不是**通配符；`.*` 才是任意字符任意次。
- 贪婪匹配：`.*` 会尽量吃最多，用更精确的字符集（如 `[^"]*`）限制范围。
- 锚点空行是 `^$`（仅行首接行尾），`^[[:space:]]*$` 才是"空或全空白行"。
- 转义特殊字符：`\.` 匹配真正的点，`\/` 匹配斜杠。
- 字符集里大多元字符失去特殊含义，`[.*+]` 就是字面 `.` `*` `+`。
- 分组反向引用：`sed 's/\(foo\)\(bar\)/\2\1/'` 交换前后；awk 更现代可用 `match()` / `gensub()`。

## 类比（帮助理解）
- 像"通缉令上的特征描述"：不写名字，而写"身高、穿红衣、戴帽"，警察（正则引擎）照特征抓人。模式写得越准，抓得越对。

## 设计时怎么用（反推思维）
> 做日志采集 / 字段抽取系统时，我会先为每条日志定义好正则 schema，再交给 [[sed]] [[awk]] grep 复用，而不是每次重新写解析逻辑——模式即契约。

## 典型应用 / 我在哪见过
- 校验邮箱 / 手机号格式
- 提取日志中 ERROR / WARN 行：`grep -E '^(ERROR|WARN)' app.log`
- 匹配 IP：`grep -Eo '[0-9]{1,3}(\.[0-9]{1,3}){3}'`
- 替换模板占位符：`sed 's/{{NAME}}/Alice/g'`
