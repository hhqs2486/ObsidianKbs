# 网页解析

## 一句话定义
> 从抓下来的 HTML（或非结构化文本）里**提取出有用结构化数据**的过程，是"抓取→抽取"的关键一步（本书第2篇主题）。

## 它解决什么问题 / 为什么存在
- [[网络爬虫]] 只拿到整页 HTML——混杂标签、样式、脚本，人/程序要的是"标题、价格、正文、链接"等**结构化字段**。
- 一句话：**把"一锅杂烩汤"过滤成"能吃的料"**，没有解析，抓取到的 HTML 毫无分析价值。

## 核心原理（大二能懂的水平）
- **正则表达式**：适合规则强的小片段（如提取 `href` 里的 URL）；但对嵌套/不规则 HTML 力不从心（书里第2篇讲正则也强调其局限）。
- **HTML 解析器**：把 HTML 变成 **DOM 树**，按标签/属性/类名提取。本书用 **HtmlParser**：`extracLinks()` 过滤 `<a>` 标签和 `<frame>` 的 src，抽出链接（宽度优先爬虫靠它发现新 URL，第1篇第1.2.3 节 `HtmlParserTool`）。
- **XPath / CSS 选择器**：更精准地定位节点，是现代解析主流。
- **文本清洗**：去停用词(stopword)、分词，为挖掘（分类/聚类）做准备（第3篇）。

## 关键参数 / 易错点
- **编码**：gb2312 / utf-8 必须设对，书里 `parser.setEncoding("gb2312")`——错了中文全乱码。
- **链接过滤（filter）**：只收符合规则的 URL（如以某域名开头），避免爬偏。
- **正则不适合整页 HTML**：嵌套结构正则写不出、易错；优先用解析器。
- **动态渲染页**：内容由 JS 生成，静态抓 HTML 拿不到，需无头浏览器（见 [[反爬虫]]）。
- **标签噪声**：广告/导航/脚本要剔除，只留正文。

## 类比（帮助理解）
> 像从一锅杂烩汤里用漏勺把想要的料（链接、标题、价格）捞出来——汤（HTML 标签）倒掉，料（结构化数据）留下。

## 设计时怎么用（反推思维）
> 设计抽取器时，我会**先分析目标页 DOM 结构**（反推选择器/字段位置），优先用解析器或 XPath 而非正则；对 JS 页面改无头浏览器渲染方案；解析规则与抓取解耦，做成可配置的抽取模板。

## 典型应用 / 我在哪见过
- 抽取商品信息（名/价/库存）、新闻正文、链接发现（宽度优先爬虫的灵魂）。
- 本书：第1篇 `HtmlParserTool` 抽链接；第2篇系统讲正则+解析器做抽取。
