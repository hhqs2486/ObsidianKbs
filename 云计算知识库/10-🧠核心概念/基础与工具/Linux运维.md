# Linux运维

## 一句话定义
> Linux 运维 = 对运行 Linux 的服务器 / 集群做「部署、监控、调优、故障排查、自动化」，是云上一切服务的地基。

## 它解决什么问题 / 为什么存在
- 应用最终跑在操作系统上。不懂 Linux，就无法让服务稳定上线、出问题时定位不到根因、扩缩容时手忙脚乱。
- 它是连接「写好的代码」与「用户能用的服务」的地基；也是 [[系统架构]] 与 [[服务器虚拟化]] 的承载面。

## 核心原理（大二能懂的水平）
- **一切皆文件**：配置在 `/etc`，日志在 `/var/log`，进程在 `/proc`。
- 权限模型：用户 / 组 + rwx + `sudo`；服务多走 systemd（`systemctl start/enable`）。
- 网络：防火墙（iptables / nftables / firewalld）、端口监听（`ss` / `netstat`）、DNS。
- 资源：CPU（`top`/`htop`）、内存、磁盘（`df`/`du`/`iostat`）、IO。
- 自动化：Shell 脚本 + cron + 配置管理（Ansible / Salt）。

## 关键参数 / 易错点
- 磁盘满（`df -h` / `du`）是头号线上事故；**inode 耗尽**也会「空间有但写不进」。
- `ulimit` / 文件描述符上限；`net.ipv4.tcp_*` 等内核参数调优。
- 易错：`rm -rf` 误删；改 `/etc` 配置没备份；防火墙开了没放端口。
- 排障顺序：看日志 → 看资源 → 看网络 → 看进程。

## 类比（帮助理解）
- Linux 运维像「大楼物业」：电路（供电）、水管（网络）、电梯（调度）平时看不见，一旦罢工整栋楼瘫痪；好物业靠监控 + 预案 + 自动化把事故消灭在萌芽。

## 设计时怎么用（反推思维）
> - 需求「服务 7x24 稳定」→ 反推：systemd 托管 + 日志轮转（logrotate）+ 监控告警（[[运维监控系统]]）+ 资源预留。
> - 需求「快速扩百台机器」→ 反推：镜像 + 自动化脚本 + [[高可用]] 架构，而非手工登每台。
