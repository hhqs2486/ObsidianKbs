# 服务器虚拟化

## 一句话定义
> 服务器虚拟化 = 用一层「虚拟机监控器（Hypervisor）」把一台物理服务器切成多台相互隔离的 [[虚拟机]]，每台都以为自己独占硬件。

## 它解决什么问题 / 为什么存在
- 物理机资源利用率低（一台只跑一个应用，CPU 长期 5%）；业务隔离差（一个挂全挂）；扩容靠买机器、周期长。
- 虚拟化让「一台变 N 台」，资源池化、灵活分配，是云计算的底层技术之一（见 [[虚拟化KVM]]、OpenStack）。

## 核心原理（大二能懂的水平）
- Hypervisor 两类：Type-1（裸金属，如 KVM / VMware ESXi）直接跑硬件；Type-2（宿主型，如 VirtualBox）跑在 OS 上。
- 通过 CPU 虚拟化（Intel VT-x / AMD-V）、硬件辅助实现「近似原生」性能。
- 计算 / 网络 / 存储都做虚拟化（vCPU、虚拟网卡、虚拟磁盘），由 [[高可用]] 机制做迁移 / 快照。
- 演进：虚拟机 → 容器（[[容器]]，更轻、共享内核）→ 云原生。

## 关键参数 / 易错点
- **超分（overcommit）**：vCPU / 内存可超分配，但过度超分会「邻居吵闹（noisy neighbor）」互相拖累。
- 易错：虚拟化开销被忽略（IO 密集业务损耗明显）；许可证按物理核计费。
- 与容器区别：VM 隔离强（内核级）、启动慢；容器启动秒级、密度高。

## 类比（帮助理解）
- 服务器虚拟化像「把大仓库用隔板分成多个独立小仓」：每家以为自己独占整仓，实则共享建筑与水电；隔板（Hypervisor）保证一家着火不殃及别人。

## 设计时怎么用（反推思维）
> - 需求「多租户强隔离 + 跑不同 OS」→ 反推：用 [[虚拟机]]（KVM），而非容器。
> - 需求「高密度、快速启停的云原生负载」→ 反推：用 [[容器]] + [[Kubernetes]]，虚拟机只作底层底座。

## 典型应用 / 我在哪见过
- 公有云（[[弹性云服务器ECS]]）、OpenStack（见 [[虚拟化KVM]]）、企业私有云。
