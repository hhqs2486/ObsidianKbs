# bash

## 一句话定义
> bash（Bourne-Again Shell）是 Linux/Unix 上默认的命令行解释器，既能让你在终端逐条敲命令，也能把一堆命令写成脚本文件自动运行——它是 Linux 自动化的总入口。

## 它解决什么问题 / 为什么存在
- 手动敲命令慢、易错、不可重复。bash 把"人一遍遍手动操作"变成"机器按工序单自动执行"，让备份、发布、巡检这类重复活儿一次写好、处处可跑。
- 它是连接你和内核的"翻译 + 调度"层：你写人话（命令/脚本），它拆词、展开、fork 子进程去真正干活。

## 核心原理（大二能懂的水平）
- 读取输入（终端或脚本）→ 逐行解析（拆词、做变量/通配符/命令替换展开）→ 对每条命令 fork 一个子进程去执行 → 收集退出状态 `$?`。
- bash 自己只是"解释器"，真正干活的要么是外部命令（`/bin/ls`、`/usr/bin/grep` 等 PATH 里的程序），要么是内置命令（`cd`、`echo`、`read`、`export` 等，不 fork 子进程）。
- 脚本首行的 `#!/bin/bash`（shebang）告诉系统"用哪个解释器来跑我"。

## 关键参数 / 易错点
- 变量赋值 `var=value`：**等号两侧不能有空格**（有空格就变成"运行命令 var 并传参"）。
- `$?` 退出状态：命令成功返回 `0`，失败返回非 `0`（这是 `if` 判断和管道后面判断成败的依据）。
- 三个保命开关：
  - `set -e`：任意命令失败立刻退出脚本（防错误雪崩）；
  - `set -u`：用到未定义变量直接报错（防拼错变量名静默出错）；
  - `set -x`：打印每条实际执行的命令（排障神器）。
- `bash script.sh` 与 `source script.sh`（或 `. script.sh`）的区别：前者开**子 shell** 跑，脚本里改的环境变量不影响当前终端；后者在**当前 shell** 跑，能改你的环境变量（常用于 `source ~/.bashrc`）。
- bash 与 sh（POSIX）的差异：`[[ ]]`、`数组`、`<()` 进程替换、`{a,b}.txt` 大括号展开是 bash 独有，写 `#!/bin/sh` 时不能用。

## 类比（帮助理解）
- bash 像工厂的「总调度」：你写一张工序单（脚本），它按单子把一个个工人（命令）叫起来干活，最后把完工报告（`$?`）交给你。哪个工人干砸了（非0），单子可以选择停下或记一笔。

## 设计时怎么用（反推思维）
> 做运维 / [[CI-CD]] 系统时，凡是"按固定步骤重复做"的事（备份、发布、健康检查、批量建用户），都先用 bash 串成脚本；再把它挂进 [[CI-CD]] 流水线里自动跑，而不是人工逐台登录敲命令。

## 典型应用 / 我在哪见过
- 日志按天切割、MySQL 自动备份、批量创建系统账户、服务存活巡检。
- 在 [[CI-CD]] 里作为"构建 / 部署 / 冒烟测试"步骤的载体（见 249 个脚本合集与 100 个案例里的实战脚本）。
