# 网络爬虫

## 一句话定义
> 一种按既定规则**自动遍历并抓取互联网信息**的程序/脚本，本质是在"互联网这张大图"上做遍历。

## 它解决什么问题 / 为什么存在
- 百度、Google 如何获取亿级网页并实时更新？靠的就是爬虫。
- 即使有搜索引擎，"深入整合信息"的需求仍广泛存在：企业把爬来的数据做数据仓库多维展现、做数据挖掘来源；个人也会为炒股专门抓股票信息（第1篇前言）。
- 简言之：**把散落在各网页上的非结构化信息，集中采集回来供后续使用**。

## 核心原理（大二能懂的水平）
- 把互联网看成一张超级大的"图"：**网页=节点，页面里的超链接=有向边**。
- 从一个或多个**种子 URL**出发：
  1. 下载该页 HTML（抓取）；
  2. 从页面里抽出新链接（这一步靠 [[网页解析]]）；
  3. 把新链接放入 **TODO 队列**，已处理的放入 **Visited 表** 去重；
  4. 循环，直到队列空或达到数量上限。
- **遍历策略**：最常用**宽度优先（BFS）**——重要网页通常离种子更近、利于多爬虫合作；深度优先易陷"黑洞"；**带偏好的爬虫**用 PageRank 给链接算重要性、按优先级抓（第1篇第1.2 节）。
- **抓取 = 发 HTTP 请求读响应**：用 HttpClient（或任意 HTTP 客户端）模拟浏览器，`GetMethod`/`PostMethod` 取正文；POST 可传不限长参数，GET 受 URL 长度限制。
- **HTTP 状态码决定动作**（第1篇第1.1.4 节）：200 成功取正文；3XX(301/302/303/307) 跟随 `Location` 重定向；4XX(400/401/403/404)、5XX 直接丢弃。

## 关键参数 / 易错点
- **去重**：Visited 表必须用 `HashSet`（O(1) 查找、Key 不重复），否则海量 URL 下性能崩（书里 `LinkQueue` 用 HashSet）。
- **状态码处理**：重定向必须跟随，4XX/5XX 别傻等。
- **超时**：连接超时 + 读取超时都要设（书里设 5s），否则一个慢站拖死整个爬虫。
- **URL 长度**：参数多用 POST，GET 有长度上限。
- **礼貌/合规**：控制频率、遵守 robots.txt，别把对方服务器打挂（见 [[反爬虫]] 的攻防视角）。

## 类比（帮助理解）
> 像图书馆管理员按书架顺序逐本翻书：把感兴趣段落抄下来（抓取），书里"参见 XX 书"的引用再列入待抄清单（提取链接入队），已经抄过的书不再抄第二遍（Visited 表）。

## 设计时怎么用（反推思维）
> 做数据采集系统时，我会用**网络爬虫作为"数据入口"**：先定种子 URL 和抓取策略（宽度优先 or 带偏好），再分层接 [[网页解析]] 与存储；把它当成一个可独立部署、可水平扩展的 [[微服务]]。

## 典型应用 / 我在哪见过
- 搜索引擎建库、比价/价格监控、舆情监控、竞品分析、死链检测。
- 本书第1篇即从零实现了宽度优先爬虫（Java：`Queue`/`LinkQueue`/`DownLoadFile`/`HtmlParserTool`/`MyCrawler`）。
