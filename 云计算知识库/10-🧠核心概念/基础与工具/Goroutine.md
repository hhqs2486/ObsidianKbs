# Goroutine

## 一句话定义
> Goroutine 是 Go 运行时管理的轻量级线程，用 `go` 关键字一行启动，以「极低开销（初始栈 2KB）+ 多路复用到 OS 线程」实现海量并发。

## 它解决什么问题 / 为什么存在
- OS 线程太重（默认栈 MB 级、创建 / 切换成本高），C10K~C100K 连接用线程模型撑不住。
- Goroutine 让单机轻松跑数十万并发任务——这正是云原生高并发服务的底座，也是 [[Go语言]] 被称为云原生母语的核心原因。

## 核心原理（大二能懂的水平）
- `go func()` 即启动一个 Goroutine；由 Go 调度器（G-P-M 模型）在少量 OS 线程上多路复用。
- 通信靠 **Channel（CSP 模型）**：`ch := make(chan int)`，`ch <- v` 发送，`v := <-ch` 接收。
- 无缓冲 channel 做同步交接；有缓冲 channel 解耦生产 / 消费。
- 共享变量用 `sync.Mutex` / `sync.WaitGroup` / 原子操作避免竞争（race）；`context.Context` 做超时与取消。

## 关键参数 / 易错点
- 默认无并发数限制 → 需 worker pool 或信号量（`chan struct{}`）限流，防资源耗尽。
- 易错：**Goroutine 泄漏**（channel 永不关闭、没有退出条件）；用 `context` 控超时。
- Go 1.22 前 `for i := range` 循环变量会被闭包共享，注意捕获。
- 检测竞争：`go run -race`。

## 类比（帮助理解）
- OS 线程像「正式员工（工位 + 电脑，成本高）」；Goroutine 像「随时叫来的兼职，几秒到岗、干完就走」，一个主管（调度器）把成千上万兼职排到几个正式员工上并行干活。

## 设计时怎么用（反推思维）
> - 需求「一个请求要并发调 10 个下游服务并汇总」→ 反推：起 N 个 Goroutine + 一个聚合 channel，用 `context` 控超时。
> - 需求「高并发网关 / 代理」→ 反推：每连接一个 Goroutine，天然契合 [[微服务]] / [[容器]] 化网关。

## 典型应用 / 我在哪见过
- 高并发 API 网关、消息消费、Kubernetes controller 的 informer 监听（见 [[Kubernetes]]）。
