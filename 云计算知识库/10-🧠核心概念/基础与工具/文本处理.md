# 文本处理

## 一句话定义
> 文本处理是对纯文本做"清洗、提取、转换、统计"的一类操作；sed、awk、grep 是 Linux 下最经典的命令行三件套，运行在命令行环境（依赖 Linux基础 的终端与文件系统概念）之上。

## 它解决什么问题 / 为什么存在
- 现实里大量数据是纯文本：日志、配置、CSV、命令输出。需要快速抽取有用信息、批量改写、生成报表，而不必打开大型软件或写重程序。文本处理让"一行管道解决的小需求"成为可能。

## 核心原理（大二能懂的水平）
- 核心范式是"流(stream) + 模式(pattern)"：数据像水流过一组过滤器，每个过滤器只做一件事，靠管道 `|` 串起来（Unix 哲学"小而专、可组合"）。
- 经典分工：**grep 找行、sed 改行（行级流编辑）、awk 拆列算列（列级结构化处理）**。
- 流式处理边读边算，不整文件加载，对大文件很友好。

## 关键参数 / 易错点
- 分工铁律：**sed 做行级流编辑（替换 / 删除 / 打印），awk 做列级结构化处理（按字段 / 模式处理文本）**——别用 sed 硬解字段，也别用 awk 硬做整行替换。
- 管道思维：小工具组合（`grep | sed | awk | sort | uniq`）胜过巨型单程序。
- 不确定就先不加 `-i`，先看 stdout 输出再决定改不改文件。
- 注意编码 / 换行符：Windows 的 CRLF 在 Linux 下会多出 `\r`，可用 `dos2unix` 或 `sed 's/\r$//'` 清掉。
- 大文件谨慎：awk / grep 流式很快；把全文件读进内存的写法会 OOM。

## 类比（帮助理解）
- 像"自来水厂的净水流程"：原水（原始文本）依次过沉淀（过滤行）、加药（替换）、分质（按列分流），最后出水（干净结果）。每道工序独立、可重组。

## 设计时怎么用（反推思维）
> 做日志分析 / 配置管理 / [[CI-CD]] 中的文本转换时，我会先判断"这是行级还是列级"，再选 sed 还是 awk，把处理拆成可组合的小步——这也是从需求反推工具的典型训练。

## 典型应用 / 我在哪见过
- 日志清洗（去敏感字段、抽关键行）
- 报表生成（awk 分组计数 + END 汇总）
- 配置批量改写（sed 遍历 `*.conf`）
- 数据抽取进库（awk 抽列 → 拼 INSERT）
