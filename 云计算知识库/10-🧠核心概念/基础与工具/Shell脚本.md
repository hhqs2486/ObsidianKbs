# Shell脚本

## 一句话定义
> Shell 脚本是把一系列 Shell 命令写进文件、可重复执行的小程序；sed、awk、grep 常在脚本里充当"文本处理零件"，靠管道串成流水线。

## 它解决什么问题 / 为什么存在
- 把人工在终端敲的多条命令自动化、可复现：每天凌晨跑日志分析、批量改几百台机器配置、构建前做代码检查。一次写好，处处可跑——也是 [[CI-CD]] 流水线里最常见的载体。

## 核心原理（大二能懂的水平）
- Shell（如 bash）逐行读命令、解释执行；支持变量、条件(`if`)、循环(`for`/`while`)、管道(`|`，把一个命令输出喂给下一个)、重定向(`>` `>>` `<`)。
- sed/awk 通过管道嵌入：`cat log | awk '...' | sort | uniq -c`，每个工具只做一件事，组合出复杂处理。

## 关键参数 / 易错点
- 管道 `|` 是 sed/awk 最常用搭档：`cmd | awk '{...}'`。
- 变量赋值 `x=1` 等号两侧**无空格**；引用变量用 `"$x"` 防分词 / 空格炸裂。
- `$(...)` 做命令替换：`now=$(date)`（反引号 `` `...` `` 同义但已不推荐）。
- 脚本开头 `#!/bin/bash`（shebang）指明解释器。
- 易错：管道里的变量赋值发生在子 shell，不影响父 shell——想改原文件得用 `-i` 或重定向写回。
- 加固：`set -e` 遇错即停、`set -u` 防未定义变量，脚本更稳。

## 类比（帮助理解）
- 像"厨房的标准作业流程(SOP)"：把"洗菜→切菜→下锅"写成清单，任何人照做都能复现同一道菜。Shell 脚本就是给机器看的 SOP。

## 设计时怎么用（反推思维）
> 做运维自动化 / [[CI-CD]] 流水线时，我会把重复的手工步骤沉淀成 Shell 脚本，其中 [[sed]] [[awk]] 负责文本转换环节，让"部署 / 清洗 / 报表"一键可复现。

## 典型应用 / 我在哪见过
- 日志轮转脚本（`mv` + 发信号重载）
- 批量改配置（`sed -i` 遍历）
- CI 构建步骤（编译、单测、打包）
- 数据预处理（awk 抽取 → 拼 SQL → 入库）
