# 大数据

## 一句话定义
> 大数据 = 体量（Volume）、速度（Velocity）、多样（Variety）超出传统单机 / 关系库处理能力的数据集合，及其「采集 → 计算 → 服务 → 应用」的全链路体系。

## 它解决什么问题 / 为什么存在
- 数据量从 GB 到 EB（阿里 PB~EB 级、单表日增千亿行），传统数据库算不动、存不下、出数慢。
- 大数据体系把「海量、多样、实时」的数据变成可复用的资产与决策依据，是 [[数据中台]]、[[数据仓库]]、[[离线计算]]、[[实时计算]]、[[数据治理]] 的上层概念。

## 核心原理（大二能懂的水平，以阿里体系为例，《大数据之路》）
- **四层架构**：
  - 数据采集层：Aplus.JS / UserTrack 日志、TimeTunnel 传输、DataX 同步。
  - 数据计算层：[[离线计算]] MaxCompute + [[实时计算]] StreamCompute + OneData 整合。
  - 数据服务层：OneService 接口化对外。
  - 数据应用层：搜索 / 推荐 / 广告 / 大屏。
- 统一整合方法 [[数据中台]]（OneData）+ 统一服务（OneService）避免数据烟囱。
- 分层 [[数据仓库]]（ODS / DWD / DWS / ADS）+ [[数据治理]] 保质量。

## 关键参数 / 易错点
- 数据爆炸式增长（2020 全球超 40ZB）；处理需 EB 级存储、千亿级记录。
- 易错：不做分层 → 数据冗余与口径不一致；只采集不治理 → 「数据灾难」。
- 离线按天 / 小时、实时秒级，按业务时效选型。

## 类比（帮助理解）
- 大数据像「城市自来水系统」：水源（采集）→ 水厂净化分层（计算 / 仓库）→ 管网送达各家（服务）→ 居民用水（应用）。没有水厂，源头的水再多也喝不上。

## 设计时怎么用（反推思维）
> - 需求「老板要大屏实时看双 11 成交」→ 反推：[[实时计算]]（StreamCompute）+ 实时服务推送。
> - 需求「T+1 报表与用户画像」→ 反推：[[离线计算]]（MaxCompute）+ [[数据仓库]] 分层。

## 典型应用 / 我在哪见过
- 阿里双 11 实时大屏、用户画像、搜索推荐；与 [[数据中台]] [[数据仓库]] [[离线计算]] [[实时计算]] [[数据治理]] 配合。
