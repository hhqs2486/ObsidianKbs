# 云容器引擎CCE

## 一句话定义
> 云容器引擎（Cloud Container Engine，CCE）是华为云上「托管的 Kubernetes 集群服务」——你不用自己装 K8s 控制面，华为帮你管，你只管往里部署 [[容器]] 应用。

## 它解决什么问题 / 为什么存在
- 自建 [[Kubernetes]] 控制面（APIServer / etcd / 调度器）运维重、易出错。CCE 把 K8s 当托管服务交付，降低 [[云原生]] 落地门槛，让团队专注写业务而非管集群。

## 核心原理（大二能懂的水平）
- CCE 集群 = 控制面（华为托管、自带 [[高可用]]） + 节点（用 [[弹性云服务器ECS]] 或 [[裸金属服务器BMS]] 当 worker 节点，节点在 [[虚拟私有云VPC]] 子网里）。
- 你用 kubectl / 控制台部署 [[容器]]，由 [[容器编排]]（K8s 调度器）分配到节点；CCE 对接 [[对象存储OBS]]（作为存储类 / PVC）、[[负载均衡ELB]]（把 Service / Ingress 暴露到公网）。
- 简单说：**CCE 就是华为云里的 [[Kubernetes]]**，把「跑容器」变成一项开箱即用的云服务。

## 关键参数 / 易错点
- 集群类型：CCE Standard（节点池管理 ECS）、CCE Turbo（面向高性能，Pod 直接用 VPC 子网 IP）。
- 网络模型：VPC 网络（容器网段独立于节点网段） / 容器隧道网络（Overlay）。
- 节点池 / 节点规格、可用区分布、插件（监控、日志、存储）。
- 易错：节点子网要规划够 IP（否则扩节点失败）；容器镜像放 SWR（容器镜像服务）；Turbo 集群对 VPC 网段有特殊要求。

## 类比（帮助理解）
- 像「租了带管家的 Kubernetes 厨房」：锅碗瓢盆（控制面）房东管、还保证不罢工（高可用），你只负责炒菜（部署应用）。

## 设计时怎么用（反推思维）
> 做「微服务 / [[云原生]] 应用、要弹性扩缩、要用 K8s 生态」的系统时，用 [[云容器引擎CCE]] 跑 [[容器]]——它就是华为云里的 [[Kubernetes]]。计算节点用 ECS、网络用 VPC、对外暴露用 ELB、持久化用 OBS。

## 典型应用 / 我在哪见过
- 本书未单列 CCE 实验，但在弹性文件服务（SFS）说明里点名「容器（CCE & CCI）」可挂载共享文件系统——说明 CCE 是华为云承载 [[容器]] 的一等公民。
- 理解 CCE = 理解 [[云原生]] 在华为云的落点，与 [[弹性云服务器ECS]]（纯虚机）形成「虚机 vs 容器编排」的互补。
