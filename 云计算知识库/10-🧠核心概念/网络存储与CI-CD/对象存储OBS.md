# 对象存储OBS

## 一句话定义
> 对象存储服务（Object Storage Service，OBS）是「无限容量、按对象存文件」的网盘式存储，适合图片 / 视频 / 备份 / 静态网站等非结构化数据。

## 它解决什么问题 / 为什么存在
- 云硬盘（EVS）是块存储，要格式化、容量有限且绑单机；OBS 是对象存储，海量、免格式化、HTTP 直接访问、多 AZ 冗余，适合「随便存、随时取」的大文件。

## 核心原理（大二能懂的水平）
- 数据以「桶（Bucket）+ 对象（Object，含 Key/Value/元数据）」组织。桶名全局唯一；通过 REST API / 控制台 / OBS Browser+（用 AK/SK 鉴权）访问。
- 支持标准 / 低频 / 归档存储类别、多版本控制、桶策略（私有 / 公共读）。本书实验四实操。

## 关键参数 / 易错点
- 桶名（全局唯一、不可改名）、存储类别（标准 / 低频 / 归档）、冗余策略（单 AZ / 多 AZ）、桶策略、多版本控制。
- 易错：桶名全局唯一且不可改；删桶前先清空对象；公共读有泄露风险；AK/SK 别硬编码到代码里。
- 本书实操：建桶 cloud-service-hw（多 AZ、标准存储、私有策略）；上传/下载/分享文件；开启多版本后可恢复被改/删的对象。

## 类比（帮助理解）
- 像「带无限格子的自助储物柜」，每件东西贴标签（Key）随时取，不怕格子不够；多版本像「每次改东西都留底稿，能翻回旧版」。

## 设计时怎么用（反推思维）
> 做「存图片 / 视频 / 日志 / 备份、或静态网站、或给 [[云容器引擎CCE]] / [[弹性云服务器ECS]] 当共享文件仓库」时，用 [[对象存储OBS]]；热数据放标准，冷数据归档省钱。

## 典型应用 / 我在哪见过
- 本书实验四：建桶、上传下载分享、多版本控制、OBS Browser+（AK/SK）管理。
- 云日志服务 ICAgent 安装脚本也托管在 OBS 桶上（实验五）。
