# 弹性伸缩AS

## 一句话定义
> 弹性伸缩（Auto Scaling，AS）按业务负载自动「加机器 / 减机器」，让 ECS 实例数量随流量涨跌。

## 它解决什么问题 / 为什么存在
- 固定台数 ECS 要么高峰扛不住、要么低谷浪费钱。AS 按策略自动扩缩，省成本又保稳，是 [[高可用]] 与降本的关键手段。

## 核心原理（大二能懂的水平）
- 三大件：伸缩配置（机器模板，指定镜像 + 规格 + 登录方式）、伸缩组（机器集合 + 边界：最大/最小/期望实例数 + 挂在哪个 VPC/子网）、伸缩策略（定时 / 周期 / 告警触发加减）。
- 健康检查发现坏机器就自动换掉。本书实验二、综合实验六用 AS + 业务镜像实现网站服务器自动增减。

## 关键参数 / 易错点
- 最大 / 最小 / 期望实例数；策略类型（告警 / 定时 / 周期）；冷却时间；健康检查间隔（默认 5 分钟）。
- 易错：伸缩配置要基于「做好了的镜像」，否则新机器没业务环境；告警策略依赖监控代理采集指标；期望 ≠ 最小；多 AZ 均衡分布提升可用性。
- 本书实操：as-group 设最大 5 / 期望 2 / 最小 1；周期策略 18:00 加 1 台、23:00 减 1 台；综合实验六用 CPU≥60% 加、≤20% 减。

## 类比（帮助理解）
- 像「餐厅按客流量自动加凳子 / 收凳子」，不空着也不挤爆；坏凳子（健康检查失败）自动换掉。

## 设计时怎么用（反推思维）
> 做「流量有波峰波谷的 Web / 计算」系统时，用 [[弹性伸缩AS]] + 业务镜像，配合 [[负载均衡ELB]] 把流量分给伸缩出的多台 [[弹性云服务器ECS]]，达成 [[高可用]] 与省钱。

## 典型应用 / 我在哪见过
- 本书实验二：创建伸缩配置 / 伸缩组 / 周期策略，验证带宽伸缩。
- 综合实验六：以 Web 服务器镜像为模板，按 CPU 水位自动扩缩网站业务节点。

## 关联
- 前置知识：[[弹性云服务器ECS]]、[[虚拟私有云VPC]]
