# 数据仓库

## 一句话定义
> 数据仓库 = 面向分析的「主题化、集成、相对稳定」的数据存储与建模体系，通过分层（ODS → DWD → DWS → ADS）把原始数据加工成信息资产。

## 它解决什么问题 / 为什么存在
- 业务库（OLTP）为事务优化，不适合跑复杂分析（慢、连表炸）。
- 数据仓库按「分析」重新组织数据，让报表 / BI / 挖掘又快又稳，且口径统一（见 [[大数据]]、[[数据中台]]）。

## 核心原理（大二能懂的水平，阿里分层）
- **ODS**（操作数据层）：贴源原始数据。
- **DWD**（明细数据层）：清洗、脱敏、规范化后的明细事实。
- **DWS**（汇总数据层）：按主题 / 维度预聚合（如用户日粒度汇总）。
- **ADS**（应用数据层）：面向具体报表 / 应用的结果。
- 加工过程实现「数据资产 → 信息资产」转化；配 [[数据治理]]（元数据 / 质量）。

## 关键参数 / 易错点
- 离线数仓按天（或小时 / 周 / 月）出数；实时数仓秒级（见 [[实时计算]]）。
- 易错：**层间职责不清**（明细里塞聚合）；维度不一致导致指标对不上。
- 建模：星型 / 雪花模型、维度建模（Kimball）是主流。

## 类比（帮助理解）
- 数据仓库分层像「原材料 → 净菜 → 预制菜 → 成品套餐」：ODS 是带泥蔬菜（原样），DWD 是洗切好的菜（干净明细），DWS 是配好的半成菜（汇总），ADS 是端上桌的套餐（应用结果）。

## 设计时怎么用（反推思维）
> - 需求「每天出经营日报」→ 反推：ODS 入仓 → DWD 清洗 → DWS 汇总 → ADS 出报表，跑在 [[离线计算]]。
> - 需求「口径统一不背锅」→ 反推：公共层（DWD / DWS）由 [[数据治理]] 管维度与指标定义。
