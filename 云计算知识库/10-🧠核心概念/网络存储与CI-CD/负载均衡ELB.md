# 负载均衡ELB

## 一句话定义
> 弹性负载均衡（Elastic Load Balance，ELB）把外部访问流量「按策略分给后端多台服务器」，既是流量分流器，也是 [[高可用]] 开关。

## 它解决什么问题 / 为什么存在
- 单台 ECS 扛不住并发，且一旦挂了服务就断。ELB 横向扩展应用能力 + 消除单点故障，是 [[负载均衡]] 在华为云里的具体实现。

## 核心原理（大二能懂的水平）
- 建 ELB（共享型 / 独享型）→ 加监听器（前端协议端口，如 HTTP:8881）→ 建后端服务器组（分配策略：加权轮询 / 最少连接 / 源 IP）→ 加后端 ECS（端口 + 权重）→ 健康检查（ELB 主动探活，坏节点自动摘除）。
- 流量从 ELB 的公网 / 私网 IP 进入，分发到健康后端。本书实验三、综合实验六实操。

## 关键参数 / 易错点
- 实例规格类型（共享型 / 独享型）；前端协议端口；分配策略类型；健康检查协议 / 端口 / 间隔（默认 5 秒）；后端端口 / 权重。
- 易错：后端 ECS 安全组要放通健康检查端口，否则节点被误判不健康；删 ELB 前先移除后端；私网 ELB 用内网 IP，公网 ELB 配 EIP。
- 本书实操：共享型 ELB + HTTP 监听器 8881 + 加权轮询 + 后端端口 8889 + 健康检查 HTTP/8889；用 `curl` 验证流量在 SERVER1 / SERVER2 间轮转。

## 类比（帮助理解）
- 像「餐厅门口领位员」，把客人均匀分到各桌；某桌撤了（健康检查失败）就别再带客人去。

## 设计时怎么用（反推思维）
> 做「多实例 Web / API、要容错与扩展」的系统时，用 [[负载均衡ELB]] 前置多台 [[弹性云服务器ECS]]（或 CCE 节点），再配合 [[弹性伸缩AS]] 动态扩缩，达成 [[高可用]]。ELB 即是 [[负载均衡]] 在华为云的落地。

## 典型应用 / 我在哪见过
- 本书实验三：ECS 起 http 服务，ELB 做流量分发验证。
- 综合实验六：ELB 把网站访问流量分发到多台 Web 服务器，配合 AS 实现网站级高可用。
