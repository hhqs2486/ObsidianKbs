# 实时计算（流处理）

## 一句话定义
> 实时计算（流处理）= 对「源源不断产生的数据流」做毫秒 ~ 秒级的持续计算，典型如阿里 StreamCompute、开源 Flink / Kafka Streams。

## 它解决什么问题 / 为什么存在
- 业务要「现在发生、现在知道」：双 11 实时大屏、实时风控、实时监控。
- 离线按天太慢（见 [[离线计算]]）。实时计算让数据「边产生边算」，秒级出结果（见 [[大数据]]）。

## 核心原理（大二能懂的水平）
- 以「无界数据流（unbounded stream）」为输入，事件驱动、状态化计算。
- 组件：消息中间件（Kafka / TimeTunnel）供数 → 流引擎（Flink / StreamCompute）算 → 结果写存储 / 推送。
- 关键能力：窗口（window）、状态（state）、Exactly-Once 语义、乱序与 watermark。
- 与 [[离线计算]] 互补：实时出快数、离线出准全量（Lambda / Kappa 架构）。

## 关键参数 / 易错点
- 时效：秒级 ~ 亚秒级；但「精确一次」需引擎 + 上游配合。
- 易错：状态过大撑爆内存；窗口乱序导致丢数；峰值流量背压（backpressure）。
- 与 [[数据仓库]] 关系：实时结果常落 ADS / 明细层供查。

## 类比（帮助理解）
- 实时计算像「水库实时监测」：水（数据）一边流一边测水位流量（边算边出），一旦超限立刻报警；不像月底盘库等 accumulated。

## 设计时怎么用（反推思维）
> - 需求「双 11 成交大屏每秒刷新」→ 反推：Kafka + [[实时计算]]（Flink）+ 实时推送服务。
> - 需求「交易反欺诈（秒级拦截）」→ 反推：流计算 + 规则引擎 + 实时告警。

## 典型应用 / 我在哪见过
- 阿里双 11 媒体大屏、实时风控；与 [[大数据]] [[数据仓库]] [[离线计算]] [[数据中台]] 配合。
