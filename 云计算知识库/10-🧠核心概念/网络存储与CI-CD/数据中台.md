# 数据中台

## 一句话定义
> 数据中台 = 把企业各业务数据「统一采集、统一模型、统一服务」的方法体系与平台（阿里 OneData + OneService），让数据可复用、口径一致、避免重复建设。

## 它解决什么问题 / 为什么存在
- 各业务线各建一套数据（数据烟囱），口径不一、重复开发、成本翻倍。
- 数据中台用「一套标准、一个资产层、统一服务出口」把数据变成共享能力，业务方能自助取数（见 [[大数据]]）。

## 核心原理（大二能懂的水平）
- **OneData**：统一的数据整合及管理方法 / 工具——规范维度、业务过程、指标定义，构建全域公共数据层（DWD / DWS），避免冗余与不一致。
- **OneService**：统一数据服务平台，以接口方式对外提供「简单查询 / 复杂查询 / 实时推送」三类服务，屏蔽底层存储（MySQL / HBase / RDS / TableStore）。
- 核心思想：**复用 > 重复**；沉淀公共层，业务方在应用层（ADS）组装。

## 关键参数 / 易错点
- 强调「方法论 + 工具 + 组织」三位一体，不是买个软件就成。
- 易错：只有平台没有统一建模 → 仍是烟囱；指标定义没收敛 → 口径打架。
- 与 [[数据仓库]] 区别：数仓偏「存储计算分层」，中台偏「资产复用 + 服务化」。

## 类比（帮助理解）
- 数据中台像「中央厨房」：各门店（业务线）不用各自买菜切菜，中央厨房统一备好净菜和半成品（公共数据层），门店按需炒（应用层），口味一致、成本低。

## 设计时怎么用（反推思维）
> - 需求「多个业务线都要用户画像 / 成交指标」→ 反推：建 [[数据中台]] 公共层，避免每条线各算一遍。
> - 需求「前端要稳定低延迟取数」→ 反推：OneService 接口化，屏蔽底层 [[数据仓库]] 细节。
