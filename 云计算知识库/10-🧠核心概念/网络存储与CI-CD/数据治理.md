# 数据治理

## 一句话定义
> 数据治理 = 保证数据「找得到、看得懂、信得过、管得住」的一整套机制：元数据管理、数据质量、模型规范、成本与安全。

## 它解决什么问题 / 为什么存在
- 数据多了反而成灾：找不到（谁有这数据）、看不懂（字段啥意思）、不可信（口径不一、脏数据）、管不住（存储算力成本失控）。
- 治理让数据资产可控、可信任，是 [[大数据]] 体系的保障层（见 [[数据仓库]]、[[数据中台]]）。

## 核心原理（大二能懂的水平，阿里实践）
- **元数据（Metadata）**：「关于数据的数据」，打通源 → 仓 → 应用全过程；分技术元数据（表 / 列 / 分区 / 作业）与业务元数据（维度 / 指标 / 业务过程）。是治理的底座。
- **数据质量**：监控（空值、重复、波动）、告警、故障定位。
- **计算 / 存储成本管理**：找超长运行节点、回收无用表、生命周期管理。
- **模型与规范**：统一维度 / 指标定义（与 [[数据中台]] OneData 同源）。

## 关键参数 / 易错点
- 易错：只建平台不建规范 → 元数据脏、质量无保障。
- 价值落到「计算 / 存储 / 成本 / 质量 / 安全 / 模型」六类治理域。
- 与 [[数据仓库]] 关系：治理管「怎么分层的规矩与质量」，数仓是承载。

## 类比（帮助理解）
- 数据治理像「图书馆编目 + 质检」：元数据是索书号（找得到），业务元数据是书的内容简介（看得懂），质量检查是剔除非盗版错页（信得过），成本管理是下架没人借的书（管得住）。

## 设计时怎么用（反推思维）
> - 需求「报表数字对不上、被业务质疑」→ 反推：上 [[数据治理]]，统一指标定义 + 质量监控。
> - 需求「存储算力账单爆了」→ 反推：元数据找长任务 / 冷数据，做生命周期治理。
