# DevOps

## 一句话定义
> DevOps 是一套整合软件开发（Dev）与 IT 运维（Ops）的文化、方法论与工具链，目标是用自动化把代码快速、稳定地变成可交付、可运维的软件。

## 它解决什么问题 / 为什么存在
- 开发与运维之间壁垒高、"抛过墙"式交付：开发写完就丢给运维，上线难、回滚慢、故障互相甩锅。
- 传统发布周期长（书里提到某些企业 TTM 长达 1~1.5 年），无法响应市场变化。
- 缺乏统一的度量与自助能力，IT 服务没法像产品一样被内部用户按需取用。

## 核心原理（大二能懂的水平）
- **文化**：开发运维一体、共担责任、小步快跑、快速反馈；落地要从"组织、技术、流程"三个维度一起改（内参强调单买工具没用）。
- **技术主线**：用 [[CI-CD|CI/CD]] 自动化流水线贯穿软件生命周期的 7 个环节——代码 → 构建 → 测试 → 打包 → 发布 → 配置 → 监控。
- **度量（DORA 四大指标）**：变更前置时间、部署频率、故障恢复时间（MTTR）、变更失败率。只有跟踪这些指标，DevOps 的价值才看得见。
- **平台化**：把 IT 能力产品化，提供统一工作台与自助服务（如开发者自己查生产日志、自动开/销账号），打通工具链做到自动化与自助化。

## 关键参数 / 易错点
- DORA 数据（devops-cloud 引用）：采用 DevOps 后部署效率提升约 **46 倍**、变更速度提升约 **2500 倍**、故障恢复快约 **2600 倍**、变更失败率低约 **7 倍**。
- 易错 1：把 DevOps 等同于"装一套 Jenkins"——它本质是文化+流程+工具，工具只是载体。
- 易错 2：只做 [[持续集成]] 不做 [[持续部署]]，交付价值大打折扣；内参指出"从持续发布开始"是企业落地最大痛点。
- 易错 3：没有监控就和没有闸门一样，CD 直接上生产会放大事故。

## 类比（帮助理解）
- 像一条把"写菜谱"（开发）和"开餐厅上菜"（运维）打通的中央厨房：厨师和服务员共用同一套订单系统，菜做出来立刻能上桌，翻车也能秒级重做，而不是各自闷头干、最后拼成一个没人敢吃的拼盘。

## 设计时怎么用（反推思维）
> 做需要频繁上线、快速响应市场的系统时，我会用 DevOps 把发布流程自动化、把监控左移，让"小步快跑、出了问题秒回滚"取代半年一次的大版本豪赌。

## 典型应用 / 我在哪见过
- 互联网公司高频发布（一天多次部署）是 DevOps 的天然土壤。
- 华为云全栈端到端 DevOps（基于华为云打造，覆盖硬件到开发者工具）。
- 基于容器云的 DevOps 平台三层架构：基础设施层（IaaS/CaaS，基于 [[Kubernetes]]+[[容器]]）→ 基础服务层（注册中心、编排、伸缩漂移）→ DevOps 层（需求/设计/开发/测试/发布串接、看板）。
