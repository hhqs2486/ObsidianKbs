# 软件定义数据中心

## 一句话定义
> 软件定义数据中心（Software-Defined Data Center, SDDC）是把计算、存储、网络全部用软件抽象与池化，由统一软件平面自动化管理整个数据中心，硬件只是可被按需调度的资源池。

## 它解决什么问题 / 为什么存在
- 传统数据中心硬件强绑定、扩容慢、运维靠人肉、资源无法弹性调度。
- 企业希望像云一样"按需取用"资源，同时保留本地可控与安全合规。

## 核心原理（大二能懂的水平）
- 三大支柱都要"软件定义"：
  - 计算虚拟化（如 [[vSphere]]/ESXi）
  - 软件定义存储（如 vSAN，把服务器本地盘组成分布式存储）
  - 软件定义网络（如 NSX，分布式交换/路由/防火墙/负载均衡）
- 统一自动化管理平面（如 **SDDC Manager**）负责整个堆栈的部署、补丁、升级、重新配置，并能感知 [[Kubernetes]]、编排 vSphere Pod Service。
- VMware Cloud Foundation（VCF）是 SDDC 的完整套件：用 SDDC Manager 全自动把 vSphere 部署成私有云，包含 vSAN 与 NSX-T。

## 关键参数 / 易错点
- 关键判定：计算、存储、网络**三者都**软件定义 + 统一自动化，才算 SDDC；只做服务器虚拟化不算。
- 易错：把"用了 [[虚拟机]]"当成 SDDC——那只是虚拟化的一小步，缺了存储/网络的软件定义与统一编排。
- 与超融合关系：超融合偏"硬件集成架构"，SDDC 偏"软件管理平面"，二者常结合（见 [[超融合]]）。

## 类比（帮助理解）
- 像把电厂（计算）、水厂（存储）、管网（网络）全部改成可由一个中央调度系统按需分配的"公用事业"，而不是每家企业自己买发电机、挖水井、拉私线。

## 设计时怎么用（反推思维）
> 做企业私有云/混合云底座时，我会用 SDDC 思路把三类资源池化，用 SDDC Manager 自动化生命周期（部署/补丁/升级），把运维复杂度从"人肉伺候硬件"降到"点几下配策略"。

## 典型应用 / 我在哪见过
- VMware Cloud Foundation（VCF）作为标准化、可重复的混合云体系；
- 企业从传统虚拟化平滑演进到"既能跑 VM、又能跑云原生"的现代数据中心。
