# 超融合

## 一句话定义
> 超融合（Hyper-Converged Infrastructure, HCI）是把计算、存储、网络集成到标准 x86 服务器节点、并用软件统一管理的架构；横向加节点即可同时扩容算力与容量。

## 它解决什么问题 / 为什么存在
- 传统三层架构（计算/存储/网络分离）：SAN 存储贵、扩容复杂、运维割裂，小企业根本玩不起也养不动。
- 业务需要"小步扩容、开箱即用"的本地底座，而不是一次性重资产机房建设。

## 核心原理（大二能懂的水平）
- 每个节点"既是计算又是存储"：跑 Hypervisor（如 ESXi）提供算力，同时用软件把本节点磁盘组成分布式存储（如 vSAN），统一软件平面管理。
- 扩容方式：**加节点 = 加算力 + 加容量**，线性扩展，无需单独采购和配置外置存储。
- VMware 的超融合实现即 **vSAN + vSphere**：本地盘经 vSAN 抽象为集群共享存储，给 VM 和 K8s 持久卷用。

## 关键参数 / 易错点
- 与 [[软件定义数据中心]] 的关系：超融合偏"硬件集成/交付形态"，SDDC 偏"软件管理与资源平面"，两者常结合——HCI 是 SDDC 的常见落地形态。
- 易错 1：以为超融合 = 分布式存储。它包含"计算+存储一体"，存储只是其中一层。
- 易错 2：把超融合和分离式架构混为一谈；与 [[OpenStack]] 那种计算/网络/存储分层独立部署的路线是正交思路。

## 类比（帮助理解）
- 像乐高积木块：每块都自带"CPU+硬盘+网卡"，拼几块就得到一个更大的统一资源体；而不是先盖好机房、再单独拉存储柜、再布线——拼装即扩容。

## 设计时怎么用（反推思维）
> 做中小规模私有云或边缘/分支站点（ROBO）时，我会用超融合降低部署与运维复杂度，一个节点一个节点地扩，避免一开始就背上传统三层架构的沉重包袱。

## 典型应用 / 我在哪见过
- VMware vSAN 超融合集群；作为 VMware Cloud Foundation 的底层硬件形态。
- 边缘计算、远程办公室、需要快速交付的标准化私有云节点。
