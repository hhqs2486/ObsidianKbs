# 自我进化与多模态实时

## 这条教程在解决什么
两章合起来回答一个递进问题：文本世界的 Agent 已经能靠上下文、工具、代码做事，但①它**不会自动变强**（每次都得从头探索），②它**跳不出对话框**（听不懂语音、看不了屏幕、控制不了物理世界）。第8章给出"不改模型权重的进化"路径——自我进化（外部化学习）；第9章把视角从纯文本推向**多模态实时交互**，并揭示语音/Computer Use/机器人三类场景共享"多模态 + 实时性"两道坎，共同推动架构从串行流水线走向端到端/全双工。

## 关键内容（按 PDF 章节提纲）
### 第8章 自我进化（ch09）
- **动机（8.1–8.2）**：为什么 Agent 不会自动学习？注意力擅长"检索"不擅长"归纳统计"，无限上下文也不会自动把"具体记录"提炼成"一般模式"，且上下文越长检索质量越差（上下文腐化）。三种学习范式定位：后训练（改权重、成本高周期长）/ 上下文学习 ICL（临时、随会话消失）/ 外部化学习（文件·知识库·工具，持久可解释可修正）。自我进化 = 外部化学习，把知识流程从参数和临时上下文抽成可持久、可检索、可复用的外部资源。
- **反思 Reflection（8.4.1）**：Reflexion（Shinn et al., 2023）——任务失败后 LLM 用自然语言复盘失败原因，存入情景记忆，下次同类任务读取避免重蹈覆辙；不改权重，语言承载的反思信息量远大于标量奖励。失败经验沉淀为错误模式库、负面规则。
- **自我改进循环（8.4、8.4.4）**：外部化学习闭环 = 完成任务→产生原始经验→提炼(总结·压缩·结构化)→存入外部系统(知识库/工具)→检索复用。三种产物：事实性→知识库；参数复杂频繁用→代码工具；常变涉策略→Skill 文档。系统提示词自动优化（Karpathy"系统提示学习"、DSPy/OPRO/GEPA）从边界案例提炼规则，数据效率高、完全可解释。
- **经验学习（8.3、8.4、8.4.3）**：从"聪明"到"熟练"——学到的是动态非公开领域知识（某运营商退订填特定表单、某优惠适用条件）。分层机制（表8-2）：知识提炼(策略摘要/工作流录制/失败反思)→知识组织(Skills/睡眠整合)→知识应用(系统提示词优化)→工程支撑(跨会话续跑)。睡眠整合（Claude Code MEMORY.md、Hermes 常驻 daemon）异步后台把零散经验去冗余融合成长期记忆。
- **轨迹回放（8.4，PreAct）**：工作流录制（browser-use-rpa）= 首次用多模态 LLM 观察-思考-行动，系统从 DOM 树提取元素 XPath+操作+参数+验证信息，存成参数化工作流；回放时语义匹配+Playwright 执行，参数由轻量 LLM 填入模板。PreAct 把成功轨迹编译成带**验证谓词**的状态机（回放前先核对实时屏幕），并设"存前验证"闸门防止烂流程入库。Voyager 在 Minecraft 把成功操作沉淀为可组合技能库。长任务跨会话续跑：Initializer Agent 生成 feature-list.json/progress.json，Coding Agent 循环恢复现场。

### 第9章 多模态与实时交互（ch10）
- **多模态输入（视觉/语音）**：多模态=同时处理文字/语音/图像/视频/动作。静态图像理解已成熟（当感知工具用），本章聚焦**实时**多模态（语音对话/Computer Use/机器人），难点在"持续流动输入 + 严格时间预算"。
- **实时交互架构（9.2–9.5）**：语音三范式演进——级联(VAD→ASR→LLM→TTS 串行)、端到端全模态 Omni(单模型听想说，仍轮流)、全双工(Moshi/GPT-Live 边听边说，取消轮次)。主线是"如何摆脱 VAD 对轮次的猜测"。全链路流式化把级联端到端压到 600-800ms；流式语音感知（Ultravox/Qwen2-Audio，因果/分块编码器）替代 VAD+ASR，输出声学事件 token（<speak_start>/<interrupt>/<emotion>）。思考架构（9.6）调和实时响应与深度思考：方案一快慢并行(自相矛盾)、方案二慢当军师(后台推理经状态栏回传)、方案三 Step-Audio R1 边想边说(MGRD 声学锚定思考 + MPS 双脑并行)；快慢之间接口 Latent Bridge（潜 token 而非文本）。
- **流式输出（9.3.1、9.4）**：ASR 边听边转、LLM 按句切分、TTS 句级流式合成，三级重叠成流水线工位；Qwen3-Omni 用多码本因果 codec 首包 234ms。
- **ASR / TTS（9.3、9.7）**：ASR 把音频转文字（Whisper/SenseVoice 50-200ms，大模型/受限环境 200-500ms），新路线基于 LLM 的流式听觉感知合并"识别+理解"；TTS 把文字转语音（200-500ms），"更像人"的做法是让 LLM 输出控制标记([THINKING]/[EMO]/[SPEED])驱动 TTS，或用 voice cloning 多参考音库。
- **延迟与打断处理（9.3、9.5）**：级联延迟 VAD(500-800)+ASR(50-200)+LLM(100-500)+TTS(200-500)≈0.9-2.3s；排队论总延迟≈空载×1/(1-ρ)，ρ=0.8→5倍。打断（barge-in）：全双工天然支持（一直在听），级联需专门检测；gpt-realtime 异步函数调用把工具延迟藏在对话中。
- **Computer Use / 视觉理解（9.8）**：感知-思考-行动循环（截图→多模态模型输出思考+动作→执行→再截图）。视觉定位(Grounding)三路线：SoM(分割模型切区域编号)、DOM/Accessibility Tree(结构化元素索引，最稳)、纯坐标预测(需双向坐标缩放按宽高比匹配训练分辨率)。AOI 中间件把"帧叙述成持久文字"补上连续/音频感知。实时性瓶颈：串行循环不会提前想，效率远低于人类，靠快慢解耦(纯文本契约)把慢藏起来。
- **机器人（9.9）**：双层架构=长程规划(慢,VLM)+VLA 控制(快,视觉-语言-动作)；动作分块(π₀ 50Hz 下 25-50/块)摊薄推理延迟；Sim2Real 用领域随机化弥合现实差距。

## 我卡住/没懂的地方
- "文本代理思考 Textual Surrogate Reasoning"为何会让思考链越长性能越差，而 MGRD 声学锚定后反而链越长越准——机制上还需要再多读 Step-Audio R1 原文才完全吃透。
- Latent Bridge 在游戏场景有效（r≈0.9 相关），但"何时值得请慢军师"的判定在工程上如何自动决策，原文只给相关性未给决策算法。
- Computer Use 连续视觉流（看视频/动画）目前只有 AOI"帧叙述成文字"的近似解，真正的时序视觉理解仍是开放问题。

## 它背后的原理（别只记操作）
- **学习不会自动发生，必须显式设计**：注意力的"检索而非归纳"本质决定了——无限上下文也不自动提炼规律，必须靠额外一次 LLM 调用把经验压成结构化知识（外部化学习）。
- **知识载体决定能力边界**：后训练(参数)/ICL(上下文)/外部化(文件·知识库·工具)对应三种载体，协同而非竞争；自我进化把能力扩展逻辑从"模型内部"延伸到"外部世界规模"。
- **延迟由两处构成且只有一处可重叠**：计算延迟(转录/思考/合成)靠流式化重叠；流水线开工前提(VAD 静音等待)压不掉，必须替代 VAD 本身——这是级联→Omni→全双工演进的根本推力。
- **快慢解耦是 2026 主流**：前台轻量交互模型 + 后台冻结的前沿推理模型，可随时换用最新"大脑"，避免把快速演进的推理能力塞进同一模型（移动靶子问题）。

## 我能复用/改编的点
> 换个需求，这套做法还能怎么用？
- 做**长期运行的客服/办公 Agent**：加"任务完成后反思总结"环节，把成功路径压成策略摘要或参数化工作流存知识库，并设"存前验证"闸门防止烂流程入库——直接套用 ch09 外部化学习闭环。
- 做**语音/电话 Agent**：按延迟-成本-自然度取舍三范式，优先全链路流式化 + 流式语音感知替代 VAD，并用 GPT-Live 式"快慢解耦"把深度思考藏后台，避免让用户干等。
- 做**Computer Use/浏览器自动化**：视觉定位优先 DOM/Accessibility Tree 索引（最稳），无结构界面回退坐标预测(双向缩放)；加 AOI 观察中间件处理动态/音频内容；用"快慢解耦 + 纯文本契约"隐藏慢操作延迟。
- 做**机器人/具身控制**：长程规划(VLM) + VLA 控制(动作分块) 双层；Sim2Real 用领域随机化 + 环境对齐 + 背景替换弥合现实差距。
