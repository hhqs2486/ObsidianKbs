# Agent 评估与模型后训练

## 这条教程在解决什么
- 评估（第6章）：当 Agent 系统面对大量没有标准答案的设计选择（选什么模型、工具、知识库、用户记忆、提示词、Harness 约束）时，如何科学地判断"哪个更好、改动到底有没有用"。给出"评估环境 → 数据集 → 评估方法 → 驱动决策"的完整体系。
- 后训练（第7章）：评估与仿真环境是后训练的基石；本章回答"如何真的改动模型权重，把能力沉淀进参数"——即预训练 / SFT / RL 三阶段，以及 RLHF / DPO / PPO 等算法、奖励模型、偏好数据、模型蒸馏。

## 关键内容（按 PDF 章节提纲）
### 评估（第6章）
- 为什么 Agent 难评估：评估对象应是"模型 + Harness 组合体"而非孤立模型；用模型替换实验（固定 Harness 只换模型）区分"瓶颈在模型还是 Harness"；消融实验（关掉某组件）定位 Harness 内部哪个部件重要。
- 评估三层次：①评估环境（在哪测：工具调用型 Verifiers / 人机交互型 τ-bench / 仿真环境）；②评估方法（数据集设计、指标体系、LLM-as-Judge、配对比较与排名）；③评估驱动决策（模型选型、架构优化、持续迭代）。
- 数据集设计原则：明确性 vs 开放性、真实性 vs 可控性、多样性 vs 系统性、成本 vs 覆盖、防数据泄漏（canary GUID、动态参数生成、时间新鲜度 SWE-bench-Live）。
- 指标体系：过程指标（行动合法率、路径效率、检索覆盖率、成本与延迟）、结果与质量（Pass@k / Pass^k / Best@k 的区别）、安全合规（零容忍否决项）、鲁棒性；轨迹(trajectory) 与结果(outcome) 双重覆盖。
- LLM-as-Judge：Rubric 四准则（基于专家指导、全面覆盖含陷阱项、标准重要性权重含一票否决 Veto、自包含评估）；防范长度偏差与同源模型问题 → 多源异构评判；扩展到多模态（TTS / ASR / UI / 视频）。
- 配对比较与排名：Elo / Bradley-Terry 模型、位置偏差缓解（交换顺序各评一次）。
- 模型选型与成本：TTFT、p95 尾部延迟、KV Cache（省 30-60% 输入）、上下文累积使成本非线性增长；特性开关（编译时/运行时）、AB 测试、统计显著性（标准误、McNemar 配对分析、多重比较）。
- 可观测性（Trace / span 树）、从 Benchmark 报告到改进（观察 → 假设 → 实验 → 决策 → 迭代）、内部评估基础设施、仿真环境（评估 → 后训练的桥梁，RLVR 可验证奖励）。

### 后训练（第7章）
- 三阶段全景：预训练（海量文本预测下一个词）→ SFT（换了数据、只在回答上算损失的预测下一个词）→ RL（最大化期望奖励）。
- 主线一：SFT 记忆、RL 泛化（可测量，GeneralPoints / V-IRL 实验量化规则 OOD 与视觉 OOD 下 SFT 掉、RL 涨）。
- 主线二：数据与环境比算法更重要——很多场景只要 SFT 数据质量到位，甚至不需要 RL。
- 先 SFT 后 RL（先形后神）；LoRA 参数高效微调（加全部主要权重矩阵、RL 用小 rank）。
- SFT vs RL 本质对比（优化目标、信号、学到的东西、分布漂移、样本效率、稳定性）；何时选哪个的决策框架（先问要不要后训练 → 先试 SFT → SFT 不够才加 RL）。
- RLHF：InstructGPT 三段式（SFT → 奖励模型 → PPO）、KL 惩罚（反向 KL、mode-seeking）、奖励模型过优化 / reward hacking、DPO（跳过显式 RM）、RLHF vs RLVR 关系。
- 算法比较：PPO（带价值网络裁剪）、GRPO（组内相对、无价值网络）、DPO / KTO（离线偏好优化）、Best-of-N（推理时）；在线/离线、on/off-policy 术语对齐。
- 奖励设计：二元/过程/结果奖励、PRM（过程奖励模型）/ ORM（结果奖励模型）、生成式奖励模型、RLVP（奖励结果、惩罚路径，组内方差解释）。
- 工具调用 RL（ReTool、AWorld-train、loss masking 屏蔽环境反馈 token）、On-Policy Distillation（在轨 + 稠密信号，样本效率约 RL 的 1/10）。
- 完整图景：后训练 vs RAG vs ICL 三个互补旋钮；八条常见陷阱。

## 我卡住/没懂的地方
- GRPO 与带价值网络的 PPO 在长程多轮信用分配上的取舍边界（何时必须用 PPO）。
- RLVP 的"可达性门控"如何在具体任务里先验诊断（文中提到用少量 base rollout 测组内方差）。
- 生成式奖励模型与策略模型"协同进化"时的训练稳定性如何保证。

## 它背后的原理（别只记操作）
- 评估的本质是把"没有度量就没有改进"落到 Agent：评估的是"模型 + Harness"组合，且首要价值是能快速跟上模型演进（数小时内给出切换决策），而非给当前系统打分。
- SFT 本质是换了数据、只在回答上算损失的预测下一个词 → 极大似然 → 记忆；RL 在线、按奖励塑形 → 探索泛化。两者是流水线（先形后神）而非三选一。
- "在线/离线"与"信号密度"是贯穿 RL 的两把尺：SFT = 离轨 + 稠密信号，RL = 在轨 + 稀疏信号，On-Policy Distillation = 在轨 + 稠密信号。信号越密，样本效率越高。
- KL 惩罚（反向 KL、mode-seeking）是 RLHF 稳定的核心：把策略摁在参考分布附近，防 reward hacking 与分布崩塌。

## 我能复用/改编的点
- 做 Agent 系统时，先搭可复现评估集（数据集 + Rubric + 自动判分），用模型替换实验定位瓶颈在模型还是 Harness，避免盲目换模型。
- 评估集与训练集严格隔离；好的评估环境改造一下就能当训练环境（SWE-Gym、τ²-bench / AndroidWorld 参数化模板）。
- 是否值得后训练：先用 Harness / 提示词 / 工具设计解决，再试 SFT（固化格式协议），最后才上 RL（泛化、探索最优策略）。很多场景高质量 SFT 就够了。
- 开放式任务用 LLM-as-Judge 评分时，要 Rubric 四准则 + 多源评判 + 防长度偏差 + 金标校准（kappa > 0.7）才可信。
