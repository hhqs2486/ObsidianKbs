# 05-Coding Agent 与代码生成

## 这条教程在解决什么
- 回答一个核心问题：**以开放任务为目标的通用 Agent，架构长什么样？** 答案是——一个 Coding Agent（能自主编写、修改、执行代码的 Agent）加上文件系统。
- 把"代码生成"从"写程序的小工具"提升为 Agent 的**元能力（meta-capability）**：能在运行时动态创造新工具、新约束、新表达形态，因此不必预先把所有能力都预制好。

## 关键内容（按 PDF 章节提纲）
### 5.1 Coding Agent
- **5.1.1 Coding 是基础能力**：七个核心工具——Code Interpreter（沙盒跑 Python）、Bash Shell、Read/Write/Edit File、Glob（文件名匹配）、Grep（内容匹配）。五类操作天然对应六个工具，第七个 Code Interpreter 对应"执行代码/计算"。组合可完成几乎所有任务（例：整理 TODO 清单只用 Grep + Write）。
- **5.1.2 从 Manus 到 OpenClaw**：Coding Agent + 文件系统是开放任务型通用 Agent 的核心内核。文件系统是记忆/知识/能力中枢（MEMORY.md 高层事实、SOUL.md 身份规则、按日归档、Git 回滚）。**适用边界**：垂直封闭场景（客服/语音助手）以 Coding 为"工具箱里的一件工具"而非架构中枢；但具备 coding 能力是所有 Agent 的共同底线。
- **5.1.3 Sessionless 设计**：无会话常驻，状态分两层——文件系统天然持久（workspace 挂持久存储），进程状态按需保活/重建（序列化工作目录、环境变量、后台任务清单）。
- **5.1.4 安全**：
  - 致命三要素（Simon Willison）：访问私有数据 + 暴露于不受信任内容 + 具备外部通信能力 → 攻击闭环；本书补充第四维**持久记忆**（跨会话潜伏放大器）。
  - 沙盒工程选型：网络出口**默认断网、白名单代理放行**；源码只读挂载、凭证不挂载；资源限额+超时返回**结构化错误**。
  - 安全校验：**语义解析**而非关键字黑名单（Shell 组合爆炸可绕过黑名单）；**推测性执行**让安全检查"隐形"（UI 提示先行、检查后台并行）。
  - 多方委托下的**忠诚度**：主人指令最高，外部内容默认降格为"可参考但无指令效力"。
  - 信任边界**下移到数据层**：权限内嵌的数据对象，每次写入由运行时流水线强制执行不变量（"不可能错"，代价约 2ms/次）。
- **5.1.5 整体流程（五步）**：① 项目文档化（无文档则自动生成 CLAUDE.md/AGENTS.md 项目指令文件）→ ② 需求澄清 → ③ 设计文档（交人审）→ ④ 编码与测试（测试-修复内循环，平均 2-3 轮收敛）→ ⑤ 代码审查与文档同步。关键原则：**计划先于行动、验证贯穿始终、文档与代码共同演化**。"远程友好团队也对 Agent 友好"是 AI-ready 的代理指标。
- **5.1.6 Harness 工程**：四类组件——验收基线（测试/CI/审查标准）、执行边界、反馈信号（Linter/测试/类型检查）、回退手段（Git/沙盒/快照）。任务四象限：目标明确+可自动验证最佳（代码编写天然在此象限，故成熟度最高）。原则：约束优先于指导、验证自动化、反馈越快越好、回退可靠。工具编排做**故障边界控制**（故障只在同一批并行调用内传播）。
- **5.1.7 故障与错误恢复**：四层故障（API/工具/上下文/控制流）；检测**先分类再计数**（重复调用指纹、连续失败计数、空闲看门狗）；分级恢复（静默重试→降级接续→暴露用户）；每条恢复路径有**熔断上限**（如压缩连续失败 3 次即放弃，阈值来自产线统计）；防护死亡螺旋（错误路径禁用再调 LLM、递归深度计数）。
- **5.1.8 实现技巧**：并行+流式执行（参数一完整即启动）；上下文精细化管理（行号标注、输出头尾截断）；环境信息动态注入（Agent 状态栏：cwd/git 分支/未暂存变更）；持久化终端会话；即时语法反馈（写文件后自动跑 lint 作为工具返回值）。
- **5.1.9 搜索工具**：grep（正则内容）/ glob（文件名）/ 语义搜索（向量+BM25+reranker）/ 符号引用（LSP）四种互补，"从粗到细、从语义到语法"。路线之争：Claude Code 不建索引纯靠 agentic grep+glob；Cursor 愿建嵌入索引换跨文件语义召回。
- **5.1.10 文件编辑**：五种方案对比——Diff+Apply（Cursor）/ Old→New（Claude Code，可靠优先）/ 行号（IDE 深度集成才可靠）/ 类 Vim / 首尾匹配（大段删除免全输出）。自建建议：从 Old→New 起步，大段改动用首尾匹配。

### 5.2 代码：通用 Agent 的元能力（六个方向）
1. **思考工具**：用代码（sympy/scipy/约束求解）替代易错的自然语言推理（模型负责理解，代码解释器负责精确计算）。
2. **业务规则约束**：自然语言规则 → 代码化校验。τ-bench 航空取消政策**三重保障**：提示词自然语言规则 + 参数作为 checklist 引导核对 + 服务端基于数据库**真值**的代码化校验（最后守门员）。
3. **多媒体生成**：PPT（Slidev + Proposer-Reviewer 机制，Vision LLM 看渲染）、视频（Blender/FFmpeg API 替代 GUI 操作）。
4. **系统适配器**：现场生成适配代码连接异构 API；日志自适应解析；生产日志智能诊断（生成回归测试+通过 MCP 创建 GitHub Issue）。
5. **生成式 UI**：A2UI 声明式协议（Agent 只输出界面清单，客户端用受信任组件渲染，防 XSS 类风险）；HTML 交付取代 Markdown 汇报；动态表单澄清意图；生成 SQL artifact 让数据绕过 LLM 直达前端。
6. **Agent 自举**：用代码修复/创建同类 Agent（OpenClaw doctor 自我修复；基于范例"复制脚手架+定向修改"而非从零写，继承最佳实践）。

### 5.3 小结
核心始终是：代码是 Agent 形式化思考与精确表达的语言；Coding Agent 成熟度高不是因为模型强，而是软件工程几十年的基础设施（测试/Linter/Git）天然构成强 Harness。

## 我卡住/没懂的地方
- 本章**未点名 SWE-bench** 这个具体基准，但其评测思想（以仓库自带测试为验收基线、仓库级端到端修复）与 SWE-bench 完全一致。详见 [[SWE-bench]] 卡片。
- "信任边界下移到数据层"需要 schema 把不变量写全、且堵死不可信层直连数据库的路径——工程落地成本不低，需结合具体系统权衡。

## 它背后的原理（别只记操作）
- **为什么 Coding Agent 成熟度高**：不是代码生成模型特别强，而是软件工程几十年攒下的基础设施（测试套件、类型系统、版本控制、Linter）天然构成一套强大的 Harness——可验证性最高。
- **代码作为元能力**：代码精确、可执行、可组合，因此能创造新工具（脚本/API）、新约束（断言/校验）、新表达（HTML/PPT/视频），Agent 不必预制所有能力。
- **形式化思考 vs 概率思考**：LLM 思考是概率性、近似的；代码执行是确定性、精确的；分工让各司其职（模型理解问题，解释器算精确答案）。
- **约束优先于指导 / 信任边界下移**：能把正确性"焊死"在代码层（Linter/CI/服务端真值校验），比寄望模型自觉可靠得多——这是第一章"约束优先于指导"的终极形态。

## 我能复用/改编的点
> 换个需求，这套做法还能怎么用？
- 做 Coding Agent 时，先把**验收基线定为"测试套件通过"**，而非"代码写完"——把"何时停止"交给验证判定（Loop 工程"由验证判定何时可以停"）。
- 故障恢复**不搞笼统重试**：维护"错误→恢复策略"映射表，先分类再计数，每条路径设熔断上限；长连接配独立看门狗。
- 文件编辑**从 Old→New 起步最稳**，大段改动用首尾匹配；慎用行号方案（除非 IDE 实时维护行号映射）。
- 搜索四件套组合：**语义 → 正则 → 符号**，从粗到细。
- 长内容生成（PPT/视频）用 **Proposer-Reviewer 拆分上下文**，避免主上下文膨胀、注意力分散。
- 不可逆操作（取消订单/转账/删数据）用**三重保障**：自然语言解释 + 参数 checklist 引导核对 + 服务端真值校验，最后一道防线建立在模型无法伪造的数据上。
- 任意长任务用 **Sessionless + 状态两层管理**：文件系统持久、进程状态序列化重建。
