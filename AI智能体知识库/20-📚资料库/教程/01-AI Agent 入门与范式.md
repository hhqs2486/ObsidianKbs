# 01-AI Agent 入门与范式

## 这条教程在解决什么
- 建立对 AI Agent 的全局认知，回答三个根本问题：**什么是 Agent、为什么需要 Agent、Agent 如何组成并运行**。
- 给出贯穿全书的元公式：**Agent = LLM + 上下文 + 工具**（大脑 + 眼睛 + 手脚），以及生产形态扩展式 **Agent = Model + Harness**。
- 从实践出发拆解三大支柱（上下文 / 工具 / 模型），为后续每一章建立统一的术语与参照坐标。

## 关键内容（按 PDF 章节提纲）

### 引言（ch01）
- 本书缘起：把 Agent 设计从"感觉驱动"变成"原则驱动"；行业规律是**实践在前、命名在后**——不要等名词流行才动手。
- 核心公式：Agent = LLM + 上下文 + 工具；直觉层"大脑+眼睛+手脚"；学术层映射到强化学习的 Policy / Observation Space / Action Space。
- 全书结构三大部分：基础（第1章）、三大支柱（第2–7章：上下文 / 工具 / 模型）、进阶应用（第8–10章：自我进化 / 多模态 / 多 Agent）。
- 术语约定（极重要）：**reasoning 统一译为"思考"**（模型展开中间推导、"想"的过程），**inference 译为"推理"**（模型前向计算与部署运行），二者不可混淆。
- 两个贯穿全书的硬原则：① 拥有关极高能力上限的真实业务 + 持续反馈；② 必须建立 [[评估]] 机制——没有评估就没有进步。

### 第1章 AI Agent 入门（ch02）
#### 1.1 现代 Agent = LLM + 上下文 + 工具
- **大脑（LLM）**：决策核心，理解意图→规划→执行；能"内部思考"再行动；具备零样本泛化与少样本适应；"模型即 Agent"范式把工具调用决策经后训练（尤其 RL）内化为原生能力。
- **手脚（工具）**：Agent 与外部世界交互的桥梁，分五类——感知 / 执行 / 协作 / 事件触发 / 用户沟通。[[函数调用 Function Calling]] 四步流程：声明工具→模型决策调用→结果追加上下文→模型决定下一步。
- **眼睛（上下文）**：Agent 在每决策点能看到的全部信息，由五部分构成——系统提示词、工具定义（静态前缀）+ 用户消息、模型回复（思考+内容+工具调用）、工具执行结果（动态轨迹）。**上下文 = 静态前缀 + 轨迹**。实验1-1 消融证明每一部分都不可替代。
- **ReAct 循环**：思考(Reasoning)→行动(Acting)→观察(Observing) 的迭代，轨迹不断累积；多币种汇总示例仅 3 轮、4 次工具调用即完成。

#### 1.2 Harness 工程：模型之外的竞争力
- 公式扩展：**Agent = LLM + [上下文 + 工具 + 约束 + 验证 + 纠正] = Model + Harness**。最小公式(Demo) ⊂ 扩展公式(生产)。
- Harness 五要素：Context（感知信息）、Tools（行动手段）、Constrain（行为边界）、Verify（结果对错）、Correct（错误恢复）。
- 工程范式演进（层层包含）：软件工程 → 提示工程 → 上下文工程 → Harness 工程 → Loop 工程。
- 三个核心原则：保持简单、保持透明；**ACI（Agent-Computer Interface）**——从 Agent 视角设计接口，用"防呆(Poka-yoke)"让错误无法发生。
- 模型选择：御三家(OpenAI/Anthropic/Google)、国内模型、开源闭源；绝大多数 Agent 需要支持"思考"的模型。
- 编排模式：工作流（确定性路径）vs 自主 Agent（动态决策，本质即 ReAct 循环）；实践中常混合；主流框架对比（Agents SDK / Claude Agent SDK / LangGraph / n8n / Dify / CrewAI / OpenClaw）。
- 护栏与安全性：输入侧 / 执行侧 / 输出侧三层防线；人工干预(Human in the loop) 作关键保护。

#### 1.3 本章小结
- 眼睛（上下文）是决定因素；Harness 是竞争力所在；编排顺序"提示词→工作流→自主 Agent"；安全是架构问题，从第一行代码就要考虑。

### 后记（ch12）：回到 Agent = LLM + 上下文 + 工具
- 三根支柱回顾：上下文("看到什么")、工具("能做什么")、模型("大脑本身"，评估度量智能 + 后训练放大智能)。
- **两朵乌云**：① 流式实时交互（按轮次 → 边想边说；快慢分离 / 推理加速两条路）；② 持续经验积累（小世界假设 vs 大世界假设）。
- **模型与 Agent 飞轮**：Agent 在真实业务里替模型趟坑，沉淀成训练信号；模型逐层"吃掉"Harness，但永不消失——Harness 随模型向新前沿迁移。这也回答了"模型会不会吃掉 Harness"：会，一层一层地吃，但终无止境。

## 我卡住/没懂的地方
- **二次方成本**：ReAct 每轮都看完整轨迹，成本随轨迹长度二次方增长——如何在不丢关键信息下打破？（思考题2，待第2章 KV Cache / 上下文压缩解答）
- **决策策略 vs 执行机制**："模型即 Agent"下 RL 内化的是"何时/如何调用工具"的**决策策略**，而非工具本身的执行——初读易混（见实验1-2 脚注）。
- **后训练层级**：预训练 / [[SFT]] / [[RLHF]] / [[微调]] / 后训练的从属关系，需第7章厘清。

## 它背后的原理（别只记操作）
- Agent 的本质是"智能系统与世界交互的基本模式"：**看到什么(上下文)、能做什么(工具)、如何决策(LLM)**——这三件事描述得不是某个模型的用法，而穿越模型迭代周期。
- ReAct 把 LLM / 上下文 / 工具串成闭环：上下文的累积性让 Agent 保持全局认知，轨迹的结构化带来可解释、可调试、可学习。
- Harness 是"《苦涩的教训》在工程时间尺度上的实践"：模型暂时做不稳的，Harness 先补；模型每内化一层，Harness 卸下一层。
- 三种学习范式互补：后训练（改权重，永久·通用·慢）、上下文学习（注意力软更新，临时·即时）、外部化学习（知识库+工具，持久·可验证）。

## 我能复用/改编的点
> 换个需求，这套做法还能怎么用？

- 设计**任何** Agent 时套用"大脑 + 眼睛 + 手脚 + Harness"清单：先定模型 → 再定上下文给什么信息 → 再定工具集 → 最后补约束/验证/纠正。
- 用**消融实验**思路验证每个上下文组件是否必要：去掉 A 看系统是否仍正常，避免堆砌无用上下文。
- 遵循"从简单到复杂"：单 LLM 调用能解决就不引工作流，工作流能解决就不上自主 Agent；用延迟/成本换性能前要权衡。
- 工具保持**通用性**（代码解释器优于专用计算器），给 LLM 更大组合创造空间；接口设计做防呆。
