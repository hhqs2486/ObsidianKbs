# Agent 拓扑

## 一句话定义
> Agent 拓扑（Agent Topology）指多智能体系统中「控制权与信息按什么结构流动」——即 Agent 之间的组织形态。它与「上下文是否共享」是两个正交维度，共同决定系统架构。

## 它解决什么问题 / 为什么存在
- 一旦选择不共享上下文，「信息如何流动、由谁协调」就成为必须显式设计的架构问题。
- 拓扑选择决定扩展性、容错性、全局视野——不同任务适配不同拓扑。

## 核心原理（大二电子信息工程专业学生能懂）
- 两个正交维度：
  1. 上下文是否共享（继承式 vs 隔离式）。
  2. 协作拓扑（控制权/信息流结构）。
- 二者理论上构成 2×3 组合矩阵；但共享上下文时拓扑常退化为「角色切换序列」（移交无需决定传什么，完整历史天然保留），架构决策少；故本书详细展开不共享上下文的三种拓扑，按复杂度递增：
  1. 对等协作（Peer Collaboration）：2–3 个平等 Agent 迭代改进（如提议者-审核者、辩论）。实现简单，适合快速原型。
  2. 管理者模式（Orchestration）：中心 Manager 调度子 Agent，适合 5+ 子任务/复杂依赖（见 [[编排 Orchestration]]）。
  3. 去中心化模式（Decentralized）：无运行时中心控制者，Agent 对等移交（handoff），如 OpenAI Swarm——控制权像接力棒在对等 Agent 间流转。
- 三拓扑都架在「数据平面（共享文件系统）+ 控制平面（消息/状态/终止）」两套与拓扑无关的基础设施之上。

## 关键参数 / 易错点
- 选型检查表（共享上下文维度）：子任务数量、上下文窗口、并行度、信息隔离、成本预算。经验法则：累计上下文将超窗口 50% → 不共享；信息零损耗为硬约束 → 共享。
- 拓扑退化：共享上下文 + 不共享上下文在「概念独立、实践相关」——共享时拓扑退化为角色切换序列。
- 易错点：把「拓扑」与「是否共享上下文」混为一谈——二者可错位组合（如 AutoGen group chat：共享对话记录 + 中心化调度，属混合形态）。

## 类比（帮助理解）
- 像公司组织结构图：对等=几个同事互相改稿；管理者=项目经理带团队；去中心化=各小组自理、按需把活递给另一组（无总办）。组织结构（拓扑）和「是否共用同一份工作日志」（上下文共享）是两回事。

## 设计时怎么用（反推思维）
> 做跨组织 Agent 协作时，我会用它能解决「彼此不信任、实现互不可见」——在内部消息总线之外，跨信任边界用 A2A 协议（Agent Card + 任务状态机 + 不透明协作），拓扑与控制流另算。

## 典型应用 / 我在哪见过
- 对等：提议者-审核者（PPT 生成）、辩论。
- 管理者：书籍翻译、并行搜索（实验10-3/10-6）。
- 去中心化：MetaGPT（SOP 流水线+消息池，伪去中心化）、AutoGen group chat（混合）、OpenAI Swarm（真对等 handoff）。
