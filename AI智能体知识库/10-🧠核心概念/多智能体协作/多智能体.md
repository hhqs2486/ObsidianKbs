# 多智能体

## 一句话定义
> 多智能体（Multi-Agent）指让多个拥有不同系统提示词、工具集与上下文的 Agent 协同工作，以突破单个 Agent 的模型能力边界与上下文窗口限制，乃至涌现出超越个体的集体智能。

## 它解决什么问题 / 为什么存在
- 单个 Agent 受限于自身模型能力与上下文窗口；让多个 Agent 协同，不仅可「取长补短」，更可能因群体组织（分工、协作、辩论、知识代际累积）涌现出高于任何个体的集体智能。
- Google DeepMind 把「大规模多 Agent 集体」列为从 AGI 通往 ASI 的关键路径之一。

## 核心原理（大二电子信息工程专业学生能懂）
- 两个正交的核心设计维度：
  1. 上下文是否共享：共享上下文（继承式，后一 Agent 继承前任完整轨迹）vs 不共享上下文（隔离式，靠文件/消息/结构化接口交换）。
  2. 协作拓扑：对等协作、管理者模式、去中心化模式（见 [[Agent 拓扑]]、[[编排 Orchestration]]）。
- 何时真优于单 Agent（关键判据）：协作是否引入「单个 Agent 生成时无法获得的新信息」？
  - 同一模型自我审查、不同 Agent 辩论同一段文本：不引入新信息 → 通常无效甚至有害（等计算量下与单 Agent 持平）。
  - Reviewer 用测试执行/渲染截图/外部工具验证：引入新信息 → 显著提升（RLEF、WebGen-Agent 实证）。
- 成本警示：多 Agent 并行探索 token 消耗约为普通对话 15 倍，效果收益须覆盖数倍~数量级开销。

## 关键参数 / 易错点
- 步骤预算与预算感知：单纯增加步骤数不保证性能提升；需显式预算感知（前期广探索、后期深挖）。
- 架构选型检查表：子任务数量、上下文窗口、并行度、信息隔离、成本预算。
- 易错点：以为「多 Agent 看着同一段文本互相讨论」就更强——无新信息的辩论常被单 Agent 在等 token 预算下反超（数据处理不等式）；有效用法几乎都带外部反馈环路。

## 类比（帮助理解）
- 像人类社会组织：单个人智力有限，但经分工协作与知识累积，整体智能远超任何天才个体；也像公司部门协作（共享上下文=围坐一桌、不共享=邮件+文档）。

## 设计时怎么用（反推思维）
> 做代码生成系统时，我会用它能解决「模型写完代码没跑测试就报完成」——加一个 Reviewer Agent 真正执行测试并把通过/失败结果反馈给 Proposer，引入编写时不存在的新信息。

## 典型应用 / 我在哪见过
- 书籍翻译（Glossary/Translation/Proofreading + Manager）、边打电话边用电脑的双 Agent、并行网页搜索。
- 提议者-审核者范式（见 [[辩论模式]] 扩展）、管理者模式、去中心化（OpenAI Swarm handoff）。
