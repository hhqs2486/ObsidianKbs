# 监督者 Supervisor

## 一句话定义
> 监督者（Supervisor）是多智能体里承担「运行时监管」的中心角色：它派生子 Agent（worker）、实时监控其状态、在成功或失败时做全局决策，并对卡住/多余的 worker 执行优雅或强制终止——即管理者模式（[[编排 Orchestration]]）中偏「控制平面」的那一半职责。

## 它解决什么问题 / 为什么存在
- 多个 worker 并行干活时，若无人监管，会出现「一者成功、余者空转」「某 worker 卡死拖垮整体」「异常无人介入」等问题。
- 需要明确一个角色负责生命周期：派活、盯进度、必要时叫停，保证系统不阻塞、不浪费。

## 核心原理（大二电子信息工程专业学生能懂）
- Supervisor 与 Manager 同源：本书把 Manager Agent 建模为「理解任务→分解→调度→综合」的中心协调者，而 Supervisor 强调其中监管闭环（对应控制平面三项能力，见 [[Agent 通信]]）：
  1. 派生子 Agent：spawn_subagent，传入任务参数与必要上下文。
  2. 状态查询：拉取（get_subagent_status）或推送（子 Agent 上报状态表），把 worker 状态建模为状态机（已提交/执行中/需输入/已完成/失败），加超时与心跳兜底。
  3. 执行终止：优雅终止（发 terminate，worker 在安全点清理资源返 ack）首选，强制终止兜底；级联终止需锁/幂等避免竞态。
- 资源决策：Supervisor 还需按复杂度动态分配步骤预算，并引导 worker 合理利用（先规划→实现→测试→改进）。
- 产品化实例：灵台（Lingtai）的「主器灵」即 Supervisor 位置——掌计划与记忆，派生「分神」短时并行 worker，收结构化结论。

## 关键参数 / 易错点
- 单点瓶颈：Supervisor 必须理解所有子任务性质、准确传上下文，决策偏差影响全局（同 Manager 风险）。
- 级联终止竞态：多个 worker 近同时上报成功，须加锁保证只结算一次、只广播一轮 terminate。
- 易错点：缺少状态查询/终止机制，系统会被一个阻塞的 worker 拖死；优雅终止要求 worker 在循环里定期检查终止信号，否则信号无从响应。

## 类比（帮助理解）
- 像工地工长：派活给工人、拿对讲机盯进度、谁干完就喊其他停工别白费力气、谁卡住就换人或叫停；也像操作系统调度器管进程生死。

## 设计时怎么用（反推思维）
> 做并行信息收集系统时，我会用它能解决「10 个 worker 找到目标后其余还在空转烧钱」——Supervisor 收到首个 target_found 即广播 terminate，其余优雅停止，加速约 15×。

## 典型应用 / 我在哪见过
- 实验10-6 并行网页搜索：Manager/Supervisor 动态起 10 个 Computer Use Agent、实时监控、级联终止、失败隔离（超时 2 分钟判失败）。
- 实验10-4/10-5 双 Agent：两 Agent 各自循环，靠状态消息与终止信号协调。
