# Agent 通信

## 一句话定义
> Agent 通信（Agent Communication）指不共享上下文的多智能体之间，通过显式机制交换信息与协调控制的全部方式——分为数据平面（产物交换）与控制平面（消息传递、状态查询、执行终止）。

## 它解决什么问题 / 为什么存在
- 不共享上下文时，Agent 无法直接访问彼此「内心活动」，协作完全依赖结构化数据传递。通信系统决定信息是否丢失、能否并行、能否调试。
- 本书开头列三种通信机制：工具调用参数、共享文件系统、消息总线。

## 核心原理（大二电子信息工程专业学生能懂）
- 数据平面（产物交换）：共享文件系统，Agent 通过统一 read_file/write_file/list_dir 访问虚拟文件系统（四类区域：专属工作区 / 共享空间 / 外部挂载 / 系统内置）。传递的是轻量路径字符串，而非把内容载入上下文。
- 控制平面三项常被忽略的能力：
  1. 消息传递：点对点（send_message_to_agent_b，Agent 少时）或消息总线（发布-订阅，异步、收发不必同时在线；Redis Pub/Sub 不持久、RabbitMQ 落盘）。消息带结构化信封：发送者 ID、目标、类型（task_assigned/status_update/result/terminate）、JSON 负载。
  2. 状态查询：拉取（get_subagent_status，轮询过密费 token、过疏不及时）vs 推送（子 Agent 主动上报状态，实时好但靠自觉）。常建模为状态机（已提交/执行中/需输入/已完成/失败）+ 超时心跳兜底。
  3. 执行终止：优雅终止（发 terminate，子 Agent 在安全点清理资源返回 ack）首选；强制终止（直接杀进程）兜底，可能留悬挂资源。级联终止需锁/幂等避免竞态（多个 Agent 近同时上报成功只结算一次）。

## 关键参数 / 易错点
- 跨组织协作用 A2A 协议（Agent2Agent）：Agent Card 能力名片 + 任务生命周期状态机 + 不透明协作（只交换任务与产物，不暴露提示词/思考），与 MCP（Agent↔工具）对照。
- 易错点：点对点连接数随 Agent 数平方增长，Agent 多时应换消息总线；级联终止有竞态，须加锁保证只广播一轮。

## 类比（帮助理解）
- 像公司邮件系统：发邮件不要求对方在线，服务器先存着（消息总线）；也像项目看板（状态机）让经理随时知道谁在干嘛、谁卡住了。

## 设计时怎么用（反推思维）
> 做并行搜索系统时，我会用它能解决「10 个 Agent 各找各的、找到后 others 还在空转」——用消息总线 + 级联终止：Agent_3 找到目标即广播 terminate，其余优雅停止，加速约 15×。

## 典型应用 / 我在哪见过
- 实验10-4/10-5 双 Agent 异步并行（电话+电脑）的点对点/总线通信。
- 实验10-6 并行网页搜索的实时监控 + 级联终止（竞态用锁解决）。
- A2A 协议（Google, 2025，捐 Linux 基金会）跨组织互操作。
