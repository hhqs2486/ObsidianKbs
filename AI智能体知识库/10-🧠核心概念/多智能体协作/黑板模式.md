# 黑板模式

## 一句话定义
> 黑板模式（Blackboard Pattern）是一种多智能体协作架构：所有 Agent 共享一块公共的「黑板」（知识空间），各自把中间结果写上去、也从上面读取他人产出，像一个团队围着同一块黑板接力写画——没有固定上下游，谁需要谁取用。

## 它解决什么问题 / 为什么存在
- 多个专长 Agent 需要就同一任务贡献部分结果，但又不想被绑死成固定流水线（那样失去灵活性）。
- 需要一种解耦的、基于「共享空间」的通信：发布者不必知道谁消费、消费者按需取用，新增 Agent 只声明订阅什么即可。

## 核心原理（大二电子信息工程专业学生能懂）
- 黑板 = 一块所有 Agent 都看得见、能读能写的公共区域；每个 Agent 是独立专家，平时各想各的，需要时把成果写到黑板上，或扫一眼黑板看别人写了啥。
- 在本书框架里，黑板可由两类基础设施实现：
  1. 共享文件系统（Shared Workspace）：Agent 通过 read_file/write_file 在 /workspace/shared 交换产物（Glossary Agent 写术语表、Translation Agent 读），是协作的数据平面。
  2. 消息池 + 订阅（如 MetaGPT）：每个角色把结构化消息发布到所有角色可见的池子，其他角色按订阅配置只取与自身职责相关的消息——发布者不知谁消费，新增角色只声明订阅哪些类型，零改动现有角色。
- 与「点对点传话」对比：黑板解耦更强，角色替换（如换更强模型）只要产出格式合规，下游无需修改。

## 关键参数 / 易错点
- 黑板需并发控制：多 Agent 同时写同一文件会丢失更新（乐观锁）；跨文件语义冲突（如图片编号被并行重编）需更高层语义校验或避免有依赖的文件并行改。
- 工作副本隔离（Git 分支/worktree）是更主流做法：各方在自己副本改，冲突推迟到合并点解决。
- 易错点：黑板看不出「文件级冲突」不代表逻辑一致——语义冲突更隐蔽（见 [[多智能体]] 失败模式）。

## 类比（帮助理解）
- 像课题组围一块白板：A 写公式、B 看到后补推导、C 取走结论画图；也像公司共享网盘里大家传文件，谁需要谁下载，不必挨个发邮件。

## 设计时怎么用（反推思维）
> 做多角色文档协作系统时，我会用它能解决「角色间硬编码传话、换一个角色全要改」——用共享文件系统当黑板，各 Agent 读写标准化产物文件，发布与订阅解耦。

## 典型应用 / 我在哪见过
- MetaGPT 的「共享消息池 + 按角色订阅」：PM/Architect/Engineer/QA 沿 SOP 产出标准化交付物，落进共享项目目录。
- 本书「Agent 眼中的文件系统」四类区域（专属工作区/共享空间/外部挂载/系统内置）即黑板的存储底座。
