# 神经音频编解码器

## 一句话定义
> 神经音频编解码器（EnCodec、SNAC、Mimi、DAC）将连续波形转换为离散 token 序列，让 Transformer 可以像处理文本一样"预测"音频——语义/声学 token 分离是音频生成的关键架构突破。

## 它解决什么问题 / 为什么存在
- 语言模型处理离散 token，但音频是连续信号——需要一个"音频 tokenizer"把波形变成离散序列。
- 纯重建编解码器（EnCodec、DAC）的 token 同时包含语言内容和声学细节，让语言模型在同一个 codebook 中学两件事，不 scale。
- 语义/声学分离（Mimi）：第一本 codebook 编码"说了什么"（从 WavLM 蒸馏），其余编码"怎么说的"（音色、情绪），让 Moshi 等全双工语音模型成为可能。

## 核心原理（大二能懂的水平）
- **残差向量量化（RVQ）**：不用一个巨大 codebook，而是级联多个小 codebook（每个 1024 码）。第一本量化编码器输出，第二本量化残差，依此类推。8 本 codebook 的等效词表为 1024^8 ≈ 10^24。解码时将所有 codebook 的码向量求和重建。
- **EnCodec（Meta, 2022）**：基线方案。编码器-解码器 + RVQ 瓶颈，24kHz，默认 4 本 codebook @ 1.5kbps。MusicGen 用它生成音乐。帧率 75Hz。
- **DAC（Descript, 2023）**：L2 归一化 codebook + 周期激活函数，重建质量最高。44.1kHz 全频带，12 本 codebook 时语音几乎不可区分于原始。
- **SNAC（2024）**：多尺度 RVQ——粗 codebook 在 ~12Hz、细 codebook 在 50Hz，层次化结构对自回归语言模型友好。Orpheus-3B 使用。
- **Mimi（Kyutai, 2024）**：游戏改变者。12.5Hz 超低帧率，8 本 codebook @ 4.4kbps。Codebook 0 从 WavLM 蒸馏（语义），codebook 1-7 是声学残差。10 秒语音仅 125 帧 = 1000 token，Transformer 轻松处理。

## 关键参数 / 易错点
- 帧率决定序列长度：EnCodec 75Hz（10 秒=750 帧）vs Mimi 12.5Hz（10 秒=125 帧），低帧率对 LM 更友好。
- 语义/声学分离是关键：纯重建 codec 做 TTS 时语音模糊，因为 LM 要在同一个 codebook 中同时学语言和声学结构。
- 传统编解码器（Opus 20kbps）在每比特感知质量上仍优于神经编解码器——但 Opus 不产生离散 token，无法用于生成模型。
- 选择：音乐生成 → EnCodec-24k；最高保真 → DAC-44.1k；自回归语音 LM → SNAC 或 Mimi；全双工流式 → 仅 Mimi。

## 类比（帮助理解）
- RVQ 像用多层描图纸画一幅画：第一层画出粗轮廓（粗粒度量化），第二层修正残差补充细节，第三层再修正更细的残差……叠够层就能还原精细画面。Mimi 的语义/声学分离相当于第一层只画"内容线稿"（说了什么），后面几层才上"颜色和材质"（怎么说的）。

## 设计时怎么用（反推思维）
> 做语音生成系统时，如果需要 LLM 风格的自回归生成（TTS、语音对话），选 Mimi 或 SNAC（低帧率+语义分离）。如果只需要音频压缩或重建，选 DAC（最高保真）。零样本声音克隆利用语义/声学分离：语义模型处理内容，声学模型用参考音频条件化音色。

## 典型应用 / 我在哪见过
- Moshi（Kyutai）：全双工实时语音对话，用 Mimi 做音频 token 化
- MusicGen：用 EnCodec token 做自回归音乐生成
- Sesame CSM：对话式语音模型，基于 Mimi
- Orpheus-3B：expressive TTS，基于 SNAC
- 零样本声音克隆：语义 token 控制内容 + 声学 token 控制音色
