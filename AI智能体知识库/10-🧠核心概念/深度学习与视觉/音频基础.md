# 音频基础

## 一句话定义
> 音频基础是从声波到神经网络可消费张量的转换链：波形→采样→傅里叶变换→频谱→Mel 特征，每一步的约定违反都会产生"模型训练正常但效果翻车"的静默 bug。

## 它解决什么问题 / 为什么存在
- 麦克风产生连续的压力-时间信号，神经网络消费离散张量——中间的转换栈需要严格遵循采样率和频率分析的规则。
- 语音系统的每个 bug 都追溯到三个问题：采样率不匹配、信号混叠、在时域还是频域操作。
- 搞错采样率（如给 16kHz 的 Whisper 传入 44.1kHz 音频）会让模型输出看似正常但完全是垃圾——这是最常见也最隐蔽的音频 AI bug。

## 核心原理（大二能懂的水平）
- **波形**：一维浮点数组，值域 [-1.0, 1.0]，按样本序号索引。转换为秒：`t = n / sr`。10 秒 16kHz 音频 = 160,000 个浮点数。
- **采样率（sr）**：每秒采样数。16kHz 是 ASR 标准（Whisper 等），24kHz 是现代 TTS 标准，44.1kHz 是 CD 音质，48kHz 是专业音频。
- **Nyquist 定理**：采样率 sr 能无歧义表示的最高频率是 sr/2。超过 Nyquist 的能量会被"混叠"折叠到低频。7kHz 信号用 10kHz 采样（Nyquist=5kHz）会变成 3kHz——这就是为什么降采样前必须先低通滤波。
- **DFT/FFT**：离散傅里叶变换将时域信号分解为频率分量。N 个样本产生 N 个频率 bin，bin k 对应频率 `k * sr / N`。FFT 是 DFT 的 O(N log N) 快速算法（要求 N 为 2 的幂）。
- **STFT（短时傅里叶变换）**：不整段做 FFT，而是切成重叠帧（典型 25ms 窗、10ms 步幅），每帧加窗（Hann）后做 FFT。这产生了时间-频率的二维表示（频谱图），是所有音频深度学习的输入基础。

## 关键参数 / 易错点
- Whisper 强制要求 16kHz mono float32 输入——传 44.1kHz 立体声会得到看似合理但完全错误的结果。
- 降采样前必须低通滤波（anti-aliasing），否则高频能量折叠污染低频。
- 16-bit PCM（±32767）是通用交换格式，库（soundfile）读取后返回 float32 [-1,1]。
- STFT 参数：帧长 400（25ms@16kHz）、步幅 160（10ms）、Hann 窗——这些是语音处理的工业标准。

## 类比（帮助理解）
- 音频处理像把连续的水波（声波）变成一串数字水位读数（采样），再用棱镜（FFT）把这串读数分解成不同频率的组成波（频谱）。采样率就是读水位的频率——读太慢就会把快波纹误认为慢波纹（混叠）。

## 设计时怎么用（反推思维）
> 做语音系统时，第一步永远是确认采样率匹配模型要求。ASR 用 16kHz，TTS 用 24kHz。用 torchaudio.transforms.Resample（内置抗混叠滤波器）降采样，不要简单隔点抽样。所有音频处理前先画波形和频谱图检查是否正常。

## 典型应用 / 我在哪见过
- 语音识别前置处理：波形 → log-Mel 频谱图 → [[Whisper语音模型|Whisper]]
- TTS 后置处理：神经网络输出 Mel 频谱 → vocoder → 波形
- 音乐分析：频谱图 → 音频分类模型
- 通信系统：8kHz 电话到 48kHz 会议音频的采样率转换
