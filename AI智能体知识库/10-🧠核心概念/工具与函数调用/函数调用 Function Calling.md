# 函数调用 Function Calling

## 一句话定义
> Function Calling（函数调用）是让 LLM 以结构化方式请求执行某个函数/工具的机制：模型输出函数名与 JSON 参数，由框架真正执行并把结果返回给模型。

## 它解决什么问题 / 为什么存在
- 模型本身不能执行代码或查外部系统。Function Calling 把“模型想做什么”变成“机器可执行的结构化指令”，是 Agent 使用一切 [[工具 Tool]] 的基础通道。

## 核心原理（大二电子信息工程专业学生能懂）
- 流程：① 系统给模型一份工具 schema（函数名、参数类型、描述，通常用 JSON Schema）；② 模型判断需要调用时，输出结构化调用（如 get_weather(city:"Beijing")）；③ 框架执行并把结果作为 tool result 放回轨迹；④ 模型基于结果继续推理。
- 不同框架格式不同：OpenAI 的 function calling、Anthropic 的 tool use、LangChain 的 Tool 抽象——正因格式碎片，才需要 [[MCP]] 做统一“插座标准”。
- 与 [[ReAct]] 的关系：ReAct 是“思考→行动→观察”的循环范式，而 Function Calling 是其中“行动”这一步的具体技术实现（模型如何把动作编码成可执行的调用）。

## 关键参数 / 易错点
- JSON Schema 描述参数类型/约束；弱模型可能生成非法 JSON（括号不匹配、缺参数），需强化学习或 [[工具选择]] 策略兜底。
- 易错点：参数传递保真性——框架不得在模型不知情时静默改参数（如弯引号转直引号）或静默注入参数（如 git commit 被偷偷加标记），否则模型陷入无法自诊的失败。

## 类比（帮助理解）
- 像你写一张标准格式的便条给助理：“去查北京天气（参数：城市=北京）”，助理办好把结果写回便条，你接着安排下一步——便条的格式就是 Function Calling 的 schema。

## 设计时怎么用（反推思维）
> 做 Agent 时，我会为每个工具定义清晰 JSON Schema，并把工具定义经 MCP 暴露，让模型以 Function Calling 形式准确传参。

## 典型应用 / 我在哪见过
- 所有工具调用都走 Function Calling；MCP 的 tools/call 协议；异步场景用“启动/完成解耦”的异步工具接口（initiate_xxx 立即返回任务 ID）。
