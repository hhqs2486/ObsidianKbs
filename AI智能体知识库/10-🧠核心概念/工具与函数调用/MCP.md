# MCP

## 一句话定义
> MCP（Model Context Protocol，模型上下文协议）是 Anthropic 于 2024 年底发布的开放标准，统一 AI 模型与外部工具、数据源的通信协议——相当于 AI 工具生态的通用“插座标准”。

## 它解决什么问题 / 为什么存在
- 每个框架定义工具的方式不同（OpenAI function calling、Anthropic tool use、LangChain Tool），工具开发者要为不同框架重复适配。
- MCP 让“一次开发，处处可用”：一个 MCP 服务器可被 Cursor、Claude Desktop 等任何兼容客户端使用，解决互操作问题。

## 核心原理（大二电子信息工程专业学生能懂）
- 客户端-服务器架构：MCP 服务器暴露一组工具，MCP 客户端（Agent 框架/IDE）通过标准协议通信。
- 三类原语：工具（模型可执行的操作）、资源（只读数据，如文件内容/数据库记录，可浏览不可执行）、提示模板（prompts，可复用提示词）。
- 传输层灵活：本地用 stdio，远程用 Streamable HTTP。
- 交互时序：initialize（握手）→ tools/list（发现）→ tools/call（调用）→ 返回结果。
- 解决“工具过多”的上下文开销：只把工具名索引同步到文件夹，需要时再查定义（Cursor 实测 MCP 任务总 token 减 46.9%）；更进一步的 [[工具选择]] 与主动工具发现把“平铺列表”变“按需检索”。

## 关键参数 / 易错点
- 局限：调用主体上仍是请求-响应式，协议内扩展（notifications/progress/sampling/elicitation）作用于单个会话，跨会话/离线唤醒仍需事件驱动架构（见 [[工具 Tool]] 异步）。
- 安全风险（四大类）：工具描述投毒（description 夹带指令，提示注入变种）、恶意/被劫持服务器（供应链攻击）、同名工具遮蔽（tool shadowing）、凭证管理风险。
- 缓解：把 description 当不可信输入审查、锁版本拒绝静默更新、每服务器最小权限凭证、运行时用 Sidecar 安全审查（见 [[工具调用错误处理]]）。

## 类比（帮助理解）
- 像电源插座国际标准：以前每个国家插座不同、旅行要带一堆转换头；MCP 统一成一种插座，插头（工具）插上就能用。

## 设计时怎么用（反推思维）
> 接入第三方能力时，我会优先做成 MCP 服务器，统一暴露工具/资源/提示，并审查其描述、锁版本、配最小权限，避免投毒与遮蔽。

## 典型应用 / 我在哪见过
- 实验4-1 感知工具 MCP、实验4-2 执行工具 MCP、实验4-3 协作工具 MCP；Claude Code 对 MCP 工具默认延迟加载。
