# 工具 Tool

## 一句话定义
> 工具（Tool）是 Agent 连接语言“大脑”与真实数字世界的“手脚和感官”——让 LLM 能获取信息、改变外部世界、与其他 Agent/人类协作、响应外部事件、与用户沟通。

## 它解决什么问题 / 为什么存在
- 纯 LLM 只能“说”，不能“做”：查不了实时信息、改不了文件、发不了邮件。
- 工具把 Agent 的能力从“生成文本”扩展到“作用于世界”，是实现有用 Agent 的关键。

## 核心原理（大二电子信息工程专业学生能懂）
- 按“调用方向”（谁发起）和“作用对象”（作用于什么）审视，工具分五类：
  1. **感知工具**（Agent 主动调用，获取信息）：web_search、read_file、fetch_url。
  2. **执行工具**（Agent 主动调用，改变世界）：shell_exec、write_file、send_email——错误代价高，安全是核心。
  3. **协作工具**（Agent 主动调用，驱动其他 Agent/人）：spawn_subagent、send_message。
  4. **事件触发工具**（Agent 注册、外部触发，驱动 Agent 开始）：set_timer、monitor_shell、connect_channel。
  5. **用户沟通工具**（Agent 主动调用，向用户传信息）：reply_to_user、send_notification。
- 工具以结构化 schema（常经 [[MCP]] 或 [[函数调用 Function Calling]]）暴露给模型，模型决定何时调用。

## 关键参数 / 易错点
- 通用设计原则（ACI）：粒度权衡（过细增选择负担、过粗变复杂）、通用性优于专用（如 code_interpreter 替代一堆计算器）、[[工具描述]] 质量决定调用准确率。
- 易错点：工具数量超 100 时 LLM 易选错；参数传递保真性——禁止静默转换输入（如弯引号被偷偷改成直引号）或静默注入参数，否则模型无法诊断失败。

## 类比（帮助理解）
- 像《Her》里的 Samantha：她动人是因为拥有工具——既是眼睛（感知）、手（执行），也能叫人帮忙（协作）、被闹钟唤醒（事件）、发消息给用户（沟通）。

## 设计时怎么用（反推思维）
> 做 Agent 时，我会按五类职责划分工具集，感知类重输出控制、执行类重安全分层，并用 MCP 统一暴露接口。

## 典型应用 / 我在哪见过
- 感知：搜索/读文件；执行：写代码/发邮件；协作：子 Agent；事件：定时器/Channel；沟通：卡片消息。
- 与 [[ReAct]] 配合：Agent 在循环中决定调用哪个工具。
