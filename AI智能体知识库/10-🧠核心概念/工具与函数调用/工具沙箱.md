# 工具沙箱

## 一句话定义
> 工具沙箱（Tool Sandbox）是与宿主机隔离的安全执行环境，让 Agent 的通用执行工具（Python 解释器、Shell）能运行任意代码而不影响外部系统——像密封实验室里做实验。

## 它解决什么问题 / 为什么存在
- 通用执行工具本质是“让 Agent 跑任意代码”，一旦失控（删文件、访问任意网络、消耗所有资源）后果严重。
- 沙箱把“代码执行的副作用”关进隔离区，是执行工具安全分层的最底层防线。

## 核心原理（大二电子信息工程专业学生能懂）
- 关键误区：**Python 虚拟环境（venv）不是沙箱**——它只隔离包依赖，对文件系统/网络/进程无任何约束，venv 里照样能删任意文件。
- 真正的隔离按强度递增：
  1. **OS 级**：macOS Seatbelt、Linux seccomp/namespaces，限制文件访问、禁网络、屏蔽危险系统调用——本地轻量首选。
  2. **容器**：Docker，独立文件系统视图与网络栈，但与宿主机共享内核，内核漏洞可逃逸。
  3. **microVM/虚拟机**：Firecracker，带独立内核的硬件级隔离，运行完全不可信代码的最强层级。
- 任一层级之上都应设资源配额（CPU/内存/磁盘/网络上限），防恶意或失控代码耗尽资源。
- 虚拟身份与隔离执行环境是沙箱思想在“数字身份”维度的延伸：虚拟电脑/手机给 Agent 独立账号与家目录，操作可追溯审计，错误不影响宿主（见 [[工具 Tool]] 异步架构）。

## 关键参数 / 易错点
- 易错点：以为 venv 够安全——它挡不住文件/网络破坏；生产或不可信输入场景需容器乃至 microVM 级。
- 选择依据：本地开发用 OS 级即可；生产/处理不可信输入用容器或 microVM。

## 类比（帮助理解）
- 像化学实验的密封手套箱：你在里面随便折腾试剂，就算洒了也漏不到外面实验室；级别越高（手套箱→独立实验室→异地隔离楼）越安全。

## 设计时怎么用（反推思维）
> 做代码解释器类工具时，我会把执行放进 OS 级或容器沙箱，加资源配额，绝不靠 venv 当安全边界；不可信代码用 microVM。

## 典型应用 / 我在哪见过
- 执行工具 MCP（实验4-2 沙盒 Python、终端命令超时控制）；虚拟电脑/虚拟手机（Agent 独立身份）；Sidecar 在沙箱运行校验。
