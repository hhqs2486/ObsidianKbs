# Agent

## 一句话定义
> Agent（智能体）是一个能自主规划执行步骤、调用工具完成任务、并根据结果不断调整策略的智能系统，其核心公式为 **Agent = LLM + 上下文 + 工具**。

## 它解决什么问题 / 为什么存在
- 传统聊天机器人是"你问一句、它答一句"的被动对话；Agent 解决的是"把目标交给系统，它自己想办法完成"的问题。
- 它把 LLM 的通用思考能力，通过上下文（信息）和工具（行动）落地到真实世界任务中。

## 核心原理（大二电子信息工程专业学生能懂）
- **三元公式**：LLM = 大脑（思考决策），上下文 = 眼睛（能"看"到什么信息），工具 = 手脚（能"做"什么）。
- **ReAct 循环**：Agent 不断重复"思考（Reasoning）→ 行动（调工具 Acting）→ 观察（看工具结果 Observing）"，直到任务完成。
- 直觉层：大脑 + 眼睛 + 手脚；学术层（强化学习视角）：Policy（策略）+ Observation Space（观察空间）+ Action Space（动作空间）。
- 自主 Agent 本质就是"在一个循环里不断调用工具的 LLM"，靠停止条件（任务完成 / 调 final_answer / 无工具调用 / 达最大轮次）退出。

## 关键参数 / 易错点
- 三个组件缺一不可：去掉工具定义→无法行动；缺工具结果→盲目循环；缺思考过程→决策不连贯；缺历史→重复操作（消融实验 1-1）。
- 自主不等于无限制，必须设停止条件，否则易死循环或过度执行。

## 类比（帮助理解）
- Agent 像一位能打电话、查资料、填表单的"全能新员工"：脑子（LLM）想方案，眼睛（上下文）看资料，手脚（工具）去办事。

## 设计时怎么用（反推思维）
> 做智能客服系统时，我会用 Agent 公式拆需求：大脑选什么模型、眼睛喂哪些用户记忆与业务规则、手脚开放哪些工具（查订单、退款），再用 ReAct 把它们串成闭环。

## 典型应用 / 我在哪见过
- Cursor（编程）、Deep Research（调研）、Manus（电脑操控）、豆包（手机助手）、Pine AI（打电话办事）等。
