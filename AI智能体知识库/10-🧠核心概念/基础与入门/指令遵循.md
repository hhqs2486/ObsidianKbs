# 指令遵循

## 一句话定义
> 指令遵循（Instruction Following）是 LLM 按照给定指令（系统提示词、规则、示例）正确行动的能力——是 Agent 可靠执行任务的前提。

## 它解决什么问题 / 为什么存在
- 模型能力再强，若不遵循指令，Agent 就会偏离业务规则、乱用工具。指令遵循决定了"聪明能不能用在正道上"。
- 提示工程的核心目的，就是把复杂指令写成模型能稳定遵循的形式。

## 核心原理（大二电子信息工程专业学生能懂）
- 模型经后训练（SFT/RLHF）学会"照指令办事"。System Prompt 定义身份、规则、约束；结构化（XML/Markdown）与流程驱动（SOP）能显著提升遵循率。
- 大模型优势在于"遵循复杂指令、从长上下文提取信息"，但不应在业务规则制定上被赋予过多自由裁量权——规则要写到可执行程度。
- 位置影响遵循：放在上下文末尾的指令（如 Agent Skills 方式三、状态栏）注意力位置最优，但对模型的指令遵循要求更高（需在长上下文中间准确遵从）。

## 关键参数 / 易错点
- 模糊规则（"根据情况自行选择"）导致行为极不稳定；规则必须明确到可执行（如"退款绝不用百分比计费"）。
- 大写强调（"NEVER do X"）比委婉语气更能引起注意，但仅限于关键约束，否则被稀释。
- 提示工程消融实验：信息组织混乱使成功率下降 30% 以上。

## 类比（帮助理解）
- 指令遵循像新员工照 SOP 办事：手册写得越清楚、越结构化，他越不会"自己看着办"出岔子。

## 设计时怎么用（反推思维）
> 设计 Agent 时，我会把业务规则写成清晰 SOP 与结构化指令，让模型专注于真正需思考的部分，而非自由裁量业务逻辑。

## 典型应用 / 我在哪见过
- 系统提示词设计、Agent Skills 渐进式披露、Claude Code 的工具描述边界。
