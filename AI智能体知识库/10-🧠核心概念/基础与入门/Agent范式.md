# Agent范式

## 一句话定义
> Agent 范式指构建现代 Agent 的几种核心"套路"与设计模式——从三元组成公式，到运行循环，再到学习机制与编排方式。

## 它解决什么问题 / 为什么存在
- Agent 领域名词繁多（Skill、harness、loop engineering…），本书主张"实践在前、命名在后"：范式帮你在名词流行前就理解该怎么做。
- 掌握范式，才能在模型迭代时判断新能力该放进公式的哪个位置。

## 核心原理（大二电子信息工程专业学生能懂）
现代 Agent 有四类关键范式：
1. **组成范式**：Agent = LLM（大脑）+ 上下文（眼睛）+ 工具（手脚）；扩产形态 = Model + Harness（外加约束、验证、纠正）。
2. **运行范式（ReAct）**：思考 → 行动 → 观察 的循环，把 LLM、上下文、工具串起来。
3. **学习范式（三种互补）**：
   - 后训练（Post-training）：改权重，永久、通用、成本高；
   - 上下文学习（In-Context Learning）：靠注意力软更新，临时、即时、受窗口限制；
   - 外部化学习（Externalized Learning）：知识库 + 工具代码，持久、可验证。
4. **编排范式（光谱）**：从简单到复杂——单 LLM 调用 → 工作流（Workflow，固定路径）→ 自主 Agent（Autonomous，动态决策）；还可混合使用，并进一步发展为 Harness 工程、Loop 工程。

## 关键参数 / 易错点
- 编排原则：先优化提示词，再考虑工作流，最后才引入自主 Agent——降低意外风险。
- 自主 Agent 必须设停止条件（完成 / 调 final_answer / 无工具调用 / 达最大轮次 / 错误超限）。
- 五层工程范式层层包含：提示工程 ⊂ 上下文工程 ⊂ Harness 工程 ⊂ Loop 工程。

## 类比（帮助理解）
- 范式像做菜的方法论：组成是食材（脑/眼/手），运行是翻炒循环，学习是"练手感/看菜谱/记笔记"，编排是"照固定菜谱"还是"随食材自由发挥"。

## 设计时怎么用（反推思维）
> 做订票系统时，我会先用工作流固定"核身份→搜航班→付款→确认"的合规路径，遇到需灵活决策的分支再切到自主 Agent，并明确退出条件。

## 典型应用 / 我在哪见过
- 工作流：n8n 可视化编排；自主：Claude Agent SDK、OpenAI Agents SDK；多 Agent：CrewAI。
