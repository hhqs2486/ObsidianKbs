# Transformer

## 一句话定义
> Transformer 是当前几乎所有大语言模型的底层神经网络架构，其核心是**注意力机制（Attention）**——让模型在处理每个 token 时决定"关注哪些信息"。

## 它解决什么问题 / 为什么存在
- 传统序列模型（RNN）难以并行、长程依赖弱。Transformer 用自注意力机制并行处理整段序列，奠定了现代 LLM 的基础。
- 理解 Transformer 有助于理解上下文如何被处理、KV Cache 为何有效、上下文学习为何"更像检索"。

## 核心原理（大二电子信息工程专业学生能懂）
- 输入 token 经 Embedding 成向量，加位置编码（Positional Encoding / RoPE）保留顺序信息。
- 多层 **自注意力（Self-Attention）**：每个 token 计算与序列中其他 token 的关联权重，加权求和得到新表示——即"关注重点"。
- 每个 token 在注意力计算中会产生 Key（K）和 Value（V）向量，这些 K/V 会被缓存（即 [[Prompt 缓存|KV Cache]]），新 token 直接复用，避免重算。
- 残差连接 + 前馈网络堆叠多层，最后经 softmax 输出下一个 token 的概率。

## 关键参数 / 易错点
- 注意力是因果的（causal）：第 i 个 token 只能看前面的 token——这决定了"静态前缀不变则缓存可复用"。
- 上下文学习本质是注意力在已有内容里"查找"，而非一次前向就完成归纳（详见[[上下文压缩]]）。

## 类比（帮助理解）
- 自注意力像读论文时，每看一个词都在脑中回看前文相关段落并赋权重——重要的多关注，无关的就略过。

## 设计时怎么用（反推思维）
> 做上下文工程设计时，我会利用 Transformer 因果注意力的前缀性质：把稳定内容（System Prompt、工具定义）放前面，动态信息追加末尾，保护缓存。

## 典型应用 / 我在哪见过
- GPT、BERT、Claude、Gemini 等全部主流 LLM；本书推荐《图解大模型》补充此基础。
