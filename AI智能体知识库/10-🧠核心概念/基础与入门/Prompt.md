# Prompt

## 一句话定义
> Prompt（提示词）是用户或开发者提供给模型的输入文本/指令，用于引导模型生成期望的回复；它是人与模型沟通的基本通道。

## 它解决什么问题 / 为什么存在
- 没有 Prompt，模型不知道要做什么。它是"你问一句、它答一句"交互模式的核心载体。
- 通过精心设计的 Prompt，可以控制模型的身份、风格、任务与约束（即提示工程 Prompt Engineering）。

## 核心原理（大二电子信息工程专业学生能懂）
- 在 API 消息列表中，Prompt 通常以 `role: "user"` 的**用户消息**出现；而与之并列的还有 `role: "system"` 的**系统提示词（System Prompt）**（由开发者写、全程不变）。
- 模型是无状态的：每次调用必须把全部所需信息放进 messages 列表（含 system、user、历史 assistant/tool 消息）。
- 好的 Prompt 可用结构化格式（XML 标签 + Markdown）降低模型理解成本；可用流程驱动（SOP）而非规则堆砌。

## 关键参数 / 易错点
- 区分 System Prompt（员工手册，稳定）与 User Prompt（每轮请求，动态）。
- 过度堆砌规则会稀释模型对关键内容的注意力；模糊规则导致行为不稳定。
- 提示注入风险：外部内容可能夹带恶意指令劫持上下文（见[[上下文工程]]中的提示注入防御）。

## 类比（帮助理解）
- Prompt 像你交给新同事的"这会儿要办的事"的便条；System Prompt 则是装订好的岗位手册。

## 设计时怎么用（反推思维）
> 做翻译 Agent 时，我会在 System Prompt 写清身份与风格，在 User Prompt 放待译文本，并用 XML 标签隔离原文与指令，避免混淆。

## 典型应用 / 我在哪见过
- ChatGPT/Claude 的输入框；Agent 的系统提示词与每轮用户请求。
