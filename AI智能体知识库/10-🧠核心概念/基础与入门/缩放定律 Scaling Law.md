# 缩放定律 Scaling Law

## 一句话定义
> 模型性能（交叉熵损失）随参数量 N、训练数据量 D、算力 C 近似按幂律下降——只要 N 和 D 按算力最优比例一起涨，模型就稳定变好。

## 它解决什么问题 / 为什么存在
- 训练一个大模型要烧掉海量算力与数据，开工前你最想知道："给我 C 的预算，模型能有多好？我该把钱砸在更大模型还是更多数据上？"
- 缩放定律把"炼丹靠运气"变成"可预测的预算分配"：它给了你一张经验地图，回答"加 10 倍算力能换来多少损失下降"。
- 它也是选型依据：当你要在"小模型长训练"和"大模型短训练"之间选时，定律告诉你推理成本会怎样变化。

## 核心原理（大二能懂的水平）
- 经验公式（Chinchilla / Hoffmann 2022）把损失写成两项之和：
  `L(N, D) = A / N^α + B / D^β + E`
  - N = 参数（不含词表嵌入），D = 训练 token 数；α≈0.34，β≈0.28，E≈1.69 是不可约损失下限（数据本身的熵）。
  - 每一项随规模增大而呈幂律下降，所以整体是平滑曲线，没有"突然开窍"的台阶。
- 算力近似：`C ≈ 6·N·D`（每训一个 token，每个参数大约 6 次浮点运算）。固定 C 时，N 和 D 是跷跷板的两端。
- 经典结论（Chinchilla 最优）：在固定算力下让损失最小，应取 `D/N ≈ 20`，即约 20 个 token 对应 1 个参数。GPT-3（175B 参数、300B token，比例≈1.7）被发现"训练严重不足"。
- 2026 年的转向——"过训练"：推理成本决定总开销，所以愿意牺牲训练最优、把小模型训更久（如 Llama 3 8B 用 15T token，D/N≈1875），换更便宜的部署。

## 关键参数 / 易错点
- `D/N` 比例：Chinchilla 说 20，2026 生产常取 100–500（推理主导场景），极端如 Llama 3 8B 达 1875。别再 blindly 照抄 GPT-3 的"大力出奇迹"。
- 不可约损失 E：无论怎么堆算力，损失都压不到 E 以下——这是数据本身的信息上限。
- 易错：把"涌现能力突现"当真。Schaeffer 等指出，很多"突然学会"是评测指标不连续（精确匹配、阈值准确率）造成的假象；连续指标（交叉熵）始终是平滑的。
- 有效算力乘数：数据质量（Phi 式清洗可带来 >2× 等效算力）、MoE（总参数与激活算力解耦）、Muon 优化器（比 AdamW 省约 2× 算力）都只改公式常数，不改幂律形状。

## 类比（帮助理解）
- 像给功放配音箱：功率（算力）固定时，要么上大喇叭（大 N），要么多喂信号（大 D）。比例配错，声音（性能）就上不去。
- 又像"复习时间 vs 智商"：智商（容量 N）和刷题量（数据 D）共同决定分数，且二者存在最优配比。

## 设计时怎么用（反推思维）
> 做预训练或选基座模型时，我会先用缩放定律反推预算：先定可用算力 C，按 `D/N≈20` 算出 Chinchilla 最优的 (N, D)；若我的服务是推理主导（如日吐万亿 token 的聊天机器人），则主动把 N 压小、D 拉大（过训练）以省推理钱。我还会用"连续损失是否平滑"来戳破"涌现"神话，避免被不连续的 benchmark 分数误导。

## 典型应用 / 我在哪见过
- 决定自训基座的 (参数量, 数据量) 配比；解释为什么 Llama 3 8B 敢用 15T token。
- 判断 fine-tune 数据是否够：若任务数据远低于基座"每参 20 token"，性能会卡在某个损失地板上。
- DeepSeek-V3、Mixtral 用 MoE 把"总参数"与"每 token 激活算力"解耦，本质是在同一算力下塞更多参数。
