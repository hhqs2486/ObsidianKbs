# 推理 Reasoning

## 一句话定义
> 推理 Reasoning 指模型在给出最终答案前展开中间推导（"思考"）的过程，表现为思维链（Chain-of-Thought）与思考 token；本质是把复杂问题分解成一步步可验证的中间步骤。

> ⚠️ 术语注记：本书刻意区分两个词——**reasoning（模型展开中间推导、"想"的过程）统一译为"思考"**；**inference（模型前向计算与部署运行）统一译为"推理"**。本卡片按文件名取 **Reasoning = 思考/推导过程** 的含义。

## 它解决什么问题 / 为什么存在
- 复杂任务（多步规划、工具选择、数学推算）无法一次生成正确结果；显式推理让模型"想清楚再答"，显著提升准确率与可解释性。
- "思考模型"（OpenAI o 系列、DeepSeek-R1 等）把推理作为原生能力，常驻开启。

## 核心原理（大二电子信息工程专业学生能懂）
- 推理在 Agent 中以 **reasoning 字段**出现在 assistant 消息里，保持思维连贯、决策可解释；它可与 tool_calls（行动）或 content（回复）配合。
- 思维链（CoT）：模型逐条推导（如"先把 EUR、GBP 转成 USD，再汇总"），代价是产生额外思考 token。
- 上下文学习"检索而非推理"：单次前向里消费已有上下文更像查找；真正的归纳统计需靠推理（思维链）一步步完成——也因此把结论"提前算好写进上下文"（状态栏/压缩）能省下反复推理的成本。

## 关键参数 / 易错点
- 思考越深越准，但输出 token 与延迟越高（可用 Reasoning Effort 参数调深度）。
- 没有 CoT 时，模型难做统计归纳（如"数出黑猫几只"）；有 CoT 则每次都要重算，成本高。
- 绝大多数 Agent 需支持思考的模型；仅单步简单任务可用不思考模型。

## 类比（帮助理解）
- 推理像你解题时在草稿纸上写的中间步骤——不是直接写答案，而是"因为…所以…"，既防错又方便别人检查。

## 设计时怎么用（反推思维）
> 做研究 Agent 时，我会开启思考模型并把 Reasoning Effort 调高，让它在搜索-阅读-分析循环中先推演再行动；同时用状态栏缓存已算结论，避免每轮重算。

## 典型应用 / 我在哪见过
- OpenAI o 系列、DeepSeek-R1、Kimi K3（常开 thinking mode）、GPT-5.6 的 Reasoning Effort 参数。
