# Tokenizer

## 一句话定义
> Tokenizer（分词器）是把原始文本切分成模型可处理的最小单元——token 的程序，是文本进入 LLM 的第一道关口。

## 它解决什么问题 / 为什么存在
- 模型不能直接吃字符，需要把文本转成数字 id 序列。Tokenizer 决定了"一句话被切成多少个 token"，直接影响上下文长度、成本与延迟。
- 所有上下文（System Prompt、对话历史、工具结果）最终都序列化为 token 流，交给 Transformer 注意力机制处理。

## 核心原理（大二电子信息工程专业学生能懂）
- 文本 → Tokenizer → token 序列（每个 token 对应词表中的一个 id）→ 模型 Embedding 成向量。
- 一个 token 不一定是一个字：英文常是词根/子词，中文常是字或词片段；不同模型词表不同，切分结果不同。
- 上下文窗口、KV Cache、API 计费都以 **token 数**计，不是字符数。

## 关键参数 / 易错点
- 同一段文本在不同模型里 token 数不同；决定"窗口还够不够""缓存命中率""花多少钱"。
- 控制上下文成本，本质上就是控制 token 数（如压缩工具结果、精简状态栏）。

## 类比（帮助理解）
- Tokenizer 像把一整篇文章拆成"乐高小块"——模型只能一块块拼着理解；块切得粗细不同，拼起来的成本和速度也不同。

## 设计时怎么用（反推思维）
> 做长文档 Agent 时，我会关注 tokenizer 的切分，估算 token 占用，对超长工具输出做摘要压缩，避免撑爆[[上下文窗口]]。

## 典型应用 / 我在哪见过
- 所有 LLM API 的 token 计数与计费；Chat Template 把 messages 转成 token 流。
