# 幻觉 Hallucination

## 一句话定义
> 幻觉（Hallucination）指 LLM 生成看似合理但不符合事实或不存在的内容——在 Agent 中典型表现为编造不存在的工具或参数、给出虚假执行结果。

## 它解决什么问题 / 为什么存在
- 模型概率式生成，并非"知道真相"；当信息不足或缺乏约束时，会"自信地编"。这是 Agent 从 Demo 到可靠产品的核心脆弱点之一。
- Harness 工程的约束、验证、纠正机制，正是为了兜住幻觉带来的错误。

## 核心原理（大二电子信息工程专业学生能懂）
- 幻觉来源：训练数据噪声、上下文信息缺失、模型过度泛化。
- 在 Agent 中：模型可能"幻想"一个根本没定义的工具名、或编造参数值；也可能在没真正执行时就回复"退款成功"。
- 防御思路（Harness）：上下文给足真实信息（减少凭空编）、工具定义明确、对工具结果做校验、失败重试与人工干预。

## 关键参数 / 易错点
- 缺上下文 + 缺验证 = 幻觉最易酿成事故（如编造退款结果）。
- 幻觉不一定是"胡说"，也可能是"看起来很对但错"（如状态栏数字写错，模型无条件相信）。

## 类比（帮助理解）
- 幻觉像被问到不懂的问题却硬编答案的人——越没资料越容易编，且编得理直气壮。

## 设计时怎么用（反推思维）
> 做退款 Agent 时，我会用 System Prompt 写明退款政策（上下文）、校验退款金额不超订单（约束）、查库确认成功（验证）、超时重试（纠正），层层防幻觉。

## 典型应用 / 我在哪见过
- 编造工具/参数、虚假执行结果；缺乏约束验证时的错误回复。

## 关联
- 前置知识：[[大语言模型 LLM]]、[[上下文 Context]]
- 相关：Harness、约束（Constrain）、验证（Verify）、纠正（Correct）、提示注入
- 反例/误区：认为"大模型升级就不会幻觉"——模型越强仍可能编，工程兜底长期必要。
