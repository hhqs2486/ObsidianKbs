# 进化式编码

## 一句话定义
> 进化式编码（evolutionary coding）是指 Coding Agent 在「写代码→跑测试→读报错→改代码」的循环里，像生物进化一样「试错—筛选—保留」，逐步逼近能通过全部检查的实现，而非一次写对。

## 它解决什么问题 / 为什么存在
- 复杂编码任务几乎不可能「一遍写对」：依赖多、边界多、测试严。人也是改出来的。
- 进化式编码把「不可控的灵感」换成「可控的试错循环」：用测试/编译当筛选压力，让正确版本被保留、错误版本被淘汰。

## 核心原理（大二电子信息工程专业学生能懂）
- 循环：生成候选补丁 → 执行构建/测试（适应环境）→ 收集失败信号（自然选择）→ 模型据信号改出新候选（变异）→ 再筛选。
- 保留机制：通过的检查项成为「不变式」，后续修改不能把它弄坏（回归守护）。
- 常配合「多候选并行」：一次生成几个方案，跑测试筛出最优，类似种群选择。
- 与推理模型、经验回放强相关：用推理模型想方案，用经验回放避免重复踩坑。

## 关键参数 / 易错点
- 反馈质量决定进化速度：报错信息越清晰（含行号、期望/实际），模型改得越快。
- 循环上限（max iterations）：必须设上限防死循环烧钱；卡住要换策略或求助人。
- 回归守护：每次改动要重跑全量相关测试，防止「修一个 bug 引入三个」。
- 易错点：只让模型「看绿了就停」却不留记录——好的进化式编码会把「为何这样改」沉淀下来（见经验回放与改进）。

## 类比（帮助理解）
- 像「自然选择写代码」：先长出几个版本，让「测试」当考官淘汰不及格的，活下来的继续交配（组合）出更好的下一代，直到全及格。

## 设计时怎么用（反推思维）
> 做 Coding Agent 时，我会把它设计成「带测试反馈的进化循环」：每轮生成→执行→读错→改写，设 max iterations 与回归守护，并把踩过的坑写进经验库供下次复用。
