# Agent 安全

## 一句话定义
> Agent 安全指围绕"会调用工具、会执行动作"的 Agent 建立的多层防护：在输入侧挡注入、在输出侧挡有害/泄漏、在工具侧控权限，形成纵深防御（defense-in-depth）。

## 它解决什么问题 / 为什么存在
- 任何带聊天框的系统上线 48 小时内就会遭 prompt injection 尝试。
- Agent 比普通 chatbot 更危险：它不仅能"说"，还能"做"（删文件、发邮件、付钱）。一次成功注入可能直接造成现实损失。

## 核心原理（大二电子信息工程专业学生能懂）
- **护栏三明治（Guardrail Sandwich）**：输入校验 → 模型处理 → 输出校验；既不信任用户，也不信任模型。
- **攻击分类**：
  - 直接注入：用户明说"忽略之前指令"。
  - 间接注入：恶意指令藏在检索文档/网页/邮件里，模型分不清"指令"和"数据"。
  - 越狱（jailbreak）：绕过模型安全训练（如"你是 DAN"）。
  - 数据/PII 窃取：套取系统提示或隐私。
- **输入护栏**：话题分类、注入检测（LlamaGuard / 微调 BERT）、PII 检测（Presidio）、长度与限流。
- **输出护栏**：毒性过滤（OpenAI Moderation / Perspective）、PII 脱敏、相关性检查、格式校验、与源比对防幻觉。
- **工具侧安全**（补充）：[[函数调用 Function Calling]] 里"绝不直接拼模型生成的 SQL""工具白名单""参数校验""结果脱敏""限流"。
- **纵深防御**：单层不够，多层叠加让攻击从"reddit 就能搞"变成"需要 PhD"。

## 关键参数 / 易错点
- 只做输入或只做输出都漏：攻击者总能绕过其中一层。
- 把检索内容当"数据"不是"指令"（指令层级 / 内容隔离）。
- 工具投毒：MCP 工具描述里能藏隐藏指令（见 [[MCP 协议 v2]]、[[工具接口设计]]）。

## 类比（帮助理解）
- 像机场安检：值机查证件（输入）、登机前再查（输出）、行李 X 光（工具/数据隔离），三层都过才放行。

## 设计时怎么用（反推思维）
> 做 Agent 系统时，我会默认"一定会被攻击"，在输入/输出/工具三处都布防，并把高风险动作交给 [[Agent 安全门禁]] 做人工确认。

## 典型应用 / 我在哪见过
- 银行客服、代码助手、RAG 产品；工具：LlamaGuard、NeMo Guardrails、Guardrails AI、Presidio、OpenAI Moderation。
