# Agent 安全门禁

## 一句话定义
> Agent 安全门禁（safety gate）是在 Agent 运行生命周期的三个检查点（生成前 / 生成中 / 生成后）做校验，并汇总各信号给出"放行 / 拦截 / 脱敏 / 告警"裁决、且留下可审计 trace 的机制。

## 它解决什么问题 / 为什么存在
- 单点护栏（只在输入或只在输出）容易被绕过；把检测器、流式过滤器、分类器、规则引擎组合起来，并在正确时机触发，才能真正挡住攻击。
- 合规与复盘需要：一次请求"为什么被拦 / 被放行"要能查、能追责。

## 核心原理（大二电子信息工程专业学生能懂）
- **三个检查点**：
  1. `pre-gen`（生成前）：检测器扫 prompt，高置信攻击直接 block，可疑的打标。
  2. `during-gen`（生成中）：流式过滤器缓冲 token，出现违禁续写就提前终止流（prefix-injection 只在事后看会漏）。
  3. `post-gen`（生成后）：分类器 + 规则引擎审完整输出，再汇总裁决。
- **汇总裁决表（确定性）**：
  - 任一 high 严重度 → block（拒绝）；
  - 任一 medium → redact（脱敏后发）；
  - 任一 low → warn（带提示发）；
  - 全 none 且检测器置信<0.5 → allow。
- **每请求 trace**：含 `request_id`、各检查点裁决、`final_action`、`final_output`、`latency_ms`，可供周一早上复盘。

## 关键参数 / 易错点
- 门禁要在"副作用之前"拦：删库/发信的动作应在执行前走门禁，不是事后。
- 流式终止要当 medium 信号参与汇总，否则中途生成的有害片段会被放过。
- 裁决表要确定性、可解释，别用黑盒分数随意放行。

## 类比（帮助理解）
- 像快递安检 X 光（生成前）+ 传送带抽检（生成中）+ 出库复核（生成后），三关都过才送达，且每关有记录。

## 设计时怎么用（反推思维）
> 做高风险 Agent（能发消息/付款/删数据）时，我会把危险动作包进"三级门禁"：block / approval_required / allow，没有审批不执行（见 [[Agent 安全]]）。

## 典型应用 / 我在哪见过
- 银行/医疗/政府级 Agent、能操作生产系统的 Coding Agent（见 [[Claude Code]] 权限链路）。
