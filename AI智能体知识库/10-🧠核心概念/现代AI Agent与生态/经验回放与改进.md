# 经验回放与改进

## 一句话定义
> 经验回放与改进是指 Agent 把「每次任务的成败过程」记录成可检索的经验，在后续相似任务中回放借鉴，从而少踩坑、越做越好——是 Agent 持续自我提升的记忆与学习机制。

## 它解决什么问题 / 为什么存在
- 没有记忆的 Agent 每次都从零开始：同样的坑反复踩，同样的妙招反复现编，无法积累。
- 经验回放让「一次教训」变成「永久资产」：遇到相似情境自动调出历史解法/警示，质量与效率随运行次数上升。

## 核心原理（大二电子信息工程专业学生能懂）
- 记录（experience）：任务结束后存下「情境（什么任务/什么报错）+ 做法（用了啥工具/怎么改的）+ 结果（成/败/为何）」。
- 检索（replay）：新任务开始时，按相似度从经验库捞相关条目，作为上下文提示模型「上次这么走成功了 / 别走那条死路」。
- 改进（improve）：定期汇总经验，提炼出可复用的 Skill（见 Skill 封装）或更新策略；失败经验用于强化护栏。
- 与强化学习中的「经验回放池（replay buffer）」同源思想：把历史样本重复利用来稳定学习，这里用于提示工程层面的借鉴。

## 关键参数 / 易错点
- 检索相关性：经验库太大时，捞错条目会误导——需要好的嵌入检索与情境摘要。
- 经验质量：记录「为什么成/为什么败」比只记「做了啥」有用得多；纯操作日志价值低。
- 防污染：错误经验若被当作正确反复回放，会固化错误——要有「被推翻/过期」标记。
- 易错点：只存不下「复盘结论」——经验的价值在「教训提炼」，不在「流水账」。

## 类比（帮助理解）
- 像「老师的错题本 + 妙招本」：每次考完把错因和好解法记下来，下次考前翻一翻，同样的坑不再踩，同样的题更快解。

## 设计时怎么用（反推思维）
> 做长期自治 Agent 时，我会给它配一个经验库：每轮任务后写「情境—做法—成败原因」，新任务先检索相似经验再动手，并定期把高频经验固化成 Skill，让它随运行越用越聪明。
