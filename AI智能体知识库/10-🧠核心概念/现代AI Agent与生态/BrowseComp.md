# BrowseComp

## 一句话定义
> BrowseComp 是 OpenAI 提出的「面向浏览型智能体」的基准测试，考察 Agent 在开放互联网上通过大量、隐蔽、多跳的信息检索，定位一个唯一、可验证答案的能力。

## 它解决什么问题 / 为什么存在
- 许多任务不是「知识问答」，而是「上网翻很多页、交叉验证、最后锁定一个冷门事实」（如：某被收购小公司的原始域名现在指向哪）。
- 普通知识问答基准（MMLU 等）测不出「会不会用浏览器做长链路调研」。BrowseComp 专门衡量 Agent 的检索耐力、信息甄別与可验证产出。

## 核心原理（大二电子信息工程专业学生能懂）
- 每个题目给一段自然语言描述，答案是一个「唯一字符串」（名称、日期、URL 等），机器可自动核对对错。
- Agent 被允许自由上网浏览（搜索、点链接、读页面），需要自己规划查哪些词、怎么交叉验证。
- 评分只看「最终答案对不对」，但背后考察的是长链路检索策略：何时换关键词、何时判定证据足够、如何避免被误导页面骗到。
- 与 BrowseComp 配套还有 BrowseComp-ZH（中文浏览器基准），考察中文网页检索能力。

## 关键参数 / 易错点
- 答案唯一可验证：不是开放论述，必须能机械判定对错——这保证评分客观。
- 难度来自「隐蔽 + 多跳」：答案常藏在很深处，单靠一次搜索找不到。
- 易错点：用「会聊天」的模型直接答，而不真正去检索——基准考的就是检索行为，不是参数记忆。

## 类比（帮助理解）
- 像「侦探查案」：给你一条模糊线索，要自己去翻档案、问人、比对，最后指认唯一嫌疑人；光靠脑子记人名是破不了案的。

## 设计时怎么用（反推思维）
> 做「深度研究 / 联网调研 Agent」时，我会用 BrowseComp 这类基准来验收：我的 Agent 是否能稳定完成多跳检索、并产出可验证的唯一答案，而不是只会用一次搜索就编一个看起来像的答案。

## 典型应用 / 我在哪见过
- 评测 Web Agent、深度调研助手、竞品/背景调查工具的信息查找可靠性。
- 常见于 Agent 能力榜单与论文（OpenAI BrowseComp、BrowseComp-ZH）。
