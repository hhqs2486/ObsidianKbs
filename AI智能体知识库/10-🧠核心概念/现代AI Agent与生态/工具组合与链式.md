# 工具组合与链式

## 一句话定义
> 工具组合与链式是指让 Agent 把多个工具「串起来用」：前一个工具的输出作为后一个的输入，或按规划依次调用，从而完成单个工具无法搞定的复合任务。

## 它解决什么问题 / 为什么存在
- 单个工具通常只解决原子动作（查天气、算汇率）。真实任务往往是「查 A → 用 A 的结果做 B → 再把 B 的结果写进 C」。
- 链式把原子能力拼成工作流，是 Agent 从「会调一个函数」升级到「能办成一件事」的关键。

## 核心原理（大二电子信息工程专业学生能懂）
- 函数调用循环：模型生成「调用工具」的请求 → 系统执行 → 把结果回灌给模型 → 模型决定下一步（再调工具 or 收尾作答）。
- 链式就是在这个循环里「多转几圈」：第 1 圈调 search，第 2 圈用 search 结果调 fetch，第 3 圈用 fetch 内容调 summarize。
- 编排方式有两种：由模型「动态决定下一步」（ReAct 式），或由代码「固定流程串起来」（workflow 式）。前者灵活，后者可控。
- 与工具接口设计强相关：工具越原子、描述越清，链式越不容易在中间一步断掉。

## 关键参数 / 易错点
- 错误传播：链中任一步失败/返回脏数据，会顺着链放大——需要每步有校验与重试。
- 循环上限（max steps）：必须设最大步数，防止模型陷入「无限调工具」烧钱。
- 上下文膨胀：链越长，塞回模型的工具结果越多，要注意裁剪与摘要。
- 易错点：把链式写死成脆弱脚本，一旦中间格式略变就全崩；应保留模型对「异常」的修复空间。

## 类比（帮助理解）
- 像「流水线作业」：原料（用户问题）进第一台机器（工具A）加工，半成品送第二台（工具B），最后出厂（答案）；任何一台卡住，整条线都得处理。

## 设计时怎么用（反推思维）
> 做「多步骤任务 Agent」（如「查资料→写报告→发邮件」）时，我会把每个环节拆成原子工具，用函数调用循环串成链，并在每步加校验与 max steps 上限，避免链断裂或失控。

## 典型应用 / 我在哪见过
- 研究助手、数据流水线、RPA 式自动化、Coding Agent 的「读代码→改文件→跑测试」链。
- 仓库 `phases/11-llm-engineering/09-function-calling` 讲解函数调用循环与链式编排、并行调用与安全规则。
