# ACP

## 一句话定义
> ACP（Agent Client Protocol，Agent 客户端协议）是 Anthropic 提出的开放协议，目标是标准化"客户端应用 ↔ 远程 Agent 运行时"之间的通信，让同一套客户端能驱动不同的 Agent 后端。

## 它解决什么问题 / 为什么存在
- 一个聊天/IDE 前端想接入各种 Agent 后端（本地 Claude、云端 Agent、第三方服务），如果每家后端 API 都不一样，前端要逐个适配。
- ACP 把"前端怎么把任务交给 Agent、怎么收流式结果、怎么处理中断"标准化，类似 MCP 但层次更高：MCP 是 agent↔tool，ACP 是 client↔agent。

## 核心原理（大二电子信息工程专业学生能懂）
- **角色**：一端是"客户端"（UI / IDE / 编排器），一端是"Agent 运行时"（真正跑循环的东西）。
- **关注点**：任务提交、消息/事件流、取消、中断与恢复、能力声明。
- 与 MCP 互补而非竞争：
  - MCP = 应用怎么连工具/数据；
  - ACP = 应用怎么连 Agent 本身；
  - A2A = Agent 之间怎么互相发现与协作。
- 通常也用 HTTP + JSON/流式事件，便于跨语言、跨厂商。

## 关键参数 / 易错点
- 别和 A2A 搞混：ACP 是"客户端到 Agent"，A2A 是"Agent 到 Agent"。
- 流式事件要定义清楚：文本增量、工具调用、中断请求、完成信号各是什么。

## 类比（帮助理解）
- MCP 是"插头标准"（机器接电源），ACP 是"遥控器和电视机之间的协议"（人通过遥控器指挥电视）。

## 设计时怎么用（反推思维）
> 做"一个前端要同时接多个 Agent 供应商"的产品时，我会用 ACP 这类协议统一客户端侧，避免为每个后端写一套适配。

## 典型应用 / 我在哪见过
- IDE/聊天客户端接入可替换的 Agent 后端、Agent 网关、多供应商编排。
