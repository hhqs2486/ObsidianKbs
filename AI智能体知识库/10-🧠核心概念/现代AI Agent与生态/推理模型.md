# 推理模型

## 一句话定义
> 推理模型（reasoning model）是一类在给出最终答案前，会显式展开「中间思考过程」的大模型，典型如 OpenAI o 系列、DeepSeek-R1、Claude 思考模式等，擅长数学、代码、规划等需要多步推导的任务。

## 它解决什么问题 / 为什么存在
- 普通对话模型对「多步逻辑、复杂约束、易错计算」容易一步答错、且看不出错在哪。
- 推理模型通过「先想清楚再答」提升难题准确率，并把思考链暴露出来便于检查与纠错，是 Coding Agent、复杂决策 Agent 的常用「大脑」。

## 核心原理（大二电子信息工程专业学生能懂）
- 训练上常用「强化学习 + 可验证奖励」：让模型生成思考过程和答案，只有答案在测试（如单测通过、数学判对）上正确才给奖励，逐步学会「该多想几步」。
- 推理时模型会先产出一段隐藏或可见的「思维链（CoT）」，再给最终答案；常可设「思考预算 / reasoning effort」控制想多久。
- 本质是把「搜索与验证」更多放在生成阶段：多采样、多自检、再收敛。

## 关键参数 / 易错点
- 推理预算（thinking/reasoning effort）：越高越准但越慢越贵。
- 思维链可见性：有些模型思考过程对用户隐藏，只给答案。
- 过度思考：简单题也想太久，浪费延迟与成本——需按任务难度调预算。
- 易错点：把推理模型当普通模型无脑套；或以为「有思考链就一定对」——它仍会出错，只是更易核查。

## 类比（帮助理解）
- 像「考试时打草稿」：普通模型直接写答案，推理模型先把推导写在草稿纸上再誊抄，错了也容易从草稿里发现哪步算岔了。

## 设计时怎么用（反推思维）
> 做 Coding Agent / 复杂规划 Agent 时，我会把「难题」交给推理模型当大脑（如先想清改哪个文件再动手），并把简单检索/格式化交给轻量模型，用推理预算平衡成本与准确率。

## 典型应用 / 我在哪见过
- 代码生成与调试、数学竞赛、科学推理、多步决策 Agent 的「规划器」。
- 代表：OpenAI o1/o3、DeepSeek-R1、Gemini 思考模式、Claude 扩展思考。
