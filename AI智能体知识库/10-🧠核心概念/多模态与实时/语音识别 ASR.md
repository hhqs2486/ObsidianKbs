# 语音识别 ASR

## 一句话定义
> 语音识别（Automatic Speech Recognition, ASR）把音频波形转换成文字，是语音 Agent 流水线「听」的一环——位于 VAD 之后、LLM 之前。

## 它解决什么问题 / 为什么存在
- 语音交互必须先「听懂」用户说了什么，才能交给 LLM 理解与生成回复。ASR 是把声音变成可处理文本的关键桥梁。
- 传统 VAD + ASR 级联存在延迟累积、信息丢失（二值有声/无声信号丢掉语气情绪）、准确率下降（切片段破坏上下文）三大问题。

## 核心原理（大二电子信息工程专业学生能懂）
- 传统流式 ASR：以 RNN-T、流式 Conformer 为代表，编码器因果/分块、解码增量，手机实时字幕、输入法语音输入即用此类——与 LLM 无关。
- 基于 LLM 的流式听觉感知（新路线）：以开源 LLM 为骨干后训练，直接从连续音频流输出语义级响应，把「识别」和「理解」合并进同一模型（如 Ultravox、Qwen2-Audio、Qwen2.5-Omni）。延迟保持单步推理量级（几十~一二百 ms），且能基于完整上下文做 ICL，对专业名词/发音习惯识别更准，还继承 LLM 世界知识（如知道「苹果+发布会」指 Apple 而非水果）。
- 关键区分：Whisper 不能流式，是因编码器需固定 30s 整段；流式识别靠因果/分块编码器 + 增量解码。
- 替代 VAD：在流式识别模型上加 LoRA 让它边转写边判断「这句话是否表达完整意思」，把轮次判断做进识别器（Deepgram Flux、AssemblyAI Universal-Streaming）。

## 关键参数 / 易错点
- 延迟：Whisper/SenseVoice 转录 5s 音频，GPU 中小模型 50–200ms，大模型或受限环境 200–500ms。
- 输出不止文字：还输出声学事件特殊 token（<speak_start/end>、<interrupt>、<emotion>、<laugh>、<noise>），供框架实现更自然交互。
- 易错点：VAD 把连续音频切成孤立片段破坏上下文，专有名词（如邮箱 "john dot smith"）跨片段易被误识别；纯静音阈值无法区分「轮内停顿」与「轮间间隔」。

## 类比（帮助理解）
- 像速记员边听边记：传统 ASR 是一句句记（靠静音判断断句），LLM 式流式感知是带着「前面说了啥、这人啥口音」的全局理解在记。

## 设计时怎么用（反推思维）
> 做实时字幕 Agent 时，我会用它能解决「传统 VAD 把长句在停顿处截断误识」——用基于 LLM 的流式感知模型，从对话开始到当前的连续音频流做上下文学习，正确识别带停顿的长句。
