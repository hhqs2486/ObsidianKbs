# 视觉理解

## 一句话定义
> 视觉理解（Visual Understanding）指 Agent 通过视觉-语言模型（VLM）从图像或屏幕画面中「看懂」内容——识别元素、理解布局、定位目标——是 Computer Use（GUI 自动化）和机器人操作的感知基础。

## 它解决什么问题 / 为什么存在
- Agent 要操作软件必须「看懂屏幕」：找到搜索框、确认提交按钮坐标；机器人要「看懂」摄像头画面才能抓物。
- 纯文本 Agent 没有视觉，面对 GUI/物理世界无能为力，视觉理解把像素变成可推理的语义。

## 核心原理（大二电子信息工程专业学生能懂）
- 视觉编码器把图像变成特征向量，与文本一起送入 LLM/VLM，模型输出思考与动作（如 click(512,250)）。
- Computer Use 的「感知-思考-行动」循环：①截图 → ②VLM 看截图+指令输出思考和动作 → ③执行层点鼠标/打字 → ④等界面稳定再截图循环。
- 视觉定位（Grounding）三种思路：
  1. Set-of-Mark（视觉标注）：用分割模型切候选区域、叠加编号，模型只报编号（像选择题）。
  2. 结构化元素索引（DOM/Accessibility Tree）：直接问界面「你有哪些可点击元素」，给编号（Web 上的结构化 SoM）。
  3. 纯坐标预测：模型直接输出点击坐标（SeeClick、Claude computer use），依赖训练分辨率，需双向坐标缩放。
- 机器人侧：VLA（Vision-Language-Action）在 VLM「看懂」之上再加「动手」输出控制信号。

## 关键参数 / 易错点
- 分辨率匹配：模型在固定训练分辨率（XGA/WXGA/FWXGA）预测坐标，输入分辨率不匹配会系统性偏移——需按宽高比选目标分辨率 + 双向坐标缩放。
- 观察接口升级：连续、自适应、多模态观察（帧间关键帧捕获 + 音量门控转写 + 把帧叙述成持久文字），让 Agent「长出耳朵、记住动态」。
- 易错点：把屏幕当静止帧处理，看不见视频/弹窗/转瞬即逝的通知——这是当前 Computer Use 的禁区。

## 类比（帮助理解）
- 像人看着电脑屏幕找按钮：选择题（SoM 给编号）比填空题（直接报坐标）容易答对；也像事先拿到「座位表」（DOM）比在人群里瞎找更准。

## 设计时怎么用（反推思维）
> 做浏览器自动化 Agent 时，我会用它能解决「在网页里找不到提交按钮」——用 browser-use 从 DOM 枚举可交互元素并编号，模型只输出 ID，系统换算中心坐标点击。
