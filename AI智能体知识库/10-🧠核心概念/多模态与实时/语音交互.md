# 语音交互

## 一句话定义
> 语音交互（Voice Interaction）指 Agent 以语音作为主交互界面——既能听懂用户说话（人机接口），也能代替用户对外说话（如打电话协商）。它是带宽最高、最自然的人机接口之一。

## 它解决什么问题 / 为什么存在
- 正常说话速度约为打字四倍，且无需占用双手与视线；语音正从次要输入变为日常主交互界面（whisper coding：口述指挥编程 Agent）。
- 需要一套实时语音技术同时服务「用户对 Agent 说」和「Agent 替用户对外说」两个方向。

## 核心原理（大二电子信息工程专业学生能懂）
- 语音架构三种范式（沿「如何摆脱轮流说话假设」这条轴演进）：
  1. 级联（Cascaded）：VAD → ASR → LLM → TTS 串流水线，一棒接一棒；模块清晰但延迟累积、信息在模型间丢失。
  2. 端到端全模态（Omni）：单一模型直接「听音频、想回复、说出来」，延迟更低、韵律情感保留，但仍假设轮流说话（依赖 VAD 划分轮次）。
  3. 全双工（Full-Duplex）：边听边说，每秒做多次「该说/听/停/打断/调工具」决策，彻底取消轮流假设（Moshi、GPT-Live）。
- 全链路流式化 + 流式语音感知（替代 VAD+ASR）进一步压缩延迟。
- 思考架构：快慢分工（GPT-Live 委派后台前沿模型）、或 Step-Audio R1 把思考内化进音频模型实现「边想边说」。

## 关键参数 / 易错点
- 延迟账：级联空载 ≈ 0.9–2.3s；全链路流式压到 600–800ms；Omni（如 Qwen3-Omni）首包 234ms；全双工（Moshi）≈ 200ms。
- VAD 静音阈值 500–800ms：太短误截断、太长干等。
- 易错点：Omni 仍依赖 VAD 划分发言权，用户停顿/背景噪音易被误判为「说完了」而强行插话；全双工才消解轮次本身。

## 类比（帮助理解）
- 级联像工厂流水线（前工位不做完后工位不能动）；全双工像同声传译（边听边译，聆听与翻译始终重叠）；全双工像两人面对面聊天（一方插话另一方自然停下）。

## 设计时怎么用（反推思维）
> 做电话 Agent 时，我会用它能解决「替用户打运营商客服等转人工」——把 PineClaw Voice 当工具接入 ReAct 循环，Agent 自主决定拨号、通话目标，结束后提取关键信息汇报。
