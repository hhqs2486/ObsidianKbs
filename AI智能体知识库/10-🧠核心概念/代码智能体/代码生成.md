# 代码生成

## 一句话定义
> 代码生成是让 Agent 把自然语言需求转化为可执行的程序代码；它不只是"写程序"，而是 Agent 的一种元能力——能当场创造新工具、新约束、新表达形态。

## 它解决什么问题 / 为什么存在
- 自然语言充满歧义（"年龄大于18且已实名认证"有多种理解），形式化代码则毫无歧义；一段能跑通的代码本身就是逻辑自洽的证明，执行结果提供客观对错标准。
- 当 Agent 缺工具、缺能力、格式变了，可以临时写代码解决——无需预先把所有可能能力都预制好。

## 核心原理（大二电子信息工程专业学生能懂）
- 代码作为元能力，有六个发挥方向（由内向外）：
  1. 思考工具：把精确计算/符号推理交给代码（如用 sympy 算题，避免 LLM 概率性算错）。
  2. 业务规则约束：把模糊政策写成确定性校验代码，在不可逆操作前设最后防线（如取消航班的政策校验）。
  3. 多媒体生成：用代码生成 PPT（Slidev）、视频（Blender/ffmpeg），配合"提议者-审核者"机制迭代。
  4. 系统适配器：现场生成解析/适配代码，连接异构 API、跟随数据格式演化（如日志自适应解析）。
  5. 生成式 UI：动态生成表单、图表、Web 应用（生成式 UI / A2UI 协议）。
  6. Agent 自举：用代码修复和创造同类 Agent（区别于[[自我进化]]）。
- 关键模式：Artifact 模式——Agent 只生成代码（如 SQL、前端），由系统直接执行并把结果直传前端，数据完全绕过 LLM，既快又准。

## 关键参数 / 易错点
- 安全：生成的代码可能有漏洞、死循环、资源耗尽；沙盒隔离能缓解但限制能力，需在安全与能力间平衡。
- 提示注入：生成式 UI 中恶意输入可能诱导生成窃取数据的脚本（类似 XSS，但成因是注入）。
- 模型与脚手架此消彼长：模型够强时脚手架可更薄，模型弱时需把关键推理交给代码兜住正确性。

## 类比（帮助理解）
- 像给 Agent 一台万能机床：不只能生产固定零件，还能临时车出新的夹具和模具。
- 像"用草稿纸代替心算"：复杂账交给计算器，人只负责理解题意。

## 设计时怎么用（反推思维）
> 做 Agent 系统时，我会让模型负责"理解需求并写代码"，把精确计算、规则校验、数据解析交给代码执行，用 Artifact 模式把大数据直传前端，避免 LLM 抄写出错。

## 典型应用 / 我在哪见过
- 数学/逻辑解题（代码辅助思考显著提效）、τ-bench 政策校验、PPT/视频生成、日志自适应解析、SQL 查询、动态表单澄清意图、ERP Agent、对话式界面定制。
