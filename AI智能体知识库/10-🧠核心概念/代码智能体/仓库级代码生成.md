# 仓库级代码生成

## 一句话定义
> 仓库级代码生成是指 Coding Agent 在理解整个代码仓库（项目结构、模块依赖、约定）的基础上，跨多个文件进行生成、修改与重构，而非仅针对单段孤立代码。

## 它解决什么问题 / 为什么存在
- 真实软件开发几乎都在"仓库"语境下进行：改一个功能要动多文件、要遵守项目约定、要不影响其他模块。
- 模型上下文窗口有限，无法把整个大代码库一股脑塞进去，需要智能的检索与状态管理。

## 核心原理（大二电子信息工程专业学生能懂）
- 起点是"项目文档化"：Agent 首次接触仓库先读 README/架构文档，缺失时主动生成 CLAUDE.md/AGENTS.md 等项目指令文件（相当于项目级系统提示词，注入 KV Cache 友好）。
- 四类互补的搜索工具（图5-3）：
  - Grep（正则内容匹配）：精确文本→所有出现位置。
  - Glob（文件名模式）：`**/*.test.ts` 快速扫描结构，不读内容。
  - 语义代码搜索：自然语言→向量+BM25 混合，能找"用词不同但语义相关"的代码。
  - 符号定义/引用（基于 LSP）：区分同名符号的定义与调用，重构时不会误改注释里的同名文本。
- 上下文精细管理：大文件按行号范围读取并带行号标注；命令输出截断（保留首尾错误上下文）；环境信息以 Agent 状态栏动态注入（cwd、git 分支、未暂存变更）；维护持久化终端会话保存工作目录与环境变量。
- 路线之争：Claude Code 不建索引、纯靠 agentic grep+glob 现场检索（避免陈旧索引与外发风险）；Cursor 愿为跨文件语义召回建嵌入索引。

## 关键参数 / 易错点
- 上下文溢出：大库需按需检索而非全量塞入。
- 行号漂移与同名歧义：靠 LSP 符号搜索而非纯文本搜索解决。
- 知识必须存在于代码库本身：Agent 看不到的等于不存在（Harness 原则）。

## 类比（帮助理解）
- 像装修前先看懂整栋楼的水电图纸，而不是只盯着一面墙。
- 像用"目录+检索"在图书馆找书，而不是把整个图书馆搬进书房。

## 设计时怎么用（反推思维）
> 做仓库级 Coding Agent 时，我会先让 Agent 建立项目指令文件，组合 Grep/Glob/语义/LSP 四类搜索，按需读片段并用状态栏注入环境信息，避免全量上下文。

## 典型应用 / 我在哪见过
- 大规模代码迁移、跨文件重构、新功能开发（Anthropic 把长任务拆成初始化/执行双 Agent）。
