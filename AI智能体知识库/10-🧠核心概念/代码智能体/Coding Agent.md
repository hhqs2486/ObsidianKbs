# Coding Agent

## 一句话定义
> Coding Agent 是一个能自主编写、修改、执行代码，并用文件系统管理工作空间（代码、数据、记忆、中间结果）的通用智能体，是开放任务型通用 Agent 的核心内核。

## 它解决什么问题 / 为什么存在
- 通用 Agent 要处理任意任务，但无法预先枚举所有需要的工具。Coding Agent 用少量通用工具（代码执行、文件读写、搜索、网络）构建运行时，再叠加浏览器自动化等能力模块，成为通用 Agent 最坚实的技术底座。
- 代码生成是一种"元能力"：能在运行时动态创造新工具和新约束，是其余能力的基础。

## 核心原理（大二电子信息工程专业学生能懂）
- 类比做实验：你有一台电脑（沙盒），一套命令行（Bash）、一个代码解释器（Python）、文件读写工具，就像实验室里的基本仪器。
- 一个基础 Coding Agent 只需 7 个核心工具：①Code Interpreter（隔离沙盒跑 Python）②Bash Shell（执行命令）③读文件 ④写文件 ⑤编辑文件 ⑥Glob（按文件名模式找文件，如 `**/*.py`）⑦Grep（按内容搜文本，如搜所有调用某函数的行）。这些都可通过 MCP 协议暴露为标准化工具。
- 典型工作流程（图5-2）：项目文档化 → 需求理解/澄清 → 编写设计文档 → 编码与测试（测试-修复循环，平均2-3轮收敛）→ 自我审查与交付。核心原则："计划先于行动，验证贯穿始终，文档与代码共同演化"。
- OpenClaw 等产品的架构：Coding Agent 运行时 + 文件系统中枢（MEMORY.md 记事实与偏好，按日归档日志，Git 做版本回滚）。文件系统的持久化让 Agent 能"越用越聪明"（外部化学习）。

## 关键参数 / 易错点
- 安全"致命三要素"：访问私有数据 + 暴露于不受信任内容 + 具备外部通信能力，三者齐备即构成攻击闭环；本书补充"持久记忆"为第四放大器。
- 沙盒隔离：默认断网（按需白名单放行）、源码只读挂载、资源限额与超时（返回结构化错误而非静默杀死）。
- 命令校验要用"语义解析"而非关键字黑名单（如 `$(echo rm) -rf /` 可绕过黑名单）。
- 故障恢复：分类（API层/工具层/上下文层/控制流层）→ 检测指纹与计数 → 分级升级重试 → 每条恢复路径必须有熔断上限，避免死亡螺旋。

## 类比（帮助理解）
- 像一个刚入职的工程师：先读 README 熟悉项目，再改代码、跑测试、写文档，而不是直接上手提交。
- 大模型像"新操作系统"：屏蔽了语言理解与规划的复杂性，为上层 Agent 提供统一智能抽象。

## 设计时怎么用（反推思维）
> 做通用 Agent 系统时，我会用 Coding Agent 作为核心运行时（而非从零造专用工具），把代码执行+文件系统作为能力中枢，并对危险操作加沙盒与检查。

## 典型应用 / 我在哪见过
- Manus、OpenClaw、Claude Code、Cursor 等均以 Coding Agent 为核心。
- 适用边界：开放任务型通用 Agent（深度调研、内容生成、数据处理）以 Coding 为核心；垂直客服等封闭任务中 Coding 是基础能力但非架构中枢。
