# 代码补全

## 一句话定义
> 代码补全是指 Agent（或 IDE 中的 AI）根据已有上下文，自动生成或填充下一段代码（一行、一个函数、或一段缺失实现）的能力，是代码生成在"局部编辑"场景下的具体形态。

## 它解决什么问题 / 为什么存在
- 写代码大量工作是"在正确位置填上正确内容"：补全函数体、实现接口、续写逻辑。让模型自动完成这部分，能显著提升 Coding Agent 与程序员的效率。
- 它也是文件编辑工具的核心：模型如何"告诉系统改哪里、怎么改"决定了补全/编辑的正确率。

## 核心原理（大二电子信息工程专业学生能懂）
- 本质仍是"预测下一个 token"，但限定在代码语境里。模型读入光标前的代码（及项目其他相关文件），输出后续代码。
- 文件编辑有五种主流方案（图5-4），对应不同的"补全/修改"表达方式：
  1. Diff + Apply Model：模型生成 diff 描述，交给小模型（Apply Model）合并。
  2. 旧字符串→新字符串（Old→New，Claude Code 采用）：精确匹配替换，可预测但大段删除需全输出。
  3. 行号定位：指定删除第X-Y行插入内容，大段高效但模型易数错行号。
  4. 类 Vim 命令：丰富编辑语义，弱模型易错。
  5. 字符串首尾匹配：只需提供首尾边界即可定位，大段删除免全输出，兼顾可靠与高效。
- Cursor 走 Apply Model 路线（fast-apply 小模型 + 推测解码，每秒上千 token）；Claude Code 走 Old→New 路线（可靠优先）。

## 关键参数 / 易错点
- 行号易漂移：每次编辑后后续行号变化，限制多处并行编辑——需在读取时给每行加行号标注缓解。
- 唯一性：Old→New 要求 old string 在文件中存在且唯一，否则失败；出现多次时需更长上下文消歧。
- 实践建议：自建 Agent 用 Old→New 最稳妥；大段改动用首尾匹配；行号方案仅限 IDE 深度集成场景。

## 类比（帮助理解）
- 像在文档里"查找替换"：你给出要找的文本和替换后的文本，系统精准定位替换。
- 像拼图：首尾匹配只给你看拼图块的两头，系统据此找到整块位置。

## 设计时怎么用（反推思维）
> 做代码编辑功能时，我会优先用"旧字符串→新字符串"保证可靠，大段改动改用首尾匹配，并把行号标注作为环境信息注入，降低模型数错行号的概率。

## 典型应用 / 我在哪见过
- IDE 内联补全（Cursor、Copilot）、Coding Agent 的 edit_file 工具、函数实现续写、bug 修复补丁生成。
