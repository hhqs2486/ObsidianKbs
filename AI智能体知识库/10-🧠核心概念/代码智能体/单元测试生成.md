# 单元测试生成

## 一句话定义
> 单元测试生成是指让 Coding Agent 为新增或修改的代码自动编写测试用例，覆盖正常路径、边界条件和异常情况，并用"测试-修复"循环保证质量。

## 它解决什么问题 / 为什么存在
- 代码写完不跑测试就报告"完成"是 Coding Agent 最常见的偷懒方式。把"测试通过"而非"代码写完"定义为完成标准，是把它从"代码生成器"提升为"可靠工程助手"的关键。
- 测试套件本身也是 Harness 的"验收基线"——提供明确、可自动验证的完成判据。

## 核心原理（大二电子信息工程专业学生能懂）
- 在 Coding Agent 流程（图5-2）的"编码与测试"阶段：实现完成后立即写测试用例，再执行测试套件（如 pytest）。
- 若测试失败，Agent 不应只报告失败，而应分析原因、定位问题、修改代码直到全部通过——这个"测试-修复"内循环平均 2-3 轮收敛。
- 即时语法反馈：文件写入完成，工具层自动跑 Linter/语法检查，把错误作为工具返回值给 Agent，让它在引入错误的那一刻就修正（像 IDE 画红线）。
- 在 SWE-bench 等评测中，测试是奖励信号：FAIL_TO_PASS 证明修了问题，PASS_TO_PASS 证明没引入新 bug。

## 关键参数 / 易错点
- 不要跳过测试环节（过早终止问题，见[[评估]]的 Loop 工程）。
- 测试要覆盖边界与异常，而非只跑 happy path。
- Linter/类型检查提供即时自动验证，是 Harness 的重要组成。

## 类比（帮助理解）
- 像交作业前自己先对一遍答案：错一题改一题，全对才交。
- 像生产线的质检台：每道工序完都过检，不合格就回炉。

## 设计时怎么用（反推思维）
> 做代码 Agent 时，我会把"测试通过"设为硬性完成标准，自动跑 Linter 给即时反馈，并用 PASS_TO_PASS/FAIL_TO_PASS 做回归验证。

## 典型应用 / 我在哪见过
- pytest 驱动的修复循环、CI 管道中的自动化测试、SWE-bench 的测试验证。
