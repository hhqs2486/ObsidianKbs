# Agent 权限系统

## 一句话定义
> Agent 权限系统是"管住自主 Agent 能做什么"的授权机制：用一套从"每步都审"到"全放行"的权限阶梯，配合审批流和最小权限原则，控制 Agent 执行敏感操作。

## 它解决什么问题 / 为什么存在
- 跑在你机器上的自主 coding agent 是个独立安全类别：它的攻击面是它能碰的一切——文件系统、网络、凭据、剪贴板、任何浏览器标签、任何开着的终端。Schneier 等公开指出 computer-use agent 不是聊天机器人的"功能更新"，而是风险画像全新的工具。
- 不能只给"自主/不自主"一个开关。需要的是按任务风险分级、可审计、可控的授权。

## 核心原理（大二能懂的水平）
- 以 Claude Code 的**六档权限阶梯**为代表（UI 把 default 标成 "Manual"）：
  - `plan`：先出计划、用户批整个计划，每步执行前都审——陌生任务/接近生产的代码/第一次用 Agent 时。
  - `default`（Manual）：Agent 自己跑，只对"高风险"动作（Shell 执行、破坏性操作、网络调用）提示用户——多数交互编码场景。
  - `acceptEdits`：文件写入自动批，但 Shell 执行和网络调用仍提示——跨多文件重构。
  - `auto`：一个**独立的分类模型**在每步执行前审一遍，拦掉超出请求范围的操作；用于受限工作区里的长程无人值守跑。
  - `dontAsk`：从不提示，规则没预批的动作直接拒绝——临时沙箱、CI、研究脚本。
  - `bypassPermissions`：全放行——文档写明"只在你愿意丢弃的一次性容器里"。
- **Auto Mode（2026-03 推出）**是把"每步审批"委派给模型：分类模型按声明任务和会话状态判每个动作，越界就拦、回退给用户。可用性受套餐/组织开关/模型/提供商限制。
- 配套预算护栏：`max_turns`（会话总迭代数）、`max_budget_usd`（金额上限中止）、按工具的动作计数上限（如 WebFetch 不超过 N 次）。

## 关键参数 / 易错点
- 分类模型能抓的：明显的工具输入提示注入（映射到已知危险动作形）、重复工具循环（action N+1≈N 连续五次）、文件编辑会话里明显越界的 shell 命令。
- 分类模型**抓不到的**：细微提示注入（不产出单个被标动作却能调行为，间接注入无法完全补）；语义级失配（每步看着安全、组合起来有害，分类器判动作不重推用户意图）；通过合法通道外泄（写你自己文件→git push 到公开仓，是组合问题）。
- Anthropic 明确 Auto Mode 是 research preview：分类器是一层不是方案，要配合预算 + 允许列表 + 隔离工作区 + 轨迹审计。
- 权限阶梯选择：陌生任务起步用 plan（读计划比回滚便宜）；已知重构用 acceptEdits；无人值守只在你量过爆炸半径的工作区用 auto；一次性容器才用 dontAsk/bypassPermissions。

## 类比（帮助理解）
- 像自动驾驶的介入等级：从全程人工握方向盘（plan），到高速上自动驾驶但变道要确认（default），到限定区域全自动（auto），到只在试车场里随便造（bypassPermissions）。
- 分类模型像"副驾安全员"，每步动作他先扫一眼是否越界——但他看的是单个动作，看不出"一串动作组合起来要去干坏事"。

## 设计时怎么用（反推思维）
> 做"让 Agent 在我机器/仓库里自主干活"的系统时，我会用权限阶梯按风险分级：陌生/生产邻近任务用 plan，已知重构用 acceptEdits，无人值守长程跑只在隔离沙箱里用 auto，并叠加 [[Agent 安全]] 的护栏与 [[Agent 安全门禁]]；同时用 max_turns/max_budget_usd 做预算熔断，绝不把 bypassPermissions 用在有凭据的真实机器上。

## 典型应用 / 我在哪见过
- Claude Code 的六档模式 + Auto Mode 分类器（2026-03-24 推出）。
- 企业里把 Auto Mode 与预算、允许列表、隔离工作区、轨迹审计组合使用。
