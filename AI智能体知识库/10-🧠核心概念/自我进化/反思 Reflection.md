# 反思 Reflection

## 一句话定义
> 反思（Reflection）是 Agent 在任务失败后，用自然语言对自身失败原因进行复盘，并把这份反思文本作为经验存入记忆，下次遇到同类任务时读取以避免重蹈覆辙——它是「不改权重的进化」的经典范式。

## 它解决什么问题 / 为什么存在
- 策略摘要、工作流录制都只从「成功轨迹」提炼经验；但失败经验信息量往往更大：一次失败明确排除了一条路径，而成功只是众多可行路径之一。
- 需要一种机制让 Agent 能从失败中沉淀知识，而非只记成功经验。

## 核心原理（大二电子信息工程专业学生能懂）
- 代表工作 Reflexion（Shinn et al., 2023）：任务失败后，Agent 用语言对失败原因做反思（例如「我应该在第三步先验证身份，而不是直接提交表单」）。
- 反思文本存入情景记忆（episodic memory）；下次尝试同类任务时，把这些反思作为额外上下文读取，避免再犯同样的错。
- 整个过程不更新任何模型参数——典型「外部化学习」。
- 用语言承载的反思，信息量远比一个标量奖励（对/错）丰富；失败经验的另一出口是写入系统提示词（负面规则）。

## 关键参数 / 易错点
- 失败经验两种沉淀形态：错误模式库（什么情况用什么方法会失败、失败信号是什么）、负面规则（「不要再用 X 方法做 Y」）。
- 易错点：反思若未经审查就被当成「经验」沉淀，可能把错误结论固化、甚至被提示注入污染（记忆投毒）。

## 类比（帮助理解）
- 像考试做错题后写错题本：不重做模型权重，只在笔记本上记下「这道题我哪步想错了」，下次看到同类型题先翻错题本。

## 设计时怎么用（反推思维）
> 做编程 Agent 时，我会用它能解决「同一个编译错误反复犯」——失败后让模型写一段反思存入情景记忆，下次遇到相似报错先读这段反思再动手。

## 典型应用 / 我在哪见过
- Reflexion（2023）：用语言反思驱动 verbal reinforcement learning。
- 客服 Agent 把「不要打电话办某运营商退订，电话渠道无权限」沉淀为负面规则。
- 系统提示词自动优化把失败案例提炼的负面规则写进系统提示（详见 [[自我改进]]）。
