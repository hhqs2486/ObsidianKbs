# 自我改进

## 一句话定义
> 自我改进（Self-Improvement）指 Agent 通过「系统提示词自动优化」等机制，从失败案例和边界情况中提炼规则、持续改写自身的系统提示词（或工具描述），从而「越用越准」——Karpathy 称之为「系统提示学习（System Prompt Learning）」。

## 它解决什么问题 / 为什么存在
- 很多 Agent 的学习过程更像「系统提示」的更新：遇到问题想通了，用明确语言给自己记下来（「下次遇到这种问题，先试这种方法」）。
- 传统系统提示由人类手工编写，无法随每次失败快速进化；需要 Agent 自主、可解释地改进自己的行为约束。

## 核心原理（大二电子信息工程专业学生能懂）
- 核心思想：系统提示词本身就是一种经验载体。遇到边界情况（edge cases），由 Coding Agent 读取现有系统提示，生成精确 diff，把新规则写进去，人类专家审核。
- 反馈带宽优势：RL 只有「对/错」一个标量奖励；系统提示学习是一整段自然语言复盘（「应先验证身份证再走退款流程」），信息量天差地别——同一次失败吸收的信息远多于一个比特。
- 本质是通过边界情况让规则边界更清晰：典型场景运行良好，真正的挑战在灰色地带（「用户不满意政策」算不算超出能力范围？）。
- 自动化框架补充：DSPy 把提示词当可优化参数搜索；OPRO 让 LLM 自己当优化器迭代改写；GEPA 对失败轨迹做自然语言反思、维护帕累托前沿（一组互补候选解），在多项任务上超过 GRPO 微调。

## 关键参数 / 易错点
- 离线 vs 在线：DSPy/OPRO/GEPA 在评估集上批量优化；diff 方案随生产边界案例逐条演进。
- 有无人工把关：自动化框架端到端改写可能过拟合评估集；diff 方案保留人类审核，更适合高风险场景。
- 是否需要评估集：前者依赖带评分任务集；后者只需单个失败案例 + 人类反馈。

## 类比（帮助理解）
- 像专家在工作中不断完善自己的笔记：每踩一次坑就加一条规则，最终系统提示演化成一本详尽的「问题处理手册」。

## 设计时怎么用（反推思维）
> 做航空客服 Agent 时，我会用它能解决「一遇政策争议就转人工」——从过度转接的失败案例提炼「绝不因政策争议而转接」的负面规则，由 Coding Agent 生成 diff 写进系统提示，人工审核后上线。

## 典型应用 / 我在哪见过
- tau-bench 航空客服场景：把转接边界明确为「用户明确要求人工 + 紧急安全情况」，新增负面规则。
- GEPA（2025）对失败轨迹做反思式提示进化，采样次数比 RL 少 1–2 个数量级却超过 GRPO 微调。
