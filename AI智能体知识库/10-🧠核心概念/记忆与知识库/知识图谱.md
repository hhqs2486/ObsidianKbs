# 知识图谱

## 一句话定义
> 知识图谱（Knowledge Graph，在 RAG 中称 GraphRAG）是用“实体—关系—实体”三元组构建的知识之网，擅长多跳推理和同名实体消歧，是 [[RAG]] 的结构化索引方案之一。

## 它解决什么问题 / 为什么存在
- 扁平文本块检索（见 [[分块策略]]）只能“找最相关的几个”，答不了“A 如何影响 B”“我的医生所在医院地址”这类跨实体、多跳的问题。
- 知识图谱把知识建模成图，沿关系边遍历，使多跳查询既高效又可靠；还能原生区分两个同名“张医生”（靠各自关系边）。

## 核心原理（大二电子信息工程专业学生能懂）
- 三元组（主语-关系-宾语）表达一条知识，如（北京, 是首都, 中国）、（张三, 就职于, 腾讯）。大量三元组交织成网。
- 构建：先用 LLM 从文本抽取实体（人/地/概念）和关系，再靠社区发现（Community Detection）算法找紧密集群、生成摘要，自动发现主题。
- 两大不可替代能力：
  - **多跳推理**：沿“用户→医生→医院→地址”逐跳遍历，扁平存储要多次检索且易断链。
  - **实体消歧**：两个“张医生”是图中不同节点，靠“牙科/心内科”关系边区分——这不同于“bank”一词多义（词义消歧靠嵌入即可）。
- 与 RAPTOR（树状层次摘要，适合“从概念钻细节”）互补：GraphRAG 适合“谁和谁有关系”类问题。

## 关键参数 / 易错点
- 代价：把自然语言拆三元组会造成语义降级——条件判断、时间依赖（如“若下周还下雨就改去博物馆”）被拆成孤立事实后丢失逻辑。
- 准确性依赖 LLM 抽取，错误提取会污染知识。
- 实践推荐分层互补：以完整自然语言保核心信息，辅以图谱作专项索引（医疗/法律/家谱等垂直场景）。

## 类比（帮助理解）
- 像一张人际关系网：你知道“小明→同学→小红→住→幸福小区”，顺着线就能回答“小明同学家在哪”，而不用翻遍所有人的简历。

## 设计时怎么用（反推思维）
> 做医疗问诊助手时，我会用 GraphRAG 建“症状—疾病—药物—禁忌”关系网，让 Agent 能多跳推理“该药是否与该患者过敏史冲突”。

## 典型应用 / 我在哪见过
- 实验3-8 用 RAPTOR vs GraphRAG 索引英特尔 CPU 手册；Mem0-g 是图记忆变体；用户记忆消歧（Advanced JSON Cards 的 person/relationship 字段是图谱思想的轻量版）。
