# 长期记忆

## 一句话定义
> 长期记忆（Long-term Memory）是 Agent 跨会话、跨实例的持久化存储，通常以键值对形式与特定用户 ID 绑定，保存偏好、历史摘要和提取出的知识点。

## 它解决什么问题 / 为什么存在
- 单次会话用完即弃不够——用户希望 Agent “上次聊过的事你还记得”。
- 长期记忆让个性化与连续性成为可能：Agent 用专门的工具显式读取/更新它，实现跨会话的“懂你”。

## 核心原理（大二电子信息工程专业学生能懂）
- 在记忆的“层次结构”里，与 [[短期记忆]]（轨迹 / 工作记忆，单次会话的流水账）相对，长期记忆是跨会话提炼出的稳定信息，会被反复改写、合并、淘汰——前者是流水账，后者是档案。
- 存储形态从简单到复杂有四档（参见 [[用户记忆]]）：
  - Simple Notes：一条最小事实，开销极低但丢失关联。
  - Enhanced Notes：整段叙事，语义完整但难更新。
  - JSON Cards：类别→子类别→键值，支持部分更新。
  - Advanced JSON Cards：再加 backstory（来源背景）、person（主体）、relationship（与用户关系），解决同名实体消歧。
- 写入靠“提取—对比—决策”流水线（如 Mem0）：新对话结束→LLM 抽取候选记忆→向量检索相近旧记忆→LLM 判 ADD/UPDATE/DELETE/NOOP，保证记忆库每一条都和既有记忆对过账。

## 关键参数 / 易错点
- 关键且少量的数据（偏好、关键人物关系）用 Advanced JSON Cards 保证可检索；大量非关键事实用 Simple Notes 降本；生产系统多用混合模式。
- 易错点：只追加不合并会留下矛盾记录；长期记忆的安全更新需要冲突检测（版本化）。

## 类比（帮助理解）
- 像人的长期记忆：把工作记忆里“刚才发生的事”反复巩固，变成“我知道的事”，下次不用重新经历就能用。

## 设计时怎么用（反推思维）
> 做多轮客服系统时，我会把用户身份、偏好、已办业务存进长期记忆，新会话开始先读出来，省去重复采集，并用 UPDATE/DELETE 处理用户改口。

## 典型应用 / 我在哪见过
- 用户画像（稳定属性）、事件记忆（时间线）、跨会话的“用户有两辆车 / 护照快过期”等。
- 推荐框架：Mem0（事实条目，接近语义记忆）、Memobase（用户画像+事件记忆）。
