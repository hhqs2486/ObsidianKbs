# 用户记忆

## 一句话定义
> 用户记忆（User Memory）是为单个用户建立的、跨会话持久化的个性化知识模型，让 Agent 在多次对话后仍然“懂你”。

## 它解决什么问题 / 为什么存在
- 单次对话结束后，Agent 往往“失忆”——下次对话又要从零了解用户。
- 用户记忆把分散在漫长对话中的关键信息（偏好、习惯、身份、需求）显式提取、压缩、持久化，构建一份关于用户的预测模型，实现连续性、个性化的服务。
- 它和 [[上下文 Context]]（会话内临时信息）形成对照：上下文学习是临时的、会话结束即消失；用户记忆是持久的、可审查的。

## 核心原理（大二电子信息工程专业学生能懂）
- 本质是一个“主动、持续的学习过程”：每当一段对话结束，框架额外调用一次大语言模型 LLM 来分析对话，把值得长期记住的信息抽成结构化事实。
- 原始对话像流水账，Agent 不会逐字记，而是做三件事：
  - **选择性**：只留对未来有用的事实（如“用户素食、需要特殊餐食”），不记“返回了 3 个航班选项”这种临时信息。
  - **抽象化**：把“我偏好靠窗座位”提炼成一条通用偏好，而不是绑定到某次具体航班。
  - **结构化**：每条记忆打上类型标签（偏好 / 限制 / 账号），便于检索。
- 记忆能力可分成三层次评估框架：第一层基础回忆（精确存回直接信息）、第二层多会话检索（跨多个对象/时期拼出全部相关信息）、第三层主动服务（跨很久的会话发现隐藏联系、提前预警）。

## 关键参数 / 易错点
- 表示格式的权衡：Simple Notes（原子事实，O(1) 但丢失关联）、Enhanced Notes（整段叙事，语义完整但难更新）、JSON Cards（三层结构化，易部分更新但分类刚性）、Advanced JSON Cards（带 backstory/person/relationship，能消歧但成本高）。
- 易错点：记忆爆炸（无压缩会拖慢检索）、信息冲突（用户改口时旧记忆不更新）、隐私泄露（敏感数据进上下文）。
- 认知类型要分清：情景记忆（具体事件）、语义记忆（一般知识）、程序记忆（行为流程）。

## 类比（帮助理解）
- 就像你和朋友相处：不会记住每次聊天的原话，而是在相处中逐渐形成一个“他爱吃什么、脾气怎样”的生动模型，下次不用再问。

## 设计时怎么用（反推思维）
> 做个人助理系统时，我会在每次对话结束触发一次 LLM 抽取调用，把偏好/限制/账号写入 [[长期记忆]]，下次对话直接读取，避免重复询问。

## 典型应用 / 我在哪见过
- 订票助手记住座位偏好和常旅客号；客服助手记住用户有两辆车并主动询问为哪辆保养；报税季主动整合全年税务文件。
- 工程中常用 [[记忆管理]] 框架（如 Mem0、Memobase）落地。
