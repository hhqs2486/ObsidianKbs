# 短期记忆

## 一句话定义
> 短期记忆（在 Agent 语境中即工作记忆 / Working Memory）是 Agent 当前任务所在的临时信息空间，对应它的上下文窗口，用于处理“眼下正在做的事”。

## 它解决什么问题 / 为什么存在
- LLM 一次只能“看到”有限的上下文。短期记忆承载当前对话的即时信息，让 Agent 知道“我刚才说了什么、用户怎么回、工具返回了什么”。
- 认知科学把记忆分为工作记忆（短期）和长期记忆（跨会话）；Agent 的记忆层次也对应：轨迹 / 工作记忆管当前，[[长期记忆]]管跨会话。

## 核心原理（大二电子信息工程专业学生能懂）
- **轨迹（Trajectory）** 是短期记忆最核心的内容：一次 Agent 运行从开始到当前的完整事件序列（用户消息 + 模型回复 + 工具结果），按时间顺序“只增不改”（append-only）。
- 工作记忆与轨迹的关系：轨迹是不可变的完整序列，工作记忆是从中长期记忆里“激活加载”出来的、按相关性裁剪的动态子集。
- 短期记忆还可能包含从 [[长期记忆]] 激活加载进来的信息，以及业务状态（如“等待付款”“处理请求中”这类任务阶段抽象）。

## 关键参数 / 易错点
- 容量有限：上下文窗口大小决定它能装多少；窗口被填满后必须靠 [[上下文 Context]] 压缩或 [[RAG]] 检索来腾空间。
- 易错点：把短期记忆当成持久存储——它随会话结束而消失，重要信息必须转入 [[长期记忆]] 或 [[知识库]]。

## 类比（帮助理解）
- 像人“眼前这张便签”：记着现在正在处理的几件事，便签写满就擦掉旧的；真正重要的会抄进长期笔记本。

## 设计时怎么用（反推思维）
> 做 Agent 时，我会把当前会话的原始事件流作为轨迹 append-only 保留供即时决策，同时用上下文压缩控制窗口，必要时把关键信息抽到长期记忆防丢失。

## 典型应用 / 我在哪见过
- ReAct 循环里的“Observation”就来自短期记忆（参见 [[ReAct]]）；多轮对话的即时上下文；事件驱动架构中的当前任务状态。

## 关联
- 前置知识：[[上下文 Context]]、[[用户记忆]]
