# 数据管道与预训练

## 一句话定义
> LLM 预训练的数据管道：从原始网页爬取到可训练的固定长度 token 序列，经过 HTML 清洗、MinHash 去重、质量过滤、序列打包等步骤——数据质量决定模型质量。

## 它解决什么问题 / 为什么存在
- 模型架构大同小异（都是 Transformer 堆叠），输出质量差异 overwhelmingly 来自数据
- Chinchilla 缩放定律：给定计算预算，模型参数和训练 token 应等比缩放。70B 模型需 1.4T token 才最优
- 原始数据（Common Crawl ~250TB）充满 HTML 标签、重复页面、SEO 垃圾、PII——不能直接喂给模型
- Llama 3 用了 15.6T token，数据配比 50% 网页 + 25% 代码 + 13% 书籍论文 + 8% 数学 + 4% 多语言

## 核心原理（大二能懂的水平）
- **数据清洗步骤**：
  - HTML 剥离：用 trafilatura/readability 提取正文，去掉导航/广告/样板
  - 语言检测：fastText 分类，置信度 <0.8 的丢弃
  - 质量过滤：RefinedWeb 方法——在 Wikipedia 上训练小语言模型，给每篇文档打困惑度，高困惑度 = 不像 Wikipedia = 可能垃圾
  - PII 移除：正则匹配邮箱/电话/身份证号 + NER 模型识别上下文中的姓名
- **MinHash + LSH 近似去重**：
  1. Shingling：文档转为 n-gram 集合（如 5-word shingles）
  2. MinHash：对每个文档的 shingle 集合算 k 个哈希值，生成固定大小"签名"近似 Jaccard 相似度
  3. LSH：按签名波段分桶，同桶文档为候选近似重复——避免 O(n²) 两两比较
  4. 验证：对候选对算精确 Jaccard，>0.8 则删除一个
  - Llama 团队报告去重移除了约 38% 的网页数据
- **序列打包**：多个短文档拼入一个固定长度序列（用 EOS 分隔），注意力掩码设为块对角（文档 A 的 token 不能 attend 文档 B）
- **Chinchilla 缩放定律**：N_opt ~ C^0.5, D_opt ~ C^0.5。10x 参数需 10x token
  - Llama 3 故意违反：70B 用 15T token（严重过训练），推理更便宜——"推理最优"缩放

## 关键参数 / 易错点
- **去重是最 impactful 的清洗步骤**：>1/3 的 Common Crawl 是重复或近似重复。不去重 = 浪费算力 + 模型逐字背诵
- **MinHash 参数**：num_hashes=128（精度），bands=16（召回率）。更多 hash → 更准确；更多 bands → 抓到更多重复但假阳更多
- **序列利用率**：低于 90% 说明打包效率低，浪费算力在 padding 上
- **压缩比**：英文约 3-4 字符/token。1.5 = tokenizer 切太碎；8+ = 学了太领域化的 merge
- **数据配比无公式**：太多网页→Reddit 鹦鹉；太少代码→不会编程；太少数学→不会推理。需要实验
- **Llama 3 故意过训练**：更多数据 + 更小模型 = 推理更便宜。额外训练成本付一次，小模型便宜服务永远

## 类比（帮助理解）
- 数据管道就像"食材加工流水线"：原始食材（Common Crawl）有泥沙虫子（HTML/垃圾/重复），先清洗（HTML 剥离）→ 检测质量（困惑度过滤）→ 去掉重复食材（MinHash）→ 切成标准尺寸装盒（序列打包）
- MinHash 就像"指纹比对"：不比较整篇文档（太慢），而是比较一组哈希"指纹"——指纹相似则文档相似
- Chinchilla 定律就像"做饭的食材和锅要匹配"：10 倍大的锅（参数）需要 10 倍多的食材（数据）

## 设计时怎么用（反推思维）
> 在训练前先算数据统计：总 token 数、去重比例、序列利用率、压缩比。确认数据配比覆盖代码/数学/多语言。如果序列利用率 <90%，改进打包算法。Llama 3 路线：小模型 + 更多数据 = 推理更便宜——除非你有特殊理由，否则选这条路。

## 典型应用 / 我在哪见过
- GPT-3：300B token（Chinchilla 下欠训练 3-4x）
- Chinchilla：70B / 1.4T token（最优）
- Llama 3：70B / 15T token（故意过训练，推理最优）
- DeepSeek-V2：8.1T token
- RefinedWeb（Falcon 的数据集）：困惑度过滤的典范
