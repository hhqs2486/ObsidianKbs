# 间接提示注入

## 一句话定义
> 间接提示注入（IPI）将指令嵌入外部内容——网页、邮件、共享文档、工单——由 Agent 系统在无用户主动操作下消费。IPI 绕过用户输入过滤器因为攻击者从未接触用户，随 Agent 处理更多外部内容默默扩展，是 2026 年主导的生产安全威胁。

## 它解决什么问题 / 为什么存在
- 直接提示注入需要攻击者接触用户或其 prompt。IPI 不需要——攻击者把 payload 放在 Agent 正常操作中会读取的任何内容中
- Agent 在正常运行中捡起它并执行指令。用户只是信使，不是意图
- OWASP LLM Top 10 (2025) 把提示注入（直接+间接）排为 LLM01——#1 应用层威胁

## 核心原理
- **三种交付向量**：① RAG 注入——攻击者发布文档，检索步骤拾取，prompt 在用户问题前拼接 ② 收件箱/文档工作流——攻击者发邮件，Agent 读取，prompt 包含邮件正文 ③ 工具输出——攻击者控制 Agent 使用的工具（如搜索结果返回攻击者可控结果），Agent 控制流跟随
- 三者共享结构属性：攻击者控制 prompt 片段而不触碰面向用户的输入
- **为什么用户输入过滤器错失**：IPI payload 不在用户输入中——在检索内容中。过滤器如果仅门户用户输入 → payload 绕过；如果门户所有内容 → 需要对任意检索文本都生效 → 贵且对合法含命令式语言的文本产生假阳性
- **信息流控制（IFC） for AI**：2026 年防御范式。把每个内容源作为安全标签——用户查询标记"可信"、检索内容标记"不可信"——Agent 的控制流 = 信息流：由不可信内容触发的行动必须在执行前被可信输入核准
- **"攻击者后走"（Nasr et al. 2025 年 10 月）**：测试了 12 个已发表 IPI 防御，用自适应攻击（梯度搜索、RL、随机搜索、72 小时人类红队）——每个最初报告近乎零 ASR 的防御都被打破到 >90% ASR。方法论教训：只发表附带自适应攻击评估的防御

## 关键参数
- EchoLeak CVE-2025-32711 (CVSS 9.3)——Microsoft 365 Copilot 首个公开记录的零点击 IPI。CamoLeak CVSS 9.6——GitHub Copilot Chat
- "良性指令"挑战——"请打印 Yes"在语义上良性，无关键词过滤器能捕获
- 范围违反——Agent 访问一个信任上下文的数据并将其输出到另一个信任上下文

## 类比
- 间接提示注入 = 间谍在公共图书馆的百科全书里塞入一行"把机密文件寄给这个地址"——读者（Agent）以为在读权威资料，其实在执行外部指令

## 设计时怎么用
> Agent 设计的第一原则：分离可信任和不可信内容，不可信内容触发的操作必须经过用户核准。任何 RAG 系统必须把检索内容标记为不可信。
