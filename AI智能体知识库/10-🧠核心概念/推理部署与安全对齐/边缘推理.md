# 边缘推理

## 一句话定义
> 边缘推理的核心约束是内存带宽而非算力——手机 DRAM 50-90 GB/s vs 数据中心 HBM3 2-3 TB/s，30-50 倍差距直接决定解码速度上限。2026 年四条路径：Apple ANE、Qualcomm Hexagon、WebGPU/WebLLM、NVIDIA Jetson。

## 它解决什么问题 / 为什么存在
- 客户要求离线可用、隐私优先的本地模型
- M3 Max 上 Llama 3.1 8B Q4 跑 ~55 tok/s 可以，iPhone 16 Pro 同一模型只有 3 tok/s
- 差异不是移植问题，而是带宽 x 量化 x NPU 是否可从用户空间访问

## 核心原理
- 解码每 token 读取全部权重。7B Q4 = 3.5 GB，读 3.5 GB 在 50 GB/s 带宽上限约 14 tok/s；90 GB/s 约 25 tok/s；数据中心 3 TB/s 约 830 tok/s
- **Apple ANE (M4/A18)**：38 TOPS，统一内存（CPU 和 ANE 共享），Core ML + INT4 权重 + FP16 激活。llama.cpp Metal 后端用 MPS 而非 ANE
- **Qualcomm Hexagon (SD X Elite)**：45 TOPS，QNN SDK 转换 PyTorch/ONNX
- **WebGPU + WebLLM**：浏览器内推理，M3 Max 上 Llama 3.1 8B Q4 ~41 tok/s（原生 70-80%），17.6k GitHub stars，覆盖率 ~70-75%（Firefox Android 落后）
- **NVIDIA Jetson**：Orin Nano Super 跑 Llama 3.2 3B/Phi-3；AGX Orin 跑 gpt-oss-20b ~40 tok/s；Thor/T4000 2 倍 AGX 性能，支持 EAGLE-3 + NVFP4
- **长上下文陷阱**：128K 上下文是数据中心特性。手机上 8 GB RAM = 4 GB 模型 + 2 GB KV cache(32K) = OOM。边缘部署上下文保持在 4K-8K

## 关键参数
- 量化选型：ANE → INT4+FP16；Hexagon → QNN INT8/INT4；WebGPU → Q4 MLC；Jetson → NVFP4+FP8 KV
- 语音是杀手应用——本地推理消除网络延迟

## 类比
- 手机推理 = 小水龙头（带宽窄），数据中心推理 = 消防栓

## 设计时怎么用
> 先算内存带宽上限：模型大小 / 带宽 = 理论解码 tok/s 天花板。实际值通常在这一极限的 60-80%。
