# 分布式训练

## 一句话定义
> 当模型大到单块 GPU 装不下时，用数据并行、张量并行、流水线并行和 FSDP/ZeRO 四种策略把训练拆到多块 GPU 上——3D 并行是大规模训练的标准方案。

## 它解决什么问题 / 为什么存在
- 7B 模型 FP16：权重 14GB + Adam 状态 56GB + 梯度 14GB = 84GB（不算激活），A100 80GB 装不下
- 70B 模型：840GB（不算激活），需要 10+ 块 A100
- 405B 模型（Llama 3）：4860GB，需要 61+ 块 H100。Meta 用了 16,384 块
- Adam 优化器是内存杀手：每个参数存两个 FP32 状态（m 和 v），70B 模型 optimizer 就要 560GB
- 分布式训练不是选项，是唯一路径

## 核心原理（大二能懂的水平）
- **数据并行（Data Parallelism）**：
  - 每块 GPU 存完整模型，各处理不同数据分片，反向传播后 all-reduce 平均梯度
  - 优点：线性吞吐提升；缺点：不减少单 GPU 内存
- **张量并行（Tensor Parallelism）**：
  - 把单层权重矩阵切到多块 GPU，各算部分矩阵乘法，all-reduce 合并结果
  - 列并行（分输出维度）→ 拼接；行并行（分输入维度）→ 求和
  - 优点：减少权重内存；缺点：每层后都要 all-reduce，需 NVLink（900GB/s），通常限单节点内 8 GPU
- **流水线并行（Pipeline Parallelism）**：
  - 按层切分：GPU1 跑 1-8 层，GPU2 跑 9-16 层...数据像流水线一样流过
  - 优点：通信量小（只传层间激活），可跨节点；缺点：流水线气泡（GPU 空闲等待）
  - 用 micro-batch 重叠计算：M 个 micro-batch + N 个 stage，气泡率 = (N-1)/M
- **FSDP / ZeRO**：
  - 每块 GPU 只存 1/N 的参数/梯度/优化器状态
  - 前向时 all-gather 收集完整参数，用完丢弃；反向时再次 all-gather，然后 reduce-scatter 分发梯度
  - 70B/8GPU：840GB/GPU → 105GB/GPU
  - ZeRO 三阶段：Stage 1 分优化器状态（~4x）；Stage 2 +梯度（~8x）；Stage 3 +参数 = FSDP（~Nx）
- **3D 并行**：Llama 3 405B = 8-way TP（节点内）× 16-way PP（跨节点）× 128-way DP = 16,384 GPU
- **混合精度**：前向 BF16 + 优化器 FP32 → 7B 模型 112GB→84GB（省 25%，不是 50%——optimizer 占大头且必须 FP32）

## 关键参数 / 易错点
- **Adam 状态是内存杀手**：70B 模型 optimizer = 560GB（FP32×2）。混合精度只省 25% 不是 50%，因为 optimizer 不变
- **BF16 vs FP16**：BF16 指数位和 FP32 一样（8位），不需要 loss scaling；FP16 精度更高但溢出。2026 年行业转向 BF16
- **流水线气泡**：4 stage + 1 micro-batch → 75% 空闲！16 micro-batch → 19%。代价：存所有在飞 micro-batch 的激活
- **FSDP 通信开销**：每层前向都要 all-gather，比纯数据并行通信量大。但内存节省让不可能的训练变可能
- **ZeRO-Offload**：优化器状态卸到 CPU RAM（512GB/节点），70B 可在 4 GPU 上训练（代价：慢 30-50%）
- **DeepSeek V3 的成本优势**：MoE 架构（671B 总/37B 活跃）+ 2048 H800 = $5.6M vs Llama 3 405B 的 $100M

## 类比（帮助理解）
- 数据并行就像"多个厨师各自做不同菜品"：每人都有完整厨具（模型副本），做不同菜（数据分片），最后汇总评分（平均梯度）
- 张量并行就像"多个厨师合作做一道菜"：每人负责切不同部分的食材（权重分片），最后合并成品（all-reduce）
- 流水线并行就像"工厂流水线"：每个工位（GPU）只做一道工序（几层），产品（数据）从上游到下游流过。问题是上游等下游时空闲（气泡）
- FSDP 就像"共享工具箱"：每人只保管 1/N 的工具（参数分片），用的时候大家凑一起（all-gather），用完还回去

## 设计时怎么用（反推思维）
> 先用内存计算器算出模型需要多少 GPU：权重 + Adam 状态 + 梯度 + 激活 ≤ 80GB/GPU。从数据并行开始；放不下就加 FSDP（ZeRO-3）；张量并行限于节点内 8 GPU；流水线并行跨节点。3D 并行 = TP(节点内) × PP(跨节点) × DP(剩余)。能省内存就省：混合精度 + 梯度检查点 + FSDP offload。

## 典型应用 / 我在哪见过
- GPT-2 Small（124M）：单 GPU 够用，1.5GB
- Llama 3 8B：单 A100 80GB 可训练（96GB 需 FSDP 2-GPU）
- Llama 3 70B：8-16 GPU + FSDP
- Llama 3 405B：16,384 H100，3D 并行 8×16×128，~$100M
- DeepSeek V3 671B/37B：2,048 H800，MoE 降成本到 ~$5.6M
