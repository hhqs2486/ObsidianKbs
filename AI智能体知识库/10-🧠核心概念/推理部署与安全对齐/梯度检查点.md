# 梯度检查点

## 一句话定义
> 反向传播需要保存所有中间激活值——70B 模型 128K 上下文时单卡激活达 3TB。梯度检查点在正向时只存分段输入，反向时重算中间值，用额外 FLOP 换内存。

## 它解决什么问题 / 为什么存在
- 训练 Transformer 时每层都要存激活：attention 输入、Q/K/V 投影、softmax 输出、FFN 输入、norm 输出、残差流
- d=8192, L=8192, B=1 → 每层 ~800MB（BF16），64 层 = 51GB 激活——还不算 attention softmax 的 O(L²) 和 microbatch 倍数
- 权重 + 优化器可能塞进 80GB，但激活值把你推过极限
- 梯度检查点（aka 激活重计算）：正向时丢掉大部分激活，反向时重跑正向来恢复——用计算换内存

## 核心原理（大二能懂的水平）
- **反向传播需要什么**：对每层，backward 需要 (1) 输入（算 grad_params = input.T @ grad_output）和 (2) 激活导数中间量（ReLU/GELU/softmax 的导数依赖激活值）
- **朴素全检查点（Full Checkpointing）**：
  - 把网络分成 N 段，正向时只存每段输入
  - 反向时重跑该段正向来恢复中间值，然后微分
  - 32 层分成 32 段（每段 1 层）：内存大降，但额外算 ~33% 前向 FLOP（完整步从 1+2=3 单位变 1+1+2=4 单位）
  - Chen et al. 2016 的经典配方：每 √L 层一个检查点，内存和重算成本都 ~√L
- **选择性检查点（Selective Checkpointing, Korthikanti 2022）**：
  - 不是所有激活都一样贵：attention softmax 是 O(B·L²·heads) 随序列长度平方增长；FFN 隐藏层是 O(B·L·4d) 线性增长
  - 长序列时 softmax 占主导——只重算 attention，保留便宜的线性投影/残差
  - 代价：仅 ~5% 额外 FLOP（只重算 attention kernel ≈ 15% 的层 FLOP）
  - Megatron-Core 的"selective"模式，2024+ 前沿训练标配
- **卸载（Offload）**：
  - 替代重算：正向和反向之间把激活送到 CPU RAM
  - 需要 PCIe 带宽；当空闲带宽 > 重算成本时有利
  - 混合策略常见：某些层检查点、某些层卸载
  - FSDP2 / DeepSpeed ZeRO-Offload 支持
- **FLOP 开销模型**：
  - 朴素全检查点：overhead = 4/3 - 1 = 33%
  - 选择性检查点：overhead = (3+0.15)/3 - 1 = 5%
- **最优分段**：k = √L。64 层 → 8 个检查点，每段 8 层——内存和重算成本都 √L 级

## 关键参数 / 易错点
- **√L 规则**：对均匀成本层，最优检查点间距是 √L 层。L=64 → 8 个检查点
- **不用检查点的场景**：
  - 流水线最内层（反正要等完成）
  - 已用 FlashAttention 的层（Flash 已在反向时快速重算 softmax，再加层检查点收益微小）
  - 第一层和最后一层（如果它们主导 stage 计算——Transformer 中罕见）
- **TP 交互**：检查点输入在重算时需要重新 gather/scatter，有通信成本
- **FP8 重算**：重算时更新的 amax 历史必须和原始前向匹配，否则 FP8 scale 漂移。多数框架快照 scale
- **朴素 vs 选择性的关键差异**：朴素重算整层（33% FLOP），选择性只重算 attention（5% FLOP）——长序列时 attention softmax 内存是 O(L²) 而 FFN 是 O(L)，所以只重算 attention 性价比最高
- **Offload vs 重算**：GPU 内存瓶颈 + CPU-GPU 带宽有余 → offload；否则 → 重算

## 类比（帮助理解）
- 梯度检查点就像"做数学题时不写草稿纸，检查时重算一遍"：正向时只记下每步的输入（检查点），反向需要中间结果时重新算一遍。代价是多花 33% 时间，但省了 90% 草稿纸（内存）
- 选择性检查点就像"只重算最占地方的大题"：小步骤的中间结果留着（便宜），大题（attention softmax，O(L²)）重算——只多花 5% 时间
- √L 规则就像"排队时窗口数量和队列长度的最优平衡"——太少窗口排队太长，太多窗口管理成本高

## 设计时怎么用（反推思维）
> 默认用选择性检查点（5% FLOP 换 ~5x 内存）。长序列训练时务必启用——attention softmax 的 O(L²) 内存不经检查点会 OOM。已用 FlashAttention 的层可以不再加层检查点（Flash 已优化了 softmax 重算）。混合策略：检查点 attention 层 + offload 部分激活到 CPU。

## 典型应用 / 我在哪见过
- Megatron-Core：selective/full/block 三种模式，2024+ 前沿训练标配
- PyTorch torch.utils.checkpoint：标准 API，包装函数、存输入、反向重算
- FSDP2 offload：激活分片到 CPU
- DeepSpeed ZeRO-Offload：optimizer 状态 + 激活卸载到 CPU
- 70B 模型 128K 上下文：3TB 激活 → 不用检查点根本跑不起来
