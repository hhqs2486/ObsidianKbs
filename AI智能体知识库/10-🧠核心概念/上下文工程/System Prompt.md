# System Prompt

## 一句话定义
> System Prompt（系统提示词）是 API 消息列表中 `role: "system"` 的那条消息，由开发者编写、全程不变，相当于 Agent 的"员工手册"——定义身份、行为规则、约束与流程。

## 它解决什么问题 / 为什么存在
- 模型能力强但对你团队的具体流程一无所知。System Prompt 把"新员工该怎么干活"显式写清，是提示工程的核心对象。
- 它构成上下文的**静态前缀**，可跨请求被 KV Cache / Prompt Cache 复用，直接影响延迟与计费。

## 核心原理（大二电子信息工程专业学生能懂）
优化 System Prompt 的几个维度：
1. **语气与风格（人格）**：如"MUST answer concisely"，大写强调关键约束；过度使用会被稀释。
2. **结构化（格式）**：XML 标签承载机器可解析语义，Markdown 做层次组织，二者协同。
3. **流程驱动 vs 规则堆砌（组织）**：用 SOP（标准操作流程）替代上百条零散规则，模型随时知道"自己在哪一步"。
4. **业务规则细化（内容）**：规则要写到可执行程度（如"退款绝不用百分比计费"），避免模型自由裁量导致行为不稳定。
- 检验标准：聪明新员工读完还不知道怎么做，Agent 也不知道。

## 关键参数 / 易错点
- 放示例（Few-shot）会成为静态前缀一部分，须保持字节级稳定，否则破坏缓存。
- 工具定义与 System Prompt 一起构成静态前缀（基础模式）；2026 年起工具 schema 也可按需动态加载（见 Skills/tool_search）。
- 提示工程消融：信息组织混乱使成功率降 30%+。

## 类比（帮助理解）
- System Prompt 像入职时发的装订好的岗位手册；Agent 状态栏则像屏幕边缘实时刷新的仪表盘（手册不变，仪表盘常变）。

## 设计时怎么用（反推思维）
> 做账单协商 Agent 时，我会把退款政策、计费模式、禁止项写进 System Prompt，并用 XML 结构化、SOP 流程化，让模型在明确框架内发挥。

## 典型应用 / 我在哪见过
- "You are a helpful assistant…"；Claude Code 的系统提示与工具描述边界。
