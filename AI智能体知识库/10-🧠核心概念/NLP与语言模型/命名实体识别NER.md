# 命名实体识别NER（序列标注、BIO 标注）

## 一句话定义
> 命名实体识别(NER)是从文本里抽出"实体片段+类型"（如 Apple→ORG、iPhone→PRODUCT、US→GPE）的结构化抽取任务，常转化为序列标注。

## 它解决什么问题 / 为什么存在
- 很多系统（简历解析、合同抽取、合规扫描、医疗脱敏、搜索 query 理解）都需要把自由文本里的人名/机构/地点/日期等"钉"出来变成结构化数据。

## 核心原理（大二能懂的水平）
- 主流用 BIO 标注：每个 token 标 B-TYPE（实体开头）/ I-TYPE（实体内部）/ O（非实体）；多 token 实体连成串（New→B-GPE, York→I-GPE）。
- 架构演进：规则+词典（高精低覆盖）→ HMM/CRF（判别式、可混特征、强制合法标签序列）→ BiLSTM-CRF（用学习特征替代手工）→ Transformer（[[BERT模型]] + token 分类头，精度最高）。
- 2026 也可直接用 [[大语言模型 LLM]] 零样本/少样本抽取。

## 关键参数 / 易错点
- BIO 一致性靠 CRF 层强制（如 I-ORG 不能接在 O 后）。
- 嵌套实体（"Bank of America Tower"同时是 ORG 和 FACILITY）标准 BIO 表达不了，需嵌套/span 模型。
- 实体级 F1（span 必须完全匹配）才正确，token 级 F1 会高估。
- 长文档按实体类型分多次抽取可提召回。

## 类比（帮助理解）
- 像给一篇文章里所有人名/地名/机构名"高亮+贴标签"，而不是改写它。

## 设计时怎么用（反推思维）
> 做"从文档抽结构化字段"（合同方、药品名、人物）的需求时，我会先用 LLM 零样本 NER 作基线（常够用不必微调）；若延迟 <50ms 或要 98%+ F1 或必须本地非生成模型，则退回 CRF/BiLSTM。无论哪种，输出用 BIO/span 表示以便接下游（如喂给 [[知识图谱]] 或 [[RAG评估方法]] 的事实核对）。中文/专业领域需领域适配。

## 典型应用 / 我在哪见过
- 简历解析、合同/法律文书抽取、医疗脱敏、搜索 query 理解、RAG 中文档结构化。
