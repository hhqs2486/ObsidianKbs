# Python基础教程（第3版）

## 这条教程在解决什么
- 这是一本面向“已经会一点编程、想系统入门 Python”的教材。它不堆语法，而是按“先讲语言核心（数/串/列表/字典/控制流/函数/类），再讲怎么和外部世界打交道（文件/标准库/异常）”的顺序，把 Python 讲成一门**能用来写真实程序**的语言。
- 对我来说，它的价值不是“背语法”，而是建立一条主线：**从需求反推架构/实现**——看到一个问题，能反推出“该用哪个概念去解”。下面的 10 张概念卡就是这条主线的拆解。

## 我卡住/没懂的地方
- 递归的“基线条件 + 递归条件”怎么稳定地想清楚？——书里八皇后给了范本：先写基线（只剩最后一个皇后），再写递归（每个合法位置都往下钻），用生成器 `yield` 把结果一层层拼回。
- 参数的 `*params` / `**params` 到底什么时候用？——书里用“一次存多条姓名”演示：定义时用 `*` 收集，调用时用 `*` 拆开，两边对称。
- 类里 `super().__init__()` 忘写为什么会炸？——书里 `SongBird` 不调父类构造，`eat()` 访问 `self.hungry` 直接 `AttributeError`，是继承里最经典的坑。
- `with` 为什么能保证关文件？——它背后是“上下文管理器”的 `__enter__/__exit__`，异常也会走 `__exit__` 关资源。

## 它背后的原理（别只记操作）
- **抽象是主线**：函数抽象“操作”，类抽象“状态+操作”，模块抽象“功能边界”。书里反复强调“懒惰是美德”——不为同一件事写两遍。
- **多态靠行为不靠类型**：Python 的 `if/else` 只关心“对象有没有这个方法”（鸭子类型），不像 Java 强制接口；所以尽量少用 `type/isinstance` 做类型检查。
- **作用域与命名空间**：变量是“指向值的名字”，存在看不见的字典里；函数调用新建局部作用域；闭包是嵌套函数“带着定义时的环境”返回。
- **异常沿栈传播**：没被捕获就一层层往外冒，直到主程序才崩溃——所以可以在顶层统一兜底。
- **迭代是第一公民**：`for` 本质是迭代，文件/生成器/序列都是可迭代对象；生成器用 `yield` 把“边算边给”写得很自然。

## 我能复用/改编的点
> 换个需求，这套做法还能怎么用？
- 做课程实验平台：把“读串口/滤波/存盘”分别封成模块（[[模块与包]]），主程序只写组装逻辑；传感器帧用生成器流式处理（[[迭代器与生成器]]）。
- 做签到统计：`fileinput` 遍历多天表 + `set` 求交集（[[标准库]]）；写文件一律 `with open(..., encoding='utf-8')`（[[文件IO]]）。
- 做带状态的小系统（如智能小车）：用类把“状态+方法”捆一起，相似行为靠继承去重（[[类与对象]]）。
- 任何“外部环境不可控”的地方（网络/文件/用户输入）都套 `try/except` 兜底，别用一堆 `if` 预判（[[异常处理]]）。
- 遇到“可能无穷/数据量大”的产出，优先返回生成器而不是大列表（[[迭代器与生成器]]）。
