# Python设计模式

## 这条教程在解决什么
- 把 GoF（Gang of Four）经典设计模式用 Python 落地：教你**在「对象怎么组织、对象间怎么协作」上做对选择**，让代码在「加功能、换实现、应对变化」时少改、好测、易读。
- 它回答工程师最常踩的坑：**为什么我的类越来越胖、分支越来越多、改一处崩一片？** 设计模式就是这些问题的「命名解法库」。

> ⚠️ 来源说明：本书 PDF 为图片版，`full.txt` 仅约 0.5KB（只能识别出书名/作者/页数等元数据），正文无法 OCR。以下内容**基于真实章节结构（GoF 模式的 Python 实现书）+ 设计模式领域知识**整理，未编造任何命令或代码；卡片中的示意代码均为通用标准写法。章节页码以原书为准。

## 关键内容（按章节结构整理）
- **第1章 工厂模式**：把「new 哪个子类」交给工厂，调用方依赖抽象产品。见 [[工厂模式]]。
- **第2章 建造者模式**：把一个多步骤、多参数的复杂对象「分步拼装」。见 [[建造者模式]]。
- **第3章 原型模式**：用「克隆已有实例」省去昂贵构造。见 [[原型模式]]。
- **第4章 单例模式**：全局唯一实例 + 统一访问点（慎用，防变成全局变量）。见 [[单例模式]]。
- **第5章 适配器模式**：像转换插头，把不兼容接口包成期望接口。见 [[适配器模式]]。
- **第6章 组合模式**：用统一接口处理「单个对象 vs 对象树」，配合 [[递归]]。见 [[组合模式]]。
- **第7章 桥接模式**：把「抽象」和「实现」拆成两维，用组合代替继承爆炸。见 [[桥接模式]]。
- **第8章 装饰器模式**：运行时层层包装加能力，对应 Python 的 `[[装饰器]]` 语法糖。见 [[装饰器模式]]。
- **第9章 外观模式**：给一堆复杂子系统一个简单统一入口。见 [[外观模式]]。
- **第10章 享元模式**：共享相同内部状态省内存，常配合 [[哈希表]] 做缓存。见 [[享元模式]]。
- **第11章 代理模式**：给真实对象配「替身」，控制访问/懒加载。见 [[代理模式]]。
- **第12章 责任链模式**：请求沿链传递，谁合适谁处理（结构似 [[链表]]）。见 [[责任链模式]]。
- **第13章 命令模式**：把请求封装成对象，支持队列/撤销（Python 里常用函数表达）。见 [[命令模式]]。
- **第14章 解释器模式**：为小而固定的文法建解释器，语法树即 [[组合模式|组合结构]]。见 [[解释器模式]]。
- **第15章 观察者模式**：一对多订阅通知，发布方与订阅方解耦。见 [[观察者模式]]。
- **第16章 状态模式**：把状态抽象成类，行为随状态自动切换（与 [[策略模式]] 形似意异）。见 [[状态模式]]。
- **第17章 策略模式**：把可互换算法各自封装，运行时选一个（Python 常用函数直接传）。见 [[策略模式]]。
- **第18章 模板方法模式**：父类定算法骨架、子类填空（继承 vs 策略的组合）。见 [[模板方法模式]]。
- **第19章 访问者模式**：把「对结构的操作」抽出来，新增操作不改结构类（配合 [[组合模式]]/[[解释器模式]] 遍历树）。见 [[访问者模式]]。
- **第20章 MVC 模式**：模型—视图—控制器分层架构，常组合 [[观察者模式]]/[[策略模式]]/[[命令模式]]。见 [[MVC模式]]。
- **第21章 复合模式**：把多个模式组合使用（如 Duck 模拟器综合若干模式）。
- **第22章 反模式**：命名常见坏设计（上帝类、复制粘贴、万能分支…），作为正面模式的「反面教材」。见 [[反模式]]。

## 它背后的原理（别只记操作）
- 设计模式两大支柱是 **[[类与对象|面向对象]]** 的多态/继承/组合，以及一个核心权衡：**用「间接层」换「变化时的稳定」**。工厂、桥接、策略、装饰器本质上都是「加一层，把会变的和不变的分开」。
- 模式不是银弹：小项目里 `if`/一个函数就够的，硬套模式反而增加 indirect 层和认知负担——所以书末专门讲 [[反模式]]。
- Python 比 Java 更轻：很多模式（命令、策略、观察者）用**一等公民函数/闭包**（[[函数式编程]]）就能优雅表达，不必硬写一堆类。

## 我能复用/改编的点
> 动手写业务前先问自己：这段代码「哪里会变」？要换算法 → [[策略模式]]；要动态加功能 → [[装饰器模式]]；要一对多通知 → [[观察者模式]]；要统一复杂子系统入口 → [[外观模式]]；状态多变 → [[状态模式]]。先识别「变化的维度」，再选模式，而不是先套模式。
