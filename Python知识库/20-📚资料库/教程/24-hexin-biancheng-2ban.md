# Python核心编程（翻译版·第2版）

## 这条教程在解决什么
- 这是一本**经典且覆盖面极广**的 Python 权威教程（Wesley Chun 著，基于 Python 2.x），目标是「既能当教材、又能当参考书」——前半部分把语言核心（语法/对象/类型/函数/类）讲透，后半部分一口气铺开正则、网络、Web、数据库、扩展等大量**应用专题**，是少数把「语言 + 应用」合成一本的厚书。
- 本书在库中的角色：**基础与入门 → 语言核心** 聚类的 **ANCHOR（锚点）书之一**，主要负责打底 **advanced OOP** 这批核心概念（闭包/装饰器/描述符/类与对象/继承/多态/魔术方法/运算符重载/元类/抽象基类/属性管理）。这些卡在库中已存在，本书**只链接、不重建**。

## 我卡住/没懂的地方
- 多继承下的 **MRO（方法解析顺序）** 与 `super()` 的协同——书里基于 Python 2.x 的旧式/新式类讲法，需对照 Python 3 的 C3 线性化才算完全搞清楚。
- 描述符协议与 `@property` 的关系：理解了「property 本身就是用描述符实现的」后，才把 [[属性管理]] 和 [[描述符]] 串起来。
- **抽象基类（abc 模块）本书未覆盖**：因本书基于 Python 2.4/2.5，早于 2.6 引入的 `abc` 模块；库中虽有 [[抽象基类]] 卡，但本书文字里没有对应章节，需靠《Python编程精进》或官方文档补全。

## 它背后的原理（别只记操作）
- 高级 OOP 本质是**协议**：描述符协议、元类协议、运算符重载、魔术方法，都是「特殊方法 + 固定查找顺序」的组合。掌握协议就掌握了「为什么这样写能生效」。
- [[闭包]] 的底层是「函数对象 + 其被定义时的环境（自由变量）」的绑定；[[装饰器]] 只是闭包的一个惯用形态（包裹函数并返回）。
- [[继承]] 与 [[多态]] 统一于「对象模型」：方法在运行时按对象真实类型查找，所以鸭子类型能成立。

## 我能复用/改编的点
> 换个需求，这套做法还能怎么用？
- 第13章的「类 + 魔术方法 + 运算符重载」模板，可直接套到任何自定义数据结构（向量、矩阵、配置对象、领域模型）。
- `property`/描述符是写「受控 API」的标准手法，做 SDK/库时用来隐藏内部字段、加校验。
- 装饰器 / 闭包模式可复用到日志、缓存、权限校验、重试等横切关注点。
- Part II 的应用专题提供了「从语言到能跑的应用」的最短路径，适合做技术选型的横向参考。
