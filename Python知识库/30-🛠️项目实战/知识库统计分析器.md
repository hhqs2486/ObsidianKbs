# 知识库统计分析器

## 1. 需求拆解
- **核心功能:** 命令行工具，输入 vault 路径，输出统计报告
- **统计维度:** 总笔记数 / 按目录分布 / 标签分布 / 断链 / 无标签笔记 / 最近修改
- **美化输出:** 用 `rich` 库做彩色终端表格 + 柱状图
- **批量分析:** 一键跑三个知识库，汇总对比

## 2. 设计思路

```
vault 路径 → os.walk 扫描 .md → 逐个解析 frontmatter + wikilink
                                    ↓
                            tags / links 汇总
                                    ↓
                            Counter / defaultdict 聚合
                                    ↓
                            rich.Table 美化输出
```

## 3. 技术选型

| 层级 | 组件 | 理由 |
|------|------|------|
| 文件遍历 | `os.walk` + `pathlib.Path` | 不需要第三方库，递归扫描子目录 |
| Frontmatter 解析 | `re` + `yaml` (PyYAML) | 正则匹配 `---\n...\n---`，yaml 解析字段 |
| Wikilink 提取 | `re` 正则 | `\[\[([^\]]+)\]\]`，排除代码块内误匹配 |
| 数据聚合 | `collections.Counter` + `defaultdict` | 标签频次 / 目录分组 |
| 终端美化 | `rich` | 彩色表格 / Panel / 柱状图 / 状态提示 |

## 4. 采坑记录

**坑 1: README 里的 `[[双链]]` 被当成断链**
- 原因: README.md 在解释双链语法时写了 `[[双链]]` 字样
- 修复: 用正则先去除 ` ``` ` 代码块和 `` ` `` 行内代码，再匹配 wikilink
- 效果: 断链从 57 条降到 15 条

**坑 2: 同名笔记 stem 冲突**
- 原因: 不同目录下都有 `📌本区用途.md`，`filepath.stem` 相同
- 修复: `note_paths[stem]` 用第一个出现的，修改时间取最大值

**坑 3: 模板文件的 tags 含 Jinja2 变量 `{{date}}`**
- 修复: `yaml.safe_load` 解析失败时静默返回空 dict，不中断
