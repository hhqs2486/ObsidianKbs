# 建库总提示词（万能版）

> 复制到一次**新对话**，替换 `{{知识库名字}}` 与 `{{源文件夹路径}}`，即可从一堆 PDF/书构建一个结构化 Obsidian 知识库。完整内联流程见 skill `obsidian-kb-from-pdfs` 的 `references/template-prompt.md`。

## 三条铁律（决定图谱干不干净）
1. **仓库必须是独立 vault**：不要多个库同处一个 vault（根目录只有一个 `.obsidian`）。否则关系图里所有库混在一起、眼花缭乱。每个库自己带 `.obsidian`。
2. **每篇笔记带 `tags`**：第一维 = 库名（如 `Python`），第二维 = 子主题名（概念卡）或类型（`教程`/`MOC`/`项目实战`/`问题排查`/`收件箱`/`索引`）。Obsidian 关系图据此着色分组、可一键过滤。
3. **概念卡防重复**：先写「概念归属约定」，谁拥有谁建卡，其他人只 `[[链接]]`。`[[双链]]` 名须与文件名完全一致（大小写/中英文/空格）；文件名不用 `/`。

## 标准步骤
1. 搭骨架（编号文件夹 + README + 概念归属约定初稿 + 拷贝 6 模板）
2. 提取文本与目录（PyMuPDF，按章切分；0KB 即图片版）
3. 规划概念归属约定（anchor 拥有 / link 只链）
4. 并行 agent 写笔记（每本/每批一个，只读自己缓存）
5. gapcheck → 0 断链
6. 生成 MOC 索引地图
7. （可选）联网更新最新知识：调研该领域近 1–2 年新特性/新库，建新子主题并 `[[链接]]` 旧卡

## 图片版书
提取 ~0KB = 扫描版无文字层：按真实 TOC + 领域知识写，来源注明「PDF 为图片版」，不编造命令/代码。
