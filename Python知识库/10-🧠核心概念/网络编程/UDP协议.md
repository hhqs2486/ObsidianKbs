# UDP协议

## 一句话定义
> UDP（User Datagram Protocol，用户数据报协议）是构建在 IP 之上的「不可靠数据报」协议：一次 `sendto` 发一个独立的小包，包可能丢失、乱序、重复——它把可靠性问题原样交还给应用层，换取极简与低开销。

## 它解决什么问题 / 为什么存在
- 有些场景「可靠但慢」反而不合适：DNS 查询、DHCP、实时音视频、局域网广播——这些要么是「短自包含请求」、要么「丢了重说一句就行」、要么是「宁可丢帧也不重传拖慢整个流」。
- 名字里的 User 指：普通用户程序不经内核特权就能发「基于 IP 的包」的方式（raw socket 通常不让普通用户用）。

## 核心原理（大二能懂的水平）
- 包 = （你的数据 + 收发双方的 IP:端口）。无连接：`sendto(数据, 地址)` 直接飞出去，对方 `recvfrom()` 收。
- 服务器 `bind()` 占端口后 `recvfrom` 等包；客户端不 `bind` 也行，系统自动给个临时端口。
- 客户端 `connect()`（对 `SOCK_DGRAM`）不是真连接：只是设定默认对端 + 过滤掉非该服务器的回包，不发任何网络包。
- 包上限约 64KB，但真实网卡（以太网）只认 ~1500 字节，超大包会被 IP 分片，任何一片丢失整包作废 → 实际应当尽量发小包。
- 广播（`SO_BROADCAST`）能一个包发给整个子网所有主机；更现代的等价是组播（multicast），但书里指出广播已略显过时。

## 关键参数 / 易错点
- **不可靠是铁律**：客户端必须自己「超时重发 + 指数退避（exponential backoff）」，否则网络一堵就疯狂重发、把带宽冲垮（UDP 没有 TCP 的拥塞控制，写不好能把网络搞瘫）。
  - 做法：`settimeout(delay)` 包住 `recv`，超时就把 `delay *= 2`（如 0.1→0.2→0.4…），超过上限（如 2s）就放弃/报「服务器挂了」。守护进程可设封顶值后保持重试。
- **无法区分「服务器挂了」和「包全丢了」**：两者表现一样，只能靠重试次数放弃。
- **请求 ID（序列号）**：每个请求带随机大数 ID，回包带回同一 ID。好处：① 过滤掉重复回包；② 对「看不到你流量的攻击者」起到轻微防伪造作用（非真安全）。
- **安全提醒**：`connect()` / 校验回包地址都**不是**真安全，攻击者能伪造源地址骗过过滤（spoofing）；真安全靠 [[网络协议栈]] 之上的 TLS（书第6章）。
- 客户端 `connect()` 后 `getpeername()` 才能用，否则抛异常。

## 类比（帮助理解）
- UDP 像往人群里扔纸条：你写上「给三楼主机:53」，扔出去就不管了；对方可能没接住（丢），也可能同时接到两张（重），顺序还可能颠倒。要可靠，得在纸条里写「第 7 号问题」，对方回「第 7 号答案」，没回你就隔阵子再扔。

## 设计时怎么用（反推思维）
> 除非我是在对接一个「已经规定用 UDP」的协议（DNS、DHCP、游戏同步、局域网广播），或要广播，否则我会优先选 [[TCP协议]]。想用 UDP 做「消息队列」式通信时，书里直接建议：去用 ØMQ 这类成熟库，别自己造。需要可靠+并发，再考虑 [[异步网络编程]]。

## 典型应用 / 我在哪见过
- DNS 解析、DHCP 分配 IP、实时音视频流、局域网游戏/计分板广播、某些 RPC/探测协议。
