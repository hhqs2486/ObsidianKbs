# 网络协议栈

## 一句话定义
> 网络协议栈（protocol stack）= 一层叠一层的网络协议：底层只做「把小包从一个网卡送到另一个网卡」这种简单事，上层在它之上搭出更复杂、更有语义的服务，最终让应用能说「帮我查这个地址的经纬度」这种高级话。

## 它解决什么问题 / 为什么存在
- 计算机网络太复杂，没法用「一个协议包打天下」。把复杂问题拆成「每层只解决一小块、复用下层能力」的栈，工程上才可控、可替换、可调试。
- 对程序员的意义：你大多站在栈的高层用现成库（如 [[requests库]] 调 HTTP），只有当底层出问题时，才需要往下钻一层排查——理解栈能让你知道「我的包到底卡在哪一层」。

## 核心原理（大二能懂的水平）
- 书 ch01 用「查 Google Maps 经纬度」做了四层递进示例，从高层到底层：
  1. **应用层**：googlemaps 库 / Google Maps API（说「地址→坐标」这种业务语言）；
  2. **HTTP 层**（见 [[HTTP客户端]]）：用 URL + GET 取文档；
  3. **Socket 层**（见 [[socket编程]]）：HTTP 靠 socket 发「GET 请求」这类文本命令；
  4. **裸字节层**：socket 只懂「收发字符串」。
- 再往下是操作系统替你管的、Python 看不到的层（书 ch01 末）：
  - **TCP/UDP**（见 [[TCP协议]]/[[UDP协议]]）：socket 之下，支撑「可靠流」或「数据报」两种对话；
  - **IP（网际协议）**：给全球每台联网机器发 4 字节地址、把包从一端路由到另一端（IPv4 如 `130.207.244.244`，IPv6 16 字节如 `fe80::…`）；
  - **链路层**：最底下的以太网卡/无线，在直连机器间传物理信号。
- **每层用下层、服务上层**：上层把「语义」交给下层去搬运，下层不知上层在聊什么。这正是「turtles all the way down」——一直剥到链路层。
- 其他重要层/伴生协议：DNS（主机名↔IP，见 [[socket编程]] 的 `gethostbyname`）、TLS/SSL（加密，书第6章）、ICMP（错误信令，如 MTU 发现的「不能分片」回包）。

## 关键参数 / 易错点
- **IP 地址与端口**：IP 定位机器，端口（见 [[socket编程]]）在同一机器上定位具体程序；`127.0.0.1`/`localhost` 指本机，`10.*`/`192.168.*`/`172.16-31.*` 是私有网段。
- **IPv4 vs IPv6**：代码只管把地址交给库，系统自己选版本；一般不用关心。
- **MTU 与分片**：子网最大包通常 ~1500 字节；大 UDP 包会被 IP 分片，任一片丢则整包废；TCP 由栈自己选最优包大小。
- **路由**：边缘主机只决定「本机 / 同子网 / 交给网关」，复杂路由由骨干路由器管——应用层基本不用管。
- **错误在错层暴露**：底层网络错误（连不上 Google）可能以「低级异常」冒泡到高层库里，写客户端必须会抓网络异常。

## 类比（帮助理解）
- 像快递系统：你只填「收件人+地址+物品」（应用层语义）；快递公司翻译成「分拣中心→转运中心→网点」（各层路由/传输）；最后快递员骑电动车把包裹送到门口（链路层物理投递）。每一层都只管自己那点事，套在下一层之上。

## 设计时怎么用（反推思维）
> 做网络系统时，我会先想「我的需求落在哪一层」：调别人 API → 用现成高层库（[[requests库]]/[[HTTP客户端]]）；要自定义可靠传输 → 基于 [[TCP协议]] 的 socket；要广播/自定轻协议 → [[UDP协议]]；性能瓶颈时再往下钻到 IP/MTU。永远优先用标准库/成熟库，别手搓底层。

## 典型应用 / 我在哪见过
- 任何联网程序都是栈的某种组合：浏览器（HTTP/TCP/IP）、[[网络爬虫]]（HTTP 之上）、DNS、邮件、SSH、游戏（常 UDP/TCP 混用）。
