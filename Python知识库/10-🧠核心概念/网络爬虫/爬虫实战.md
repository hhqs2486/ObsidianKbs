# 爬虫实战

## 一句话定义
> 把爬虫各项技术按真实目标组合成可运行采集项目的方法论与套路。

## 它解决什么问题 / 为什么存在
- 单个知识点（发请求、解析、存储）不会自动变成能用的爬虫；实战是把"需求 → 技术选型 → 实现 → 部署"串起来的能力。

## 核心原理（大二能懂的水平）
- 按页面类型反推选型：
  - 静态页 → requests + BeautifulSoup
  - Ajax 接口 → 直接抓返回的 JSON
  - 动态渲染(JS) → Selenium / Splash
  - 验证码 → 第8章 OCR / 模拟 / 打码
  - 代理 / 登录 → 第9 / 10章
  - App → 第11章抓包取接口
  - 框架：pyspider（WebUI 快速） / Scrapy（强大可扩展）
  - 大规模 → 第14章分布式

## 关键参数 / 易错点
- 先分析目标（静态 / Ajax / JS / 登录 / 反爬）再选型，别一上来就造框架。
- pyspider 有 WebUI、调试方便，适合快速；Scrapy 可扩展、应对强反爬与大规模更合适。
- 遵守 robots 与访问频率，注意法律与合规风险。

## 类比（帮助理解）
- 像装修：先量房（分析站点）→ 选材料（技术）→ 施工（编码）→ 验收（数据落库）。

## 设计时怎么用（反推思维）
> 接到一个采集需求时，我按「目标站点类型 → 所需技术 → 框架选型 → 存储与部署」反推：普通新闻用 requests + BeautifulSoup；要可视化调试用 pyspider；大规模强反爬用 Scrapy + 代理 + 分布式；需要登录就上模拟登录。

## 典型应用 / 我在哪见过
- 去哪儿旅游攻略爬取（pyspider）、GitHub 动态（模拟登录）、Quotes 入门（Scrapy）、全站商品（分布式）。
