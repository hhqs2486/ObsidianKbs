# 正则表达式爬虫

## 一句话定义
> 用 Python 的 `re` 模块按"模式字符串"从 HTML 文本里匹配、提取目标字段（标题、价格、链接等）的爬虫方法。

## 它解决什么问题 / 为什么存在
- 当页面结构简单、或目标字段被固定前后缀包着时，用一条正则就能把字段"抠"出来，无需引入 DOM 解析器。
- 是解析层的"瑞士军刀"：快速、零依赖，适合临时单页抓取。

## 核心原理（大二能懂的水平）
- 正则引擎按规则扫描文本：`re.findall(pattern, html)` 返回所有匹配；`re.search` 返回第一个。
- 常用语法：`.` 任意字符、`*` 贪婪重复、`.*?` 非贪婪（最短匹配）、`()` 分组捕获、`\d \w` 字符类、`re.S` 让 `.` 也能匹配换行。
- 思路：在目标字段前后找"锚点"，用 `(.*?)` 把中间内容捕获出来。

## 关键参数 / 易错点
- 贪婪 vs 非贪婪是最常踩的坑：`<title>(.*)</title>` 会吞掉中间所有标签，应写成 `<title>(.*?)</title>`。
- HTML 不是正则的强项——嵌套结构、属性顺序变化都会让正则会失效，复杂页面别硬刚。
- 有捕获分组时，`findall` 只返回分组里的内容，不是整段匹配。
- 先 decode 成字符串再匹配，否则 bytes 与 str 混用报错。
- 页面一旦规整成标签树，应退而用 XPath选择器 / CSS选择器，更稳健。

## 类比（帮助理解）
- 像在文章里用"查找"功能圈出关键词：规则写宽了圈多、写窄了圈少，锚点选错就全错。

## 设计时怎么用（反推思维）
> 抓单页、字段被固定前后缀包着（如 `价格：(\d+)元`）时，正则最快；一旦页面是规整标签树或有层级关系，就交给 XPath选择器 / CSS选择器，别用正则硬解析整棵 DOM。

## 典型应用 / 我在哪见过
- 从纯文本/简单页里抽邮箱、手机号、价格；做快速脏数据提取；配合 urllib 抓取后即时清洗。
