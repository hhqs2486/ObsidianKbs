# 动态网页爬取

## 一句话定义
> 针对"内容由 JavaScript 在浏览器端渲染、或走异步接口加载"的网页，先让页面跑完 JS（或直连数据接口）再提取数据的整套思路与方案。

## 它解决什么问题 / 为什么存在
- 传统请求只拿到"空壳"HTML，数据藏在后加载的 JSON 接口或 JS 里，直接解析抓不到——必须先"渲染"或"抓接口"。
- 这是入门爬虫从静态页迈向真实网站的关键一关。

## 核心原理（大二能懂的水平）
- 两类解法：
  - (A) 渲染型：用 Selenium爬虫 / Playwright 把页面跑成最终态，再对 `.page_source` 用 XPath选择器 / CSS选择器 解析。
  - (B) 接口型：开浏览器 DevTools 的 Network 面板，找到真实数据接口（常是 XHR 返回的 JSON），直接用 requests库 / urllib 调接口拿结构化数据——更轻更快。
- 相关概念：AJAX 异步加载、SPA 单页应用、JSON API。

## 关键参数 / 易错点
- 优先找 JSON 接口（方案 B），资源消耗往往比驱动浏览器低一个数量级。
- 接口常需带特定 headers / Cookie / Authorization，否则返回 401 或空数据。
- 渲染型要等元素真正出现（显式等待），别用固定 sleep。
- 接口参数若加密/签名（如 token、sign），方案 B 会变难，此时才退而用渲染型（方案 A）。
- 动态页同样受 反爬虫进阶 限制，注意频率与身份伪装。

## 类比（帮助理解）
- 像看菜：空盘（初始 HTML）上看不到菜，要么等厨房做好（JS 渲染），要么直接去后厨窗口拿做好的（调数据接口）。

## 设计时怎么用（反推思维）
> 任务里页面"源码没有数据"时，我先开 DevTools 看 Network 找 XHR/JSON 接口，能直接调就调（方案 B）；接口加密或要交互（登录/翻页）才上 Selenium爬虫 渲染（方案 A）；最后再决定要不要 并发编程 提速、要不要 反爬虫进阶 配合。

## 典型应用 / 我在哪见过
- 电商商品页（价格异步加载）、微博/知乎信息流、地图 POI、后台管理系统报表。
