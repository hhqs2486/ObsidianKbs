# URL去重

## 一句话定义
> 记录已经抓过的 URL，防止重复请求同一页面——避免死循环、浪费带宽和产生重复数据。

## 它解决什么问题 / 为什么存在
- 网页相互链接会形成环（A→B→A），没有去重会反复抓同一页；大规模时去重集合还会撑爆内存。
- 去重是"不重复劳动"和"数据不重复"的基石，也是 [[增量爬取]] 与 [[分布式爬虫]] 的前提。

## 核心原理（大二能懂的水平）
- 指纹去重：对 URL 做哈希（md5 / sha1）后存集合，新 URL 先算指纹再看"在不在集合里"。
- Scrapy 内置 `RFPDupeFilter`，基于请求指纹（含 URL 与少量参数）自动去重，开箱即用。
- 超大规模用 **Bloom Filter**：用位数组表示集合，内存极小，有极低误判但"绝不漏判"（不会把没抓过的当已抓）。
- 分布式时把去重集合放 Redis，多机共享同一份，见 [[分布式爬虫]]。

## 关键参数 / 易错点
- URL 规范化：带随机参数（如 `?t=时间戳`、`?sessionid=`）会生成无穷"新"URL，要先去噪参再哈希。
- 规范化后再哈希，否则同一页被当成不同页反复抓。
- Bloom Filter 有误判（可能把新 URL 当旧的丢），但不会漏判，适合"省内存换极低误删"。
- 分布式必须共享同一去重集合，否则各机各抓各的、重复且可能死循环。

## 类比（帮助理解）
- 像在"已访问清单"上盖个章：再遇到同一页，看一眼有章就跳过，不去白跑一趟。

## 设计时怎么用（反推思维）
> 写爬虫先想过去重：单机用 Scrapy 内置去重即可；URL 先规范化（去掉时间戳/追踪参数）再哈希；超大规模或多机用 Redis + Bloom Filter。去重和 [[增量爬取]] 的内容哈希配合，既能不重抓也能不重存。

## 典型应用 / 我在哪见过
- 整站全量抓取、搜索引擎式遍历、配合 Redis 做分布式去重；与 [[并发爬虫]] [[爬虫数据存储]] 强相关。
