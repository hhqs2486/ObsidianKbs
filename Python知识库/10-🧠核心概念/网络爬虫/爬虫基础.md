# 爬虫基础

## 一句话定义
> 网络爬虫是用程序自动访问网页、按既定规则提取信息的"信息采集系统"，本质是一条「发请求 → 收响应 → 解析提取 → 存储」的流水线。

## 它解决什么问题 / 为什么存在
- 人工逐页复制海量网页信息，低效且极易出错；爬虫把"分散在无数网页里的信息"自动聚合成可检索、可分析的数据。
- 让"从互联网按需取数"变成可编程、可重复、可规模化的能力。

## 核心原理（大二能懂的水平）
- 一次抓取 = 一次 HTTP 往返：客户端发请求（URL 定位资源，GET 取数据 / POST 提交表单）→ 服务器回响应（HTML / JSON + 状态码）。
- 网页 = HTML(结构) + CSS(样式) + JS(行为)；解析就是遍历 DOM 节点树、把想要的"格子"取出来。
- 关键术语：User-Agent 表明身份、Cookie 维持登录态、Referer 防盗链；状态码 200 成功 / 404 不存在 / 503 限流。
- 两大页面类型：静态页（数据在 HTML 源码里）与动态页（数据由 JS 渲染或走独立 JSON 接口，直接请求抓不到）。
- 礼貌与合规：遵守 robots.txt，控制请求频率。

## 关键参数 / 易错点
- 请求频率与限速：太快会被封 IP，爬之前先想好间隔与并发上限。
- 编码问题：响应文本乱码时查编码（UTF-8 / GBK），手动 decode 修正。
- 相对 URL 要拼接成绝对 URL 才能继续请求。
- 重定向、gzip 压缩、超时都要处理；要维持"登录态"就靠 Cookie / Session。
- 合法性：只采集公开数据，尊重网站 robots 与版权，不碰敏感/付费内容。

## 类比（帮助理解）
- 像一个机器人按目录逐页翻书，并且只把"指定栏目"抄录到笔记本里。

## 设计时怎么用（反推思维）
> 做信息采集系统时，我会先明确「要采哪些站点、要哪些字段、数据多久更新一次」，再决定用轻量方案（urllib / requests库 + 解析器）还是上浏览器渲染（Selenium爬虫）；先判断数据是静态、动态还是接口型，再选工具链。

## 典型应用 / 我在哪见过
- 搜索引擎抓取、电商比价、舆情监控、学术文献聚合、竞品价格跟踪。
