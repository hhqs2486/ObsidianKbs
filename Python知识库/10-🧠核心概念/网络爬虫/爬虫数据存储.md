# 爬虫数据存储

## 一句话定义
> 把爬取到的字段从内存中的 Item 持久化到文件或数据库的整套方案。

## 它解决什么问题 / 为什么存在
- 爬下来的数据只放内存会丢，也无法查询复用；需要按"结构化程度 / 查询方式 / 规模"选合适的容器落库。

## 核心原理（大二能懂的水平）
- 文件存储：TXT / JSON / CSV，最简单，但难查询。
- 关系型 MySQL（PyMySQL）：事务 ACID，适合结构固定、要联表查询的数据。
- 文档型 MongoDB（PyMongo）：schema 灵活，适合半结构化、字段易变的数据。
- Redis：既做缓存/队列，也常做去重集合（指纹）与代理池。
- 大规模场景用分布式存储；清洗与类型转换通常在 Pipeline 阶段完成。

## 关键参数 / 易错点
- JSON 中文乱码：`ensure_ascii=False`。
- CSV 注意编码(utf-8-sig)与表头；MySQL 注意连接池与事务 `commit`；MongoDB 注意集合设计与索引。
- 去重可用 Redis 集合或 Bloom Filter；落库前务必在 Pipeline 做清洗，别把脏数据写进去。

## 类比（帮助理解）
- 像把抄录的卡片分别放进"便签盒 / Excel 表 / 档案柜"——按"以后怎么查"来选容器。

## 设计时怎么用（反推思维）
> 设计存储时我先问"数据多结构化、要不要联表查询、量大不大"：少量临时用文件；强结构要事务用 MySQL；字段多变用 MongoDB；高频去重/队列用 Redis；再决定在 Scrapy 的 Item Pipeline 里落库。

## 典型应用 / 我在哪见过
- 商品价格落 MySQL 做比价；社交动态落 MongoDB；代理池 / 去重落 Redis。
