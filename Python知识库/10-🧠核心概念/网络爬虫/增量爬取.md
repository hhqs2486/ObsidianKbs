# 增量爬取

## 一句话定义
> 只抓取"新增或更新过"的页面/数据，而不是每次都全量重爬，从而省带宽、降风险、避免重复数据。

## 它解决什么问题 / 为什么存在
- 站点数据持续更新（新闻、商品、帖子），全量重爬浪费资源，还会重复写库、加大被封概率。
- 增量只取"变了的部分"，是长期值守型爬虫的核心策略。

## 核心原理（大二能懂的水平）
- 判断"是否变化"的几种依据：
  - 时间维度：数据的发布时间/最后修改时间，只取晚于上次爬取时间点的。
  - 游标维度：接口分页的 `offset` / `cursor` / 自增 id，从上次位置继续。
  - 指纹维度：对内容算哈希，和上次比对（见 [[URL去重]] / 内容去重）。
- 配合定时任务（cron / 调度框架）周期性跑；首次跑一次全量"基线"，之后都走增量。

## 关键参数 / 易错点
- 页面改版式但内容没变，会被误判为"更新"——最好以内容哈希而非页面整体比对。
- 时间戳的时区、精度要统一，否则漏抓或重复抓。
- 断点续爬必须持久化"上次位置"（游标/时间戳），存在 [[爬虫数据存储]] 里，别放内存。
- 增量和全量要分清：首次必须全量基线，增量只是补充。

## 类比（帮助理解）
- 像看公众号推送：只点开"新消息"里没读过的文章，不把历史列表全刷一遍。

## 设计时怎么用（反推思维）
> 目标站点持续更新时，我先定"变化判定键"：有接口游标就追游标，有更新时间就按时间，否则用内容哈希比对；用 [[URL去重]] + 内容哈希做增量；首次跑全量基线，之后定时增量，落库逻辑放 [[爬虫数据存储]]。

## 典型应用 / 我在哪见过
- 新闻/论坛定时更新采集、商品价每天比价、舆情每日增量监控；常与 [[Scrapy]] 调度、[[分布式爬虫]] 搭。
