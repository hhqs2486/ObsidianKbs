# 网络爬虫

## 一句话定义
> 自动按既定规则抓取网页、并从中提取结构化数据的程序或系统。

## 它解决什么问题 / 为什么存在
- 人工逐页复制海量网页信息，低效且极易出错；爬虫把"分散在无数网页里的信息"自动聚合成可检索、可分析的数据。
- 让"从互联网按需取数"变成可编程、可重复、可规模化的能力。

## 核心原理（大二能懂的水平）
- 本质是「发 HTTP 请求 → 拿到响应(HTML/JSON) → 解析提取字段 → 存储」。
- 关键术语：URL 定位资源；GET 取数据、POST 提交表单；请求头里的 User-Agent 表明身份、Cookie 维持登录态、Referer 防防盗链；响应状态码(200 成功 / 404 不存在 / 503 限流)。
- 网页 = HTML(结构) + CSS(样式) + JS(行为)；解析就是遍历 DOM 节点树取想要的格子。
- 会话(Session)与 Cookies：服务器用 Cookie 里的 SessionID 认出"你是登录后的同一个你"。

## 关键参数 / 易错点
- 遵守 robots.txt（爬虫礼仪，也可在框架里开关）。
- 请求频率与限速：太快会被封 IP。
- 编码问题：响应 .text 乱码时查 .encoding 或改用 .content 手动解码。
- 相对 URL 要拼接成绝对 URL（Scrapy 用 `response.urljoin`）。
- 重定向、gzip 压缩、超时都要处理；会话要保持就用 Cookie/Session。

## 类比（帮助理解）
- 像一个机器人按目录逐页翻书，并只把"指定栏目"抄录到笔记本里。

## 设计时怎么用（反推思维）
> 做信息采集系统时，我会先明确「要采哪些站点、要哪些字段、数据多久更新一次」，再决定用轻量方案(requests + BeautifulSoup)还是框架(Scrapy)，以及要不要上代理 / 模拟登录 / 分布式。

## 典型应用 / 我在哪见过
- 搜索引擎抓取、电商比价、舆情监控、学术文献聚合、竞品价格跟踪。
