# XPath选择器

## 一句话定义
> 用路径表达式在 XML/HTML 文档的节点树上"定位"元素的查询语言；Python 中由 `lxml` 库提供 `.xpath()` 支持。

## 它解决什么问题 / 为什么存在
- 在结构清晰的页面里，用层级路径精确选中节点或属性，比正则稳健、比手动遍历整棵树省事。
- 能表达"第几个、包含某文本、某属性等于某值"等复杂条件，是解析层的主力工具之一。

## 核心原理（大二能懂的水平）
- 把文档看成一棵树：`/html/body/div` 是绝对路径，`//div` 表示任意层级下的 div，`@class` 取属性。
- 示例：`//a[@id='next']/text()` 取 id 为 next 的链接文本；`//div[contains(@class,'price')]` 取 class 含 price 的 div；`[1]` 取第一个。
- 流程：`lxml.etree.HTML(html)` 把字符串解析成树，再 `.xpath('表达式')` 返回节点或字符串列表。

## 关键参数 / 易错点
- 路径写错或页面结构一变，xpath 会静默返回空列表，要写容错（判空、打日志）。
- 取文本用 `text()`，取属性用 `@href`；返回多个节点时循环处理。
- 浏览器 DevTools "复制 XPath" 给的是绝对路径，极易碎；宜改成相对路径或带特征属性（id/class）的写法。
- `lxml` 是第三方库，需 pip 安装；HTML 不规范时建议用 `etree.HTMLParser` 容错解析。

## 类比（帮助理解）
- 像在文件夹树里用"路径"精确定位某个文件：`C:/用户/文档/报告.docx` 那种感觉。

## 设计时怎么用（反推思维）
> 解析规整静态页、要按层级或属性精确取数时，我用 XPath；它和 CSS选择器 二选一，看团队习惯；若页面是 JS 渲染的，先让 Selenium爬虫 拿到渲染后源码，再上 XPath 解析。

## 典型应用 / 我在哪见过
- 抓列表页（每一条 `<li>`）、按 class 批量取商品标题/价格、定位分页"下一页"按钮。
