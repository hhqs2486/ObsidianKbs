# Selenium爬虫

## 一句话定义
> 用 Selenium 驱动真实浏览器（Chrome/Firefox）自动打开网页、执行 JS、模拟点击与输入，从而拿到"人眼看到的最终页面"的爬虫方案。

## 它解决什么问题 / 为什么存在
- 对抗 JS 动态渲染、登录弹窗、滑动验证等"普通 HTTP 请求拿不到"的页面。
- 当页面必须"跑起来"才有数据时，Selenium 是唯一省心的办法——它看到的，就是浏览器渲染后的完整页面。

## 核心原理（大二能懂的水平）
- Selenium 通过 WebDriver 协议操控浏览器：`webdriver.Chrome()` 启动浏览器 → `.get(url)` 加载 → 页面 JS 跑完后 `.page_source` 是渲染后的 HTML。
- 定位与交互：`find_element(By.XPATH, ...)` 或 `By.CSS_SELECTOR` 选中元素，再 `.send_keys()` 输入、`.click()` 点击。
- 等待：用 `WebDriverWait` + `expected_conditions` 显式等某个元素出现，而不是 `time.sleep` 硬等。

## 关键参数 / 易错点
- 必须装浏览器驱动且版本匹配（ChromeDriver）；新版 Selenium 可用 Selenium Manager 自动管理，省去手动下载。
- 速度慢、吃内存，不适合大规模采集；它适合"少量但需要渲染"的页。
- 无头模式（headless）省资源、适合服务器；但某些反爬会识别 headless，需权衡。
- 等待要用显式等待，别用固定 sleep，否则快了漏数据、慢了浪费时间。
- 仍要配 User-Agent、注意被封；可与 反爬虫进阶 配合。

## 类比（帮助理解）
- 像雇一个人坐你电脑前，按你指令"打开网页、点这个、填那个、把页面抄下来"。

## 设计时怎么用（反推思维）
> 遇到"右键查看源代码没有、但浏览器里能看到"的内容，或要模拟登录/点击翻页，我用 Selenium爬虫 驱动浏览器；纯静态页没必要，urllib / requests库 更轻更快。

## 典型应用 / 我在哪见过
- 登录后才能看的页面、需要点击"加载更多"的瀑布流、带验证码/滑块的表单、SPA 单页应用。
