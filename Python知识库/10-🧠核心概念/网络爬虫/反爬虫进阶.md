# 反爬虫进阶

## 一句话定义
> 网站识别并限制爬虫的手段，以及爬虫对应的突破 / 规避策略。

## 它解决什么问题 / 为什么存在
- 目标站会封 IP、要求登录、加验证码、限制频率；直接请求拿不到数据，需要一套"反反爬"能力才能稳定采到。

## 核心原理（大二能懂的水平）
- 封 IP → 代理池：用 HTTP/HTTPS/SOCKS 代理（高匿/普通/透明），ADSL 拨号可换 IP；代理池用 Redis 有序集合存储并按"分数机制"给每个代理打分，失败扣分、成功加分，自动剔除失效代理。
- 验证码 → OCR/模拟/打码：图形验证码用 tesserocr 识别；极验滑动验证码用 Selenium 模拟拖动缺口与轨迹；点触验证码接超级鹰等打码平台。
- 模拟登录 → 维护 Cookies 池：分析登录请求拿到登录后 Cookie，定时刷新避免过期。
- 请求头 / 行为伪装：伪造 UA、控制访问节奏、随机延迟降低被识别概率。

## 关键参数 / 易错点
- 代理质量：透明代理会泄露真实 IP，要用高匿代理。
- 验证码识别率有限，复杂验证码上打码平台；滑动轨迹太"完美"反而像机器。
- Cookies 会过期，需机制刷新；频率过高必被封。

## 类比（帮助理解）
- 像门卫查证件：代理是"换不同人进去"，验证码是"过安检"，登录态是"持工牌"，节奏伪装是"别跑太快引起注意"。

## 设计时怎么用（反推思维）
> 遇到目标站反爬时，我先"诊断它反的是什么"：封 IP 就上代理池；要登录就模拟登录 + Cookies 池；有验证码就 OCR / 打码平台 / 模拟滑动；并配合限速与请求头伪装把被封概率压到最低。

## 典型应用 / 我在哪见过
- 采集需登录的社区动态、突破限频新闻站、批量打码登录。
