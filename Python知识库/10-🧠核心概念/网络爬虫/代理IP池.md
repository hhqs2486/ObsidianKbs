# 代理IP池

## 一句话定义
> 维护一组可用代理 IP（HTTP / HTTPS / SOCKS），请求时按策略选用，隐藏真实出口 IP、绕过"封 IP"类反爬限制。

## 它解决什么问题 / 为什么存在
- 单机固定 IP 高频访问会被目标站封禁（拉黑），导致整批采集失败；代理池让出口 IP 多变，把风险摊薄。
- 配合限速与 UA 伪装，是突破强反爬的标配。

## 核心原理（大二能懂的水平）
- 代理类型：透明代理（目标站能看到真实 IP）、匿名代理（隐藏真实 IP 但不隐瞒用了代理）、高匿代理（连"用了代理"也隐瞒）——爬取要用高匿。
- 代理池维护：用 Redis 有序集合存代理并按"分数机制"打分，请求成功加分、失败扣分，分数低于阈值自动剔除；也可接 ADSL 拨号动态换 IP。
- 在 Scrapy 里通过 `DOWNLOADER_MIDDLEWARES` 设置代理；requests 用 `proxies={'http': 'ip:port'}`。
- 免费代理不稳、付费代理更可靠；质量优先选高匿付费。

## 关键参数 / 易错点
- 透明代理会泄露真实 IP，等于白用，必须高匿。
- 免费代理大多慢且易失效，要做可用性探测与定时刷新。
- 代理协议要和目标匹配：抓 HTTPS 站点需用支持 HTTPS 的代理。
- 有代理也要控频率——代理不是免死金牌，见 [[爬虫限速]]。
- 代理 IP 的法律与合规风险同样存在，仅用于公开数据。

## 类比（帮助理解）
- 像借一堆不同地址的门牌：每次寄信都换个发件地址，对方难以把"同一寄信人"联系起来封掉。

## 设计时怎么用（反推思维）
> 目标站强封 IP 时我上代理池；自建 Redis 代理池用"分数机制"自动维护质量，高匿优先；在 Scrapy 中间件里注入；同时配合 [[User-Agent池]] 与 [[爬虫限速]] 把被封概率压到最低。

## 典型应用 / 我在哪见过
- 全站商品比价、舆情全量采集等需要大量出口 IP 的场景；与 [[反爬虫进阶]] 的"代理池"同一主题。
