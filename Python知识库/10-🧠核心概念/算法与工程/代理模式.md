# 代理模式

## 一句话定义
> 代理模式给真实对象**配一个「替身」**，替身和原对象实现同一接口，调用方先打到替身，由它决定何时、如何访问真实对象。

## 它解决什么问题 / 为什么存在
- 真实对象很贵（远程调用、大图加载）或需要保护（权限校验）。直接让所有人碰真实对象不行。
- 代理在中间做「懒加载 / 缓存 / 鉴权 / 日志记录」，对调用方透明。

## 核心原理（大二能懂的水平）
- 代理持有真实对象的引用（或能创建它），实现同一接口；在方法里加控制逻辑后再转发。
- 常见变体：虚拟代理（懒加载大资源）、保护代理（权限）、远程代理（RPC 封装）、缓存代理。
- 与 [[装饰器模式]] 区别：代理**控制访问**（要不要放行），装饰器**增加职责**（加功能）。

## 关键参数 / 易错点
- 代理别越权做业务改造，它的职责是「管访问」不是「改结果」。
- 多层代理叠加会增加延迟，注意关键路径。

## 类比（帮助理解）
- 像明星的经纪人：找明星拍戏先过经纪人（代理）谈档期、验身份，合适了才转给明星本人。

## 设计时怎么用（反推思维）
> 做「图片画廊，懒加载大图避免首屏卡顿」时，我会用 **代理模式**：`ImageProxy` 先显示占位，真正滚到可视区才去加载原图（`Image`），调用方只调 `show()` 无感知。

## 典型应用 / 我在哪见过
- Python 的 `weakref.proxy`、ORM 的懒加载关联、RPC 客户端桩（stub）、防火墙/网关。
