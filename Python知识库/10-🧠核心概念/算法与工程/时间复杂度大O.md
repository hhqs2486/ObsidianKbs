# 时间复杂度大O

## 一句话定义
> 时间复杂度用「大 O 记号」描述算法运行时间随输入规模 n 增长的**增长趋势（量级）**，忽略常数系数和低阶项，回答「数据翻倍时，时间大概翻几倍」。

## 它解决什么问题 / 为什么存在
- 同样能完成任务的两个算法，在 n 很大时快慢可能天差地别。需要一种与具体机器、语言无关的语言来比较「可扩展性（scalability）」。
- 帮你在写代码前就判断：这个写法会不会在大数据量下爆掉。

## 核心原理（大二能懂的水平）
- O(1)：常数时间，无论 n 多大一步到位（如按索引取 [[列表]] 元素）。
- O(log n)：对数，每次砍掉一半（如 [[查找算法|二分查找]]）。
- O(n)：线性，n 多大就整体扫 n 遍。
- O(n log n)：很多优秀排序（归并、快排平均）的水平。
- O(n²)：双重循环典型，n=10000 时就是一亿次，是危险信号。
- O(2ⁿ)：指数，递归爆搜常见，n 稍大就不可承受。
- 大 O 只看「主导项」：3n²+100n+5 就是 O(n²)。

## 关键参数 / 易错点
- **常数被吃掉**：O(1000n) 仍是 O(n)。小数据量时常数更重要，大 O 不描述常数项。
- **最坏 vs 平均**：快排平均 O(n log n)，最坏 O(n²)（已有序且选错基准）。谈复杂度要说明是哪种。
- **隐藏的 O(n²)**：`if x in lst` 每次 O(n)，循环里用就成 O(n²)；换成 [[集合]]/[[哈希表]] 的 `in` 是 O(1)。
- 别把「循环层数」和复杂度画等号：有的双层循环实际只跑 O(n)（如双指针）。

## 类比（帮助理解）
- 像评估「搬家公司按体积收费的曲线」：不管箱子里塞得多满（常数），关键是箱子数量 n 增大时，总费用按什么规律涨——线性、平方还是指数。

## 设计时怎么用（反推思维）
> 做「从 1 万条涨到 1 亿条数据」的系统时，我会先用大 O 估核心循环：是不是 O(n²)？是就改 [[哈希表]]/[[排序算法]]/[[分治算法]] 把量级压下来，而不是等上线被拖垮再优化。

## 典型应用 / 我在哪见过
- 选排序、选查找、评估 [[递归]] 层数会不会爆栈。
- 与 [[空间复杂度]] 一起构成算法分析的两条主线。
