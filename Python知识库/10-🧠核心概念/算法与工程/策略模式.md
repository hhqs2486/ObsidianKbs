# 策略模式

## 一句话定义
> 策略模式把「可互换的算法」各自封装成策略类，让上下文在运行时**选一个**来用——切换算法不用改使用它的代码。

## 它解决什么问题 / 为什么存在
- 同一件事有多种做法（排序、压缩、折扣计算、路由），若写 `if algo=='a': ...` 切换，新增算法要改主逻辑、还违反开闭原则。
- 策略把每种算法做成独立类，按需注入。

## 核心原理（大二能懂的水平）
- 策略接口定义 `do()`；具体策略实现不同算法；上下文持有当前策略，调用时委托它执行。
- Python 里策略常直接是「函数」（见 [[函数式编程]]），比类更轻：把函数当参数传进去即可。
- 与 [[状态模式]] 区别：策略是客户主动挑算法，状态是对象随内部状态自动换行为。

## 关键参数 / 易错点
- 若策略间只差一两个参数、算法本质相同，别硬拆类——用参数配置更合适。
- 上下文要面向策略接口编程，别依赖具体策略类型。

## 类比（帮助理解）
- 像导航 App：同一段路可选「最快」「最短」「避开高速」三种策略，你随手切，App 只管按当前策略算路线。

## 设计时怎么用（反推思维）
> 做「电商促销，支持满减/折扣/拼团多种计价」时，我会用 **策略模式**：每种促销是一个 `PricingStrategy`，订单注入当前策略算价，运营加新活动只加一个策略类。

## 典型应用 / 我在哪见过
- `sorted(key=...)` 的比较策略、`pandas` 的聚合函数、压缩/序列化算法选择。
