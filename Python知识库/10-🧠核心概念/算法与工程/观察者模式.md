# 观察者模式

## 一句话定义
> 观察者模式建立「一对多」的依赖：主题（被观察者）一变，所有订阅它的观察者自动收到通知——发布方和订阅方彼此不知道对方细节。

## 它解决什么问题 / 为什么存在
- 一个状态变化要触发多处反应（UI 刷新、写日志、发消息），若写死「变完调 a、调 b、调 c」，新增反应就得改主题代码。
- 观察者让主题只管「我变了，通知大家」，订阅者自行决定怎么反应。

## 核心原理（大二能懂的水平）
- 主题维护观察者列表（`attach`/`detach`），状态变化时遍历调用每个观察者的 `update()`。
- Python 自带 `Observer` 思想的简化实现：`blinker` 信号、`django` 的 `signal`、以及 `weakref` 防内存泄漏。
- 与 [[责任链模式]] 区别：观察者是一对多「广播」，责任链是一对一「沿链传递直到有人处理」。

## 关键参数 / 易错点
- 观察者方法别做耗时操作，否则阻塞主题；重活应异步/丢队列。
- 观察者持有主题引用易致循环引用/内存泄漏，可用弱引用或及时 `detach`。

## 类比（帮助理解）
- 像公众号：你（观察者）关注（订阅）后，号主（主题）发文章你自动收到；取关就不再收到，号主从不用记粉丝是谁。

## 设计时怎么用（反推思维）
> 做「订单支付成功后要发短信、更新库存、记日志」时，我会用 **观察者模式**：`Order` 支付完成时 `notify()`，各观察者各自处理，新增「发积分」只要加一个观察者，不动订单代码。

## 典型应用 / 我在哪见过
- MVC 里 Model 通知 View、事件总线、信号槽（Qt）、`blinker`/`django signals`。
