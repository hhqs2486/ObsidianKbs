# 排序算法

## 一句话定义
> 排序算法把一串数据按指定顺序（通常升序）排好；它是大量后续操作（高效查找、去重、合并、分治）的前置步骤。

## 它解决什么问题 / 为什么存在
- 有序数据才能做二分查找、范围扫描、双指针、外排序。
- 比较类排序的理论下界是 O(n log n)，理解它才能判断「还能不能更快」。

## 核心原理（大二能懂的水平）
- 教学/朴素：冒泡、插入、选择，都是 O(n²)，胜在好写好懂。
- 高效比较类（O(n log n)）：
  - 归并排序：稳定、需 O(n) 额外空间，靠 [[分治算法]]。
  - 快速排序：平均 O(n log n)、原地、但不稳定，基准选错退化 O(n²)。
  - 堆排序：O(n log n) 原地，借 [[堆]]。
- 非比较类（O(n)，但受限）：计数排序、桶排序、基数排序，要求数据范围/分布友好。
- Python 内置 `sorted()` / `list.sort()` 是 **Timsort**（归并+插入的混合，稳定）。

## 关键参数 / 易错点
- **稳定性**：相等元素相对顺序是否保持——按多关键字排序时很关键。归并/Timsort 稳定，快排/堆排不稳定。
- `sort()` 原地改、`sorted()` 返回新列表（见 [[列表]]）；可传 `key=` 自定义排序依据。
- 自己写快排时基准（pivot）选错或已有序会退化；递归深度带来 [[空间复杂度]] 开销。

## 类比（帮助理解）
- 整理一摞乱牌：一张张插（插入排序）很慢但稳；先对半理再合并（归并）快；随便挑张当尺子左右分（快排）通常最快。

## 设计时怎么用（反推思维）
> 99% 场景直接用内置 `sorted()`；需要自定义顺序传 `key=`；海量数据或外部存储用 [[分治算法]] 思想的外排序；需要 Top-K 用 [[堆]] 而非全排。

## 典型应用 / 我在哪见过
- 预处理让 [[查找算法]] 能用二分；去重前先排序；排行榜。
