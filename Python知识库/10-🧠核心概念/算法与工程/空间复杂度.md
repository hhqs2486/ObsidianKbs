# 空间复杂度

## 一句话定义
> 空间复杂度描述算法运行所需的**额外内存**随输入规模 n 增长的趋势，与时间复杂度对应，回答「数据变大时，内存会不会爆」。

## 它解决什么问题 / 为什么存在
- 内存受限（嵌入式、大数组、递归深）时，算法再快也扛不住 OOM。
- 与时间做权衡（trade-off）：常可用空间换时间，或反之。

## 核心原理（大二能懂的水平）
- O(1)：原地算法，开固定几个变量（如冒泡排序）。
- O(n)：开一个与原数据等大的辅助数组/表（如归并排序、[[动态规划]] 的 dp 表）。
- O(n²)：开二维表（某些 DP、邻接矩阵）。
- 递归的栈空间 = O(递归深度)（见 [[递归]]、[[栈]]）。

## 关键参数 / 易错点
- **递归深度导致栈溢出**：每层调用都占栈帧，过深直接 RecursionError（Python 默认约 1000 层）。
- **副本开销被忽略**：[[列表]] 切片 `a[1:]`、`list(a)` 都 O(n) 复制；Python 某些操作会偷偷复制。
- 以为「没 new 对象就没开销」——生成器表达式、迭代器往往比先收集成列表省内存（见 [[迭代器与生成器]]）。

## 类比（帮助理解）
- 做一桌菜额外占用的台面面积：有的菜边做边清（O(1) 原地），有的得摆满一整排备料盘（O(n)）。

## 设计时怎么用（反推思维）
> 处理「单机内存装不下」的超大文件时，我会用 [[迭代器与生成器]] 流式处理而非一次性读进 [[列表]]；[[递归]] 改迭代避免爆栈；[[动态规划]] 用滚动数组把 O(n²) 空间压成 O(n)。

## 典型应用 / 我在哪见过
- 选「原地排序」还是开辅助数组；评估 DP 表大小；判断递归是否要改迭代。
