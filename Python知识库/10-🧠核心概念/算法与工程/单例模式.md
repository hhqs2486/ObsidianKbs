# 单例模式

## 一句话定义
> 单例模式保证一个类**全局只有一个实例**，并提供一个统一的访问点——所有调用方拿到的是同一个对象。

## 它解决什么问题 / 为什么存在
- 有些资源天生该唯一：数据库连接池、配置管理器、日志器、线程池。多个实例会浪费资源或状态冲突。
- 单例把「实例数量 = 1」这个约束固化在类里，调用方不用自己管。

## 核心原理（大二能懂的水平）
- 经典写法：类变量保存唯一实例，`__new__` 里判断「还没有就造一个，有就返回旧的」。
- Python 更省事的做法：模块级变量本身就是单例（模块只导入一次）；或用装饰器/元类实现。
- 通用示意（重写 `__new__`，非本书代码）：
  ```python
  class Singleton:
      _inst = None
      def __new__(cls):
          if cls._inst is None:
              cls._inst = super().__new__(cls)
          return cls._inst
  ```

## 关键参数 / 易错点
- 多线程下「判断 + 创建」不是原子操作，可能造出两个——需要加锁（双重检查）。
- 单例容易被用成「全局变量」：它隐蔽了依赖、不利于测试和并发，能不用就不用。

## 类比（帮助理解）
- 像公司唯一的一枚公章：谁要用都去同一处盖，不会出现两枚并行的公章导致混乱。

## 设计时怎么用（反推思维）
> 做「全局配置中心」时，我会用 **单例模式**：所有模块统一从一个 `Config` 实例读配置，改一处全生效；但业务状态尽量不放单例里，避免隐式共享。

## 典型应用 / 我在哪见过
- 日志器 `logging.getLogger`、数据库连接池、应用全局状态。
