# 动态规划

## 一句话定义
> 动态规划（DP）把问题拆成**重叠的子问题**，每个子问题只算一次并缓存复用，从而把指数级的暴力递归压成多项式时间。

## 它解决什么问题 / 为什么存在
- 最优化类问题：求最值、方案数、可行性（如最长公共子序列、背包、编辑距离）。
- 当 [[递归]] 出现大量重复子问题时，DP 是「去重加速」的系统性方法。

## 核心原理（大二能懂的水平）
- 两大特征：**最优子结构** + **重叠子问题**。
- 两种写法：
  - 自顶向下记忆化：[[递归]] + 缓存（如 `functools.lru_cache`）。
  - 自底向上填表：用 [[列表]] 当 dp 表，从最小子问题推到大问题。
- 常套路：先写暴力递归 → 加记忆化 → 改写成填表 → 用滚动数组压缩 [[空间复杂度]]。

## 关键参数 / 易错点
- 不是所有 [[递归]] 都适合 DP——没有重叠子问题就没收益（那种更适合 [[分治算法]]）。
- 状态定义不清、转移方程写错，结果就错；要先能用数学描述「状态」与「转移」。
- 多维 dp 空间爆炸时，考虑状态压缩/滚动数组。

## 类比（帮助理解）
- 爬楼梯：到第 n 级的方法数 = 到第 n-1 级 + 到第 n-2 级；每算出一个值就记墙上，下次直接查，不重算。

## 设计时怎么用（反推思维）
> 遇到「最多/最少/能否」，且输入规模适中、子问题重叠，我会先想 DP：先写递归版验证正确性，再加记忆化，最后考虑填表与降维。

## 典型应用 / 我在哪见过
- 背包、最长公共子序列/子串、编辑距离（也见 [[字符串算法]]）、股票买卖最佳时机。
