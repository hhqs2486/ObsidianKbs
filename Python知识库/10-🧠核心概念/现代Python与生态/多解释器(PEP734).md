# 多解释器 concurrent.interpreters（PEP 734）

## 一句话定义
> Python 3.14 将已有 20+ 年的子解释器功能通过 `concurrent.interpreters` 模块暴露给 Python 层，实现进程级隔离 + 线程级效率的真多核并行。

## 它解决什么问题 / 为什么存在
- `threading`：共享内存、GIL 限制、调试地狱
- `multiprocessing`：进程隔离好，但开销大、序列化成本高
- 子解释器：进程的隔离性 + 线程的效率，opt-in 共享

## 核心原理（大二能懂的水平）
- 同一进程内运行多个独立 Python 解释器，各自有独立的 GIL
- 默认不共享任何状态（类似 multiprocessing），通过 `memoryview` 或 channel 通信
- 支持 CSP/Actor 模式，类似 Erlang/Go 的并发哲学
- 配合 free-threaded 构建可达真多核并行

```python
import concurrent.interpreters as ci

interp = ci.create()
interp.run("print('Hello from sub-interpreter')")
```

## 关键参数 / 易错点
- 当前仍有限制：启动开销未优化、内存占用偏高、第三方 C 扩展需适配
- 与 multiprocessing 不同：不支持 fork（必须在主线程创建）
- 标准库扩展模块已全部兼容，PyPI 包进度不一

## 类比（帮助理解）
- 像一个楼里（进程）的不同房间（子解释器）：每个房间独立隔音（隔离），但比另买一栋楼（multiprocessing）便宜。

## 设计时怎么用（反推思维）
> CPU 密集型且需要高度隔离的并发任务（如沙箱执行用户代码），优先考虑子解释器替代 multiprocessing。
