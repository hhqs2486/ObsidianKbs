# 延迟求值注解（PEP 649/749）

## 一句话定义
> Python 3.14 起，函数/类/模块的注解不再立即求值，而是延迟到 `annotationlib.get_annotations()` 调用时才求值，解决前向引用和性能问题。

## 它解决什么问题 / 为什么存在
- 之前注解在定义时立即求值，前向引用必须用字符串包裹（如 `def f() -> "MyClass"`），或加 `from __future__ import annotations`
- 立即求值拖慢模块导入速度

## 核心原理（大二能懂的水平）
- 注解被存储为特殊函数（annotate function），仅在 `get_annotations()` 调用时执行
- 新模块 `annotationlib` 提供三种格式：
  - `VALUE`：求值为运行时值（旧行为）
  - `FORWARDREF`：未定义名替换为 `ForwardRef` 标记
  - `STRING`：返回字符串
- `from __future__ import annotations` 不再需要，被视为废弃
- 前向引用再也不用加引号：`def f(x: MyClass)` 直接能跑

## 关键参数 / 易错点
- 读取 `__annotations__` 属性的第三方库可能需要适配
- `dataclasses` 等标准库已自动适配 FORWARDREF 格式
- `from __future__ import annotations` 在 3.14 仍可用，但未来版本将移除

## 类比（帮助理解）
- 像快递「货到付款」：包裹（注解）先送到，需要时才拆（求值），不用就一直不动。

## 设计时怎么用（反推思维）
> 写类型标注时不用再为前向引用加引号，代码更干净；读取注解用 annotationlib 替代直接访问 __annotations__。

## 典型应用 / 我在哪见过
- 所有使用类型标注的 Python 代码自动受益
- dataclasses、pydantic、FastAPI 等库内部已适配
