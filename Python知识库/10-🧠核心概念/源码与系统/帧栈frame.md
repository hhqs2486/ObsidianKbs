# 帧栈 frame（PyFrameObject）

## 一句话定义
frame 即 `PyFrameObject`，是 CPython 虚拟机执行一段代码时的「运行现场」：里面装着值栈、局部/全局名字空间、当前执行的字节码位置（`f_lasti`）、以及指向上一帧的指针，从而构成调用栈；每调用一个函数/执行一个代码块就新建一帧。

## 它解决什么问题 / 为什么存在
- 解释器逐条执行字节码需要「上下文」：当前栈上有什么值、局部变量在哪、执行到哪了、谁调用了我。frame 把这些现场打包，支持函数嵌套调用、异常回溯（`traceback`）、以及 `yield` 挂起恢复。

## 核心原理（大二能懂的水平）
- 每个 `PyCodeObject`（见 [[CPython字节码]]）执行时都配一个 `PyFrameObject`。frame 里有：
  - **值栈**（evaluation stack）：字节码指令取/压操作数的地方（如 `BINARY_ADD` 弹出两个、压回一个）。
  - **名字空间指针**：`f_globals`、`f_locals`，以及自由变量/闭包变量区。
  - **指令指针 `f_lasti`**：记录下一条要执行的字节码偏移。
  - **`f_back`**：指向调用者的帧，形成帧链（调用栈）。
- 函数调用 = 创建新 frame → 把参数放进新 frame 的局部区 → 虚拟机切到新 frame 执行 → 返回时把结果压回调用者 frame 的值栈，并销毁/回收该 frame。
- 可以通过 `sys._getframe()` 或 `inspect` 在 Python 里访问当前帧，调试器/装饰器常用它。
- `f_stacktop` 字段：正常执行时为 `NULL`；**只有当 `yield` 挂起协程/生成器时**才记录栈顶，这正是 [[协程底层实现]] / 生成器能「暂停-恢复」的底层支点。

## 关键参数 / 易错点
- 递归过深 → 「maximum recursion depth exceeded」，本质就是帧链太长，每层都占栈内存。
- frame 是对象，也走 [[引用计数]] / [[垃圾回收GC]]；被引用（如闭包持有）就不会回收。
- 异常回溯 `traceback` 就是从出问题的 frame 沿 `f_back` 一路回溯得到的。
- 值栈大小在编译期就能算出（字节码不动态增删栈深度失衡），这是 CPython 能安全执行的前提之一。

## 类比（帮助理解）
frame 像「一次函数调用的工作台」：台上摆着当前要用的零件（值栈）、抽屉里是局部变量、台角贴着「上一步在哪停顿」（指令指针），台子下用绳子连着上一道工序的台子（`f_back`）。一道工序做完，把成品递回上一台，撤掉本台。

## 设计时怎么用（反推思维）
> 写装饰器、调试器、性能剖析器，或理解递归/异常/`yield` 时，我会从 frame 角度想：当前现场是什么、变量在哪一帧、怎么沿 `f_back` 回溯。排查栈溢出就数帧深度。
