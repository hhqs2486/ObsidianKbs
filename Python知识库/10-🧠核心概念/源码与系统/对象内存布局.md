# 对象内存布局

## 一句话定义
对象内存布局指「一个 Python 对象在 C 堆上由哪些字段拼成」：所有对象头部都是相同的 `PyObject`（含引用计数 `ob_refcnt` 与类型指针 `ob_type`），变长对象再额外套一层 `PyVarObject`（多一个 `ob_size`）。

## 它解决什么问题 / 为什么存在
- C 不是面向对象语言，Python 用「统一的 C 结构体头部」在 C 层面模拟对象，让任意对象都能用同一个 `PyObject*` 指针引用，从而实现对所有对象的统一管理与多态。
- 固定头部 + 各自附加字段，是「通用性」和「特化数据」之间的折中。

## 核心原理（大二能懂的水平）
- 最核心的基石是 `PyObject`：发布版里它只有两个成员——`int ob_refcnt`（引用计数）和 `struct _typeobject *ob_type`（指向类型对象）。所有对象开头这几字节含义完全一致。
- 需要容纳可变长度数据的对象（字符串、list、dict 等）用 `PyVarObject`，在 `PyObject` 基础上多一个 `int ob_size`，表示「装了多少个元素」（注意是元素个数不是字节数）。
- 所以内存布局是分层的：定长对象 = `PyObject` + 自己的数据（如 `PyIntObject` 多一个 `long ob_ival`）；变长对象 = `PyVarObject` + 一段连续数据。
- 每个对象创建后大小**不可变**：要放可变长度数据，对象内只保留一个「指向别处内存的指针」（如 list 的 `ob_item`）。这是为了避免对象长大时把后面的对象挤爆、还要更新所有指针。
- 类型对象（`PyTypeObject`）本身也是对象（`PyObject_VAR_HEAD` 开头），描述「某类实例该怎么建、占多大、支持哪些操作」，其 `tp_basicsize`/`tp_itemsize` 记录了实例该分配多少内存。

## 关键参数 / 易错点
- 对象一旦创建大小就固定；变长对象靠「内部指针」指向真正可增长的内存区。
- 类型对象「跳出三界外」：指向类型对象的指针**不算**引用，类型对象永不被引用计数析构。
- 定长 vs 变长的区别在「不同实例占的内存是否相同」，例如 `1` 和 `100` 都是 `sizeof(PyIntObject)`，而 `"Python"` 和 `"Ruby"` 不同。
- 对象头统一 → 所有对象都能用 `PyObject*` 操作，多态靠 `ob_type` 在运行时查类型再分派（见 [[Python对象模型]]）。

## 类比（帮助理解）
把每个对象想成「带统一信封的信」：信封正面（PyObject 头）写着「有几个人引用我 + 我是什么类型」，信封里面（附加字段）才是这封信专属的内容。不管信里写什么，邮局（虚拟机）只看信封就能分拣。

## 设计时怎么用（反推思维）
> 做「需要控制内存/理解对象开销」的工作（如排查内存占用、写 C 扩展、理解为何小对象有对象池）时，我会先想清楚一个对象 = 统一头 + 自己的数据 + 可能的间接指针，从而估算真实内存并解释「为什么 list 比 array 占空间」。

## 典型应用 / 我在哪见过
- 解释「为什么一切皆对象」、对象池机制（整数/字符串小对象复用）。
- 理解 [[引用计数]]（头部 `ob_refcnt`）与 [[垃圾回收GC]]（container 对象如何被 GC 跟踪）。
- 与类型系统、[[描述符协议底层]]、[[元类]] 相关：类型对象也是这套布局的产物。
