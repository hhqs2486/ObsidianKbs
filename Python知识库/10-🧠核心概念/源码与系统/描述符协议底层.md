# 描述符协议底层

## 一句话定义
描述符（descriptor）是「实现了 `__get__`（以及可选的 `__set__`/`__delete__`）协议的对象」，它被放在某个类的 `__dict__` 里，从而接管「对该类实例的某属性进行读/写」时的底层行为；`@property`、方法、`staticmethod`、`classmethod` 本质都是描述符。

## 它解决什么问题 / 为什么存在
- 普通属性读写只是查字典，无法「在读/写时插手逻辑」（校验、惰性计算、类型约束）。描述符把「属性访问」变成一次**方法调用**，让 Python 用统一机制实现 property、绑定方法、静态/类方法等一整套特性。

## 核心原理（大二能懂的水平）
- 在 CPython 内部，类型对象 `PyTypeObject` 里那些操作（如 `tp_print`、`tp_hash`）会被包装成一种叫 **`PyWrapperDescrObject`** 的 descriptor（书里称「从 slot 到 descriptor」）：`add_operators` 会遍历 `slotdefs`，为每个 slot 建一个 descriptor，再在类型的 `tp_dict` 里建立「操作名 → descriptor」的映射。
- descriptor 内部结构有公共头 `PyDescr_COMMON`（含 `d_type`），调用时走 `wrapperdescr_call`。所以它既是「类型操作的可调用对象」，也是属性查找机制的一环。
- 属性查找时：若目标在 MRO 上是 descriptor，就按其协议调用——`__get__(descriptor, instance, owner)`；若是 data descriptor（`__set__` 也存在）优先级最高。方法之所以「自动绑定 self」，正是因为函数是 non-data descriptor，其 `__get__` 返回「绑定的方法对象」。
- 用户定义的描述符：类里写一个带 `__get__`/`__set__` 的类实例作为类属性即可；`@property` 是语法糖，帮你把方法包成 descriptor。

## 关键参数 / 易错点
- **data vs non-data descriptor**：同时有 `__get__` 和 `__set__` 的是 data descriptor，优先级高于实例 `__dict__`；只有 `__get__` 的是 non-data（如方法），优先级低于实例 `__dict__`——直接决定 [[属性查找MRO]] 的结果。
- descriptor 必须作为**类属性**才有意义，放在实例 `__dict__` 里不会被当 descriptor 调用（只是普通属性）。
- 方法、property、staticmethod、classmethod 都是描述符的「特例」，理解这一点就不再觉得它们是魔法。
- 这是类型对象创建（`type.__new__`）时建立 `tp_dict` 的关键步骤，与 [[元类]] 关系极深。

## 类比（帮助理解）
把类属性想成教室墙上的「插槽」。普通属性是张便签，谁都能直接看；描述符是墙上一个「带机关的投递口」：有人来读，它内部其实去调了一个函数再返回结果（比如先算好再给、或先做校验）。property 就是工厂帮你预制好的这种投递口。

## 设计时怎么用（反推思维）
> 需要「访问属性时自动做校验/惰性加载/类型转换」，又不想到处写显式 getter 时，我会用 `@property` 或自定义描述符；需要理解框架（如 ORM 字段、Django model field）如何接管属性，我会从描述符协议往下看。

## 典型应用 / 我在哪见过
- `@property`、`staticmethod`、`classmethod`、实例方法绑定。
- ORM 字段、校验器、懒加载属性。
