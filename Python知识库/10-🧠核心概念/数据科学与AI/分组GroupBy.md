# 分组GroupBy

## 一句话定义
> 分组（GroupBy）是 pandas 按一个或多个键把数据"拆分—应用—合并"（split-apply-combine）的核心机制，是数据分析里"按 XX 分组算 XX"的发动机。

## 它解决什么问题 / 为什么存在
- SQL 只能做有限种类的分组运算；Python/pandas 表达力强，能对任何键、用任意函数做复杂分组（加权均值、组内回归、子集选取等）。
- 本章（Ch10.1）开篇即说：加载、融合、准备好数据后，通常就是计算分组统计或生成透视表。

## 核心原理（大二能懂的水平）
- 调用：`df.groupby('key1')` 或 `df['col'].groupby(df['key1'])`；返回的 GroupBy 对象**还没计算**，只是记下了分组键。
- 分组键形式很多：列名 / 等长数组 / 字典 / Series（键→组名映射）/ 函数（对索引值调用，返回值作组名）。
- 多级分组：`groupby(['key1','key2'])`，结果带层次化索引，可 `.unstack()` 转成网格。
- 迭代：`for name, group in df.groupby('key1')`，也能 `dict(list(...))` 存成片段字典。
- 选取列子集：`df.groupby('key1')['data1']` 是语法糖；按 dtype 分组用 `axis=1`；按索引级别用 `level=`。
- **通用武器 `apply`**：`groupby(...).apply(func)` 把函数应用到每个分组片段再拼回，能做 top-N、分组填充、组内回归等。

## 关键参数 / 易错点
- 易错点1：非数值列默认被排除（"麻烦列"），只聚合数值列。
- 易错点2：分组键里的缺失值会被从结果中去除。
- 易错点3：自定义 `apply` 函数比优化的 `mean/sum` 慢（有分块开销）。
- 易错点4：`group_keys=False` 可禁止把分组键叠进结果层次化索引。

## 类比（帮助理解）
- 像老师把全班试卷"按班级分成几摞（split），每摞统一批改算平均分（apply），最后把各班成绩贴回一张总表（combine）"。

## 设计时怎么用（反推思维）
> 做 **任何"按维度拆分再汇总/转换"的需求**时，我会用它能解决 **"分组统计与组内处理"**——先 `groupby` 选定键，再 `.agg()`（[[数据聚合]]）或 `.apply()`；要行列交叉汇总直接上 [[透视表]]；组内要算相关系数/回归就套 `apply`（[[相关性分析]]、[[时间序列分析]] 都常用）。
