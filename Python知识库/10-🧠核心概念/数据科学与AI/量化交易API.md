# 量化交易API

## 一句话定义
> 用程序代码（而不是手工点鼠标）获取行情、下单、查账户的一整套接口，是量化策略跑起来的「手脚」。

## 它解决什么问题 / 为什么存在
- 手工交易慢、情绪化、无法批量；API 让策略自动执行、毫秒级响应、7×24 监控，是量化与主观交易的分水岭。

## 核心原理（大二能懂的水平）
- 分两类：**数据 API**（拉行情/财务，如 tushare、yfinance）和**交易 API**（券商/交易所下单接口）。
- 书中配合 tushare 抓取模块、zwDat 数据包、`down_stk` 下载程序完成 A 股/美股日线更新去重；zwQuant 业务层可生成 CSV 导入第三方软件下单。

## 关键参数 / 易错点
- 频率限制（限流）。
- 数据延迟与复权处理（adj close）。
- 下单前必须校验（[[风险管理]]）。
- 实盘与 [[回测]] 数据格式要一致（书中用 `df2zw`/`df2zwAdj` 等转换）。

## 类比（帮助理解）
- 像餐厅的「点单系统」——客人（策略）说要什么，系统（API）传给厨房（交易所）并回报状态，全程不用服务员跑腿喊。

## 设计时怎么用（反推思维）
> 先确定数据源（tushare/akshare）→ 用 [[数据清洗]] 规整 → 接入回测/实盘；交易侧封装下单函数并接 [[止损]] 硬规则。

## 典型应用 / 我在哪见过
- zwQuant 的 `down_stk_cn010` / `down_stk_yahoo010` 数据下载、tushare 行情接口。
