# 数据聚合

## 一句话定义
> 数据聚合是把多行数据按某种规则"合并成一个标量/摘要值"的转换过程，如求平均、求和、计数、分位数等——是分组运算的"合并"那一步。

## 它解决什么问题 / 为什么存在
- 明细数据太多，人看不过来也喂不进模型；需要"每组怎样"的汇总指标来回答业务问题。
- 本章（Ch10.2）说：聚合是关系型数据库和 SQL 流行的原因之一，但 pandas 能执行复杂得多的聚合。

## 核心原理（大二能懂的水平）
- 聚合 = "从数组产生标量值的数据转换"，如 `mean`、`count`、`min`、`sum`、`std`、`var`、`median`、`quantile`。
- 这些经过优化的方法直接挂在 GroupBy 对象上（表10-1），比自己写函数快很多。
- **自定义聚合**：`aggregate` / `agg` 传入任意函数，如 `peak_to_peak = lambda arr: arr.max()-arr.min()`。
- **面向列多函数**：对一列传 `['mean','std',peak_to_peak]`，或传 `(名称,函数)` 元组列表自定义列名；对 DataFrame 可用字典 `{列: 函数}` 让不同列用不同聚合。
- **不要行索引**：`as_index=False` 或结果 `reset_index()` 让分组键变回普通列。

## 关键参数 / 易错点
- 易错点1：自定义函数比优化的 `mean/sum` 慢得多（有分组分块开销），能用品优方法就别自己写。
- 易错点2：默认所有数值列都参与聚合，非数值列（"麻烦列"）被排除。
- 易错点3：分组键里的缺失值会被从结果中去除。
- 易错点4：`describe()` 严格说不是聚合（返回多值），但 GroupBy 上也能用。

## 类比（帮助理解）
- 像把一筐混装水果"按种类称总重 / 数个数 / 算均价"：每类出一个数，筐里一堆水果变成一张小账本。

## 设计时怎么用（反推思维）
> 做 **报表 / 指标计算 / 特征工程**时，我会用它能解决 **"从明细到汇总"**——需要"按 XX 算 XX"就上 `groupby(...).agg(...)`（[[分组GroupBy]]），多指标多函数一次算清；要交叉网格汇总就用 [[透视表]]，底层同样是聚合。

## 典型应用 / 我在哪见过
- Ch10.2 数据聚合：`agg` 自定义 `peak_to_peak`、面向列多函数、`as_index=False`、分组加权均值等。
- 日常：销售按地区汇总、用户按分群统计、日志按小时计数。
