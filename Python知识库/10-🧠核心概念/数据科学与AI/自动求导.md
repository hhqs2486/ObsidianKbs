# 自动求导

## 一句话定义
> 自动求导（autograd）是深度学习框架自动计算函数对参数梯度的机制：你只写"前向计算"，框架按计算图反向追踪，自动算出梯度，省去手推链式法则。

## 它解决什么问题 / 为什么存在
- 深层网络的损失函数对成百上千个参数求偏导，手工推导既繁琐又极易出错。
- 自动求导让"写模型 = 写前向"，梯度由 `record()` 记录计算图 + `backward()` 反向传播自动得到，是训练能落地的关键基础设施。

## 核心原理（大二能懂的水平）
- 例：对 y = 2·xᵀx 求关于列向量 x 的梯度。先 `x.attach_grad()` 申请存梯度的内存；再用 `with autograd.record():` 包住前向计算，告诉框架"记录这段运算"；最后 `y.backward()`，框架沿计算图自动求梯度，结果存在 `x.grad`（理论应为 4x）。
- 框架甚至能对含 Python 控制流（if/while）的函数求梯度——因为记录的是实际执行路径。
- 训练模式 vs 预测模式：`record` 期间框架切到训练模式（如 [[正则化深度学习|丢弃法]] 才生效），可用 `autograd.is_training()` 判断。

## 关键参数 / 易错点
- 必须先 `attach_grad()` 再记录；`backward()` 默认对"标量"求梯度，若 y 不是标量，框架会先对 y 元素求和再求导（这常是初学者的坑）。
- 易错：忘了用 `autograd.record()` 包裹前向，梯度不会被记录，`x.grad` 为空。
- 预测/推理时要避免记录，否则既慢又可能改变含随机性的层的行为。

## 类比（帮助理解）
- 像让你"先把解题步骤一步步写下来"，然后有个批改机器从最后答案倒推："这道题里哪一步、对哪个数最敏感"——你不用自己倒着算，机器按你写的步骤反着走一遍就给出敏感度（梯度）。

## 设计时怎么用（反推思维）
> 训练任意 [[深度学习]] 模型时，我会把"前向计算 + 损失"写在 `autograd.record()` 里、调用 `loss.backward()` 拿到参数梯度，再交给 [[梯度下降]] / [[优化算法深度学习]] 更新；这样无论网络多深，我都不用手推 [[反向传播]] 的链式法则，只管搭前向结构。

## 典型应用 / 我在哪见过
- 所有用 Gluon/PyTorch 写的训练循环：`record → backward → trainer.step`。
- 对含循环/条件的函数求梯度（如"循环次数取决于输入"的网络）。
