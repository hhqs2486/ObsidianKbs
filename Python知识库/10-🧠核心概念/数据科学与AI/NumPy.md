# NumPy

## 一句话定义
> NumPy（Numeric Python）是 Python 科学计算的基础包，核心是多维数组 ndarray 和整套基于数组的向量化计算，几乎所有 [[数据科学]] 库都建在它之上。

## 它解决什么问题 / 为什么存在
- 原生 Python 列表循环慢、且不支持整体数学运算（不能 "列表*2" 做逐元素乘）。
- NumPy 用 C 实现的多维数组 + 向量化运算，让“对百万个数做同一运算”一行代码、且快几十到上百倍。
- 书中定义：提供快速高效的多维数组 ndarray、基于数组整体/元素级科学计算、广播(broadcasting)、整合 C/C++/Fortran、线性代数/傅里叶/随机数，是其他库的“数据容器”（Ch1 1.2.3）。

## 核心原理（大二能懂的水平）
- ndarray：同类型元素组成的多维网格，shape 描述维度（如 (100,1) 是 100 行 1 列）。
- 向量化：numpy.array(x).reshape([100,1]) 把列表转数组；之后 x*2、x+y 是逐元素算，无需 for 循环（CPU 级批量执行）。
- 广播：形状不同的数组按规则自动对齐再做运算（如 (100,1) 与 (1,3) 能算出 (100,3)）。
- 底层用 C 写，内存连续，其他低级语言库可直接读 NumPy 数据免转换——所以它是 SciPy/Pandas/scikit-learn 的“通用数据容器”。
- Ch1 案例：读出的 x、y 列表先 numpy.array(...).reshape([100,1]) 转成矩阵，再喂给 [[机器学习]] 的线性回归。

## 关键参数 / 易错点
- reshape 的总元素数必须和原数组一致，否则报错。
- dtype 要一致：混合类型会被降级成 object，失去性能优势。
- 广播虽方便，但维度对齐规则易踩坑（小维度会“沿轴复制”），写错会静默算出错结果。
- 与 Pandas 关系：DataFrame 单列/底层常是 ndarray；但 Pandas 多了标签索引，NumPy 只有位置。
- 书中提醒：Scipy 依赖 NumPy+mkl，安装顺序很重要（NumPy→Scipy→Matplotlib→scikit-learn）。

## 类比（帮助理解）
- ndarray 像“带行列表格的数字矩阵”，向量化像“整列同时乘”，而不是逐格按计算器。
- 如果 [[Python]] 是通用螺丝刀，NumPy 就是电钻——同样拧螺丝，批量且快。

## 设计时怎么用（反推思维）
> 做 **需要高性能数值计算的模块时**（如特征变换、矩阵运算、仿真），我会用它能解决 **“百万级数值运算的性能瓶颈”**——把数据转成 ndarray 后用向量化替代 for 循环，并通过 reshape/广播组织张量维度，作为 [[Pandas]] 清洗后、[[机器学习]] 建模前的计算底座。

## 典型应用 / 我在哪见过
- Ch1 销售预测里数组化 x/y；Ch3 用 np.random.randn 造测试数据、np.nan 造缺失；任何矩阵运算、随机数、傅里叶变换。
- 日常：图像处理（像素是数组）、信号分析、数值模拟。
