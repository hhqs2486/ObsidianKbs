# 数据清洗

## 一句话定义
> 数据清洗是对数据集做丢弃、填充、替换、去重等操作，以去除异常、纠正错误、补足缺失，为后续分析建模准备好“干净数据”的过程。

## 它解决什么问题 / 为什么存在
- 真实业务数据几乎都有缺失、异常、重复——直接建模会“垃圾进垃圾出”。
- 本书把它列为数据化运营工作流第二阶段“数据预处理”的第一步，是后期所有数据工作质量的根（Ch3 开篇：直接决定质量与价值输出）。
- 三大处理对象：缺失值、异常值、重复值。

## 核心原理（大二能懂的水平）
- 缺失值 4 种思路（Ch3 3.1.1）：
  1. 丢弃：删带缺失的行/列。但当缺失比例 >10% 或缺失集中在某类标签时不宜丢（会丢特征、导致过拟合）。
  2. 补全：数值用均值/中位数/加权均值，类别用众数；或用模型法把缺失列当目标预测；少量重要数据可专家补全。
  3. 真值转换：承认缺失也是一种状态，把“性别(男/女/未知)”拆成 3 个 0/1 列一起参与计算。
  4. 不处理：某些模型（KNN、决策树/随机森林、[[神经网络]]、朴素贝叶斯、DBSCAN）本身能容忍缺失。
- 异常值（Ch3 3.1.2）：先区分“伪异常”（业务动作导致，如促销日爆量，是真实业务）和“真异常”（客观分布异常）。伪异常、异常检测模型目标、对异常不敏感的模型都不该随意丢弃。
- 重复值（Ch3 3.1.3）：一般去重，但变化维度表（保留历史）、样本过采样（少数类复制）、事务型重复（重复订单=规则漏洞）三种情况要慎重。
- 实操靠 [[Pandas]]：isnull()/dropna()/fillna()/replace()，或 sklearn 的 Imputer。

## 关键参数 / 易错点
- 易错点1：缺失比例 >10% 还整行 drop，损失信息。
- 易错点2：把空字符串 "" 当缺失——它是有实体的字符串，不是 NaN/None/Null。
- 易错点3：数据库设了 default 值，让本该是 Null 的缺失“看起来正常”，需警惕（Ch3 提醒）。
- 易错点4：用 0 或均值填充会扭曲分布，决策前先想业务含义。
- 易错点5：伪异常被当噪声删掉，反而掩盖了真实业务结果。
- fillna 的 strategy：mean/median/most_frequent；method：pad/ffill/backfill/bfill。

## 类比（帮助理解）
- 像“洗菜下锅前摘烂叶、补缺损、挑出虫子”：不是所有‘不一样’的都要扔，有些是正常品种（伪异常），有些是虫子（真异常）。
- 缺失值的 4 种处理像对待一份漏填的问卷：撕掉（丢弃）/ 帮填（补全）/ 标明“未答”也当信息（真值转换）/ 留着交给能容忍空缺的阅卷老师（不处理）。

## 设计时怎么用（反推思维）
> 做 **数据管线(pipeline)的预处理层时**，我会用它能解决 **“上游脏数据导致模型失效”**——在接入 [[Pandas]] 数据后，先用 isnull 评估缺失占比与分布，再按“丢弃/补全/真值转换/不处理”决策；对异常先判伪/真再决定保留；去重前先识别是否变化维度或采样复制，保证喂给 [[数据分析]]/[[机器学习]] 的是可信数据。
