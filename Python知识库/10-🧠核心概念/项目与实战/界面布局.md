# 界面布局

## 一句话定义
界面布局（Layout）是用 Qt 的「布局管理器」自动安排控件的位置与大小，让窗口缩放时控件能跟着合理伸缩，而不用手算坐标。

## 它解决什么问题 / 为什么存在
- 手动给每个控件写死 x/y/宽/高，窗口一缩放就错位、重叠、留白难看；且不同语言文本长短不同（英文 vs 德文标签）时尺寸算不准。
- 布局管理器接管这件事：你只声明「谁和谁排成一行 / 一列 / 一张网格」，Qt 在窗口大小变化时自动重排，并给出一个「最小可用尺寸」防止窗口被缩到没法用。

## 核心原理（大二能懂的水平）
- 三种主力布局（都可互相嵌套，组合出复杂界面）：
  - **QHBoxLayout**：水平排（左→右）。
  - **QVBoxLayout**：垂直排（上→下）。
  - **QGridLayout**：网格排，控件可跨多行多列。
- 用法模式：建控件 → 建布局 → `layout.addWidget(控件)` → `窗口.setLayout(布局)`。本书第 4 章的 dial+spinbox 例子就是 `QHBoxLayout` 把两个控件横排。
- 控件还能设**尺寸策略（size policy）**控制「怎么伸缩」：
  - Fixed：死尺寸，绝不改。
  - Minimum / Maximum：有下限 / 有上限。
  - Preferred：偏好尺寸，可大可小。
  - Expanding：能缩但**更想变大**，会抢额外空间。
  - 例：QLineEdit 默认水平 Expanding + 垂直 Fixed → 横向尽量拉宽、纵向不变高。
- **拉伸因子（stretch）**：同一布局里多个控件抢空间时按比例分（如 1:3，底下的列表涨得更快）。
- 容器类控件也能当「分页」：QTabWidget（选项卡分页）、QStackedWidget（叠放只显一页）；SDI / MDI 是多文档窗口组织方式（本书第 9 章）。

## 关键参数 / 易错点
- 控件**不加到布局里就不会显示 / 不会随窗口缩放**——最常见新手坑：只 `widget.show()` 却忘了 `setLayout`。
- 顶层窗口要先 `setLayout(布局)`，布局里的控件才会被管理。
- 嵌套布局时，内层布局要先 `addWidget` 完毕，再作为一个整体 `addLayout` 到外层。
- 尺寸策略比「写死最小/最大尺寸」更优，优先用策略 + 拉伸因子调。
- 还调不好就子类化重写 `sizeHint()` / `minimumSizeHint()`（进阶，见本书第 11 章）。

## 类比（帮助理解）
布局管理器像「收纳盒里的隔板」：你只说「这几个物件竖着叠放、那个横着排」，盒子变大变小时隔板自动把空间重新分配好。尺寸策略相当于给每个物件贴标签——「我固定大小」「我尽量占满」「我最多这么大」——隔板按标签分配伸缩额度。

## 设计时怎么用（反推思维）
> 拿到界面需求，我会先画「结构草图」：哪几块是横排、哪几块是竖排、哪里要分页（选项太多用 QTabWidget）。然后用嵌套的 H/V/Grid 布局拼出来，对要抢空间的控件设 Expanding + 拉伸因子，最后几乎不写死尺寸。

## 典型应用 / 我在哪见过
- 本书第 4 章 dial+spinbox 横排；第 9 章 Layout Policies、Tab/Stacked Widgets、Splitters、SDI/MDI。
- 实际：设置对话框用 QTabWidget 分页；表单用 QGridLayout 对齐标签与输入框。
