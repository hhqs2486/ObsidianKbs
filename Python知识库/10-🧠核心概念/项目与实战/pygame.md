# pygame

## 一句话定义
> pygame 是 Python 的第三方 2D 游戏开发库，底层封装了 SDL，提供窗口、绘图、键盘/鼠标输入、声音播放等能力，让你用纯 Python 写小游戏。

## 它解决什么问题 / 为什么存在
- 原生 Python 只会跑文本、算数字，没有画面、没有声音、也没有"实时响应按键"的机制。
- pygame 把"和操作系统/显卡/声卡打交道"的脏活封装好，给你一套简单的 API：开窗口、画矩形、读按键、播音乐，让你专注写游戏逻辑。

## 核心原理（大二能懂的水平）
- pygame 像一个"舞台搭建工具箱"：SDL 是底层木工（管图形、音频、事件），pygame 给你递上已经锯好的木板（窗口、画布 Surface、事件队列）。
- 你 `import pygame` → `pygame.init()` 初始化 → 拿到一块画布 `pygame.display.set_mode((宽,高))`，之后每帧往画布上画、再 `flip()` 把画布贴到屏幕上。

## 关键参数 / 易错点
- **忘记 `pygame.init()`**：很多模块（字体、混音）不会自动初始化，会报奇怪的错。
- **画面不刷新**：画完忘了 `pygame.display.flip()` 或 `update()`，窗口永远空白。
- **坐标系统**：原点 `(0,0)` 在**左上角**，y 轴**向下**增大（和数学坐标系相反），新手极易把上下搞反。
- **阻塞调用**：在循环里用 `time.sleep()` 会让整个游戏卡住，应该用 `pygame.time.Clock.tick(FPS)` 控制节奏。

## 类比（帮助理解）
- 装好 pygame，等于拿到一个"画板 + 画笔 + 定时器 + 键盘监听器"套装，你只要决定每帧画什么、听到什么键就做什么。

## 设计时怎么用（反推思维）
> 做 2D 小游戏 / 交互式可视化原型时，我会用 pygame 快速出画面和手感；如果需要 3D、复杂物理或联网对战，再考虑专业游戏引擎（如 Unity、Godot），而不是硬扛 pygame。

## 典型应用 / 我在哪见过
- 贪吃蛇、打砖块、飞机大战、弹球、文字冒险 + 图形的小 demo。
- 也常用于"算法/物理的可视化"（比如排序动画、质点运动）。
