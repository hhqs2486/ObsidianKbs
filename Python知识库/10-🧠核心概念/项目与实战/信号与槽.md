# 信号与槽

## 一句话定义
信号与槽（Signals and Slots）是 Qt / PyQt 提供的「高级通信机制」：控件在状态变化时**发出信号（signal）**，你把一个**槽（slot，本质是可调用对象）**连到信号上，信号一触发槽就自动被调用。

## 它解决什么问题 / 为什么存在
- 用户点按钮、勾复选框、拖动滑块……底层会产生一大堆原始事件（鼠标坐标、按键状态、时间戳）。但程序员绝大多数时候**只关心「发生了什么」，不关心「怎么发生的」**。
- Qt 是第一个把这种需求抽象成「信号（宣布发生了什么）+ 槽（收到后做什么）」的 GUI 库，让界面逻辑从繁琐的底层事件处理里解放出来。
- 它是 [[Qt事件循环]] 之上的「高级层」；底层事件处理另见第 10 章（本书）。

## 核心原理（大二能懂的水平）
- 每个 QObject（包括所有控件，因为都继承自 QWidget→QObject）都能**发信号**、**收信号到槽**。
- 控件有一组预定义信号，比如按钮 clicked、复选框 toggled、滑块/数字框 `valueChanged(int)`。
- 默认情况下信号**发出后没人理会被直接丢弃**；你必须用 `connect` 把它连到某个槽才有反应。
- 在 PyQt 里，槽**可以是任何 Python 可调用对象**（函数、方法、lambda），不像 C++/Qt 那样要特殊声明——更灵活。
- 一个信号可以连多个槽；一个槽也能被多个信号连。信号还能带参数传给槽（如 `valueChanged(20)` 把新值 20 传进去）。

本书 PyQt4 的经典写法（两个控件互相同步）：
```python
self.connect(dial, SIGNAL("valueChanged(int)"), spinbox.setValue)
self.connect(spinbox, SIGNAL("valueChanged(int)"), dial.setValue)
```
现代 PyQt6 / PySide6 推荐「对象式」写法（无需字符串宏）：
```python
dial.valueChanged.connect(spinbox.setValue)
spinbox.valueChanged.connect(dial.setValue)
```
- **防无限循环**：`valueChanged` 只在值真的变化时才发。上面 dial 设成 20 → spinbox 收到设成 20 → spinbox 值没变就不重发，循环自然断掉。

## 关键参数 / 易错点
- **信号签名要对上槽**：参数类型必须匹配。不能把 `valueChanged(int)` 连到只接受字符串的 `setText(QString)`。
- **槽参数可以比信号少**，多出来的会被丢弃；但不能比信号多。
- 连 Qt 自带槽时用 `SLOT()` 更高效；连普通 Python 方法直接传函数/方法名即可。
- 现代写法优先用 `signal.connect(slot)`；本书的 `SIGNAL("xxx(int)")` 字符串宏在新版已不推荐、易拼错。
- 槽里不要执行**长时间阻塞**操作，否则会卡住 [[Qt事件循环]]，界面「假死」。

## 类比（帮助理解）
把控件想成公司的「通知喇叭」（信号），把你的处理函数想成「接到通知要去做的事」（槽）。喇叭响了（按钮被点），连在它上面的部门（槽）就自动行动；没连线的喇叭，响了也没人听（信号被丢弃）。一个喇叭可以通知多个部门，一个部门也能同时听多个喇叭。

## 设计时怎么用（反推思维）
> 做界面时，我会先列出「用户能触发哪些动作」（点保存、改数值、切选项），对每个动作找到对应控件的信号，再写对应的槽函数处理业务——**界面和逻辑通过 connect 解耦**，控件只管发信号，业务只管收信号做事。

## 典型应用 / 我在哪见过
- 本书第 4 章：QDial 与 QSpinBox 双向同步；第 5–6 章所有对话框 / 主窗口的按钮、菜单动作都靠信号槽响应。
- 实际：登录按钮 clicked→校验账号；滑块 valueChanged→实时更新图表；菜单「打开」triggered→弹文件对话框。
