# 异步编程asyncio

## 一句话定义
> `asyncio` 是 Python 3.4+ 标准库里的**异步 I/O 框架**:用 `async def` 定义协程、用 `await` 在 I/O 等待时让出控制权,由一个**事件循环**([[事件循环]])在单线程内调度成千上万个并发任务,专治 I/O 密集型慢。

## 它解决什么问题 / 为什么存在
- 见 [[并发模型]]:每次网络/文件 I/O 都会陷入“I/O 等待”,串行代码把这段时间全浪费了。`asyncio` 让你在等 A 的响应时去发 B、收 C,把空洞填满。
- 它把 gevent、tornado 等第三方方案的底层**事件循环统一化**,并提供与标准库一致的熟悉 API,是 Python 异步编程的官方正路。

## 核心原理(大二能懂的水平)
- **协程**([[协程]]):用 `async def` 定义的函数,遇到 `await 某异步操作` 就暂停,把 CPU 让给事件循环去跑别的协程;等操作完成,再回到暂停点继续。这是“协作式多任务”,非抢占式。
- **事件循环**([[事件循环]]):`asyncio.get_event_loop()` 拿到循环,`loop.run_until_complete(协程)` 启动并跑完。循环内部维护“待运行函数队列”,谁该跑就跑谁。
- **future / Task**:异步函数返回的是一个“将来会有值”的承诺;用 `asyncio.as_completed(tasks)` 或 `await future` 等结果就绪。
- 关键写法(书里爬虫示例):
  - 用 `asyncio.Semaphore(n)` 限制并发连接数(本书实证 ~100 最优),避免事件循环过载。
  - `yield from`(Python 3.4)/`await`(3.5+)把协程串起来,代码读起来接近串行,比回调地狱好维护。
- 生态:底层 socket API 很全但没有简单 HTTP 客户端,实战常配 `aiohttp`;asyncio 还能让 tornado/gevent 跑在**同一个事件循环**上,切换成本极低。

## 关键参数 / 易错点
- `asyncio` 只在 **Python 3.4+** 可用;旧代码多用 gevent/tornado。
- `requests` 不支持 `async/await`,异步 HTTP 必须用 `aiohttp` 等。
- 异步里用阻塞调用(如 `time.sleep`、纯 CPU 重算)会卡住整个循环——CPU 重活要用 `loop.run_in_executor()` 丢给线程/进程池,或改用 [[multiprocessing模块]]/[[Cython]]。
- 并发连接数不是越多越好:本书实验显示约 100 时最优,过多反而因上下文切换拖慢。

## 类比(帮助理解)
- 像一个只有一个厨师的厨房:厨师煮 A 的汤时(等水开=I/O 等待)不干瞪眼,转身去切 B 的菜;汤好了(事件触发)再回来撇沫。`await` 就是“先把锅放着,我去忙别的”。

## 设计时怎么用(反推思维)
> 做“高并发网络请求 / 高吞吐 API 聚合”时,我会用 **asyncio + aiohttp** 在单线程里并发成百上千连接,并用 `Semaphore(100)` 节流;若其中夹带本地大量计算,则把计算部分用 `run_in_executor` 丢给进程池,以免阻塞事件循环。

## 典型应用 / 我在哪见过
- 本书 ch08.5 的 asyncio HTTP 爬虫:与 gevent/tornado 同量级提速(串行 50s → 异步约 0.7s)。
- 高性能 Web 服务、实时数据处理管道、爬虫并发请求。
