# 调试器

## 一句话定义
> 调试器（Debugger）是**一个能挂住正在运行的程序、查看/修改它的内存和寄存器、单步执行指令的工具**；在安全与逆向里，它是看清程序真实运行时行为的“显微镜”。

## 它解决什么问题 / 为什么存在
- 光看反汇编（见 [[逆向工程]]）看不到“运行时”发生了什么：变量值、寄存器、内存布局。调试器让你在真实执行中观察。
- 找崩溃现场、定位漏洞触发点（配合 [[漏洞利用]] [[缓冲区溢出]]）、写脱壳/反反调试脚本都需要它。
- 本书用 Python 造调试器：自己实现断点、单步、异常处理，把“黑盒”变成可控的实验台。

## 核心原理（大二能懂的水平）
- 操作系统提供“调试接口”（Windows 的 debugging API、Linux 的 `ptrace`）：调试器把目标挂为“被调试进程”，操作系统会把目标发生的异常（断点命中、单步完成、崩溃）先“截胡”交给调试器处理。
- 软件断点：把目标指令首字节临时改成 `0xCC`(int3)，命中再改回去并让程序停下。这就是“在书页某行贴个书签，翻到就暂停”。
- Python 这里做“控制面”：PyDbg、Immunity Debugger 的 Python 接口、自己写调试器脚本都靠 Python 调度这些系统调用（见 [[标准库]] 的 `ctypes` 调 Windows API）。

## 关键参数 / 易错点
- 易错点：把“调试器(进程级)”和 Python 的 `pdb`([[调试(pdb)]]) 混为一谈——pdb 调的是 Python 字节码/源码行，这里调的是机器码/进程，目标完全不同。
- 易错点：反调试会让程序检测到自己被挂调试器就改行为/退出，需要绕过。
- 易错点：32 位与 64 位、不同 Windows 版本的 API 偏移不同，脚本不能一套通吃。

## 类比（帮助理解）
- 像给一台运转中的机器接上“透视仪+暂停键”：平时只能看外壳，调试器能让你喊“停”，然后掀开盖子看齿轮（寄存器）和油箱（内存）现在是什么状态。

## 设计时怎么用（反推思维）
> 做安全工具/分析样本时，我会用 Python 调试器脚本：先下断点定位关键函数入口，命中后 dump 出寄存器与内存片段，再判断是否进入崩溃路径；配合 [[逆向工程]] 反推漏洞偏移。业务侧也可用于“崩溃必现但日志不够”的疑难定位。
