# 恶意代码分析

## 一句话定义
> 恶意代码分析（Malware Analysis）是**在不“中招”的前提下，研究病毒/木马/勒索软件到底干了什么、怎么传播、怎么清除**。

## 它解决什么问题 / 为什么存在
- 出了安全事件，得知道“它偷了什么、连了哪台服务器、怎么自启动”，才能清理和写防御规则。
- 分两派：**静态分析**（不运行，看文件/反汇编，见 [[逆向工程]] [[反编译]]）和**动态分析**（在隔离沙箱里跑，观察行为）。

## 核心原理（大二能懂的水平）
- 静态：像拆信不拆封——扫文件头、找可疑字符串（[[字符串]]）、查导入表，判断它想干啥。
- 动态：把样本关进“玻璃房”（虚拟机/沙箱）让它跑，用工具抓它改了哪些注册表、发了哪些网络请求（配合 [[网络安全]]、[[加密与哈希]] 算哈希做样本指纹）。
- Python 常写自动化：批量算哈希、解析 pcap 流量、和 VirusTotal 类接口联动。

## 关键参数 / 易错点
- 易错点：分析真样本**绝不在本机/生产网跑**，必须用断网的隔离虚拟机，否则变“投毒现场”。
- 易错点：样本有反调试/反沙箱（检测到虚拟机就装死），需要绕过技巧。
- 易错点：动态分析只看一眼就下结论，可能漏掉“定时/条件触发”的行为。

## 类比（帮助理解）
- 像法医验尸：不碰活体（隔离），从痕迹（文件改动、网络包）还原案发经过。

## 设计时怎么用（反推思维）
> 做安全产品时，我会把“样本哈希 + 行为特征”沉淀成检测规则；平时写业务代码也留意 [[恶意代码分析]] 暴露的常见手法（比如下载执行、计划任务自启动），别让自己的程序成为跳板。
