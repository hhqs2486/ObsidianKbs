# 渗透测试

## 一句话定义
> 渗透测试（Penetration Testing）是**在授权前提下，模拟黑客的攻击手法去打自己的系统**，找出能被利用的弱点并修复，而不是真的搞破坏。

## 它解决什么问题 / 为什么存在
- 上线前没人知道系统“到底能不能被打穿”。渗透测试用**攻击者视角**把漏洞提前暴露出来，给防御方一张真实的“伤口清单”。
- 合规要求（等保、PCI-DSS 等）也常强制要求定期做。

## 核心原理（大二能懂的水平）
- 把系统想象成一座银行金库：门、窗、通风口、监控、员工。渗透测试就是请一个“白帽锁匠”，在行长同意下，试着用各种办法进金库——撬锁、伪装成员工、骗过监控——把能进的路都记下来。
- 标准流程（PTES）大致是：**侦察 → 扫描 → 拿权限 → 维持权限 → 清理痕迹 → 出报告**。Python 常用来写脚本自动化每一步（比如批量扫端口、爆破密码）。

## 关键参数 / 易错点
- **必须先有书面授权**：没授权的扫描/攻击就是违法（非法侵入计算机信息系统），哪怕只是“试试”。
- 易错点：把“渗透测试”和“红队演练”混为一谈——前者聚焦找漏洞，后者聚焦模拟真实对抗、绕过防御。
- 易错点：只在测试环境打，别误伤生产库；脚本里的目标 IP 写错会扫到别人。

## 类比（帮助理解）
- 像体检：医生（你）用各种仪器（工具/脚本）检查身体（系统），目的是早发现早治疗，不是让你生病。

## 设计时怎么用（反推思维）
> 做一套对外服务（Web/API）时，我会先画“攻击者地图”：暴露了哪些端口、哪些接口接收用户输入，然后用 Python 脚本（参考 [[网络安全]]、[[SQL注入]]、[[XSS跨站脚本]]）把常见攻击路径自动化跑一遍，把结果整理成修复清单再上线。

## 典型应用 / 我在哪见过
- 本书第 2 章“用 Python 进行渗透测试”：用 socket/requests 写端口扫描、服务识别、弱口令爆破脚本。
- 内网资产清点、Web 漏洞扫描器（如自己拼装 sqlmap 思路）。
