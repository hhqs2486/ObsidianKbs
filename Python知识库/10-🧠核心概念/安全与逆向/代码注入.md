# 代码注入

## 一句话定义
> 代码注入（Code Injection，典型如 DLL 注入）是**把一段自己的代码“塞进”另一个正在运行的进程地址空间里执行**，让它替你干活或被你操控。

## 它解决什么问题 / 为什么存在
- 想在某个进程内部运行你的逻辑（比如挂 [[钩子]]、读取它的内存、调用它的内部函数），但进程不是你启动的、也没有源码——注入是“打进去”的手段。
- 调试/沙箱/挂钩常在注入的 DLL 里完成；攻击侧则是把恶意载荷运进目标进程（配合 [[漏洞利用]] [[缓冲区溢出]]）。
- 本书第 7 章专讲 DLL 注入与代码注入技术，是调试器/钩子的“投递方式”。

## 核心原理（大二能懂的水平）
- 进程之间内存隔离。注入就是先“合法”地让目标进程开辟一块内存、写入你的代码、再创建一个远程线程去执行它（Windows 的 `VirtualAllocEx`/`WriteProcessMemory`/`CreateRemoteThread` 一套）。
- DLL 注入：让目标“自己 LoadLibrary 加载我的 dll”，借它的手把我的代码挂进去——像让仓库管理员（目标进程）帮忙把你的工具箱搬进仓库。
- 与 [[缓冲区溢出]] 的关系：溢出是“利用缺陷强行写入并执行”，注入是“借系统合法 API 写入并执行”，前者是漏洞利用、后者是技术手法。

## 关键参数 / 易错点
- 易错点：注入 DLL 位数必须与目标进程一致（32/64 混写直接失败或崩）。
- 易错点：注入代码里用了目标进程没有的库/路径，会加载失败。
- 易错点：杀软/EDR 把“远程线程注入”视为恶意特征，会被拦。

## 类比（帮助理解）
- 像把一封“委托信”塞进别人的笔记本里，让他翻到那一页时不自觉地按你写的做。注入是“塞信”的动作，钩子是“信里让他干什么”。

## 设计时怎么用（反推思维）
> 做进程内监控/测试工具时，我用 Python + `ctypes`（[[标准库]]）走合法注入 API 把探针 DLL 送进目标；同时明白这是高敏感操作，只在自己拥有/授权的进程上做，并在 [[认证授权]] 边界内使用。

## 典型应用 / 我在哪见过
- 本书第 7 章“DLL注入与代码注入技术”。
- 调试辅助、游戏模组、沙箱探针；攻击侧为恶意载荷落地手段。
