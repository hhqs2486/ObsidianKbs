# XSS跨站脚本

## 一句话定义
> XSS（Cross-Site Scripting，跨站脚本）是**把恶意 JavaScript 注入到网页里，在别的用户浏览器上执行**，从而偷 cookie、伪造操作。

## 它解决什么问题 / 为什么存在
- 攻击者借此“借用户身份办事”：盗会话、钓鱼、蠕虫传播。它和 [[SQL注入]] 是 Web 安全双璧，但一个打数据库、一个打浏览器。
- 根因：把用户输入**原样塞进 HTML 页面**且没转义。

## 核心原理（大二能懂的水平）
- 存储型：恶意脚本存进数据库，别人打开页面就中招（如评论区）。反射型：骗你点带恶意参数的链接。DOM 型：纯前端 JS 处理不当。
- 例子：评论框输入 `<script>窃取cookie发给黑客</script>`，页面没过滤就执行了。
- 防御：输出到 HTML 时**转义特殊字符**（`<` `>` `&` `'` `"`）、用 CSP（内容安全策略）限制脚本来源、重要 cookie 设 HttpOnly。

## 关键参数 / 易错点
- 易错点：只在输入时过滤，输出到不同上下文（HTML/JS/URL）转义规则不同，必须“按输出位置转义”。
- 易错点：以为 `innerHTML` 拼接用户输入没事——正是 XSS 温床，用 `textContent`。
- 易错点：富文本场景一刀切转义会破坏功能，需白名单标签过滤。

## 类比（帮助理解）
- 像在公告栏贴通知，你贴的“通知”里夹了张“自动帮人签字的纸条”，每个看公告的人都被悄悄签了字。

## 设计时怎么用（反推思维）
> 做前端/模板渲染时，我默认所有用户数据不可信：模板自动转义、JS 里用 `textContent` 而非 `innerHTML`、配合 CSP 与 HttpOnly cookie；后端也对输入做 [[正则表达式]] 校验，多层防护（见 [[网络安全]]）。
