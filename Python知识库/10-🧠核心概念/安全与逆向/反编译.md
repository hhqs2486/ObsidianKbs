# 反编译

## 一句话定义
> 反编译（Decompilation）是**把机器码/字节码自动还原成高级语言（如近似 C/Python）源码**的过程，是 [[逆向工程]] 里“自动化还原”的那一步。

## 它解决什么问题 / 为什么存在
- 人读汇编太累。反编译器直接给你一份“能大致看懂”的伪源码，省去大量手工还原。
- 对 Python 特别友好：`.pyc` 字节码保留了大量结构（常量、变量名），工具如 `uncompyle6`/`decompyle3` 能高还原度回退源码。

## 核心原理（大二能懂的水平）
- 编译器把“高级语言 → 低级表示”会丢信息（注释、宏、某些类型）。反编译器反向建一个“语义等价但更友好”的程序：先做控制流分析，再按规则把每条指令映射回高级表达式。
- Python 的 `.pyc` 里有 `co_code`（字节码）和常量表，反编译就是解释这套字节码；参考 [[导入系统]] 里关于 `.pyc` 缓存的说明。

## 关键参数 / 易错点
- 易错点：反编译结果“等价但不相同”——变量名、循环写法可能变，不能当原始源码直接用。
- 易错点：加壳/混淆/控制流平坦化会让反编译器崩或产出乱码，需先脱壳。
- 易错点：Python 版本要匹配，3.8 的 `.pyc` 用错版本工具解不出。

## 类比（帮助理解）
- 像把做好的菜（机器码）对照食谱还原成“大概的菜谱”（伪源码）；能复刻味道，但原厨师的独家备注没了。

## 设计时怎么用（反推思维）
> 怀疑同事留下的 `.pyc` 里有硬编码密钥时，我会用反编译工具还原成 `.py` 检查，再顺着 [[加密与哈希]]、[[认证授权]] 的思路整改；同时提醒：敏感逻辑别只靠“编译了别人就看不到”。
