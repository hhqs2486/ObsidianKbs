# 钩子

## 一句话定义
> 钩子（Hook）是**在程序原本的执行流程里“偷偷插一脚”的技术**：不改原程序源码，也能在函数被调用前后截获、查看甚至篡改它的参数和结果。

## 它解决什么问题 / 为什么存在
- 想监控某个系统函数（如 `CreateFile`、`send`）每次被调用时的参数，但拿不到源码——钩子让你“站在函数门口当门卫”。
- 逆向/病毒分析里用来记录样本的行为（它读了哪些文件、发了什么网络包）；也用于沙箱、输入法、屏幕取词等合法场景。
- 本书第 6 章用 Python 在 Windows 上挂钩子，把“看不见的内部调用”变成可读的日志。

## 核心原理（大二能懂的水平）
- 函数调用都要经过一块固定内存地址。钩子把这块地址开头的几条指令，临时换成“跳转到我的代码”的跳转指令；我的代码执行完，再执行被换掉的原指令，跳回去。程序浑然不觉。
- 类比：在自来水总管上接一个分流表——水（数据）照样流，但你能顺手测水质、记水量，再放它继续走。
- 与 [[调试器]] 的区别：调试器靠“暂停+单步”，钩子靠“常驻拦截、不打断整体流程”，更适合批量、长期监控。

## 关键参数 / 易错点
- 易错点：钩子代码本身不稳会让目标崩（你改了入口，自己又写得不对）。需保证“跳过去→做完→跳回来”原子正确。
- 易错点：不同位数/调用约定（stdcall/cdecl）的钩子写法不同，错则函数栈错乱。
- 易错点：反钩子/完整性校验会检测正文被改，需要绕过或先 dump。

## 类比（帮助理解）
- 见“总管分流表”。核心：不动原结构，在必经之路上插一个观察/干预点。

## 设计时怎么用（反推思维）
> 做行为监控/沙箱时，我用 Python 钩住关键 API，把每次调用的参数落盘成审计日志（配合 [[恶意代码分析]] [[网络安全]]）；也提醒自己：正式产品里的钩子要可卸载、不影响性能，别变成隐蔽后门。
