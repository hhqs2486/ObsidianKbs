# 逆向工程

## 一句话定义
> 逆向工程（Reverse Engineering）是**从已经编译好的程序（机器码/字节码）倒推出它的设计、逻辑和行为**，因为通常拿不到源代码。

## 它解决什么问题 / 为什么存在
- 没有源码也要搞清楚一个程序在干嘛：分析恶意软件、审计闭源软件的安全缺陷、做兼容性/互操作、找漏洞偏移（配合 [[漏洞利用]]）。
- 也是软件破解、协议还原的常见手段（注意法律边界：只对自己的/授权的软件做）。

## 核心原理（大二能懂的水平）
- 正常开发是“源码 → 编译器 → 机器码”。逆向是反过来：把机器码喂给反汇编器/反编译器（如 IDA、Ghidra、objdump），还原成汇编甚至近似 C 的伪代码，再人肉读逻辑。
- Python 在这里常做“胶水”：解析二进制格式、批量处理样本、写 IDA/Ghidra 插件脚本（IDA 用 Python 写脚本很常见）。

## 关键参数 / 易错点
- 易错点：混淆/加壳会让反汇编出来的东西一团乱，需要先 [[反编译]]/脱壳。
- 易错点：同名函数被编译器内联、变量名丢失，得靠行为推断，不能指望完美还原源码。
- 易错点：只盯着汇编容易迷路，先抓“输入→输出”和关键字符串（[[字符串]]）更高效。

## 类比（帮助理解）
- 像拆一台不附说明书的机器：你拧开外壳（反汇编），看齿轮怎么咬合（控制流），推测它原本的设计图（逻辑）。

## 设计时怎么用（反推思维）
> 拿到一个第三方 .so/.exe 想确认它有没有后门时，我会先查导入表/字符串（[[标准库]] 里用 struct 解析 PE/ELF 头），定位敏感函数，再用逆向工具跟一遍关键分支，必要时写 Python 脚本批量比对样本。
