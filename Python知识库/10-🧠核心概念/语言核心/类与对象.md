# 类与对象

## 一句话定义
> 类是你「自定义的一种数据类型（模板）」，对象是按这个模板造出来的**实例**；类把「数据（属性）」和「操作数据的函数（方法）」捆在一起，靠**多态、封装、继承**三大特性管理复杂度。

## 它解决什么问题 / 为什么存在
- 前面只有内置类型（数、列表、字典）和函数。但当“状态”和“操作”天然属于同一事物时（一只鸟会吃、会叫；一个购物车能算总价），用全局变量+散函数很容易乱（书里 `OpenObject` 用全局变量存名字，两个对象互相串味的反例）。
- 类让对象**自带状态**：`c.set_name('x')` 后 `c.get_name()` 还是 `'x'`，而另一个 `r` 不受影响——因为每个实例有自己的命名空间。
- 它把“对象魔法”拆成三件最实用的事：多态（不关心类型就能调方法）、封装（隐藏内部细节）、继承（少写重复代码）。

## 核心原理（大二能懂的水平）
- **对象 = 属性 + 方法**：属性是属于对象的变量，方法是存为属性的函数。关联方法第一个参数固定是 `self`（指向对象自己），调用 `foo.greet()` 等于 `Person.greet(foo)`。
- **类与实例**：`class Person:` 定义类；`p = Person()` 造实例。`issubclass` 查继承，`isinstance` 查实例归属，`__class__`/`type` 看类型。
- **多态**：不关心对象是什么类，只要它有某个方法就能调。`'abc'.count('a')` 和 `[1,2,'a'].count('a')` 都能用；`1+2` 与 `'a'+'b'` 都用 `+`（运算符也是多态）。本质是**鸭子类型**——“走起来像鸭子、叫起来像鸭子，就是鸭子”。书里强调：尽量别用 `type`/`isinstance` 做类型检查来破坏多态。
- **封装**：Python 没有强制私有，但约定：单下划线 `_x` 表示“别动”（`from mod import *` 不导入）；双下划线 `__x` 会名字改写成 `_类名__x`，从外部基本访问不到（但仍可强行访问，书里说“只是强烈信号”）。
- **继承**：`class SPAMFilter(Filter):` 让子类自动拥有父类方法，`SPAMFilter` 只需重写 `init` 把 `blocked=['SPAM']`。`issubclass`/`__bases__` 可查。`super()`（Python 3 直接 `super().__init__()`）用来调父类被重写的方法，避免重写构造函数时漏掉父类初始化（书里 `SongBird` 不调 `super` 会 `AttributeError: hungry`）。
- **魔法方法 / 构造函数**：`__init__` 在对象创建后自动调用，做初始化；`__del__` 析构尽量少用。序列/映射协议靠 `__len__/__getitem__/__setitem__/__delitem__`（见[[迭代器与生成器]]）。
- **特性 property**：用 `size = property(get_size, set_size)` 把“存取方法”伪装成普通属性，外部 `r.size=(150,100)` 实际走了 `set_size`。新式类优先用 property 而不是手写 get/set。
- **静态/类方法**：`@staticmethod` 无 self；`@classmethod` 第一个参数是 `cls`，可通过类或对象调用。
- **抽象基类 ABC**：`from abc import ABC, abstractmethod`，标记必须实现的抽象方法，类不可实例化，用于“定义接口契约”（`isinstance` 检查时才合理用）。

## 关键参数 / 易错点
- **`self` 不是关键字但必须有**：方法第一个参数习惯叫 `self`，指向实例；漏写会导致调用时参数错位。
- **`__init__` 重写必调 `super().__init__()`**：否则父类初始化没跑，访问父类属性就报错（书里 SongBird 经典坑）。
- **双下划线改名**：`self.__secret` 外部变成 `obj._类名__secret`，别指望真“看不见”，只是约定。
- **`isinstance` 慎用**：依赖多态优于类型检查；只有配合抽象基类 `abc` 时才推荐用。
- **多重继承 MRO**：多个父类同名方法，写在前面（左边）的覆盖后面的；顺序不对会叫错方法。书里建议“慎用多重继承”。

## 类比（帮助理解）
- 类像「图纸」，对象像「按图纸盖的房子」：`Bird` 是鸟类图纸，`b = Bird()` 是具体一只鸟；改一只鸟的名字不会影响另一栋“房子”。
- **多态**像“所有电器都有插头，你插上就能用，不用管它是电视还是冰箱”——你只管调用 `device.power_on()`。
- **继承**像“电动自行车继承自行车，多了电池和电机，但‘蹬’的方法直接沿用”，不用重写一遍蹬车逻辑。
- **property** 像“看着是个普通开关，背后其实连着一整套电路”——你 `r.size=...` 以为只是设值，其实触发了计算。

## 设计时怎么用（反推思维）
> 做 XX 系统时，我会用它能解决 YY：
> 做「智能小车运动控制系统」时，我会反推“哪些东西有状态、哪些行为各不相同”：把“电机”抽象成类 `Motor`（属性 `speed`，方法 `set_speed/stop`）；把不同运动模式做成子类——`Forward(Motor)`、`Rotate(Motor)` 继承同一个父类、各自重写 `move()`，主循环只写 `for m in modes: m.move()` 就实现**多态**；把“当前角度/电量”用 property 暴露成 `robot.heading`，外面读起来像普通属性但内部可能联动传感器。一句话：**先找‘名词（候选类）+ 动词（候选方法）’，再让相似类用继承去重，别用一个大字典硬扛所有状态**。
