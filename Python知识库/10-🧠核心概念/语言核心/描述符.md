# 描述符

## 一句话定义
> 描述符是一个「实现了 `__get__/__set__/__delete__` 中至少一个」的类，用来接管另一个类里某个属性的读取、赋值和删除行为——它是 Python 属性访问机制的底层。

## 它解决什么问题 / 为什么存在
- 普通属性 `obj.x = 1` 只是往 `__dict__` 里塞值，无法在「读取/赋值」时自动做校验、类型转换、延迟加载。
- 描述符把「属性的读写逻辑」外包给一个专门的类，从而写出干净、可复用的 API（如 `rectangle.width` 看起来像普通属性，背后却由 `width`/`height` 算出）。
- Python 内部的 `property`、`classmethod`、`staticmethod`、甚至函数绑定成方法，全靠描述符协议实现。

## 核心原理（大二能懂的水平）
- 描述符协议三个特殊方法：`__get__(self, obj, objtype)`、`__set__(self, obj, val)`、`__delete__(self, obj)`。
- 同时实现 `__get__`+`__set__` 叫**数据描述符**；只实现 `__get__` 叫**非数据描述符**。
- 每次访问 `instance.attr`，底层 `__getattribute__` 按固定顺序查找：
  1. 是不是类上的**数据描述符**？→ 优先用它的 `__get__`
  2. 否则看 `instance.__dict__` 里有没有这个属性
  3. 最后看类上的**非数据描述符**
- 关键推论：数据描述符 > 实例 `__dict__` > 非数据描述符。
- 非数据描述符优先级低于 `__dict__`，这正是「猴子补丁（monkey-patching）能运行时替换方法」的原因（函数对象是非数据描述符）。
- 实用例子：懒加载描述符（首次访问才真正初始化对象），以及 `lazy_property`（装饰器+数据描述符，函数只执行一次后把结果写回实例属性）。

## 关键参数 / 易错点
- 数据 vs 非数据描述符的优先级差异，是 99% 相关 bug 的来源。
- 用 `property` 装饰器写属性时，子类想覆写父类的 `fget` 必须**整段重写 property**，否则用的是父类的方法（因为 property 在类定义时实时绑定）。
- 描述符影响的是「类最基本的行为（属性访问）」，团队里所有人都要懂，否则会一头雾水。

## 类比（帮助理解）
- 像物业管家：你（实例）想拿信箱（属性），不是直接开箱，而是管家（描述符）决定给你看什么、收你什么、是否登记。
- 像银行柜台：存钱取钱表面是你自己操作，背后有柜员（描述符）做校验、记账。

## 设计时怎么用（反推思维）
> 做「ORM 模型 / 配置对象」系统时，我会用 **描述符** 解决「字段赋值要做类型校验、越界拦截、懒加载」的问题——把每个字段定义成一个描述符类，用户写 `user.age = 200` 时自动抛错，而不用在每个 setter 里手写 if。
