# 模块与包

## 一句话定义
> **模块** = 一个 `.py` 文件（变量/函数/类的容器）；**包** = 含 `__init__.py` 的目录（可装多个模块）。`import` 把它们“拼”进你的程序，解决“代码复用”和“命名空间管理”。

## 它解决什么问题 / 为什么存在
- 书里 10.1：「把代码放在模块里，就能在多个程序重用」。否则同一个客户数据库要在记账、发邮件等每个程序里重写一遍。
- 模块有**自己的作用域**：模块里定义的名称都成它的属性（`hello2.hello()`），不同模块的同名函数互不打架。
- 包解决“模块太多怎么归类”：像 `drawing/colors.py`、`drawing/shapes.py` 归到 `drawing` 包下，避免名字冲突、方便组织大项目。

## 核心原理（大二能懂的水平）
- **导入即执行**：`import hello` 会执行模块顶层代码（所以书里第一个 `hello.py` 打印了 "Hello, world!"），但**只执行一次**——重复 import 不动。这靠“模块缓存”打破循环导入（A 导入 B、B 导入 A 不会死循环）。
- **导入语法**：
  - `import 模块` → 用全名 `模块.东西`。
  - `from 模块 import 名字` → 直接用 `名字`（可能覆盖本地同名）。
  - `from 模块 import *` → 导入 `__all__` 列出的公有名（没设 `__all__` 就导入所有非下划线名）。
  - `import 包` 只执行包里 `__init__.py`；`import 包.模块` / `from 包 import 模块` 进一步取子模块。
- **`__name__`  trick**：模块被导入时 `__name__ == 模块名`，被直接运行时 `__name__ == '__main__'`。所以测试代码应包在 `if __name__ == '__main__':` 里——当模块时被忽略，当程序时才跑（书里 `hello4.py` 范例）。
- **模块放哪能被找到**：解释器查 `sys.path`（字符串目录列表）。标准做法放 `site-packages`，或把目录加进环境变量 `PYTHONPATH`，或用 `.pth` 路径配置文件。也可运行时 `sys.path.append(...)`（不持久）。
- **包结构**：目录里必须有 `__init__.py` 才被当包；里面写的代码就是“包的内容”（如 `constants/__init__.py` 里 `PI=3.14`，`import constants` 后能用 `constants.PI`）。包里还能嵌套包。
- **重新加载**：改了模块用 `importlib.reload(模块)` 热更；但已存在的实例还是旧类的对象，得手动重建。
- **探索模块**：`dir(模块)` 列属性、`模块.__all__` 看公有接口、`help(模块)` 看文档、`模块.__file__` 找源码位置。

## 关键参数 / 易错点
- **`import` 只跑一次**：以为改了模块没生效——八成是没 reload 或解释器缓存了。
- **`from x import *` 污染命名空间**：可能覆盖你已有的变量；大项目尽量写全名或显式 `from x import 需要的`。
- **`__name__` 没包测试**：把 `hello()` 直接写在模块顶层，一 import 就执行副作用（打印/写文件）。
- **包忘了 `__init__.py`**：旧式包会被当普通目录，import 报找不到。
- **循环导入**：虽然 Python 靠“只导入一次”兜底，但设计上仍应尽量让依赖单向。
- 想“发给别人、装到环境里”属于[[包管理pip]]和[[虚拟环境]]（归二拥有，本书第18章打包只点到 Setuptools，不展开）。

## 类比（帮助理解）
- 模块像「一个工具箱」：你 `import` 把它搬进工地，里面的扳手（函数）得用 `工具箱.扳手()` 取；包像「带隔层的工具柜」，每层（子模块）分门别类。
- `if __name__ == '__main__':` 像“这把螺丝刀既能在流水线上当零件用（被 import），也能单独拿出来当样品演示（直接运行）”——演示代码只在单独拿出来时才跑。

## 设计时怎么用（反推思维）
> 做 XX 系统时，我会用它能解决 YY：
> 做「课程实验数据采集平台」时，我会反推“哪些功能要被多个脚本共用、哪些该隔离”：把“串口读取”封成 `drivers/serial_reader.py`、“滤波算法”封成 `algorithms/filter.py`，统一放进包 `labkit/`（带 `__init__.py`），主脚本 `from labkit.serial_reader import read_frame`。每个模块末尾用 `if __name__=='__main__':` 写自测，方便单独调试又不影响被 import。一句话：**先按“功能边界”切模块/包，再用 import 组装，而不是把所有代码堆在一个巨文件里**。

## 典型应用 / 我在哪见过
- 书里：`hello.py`→`hello4.py`（__name__ 技巧）、`constants` 包（`__init__.py` 存常量）、`drawing` 包（colors/shapes 子模块）。
- 与[[标准库]]的关系：math/os/sys 等都是现成模块，直接 import 用；与[[函数基础]][[类与对象]]的关系是模块是它们的“装载容器”。
