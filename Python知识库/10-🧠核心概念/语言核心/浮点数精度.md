# 浮点数精度 (数值计算常见坑)

## 一句话定义
> 计算机用有限位（通常约 16 位十进制有效数字）表示实数，绝大多数小数只能「近似存储」，由此产生的微小误差会在连续计算中累积、传播，称为「舍入误差（round-off error）」。

## 它解决什么问题 / 为什么存在
科学计算本质是在做大量浮点算术。理解「为什么 1/49*49 不等于 1」「为什么积分结果是 -3.49e-16 而不是 0」，才能不被奇怪的尾巴数字吓到，也才能区分哪些是机器固有的舍入误差、哪些是真正的逻辑 bug。

## 核心原理（大二能懂的水平）
- 实数大多有无限位小数（如 1/49 = 0.0204081632…），但内存有限，只能截到约 16 位有效数字，多出来的被「四舍五入」丢掉。
- 于是 `1/49` 存的是近似值，再乘以 49 得到 `0.9999999999999999` 而非 `1.0`；而 `1/51*51` 误差恰好不显现为 `1.0`。
- 误差会沿算术链传播，最终答案只是「精确数学值」的近似。这类误差统称 round-off error。
- Python 有 `decimal` 模块可自定义精度减小舍入误差，但科学计算中算法本身（如离散差分）带来的误差通常远大于舍入误差，故不常用。

## 关键参数 / 易错点
- 整型除法陷阱（最经典）：Python 2 中 `9/5` 是整数除法得 `0`，写 `(9/5)*C+32` 会得到全 0 温度！必须写成 `9.0/5` 或 `float(C)*9/5` 触发浮点除法。Python 3 中 `/` 已是浮点除法，但混用历史代码仍要警惕。
- 不要直接对浮点结果做 `==` 精确相等判断：`0.1+0.2 == 0.3` 常为 `False`，应比较「差的绝对值小于容差」`abs(a-b) < 1e-9`。
- 别被 `-3.5e-16` 这种量级的结果吓到：它本质是 0，只是舍入误差；只要量级远小于真实值就可忽略。
- 大数减小数会丢精度（灾难性抵消），做差分式计算时要注意。

## 类比（帮助理解）
实数像一条无限长的小数尾巴，计算机是个只肯记 16 位的记事本，多写的都被橡皮擦掉——于是每次计算都带着一点点橡皮屑，算多了屑就堆成可见误差。

## 设计时怎么用（反推思维）
> 做数值积分/微分/方程求解时，我会预期结果带 ~1e-15 量级的尾差，输出/判等用容差比较而不是 `==`；公式里的常数一律写成浮点（`9.0/5`）避免整数除法，从需求（数值可靠）反推写法。

## 典型应用 / 我在哪见过
- 原书第 1 章：温度转换 `(9/5)*C+32` 在整数除法下的 bug，以及 `1/49*49` 得 `0.9999999999999999` 的演示。
- 原书命令行积分示例：`∫₀^{2π}(cos x+sin x)dx` 理论为 0，程序输出 `-3.48786849801e-16`，正是舍入误差。
- 离散微积分（附录 B）中讨论差商近似的 accuracy，常远大于舍入误差。
