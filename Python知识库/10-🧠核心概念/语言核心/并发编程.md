# 并发编程

## 一句话定义
> 并发（concurrency）是「让多个任务看起来/真正同时推进」的能力；Python 提供三条主流路线：**多线程（`threading`）、多进程（`multiprocessing`）、异步编程（`asyncio`）**。

## 它解决什么问题 / 为什么存在
- 单线程序列处理，受单核性能限制，且「上一个输入没处理完就接不了新输入」——高并发 Web、批量网络请求、响应式界面都扛不住。
- 当问题是「可拆成顺序无关的子单元」时，把它分到多个处理单元（核心/进程）就能缩短总耗时、保持响应。

## 核心原理（大二能懂的水平）
- **并发 ≠ 并行**：并发是「问题的属性」（子任务顺序无关），并行只是并发的一种实现手段。
- **多线程 `threading`**：
  - 线程共享同一内存，要加锁防竞态；不加锁会数据错乱，锁用错会死锁。
  - Python 有 **GIL（全局解释器锁）**：同一时刻只有一个线程跑 Python 字节码。所以纯 Python 计算用多线程**不能**利用多核；但**阻塞 I/O（网络/文件读写）会释放 GIL**，多线程对 I/O 密集型很有用。
  - 实战用**线程池**（`queue.Queue` + 固定数量 `Thread`），别无限制开线程；注意 `print` 在多线程里会串行化、外部 API 有速率限制（用令牌桶节流）。
- **多进程 `multiprocessing`**：
  - 独立进程**无 GIL**，真能用多核，适合 **CPU 密集型**；不共享内存，数据安全但通信要靠 `Queue`/`Pipe`/`sharedctypes`。
  - `Pool` 一行 `pool.map(func, items)` 搞定进程池，还能 `with` 用（见 [[上下文管理器]]）。
  - `multiprocessing.dummy` 提供**同款 API 但用线程**，方便在进程/线程间切换。
- **异步 `asyncio`**（Python 3.5+ `async`/`await`）：
  - 单线程内用**事件循环 + 协程**做「协作式多任务」：在 I/O 等待时 `await` 交出控制权，让别的协程跑（非抢占式）。
  - 适合大量并发连接（I/O 密集型）；注意 `time.sleep` 是阻塞的，要用 `await asyncio.sleep`。
  - 与同步/CPU 重活混用：`loop.run_in_executor()` + `concurrent.futures`（线程池/进程池）把阻塞调用伪装成可 await。
- GIL 只存在于 CPython/PyPy/Stackless；Jython、IronPython 没有。

## 关键参数 / 易错点
- GIL 是铁律：纯计算别指望多线程提速，上多进程或 C 扩展。
- 无限制开线程/进程会耗尽文件描述符/内存——永远用**池**（THREAD_POOL_SIZE / POOL_SIZE）。
- 多线程共享内存 → 必须锁；多进程不共享 → 必须 IPC。各有利弊。
- `requests` 库不支持 `async/await`，异步 HTTP 得用 `aiohttp`。
- 现实项目常**混合使用**（事件循环 + 多进程 worker + 线程），没有万能银弹，要按瓶颈选。

## 类比（帮助理解）
- 多线程=多个厨师共用一个厨房（共享冰箱/灶台，要抢位置、会撞车）；多进程=多个独立厨房（互不干扰但传菜麻烦）；异步=一个厨师在等水开时先去切菜（协作轮转，不空等）。
- GIL 像「厨房只有一把公共菜刀」：同一时刻只能一人用，I/O 等待（等水开）时把刀让出去。

## 设计时怎么用（反推思维）
> 做「同时抓取上千个网页/调用外部 API」的爬虫或聚合服务时，我会用 **并发编程** 解决「串行请求太慢、卡在等响应」的问题——I/O 密集型首选 `asyncio`+`aiohttp`（轻量高并发），或线程池；若是本地大量图片/视频转码这类 CPU 重活，改用 `multiprocessing.Pool`，绕过 GIL 吃满多核。
