# 运算符重载

## 一句话定义
> 运算符重载（operator overloading，书中称「重载操作符」）指通过实现对应的**魔术方法**（如 `__add__`、`__sub__`），让你的类对象也能使用 `+`、`-`、`*`、`len()` 等内建运算符——让自定义类型「表现得像 Python 内建类型」。

## 它解决什么问题 / 为什么存在
- 没有运算符重载，向量相加只能写 `v1.add(v2)`，既啰嗦又不符合直觉。
- 它让自定义类型无缝接入 Python 的运算符语法，代码更自然、可读性更高（书里称「模拟 Python 类型」）。

## 核心原理（大二能懂的水平）
- Python 的运算符本质是「语法糖 + 方法调用」：`a + b` 在背后调用 `a.__add__(b)`；`len(x)` 调用 `x.__len__()`。
- 常用运算符对应方法：`+ → __add__`、`- → __sub__`、`* → __mul__`、`/ → __truediv__`、`+= → __iadd__`、`== → __eq__`、`< → __lt__`、`len() → __len__`、索引 `x[i] → __getitem__`、`bool(x) → __bool__`/`__nonzero__`。
- 还可定制反向运算（如 `__radd__`，当左操作数不支持该运算时调用右操作数的方法）与增量赋值（`__iadd__` 等）。
- 注意：Python **不支持函数/方法重载**（不能靠参数不同定义多个同名函数），但「运算符重载」是另一回事——它指的是为类定义运算符对应的特殊方法。

## 关键参数 / 易错点
- 不要重载内建工厂名：`dict()`、`list()`、`type()` 等已成为内建类型/工厂，重载它们（定义同名类/函数）会带来麻烦与潜在 bug——编译器允许但你得「知道自己正在做什么」。
- 运算符方法应返回合理类型；例如 `__add__` 通常返回新对象而非原地修改（原地修改用 `__iadd__`）。
- 与「函数重载」区分：Python 无函数重载（书里明确），别混淆。

## 类比（帮助理解）
- 像给自定义「乐高块」装上标准卡扣：别人不用学新接口，直接用「拼（+=）」「数（len）」这些统一动作就能操作你的积木。
- 像给方言词配标准翻译：`+` 是通用词，你只需告诉 Python「对我的向量，+ 意味着逐分量相加」。

## 设计时怎么用（反推思维）
> 做「二维向量 / 复数扩展 / 货币类」时，我会用 **运算符重载** 解决「希望 `v1 + v2`、`-v`、`v * 2`、`abs(v)`、`v1 == v2` 直接用运算符表达」的问题——实现 `__add__/__sub__/__mul__/__abs__/__eq__`，让领域对象读起来像数学公式，业务代码更贴近人类直觉。
