# 函数基础

## 一句话定义
> 函数是「把一段操作打包、起个名字、需要时调用」的机制：用 `def` 定义，靠**参数**接收外部数据，用 `return` 把结果交回来；函数让你“只告诉计算机一次怎么做”，而不是到处重复。

## 它解决什么问题 / 为什么存在
- 书里第6章开头就说：程序小的时候无所谓，但大型程序里同一段逻辑（比如算斐波那契、下载网页算词频）会在多处用到。不抽象就只能到处复制粘贴，既难读又难改。
- 函数不只是“省事”：它让程序**能被人理解**——人看 `download_page() / compute_frequencies()` 一眼就懂主流程，至于“怎么下载、怎么统计”的细节藏在函数体里（书里 6.2「抽象和结构」的核心观点）。
- 它还带来**作用域隔离**：函数内的变量默认是局部的，互不干扰（见[[控制流]]之后自然会需要）。

## 核心原理（大二能懂的水平）
- **定义**：`def 名字(形参):` 冒号后缩进写函数体。形参 = 定义时的变量；实参 = 调用时给的值。
- **返回值**：没有 `return` 或 `return` 后没值，函数返回 `None`。所以“所有函数都返回值”，只是很多时候是 `None`——书里警告：在 `if` 分支里 return 时务必保证**所有分支都有返回值**，否则调用方期待拿到列表却拿到 `None`。
- **文档字符串**：函数体第一个字符串是 docstring，存为 `.__doc__`，`help(函数)` 会读它。比 `#` 注释强：能运行时查看。
- **参数四大玩法**：
  - 位置参数：`hello(greeting, name)`，位置比名字重要。
  - 关键字参数：`hello(greeting='Hi', name='x')`，顺序无所谓，还能给参数设默认值 `def f(name, greeting='Hello')`。
  - 收集参数：`def f(*params)` 把多余位置参数收进**元组**；`def f(**params)` 把多余关键字参数收进**字典**。可组合 `def f(x, y, z=3, *pos, **kw)`。
  - 分配参数：调用时 `f(*tuple)` 把元组拆开传位置，`f(**dict)` 把字典拆开传关键字（与收集相反）。
- **作用域**：变量本质是“指向值的名字”，存在看不见的字典（命名空间）里。除全局作用域外，**每次函数调用都新建一个局部作用域**。`global x` 声明要改全局变量；嵌套函数里用 `nonlocal` 改外层（非全局）变量。**闭包** = 嵌套函数“携带自己定义时的环境”，如 `multiplier(2)` 返回记住了 `factor=2` 的函数。
- **递归**：函数调用自己。必须有**基线条件**（最小问题直接返回）和**递归条件**（把问题拆小再调自己）。书里例子：阶乘、幂、二分查找（已排序序列中找数，每次把区间减半，100 个数只需问 7 次，10^29 个数也才约 117 次）。
- **函数式工具**：`map(func, seq)` 把函数映射到每个元素；`filter(func, seq)` 按布尔函数过滤；`reduce(func, seq)` 从左到右两两合并（来自 `functools`）。`lambda` 写匿名小函数。书里建议：map/filter 大多可用**列表推导**替代，可读性更高；reduce 用得少。

## 关键参数 / 易错点
- **`None` 陷阱**：忘了 return，`x = test()` 得到 `None` 却以为拿到了数据。
- **参数为可变对象时会被改**：传列表进函数，函数内 `lst[0]=...` 会改到外面的列表（因为传的是引用）。想保护原数据就传副本 `change(lst[:])`。数/字符串/元组不可变，重新赋值只是让局部名指向新对象，不影响外部。
- **`*` 收集 vs 分配**：定义用 `*`（收集成元组），调用用 `*`（拆开）。`def f(a, *b, c)` 时 `c` 必须关键字传，否则 `TypeError`。
- **`global` 滥用是 bug 源**：书里明确“慎用全局变量”，读全局没事，重新关联全局变量要用 `global` 且容易踩坑；更干净的做法是 `return` 修改后的值。
- **递归深度**：无基线条件会“无穷递归”，耗尽内存报 `RecursionError`；能用循环通常更高效，递归胜在可读。

## 类比（帮助理解）
- 函数像一个「带标签的工序盒子」：你塞原料（参数）进去，它按内部配方加工，从出料口（return）吐出成品；盒子内部的小仓库（局部变量）和外面的仓库（全局）是分开的。
- **闭包**像外卖小哥带着自己的保温箱（环境）出摊：`double = multiplier(2)` 这个“小哥”记住了自己倍率是 2，`double(5)=10`，另一个小哥 `triple` 倍率 3，互不干扰。
- **递归**像俄罗斯套娃：拆到最小那只（基线）直接给答案，再一层层套回去。

## 设计时怎么用（反推思维）
> 做 XX 系统时，我会用它能解决 YY：
> 做「宿舍电量查询系统」时，我会反推“哪些操作会重复、哪些操作要隐藏细节”：把“读表—解析—算余额”封成 `query_balance(room_id)`，主程序只写 `for room in rooms: print(query_balance(room))`；把“多种异常输入（空、非数字、超范围）”用**收集参数 + 默认值**做成一个 `store(data, *records)` 一次存多条；把“按房间号查、按楼栋查”做成带默认值的可选参数而非写两个函数。一句话：**先找‘会被反复喊去做的事’→ 封成函数 + 用参数适配变化，而不是在主流程里堆 200 行重复代码**。
