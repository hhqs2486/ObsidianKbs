# 类型标注

## 一句话定义
> 类型标注（type annotation / type hint）是用 `def f(x: int, y: str = '') -> bool:` 这种语法，给函数参数和返回值「标注预期类型」的**可选元信息**——它运行时什么都不做，纯粹给人和工具看。

## 它解决什么问题 / 为什么存在
- 大型 Python 项目里，函数「该传什么、返回什么」只靠猜；读代码、接别人接口时极易传错类型。
- 类型标注本身没有语法约束力（Python 运行时不检查），它的价值在于：驱动 IDE 自动补全、静态类型检查器（mypy）、文档生成、甚至函数重载/RPC 参数编组。

## 核心原理（大二能懂的水平）
- 语法（Python 3，PEP 3107 函数注解）：参数后用 `: 表达式` 标类型，返回值用 `-> 类型` 标。
- 标注存在哪？函数的 `__annotations__` 属性（一个 dict），运行时可读，但解释器不据此做任何事。
- 标注「可以是任何表达式」，但常见用法是标类型名：`def f(ham: str, eggs: str = 'eggs') -> str:`。
- Python 3.5+ 引入 `typing` 模块，提供 `List[int]`、`Dict[str, int]`、`Optional`、`Union`、`Callable` 等复杂标注。
- 静态检查需额外工具：`mypy` / `pyright` 等扫描标注、报错；IDE（PyCharm/VSCode）据此给提示。

## 关键参数 / 易错点
- ⚠️ 标注不强制执行：写 `x: int` 却传字符串，运行时**不会**报错——它只是「提示」，不是「约束」。
- 别把奇葩表达式当标注（书里举例 `def square(number: 0<=3 and 1=0) -> (+9000)`），纯属迷惑。
- PEP 3107 原意是「鼓励通过元类/装饰器/框架做试验」，实际现在主要用于类型检查与文档。
- 想真正「运行时校验类型」，得自己写装饰器（如本书的 `xmlrpc` 参数检查装饰器）或用 pydantic 之类库。

## 类比（帮助理解）
- 像外卖订单上的「备注：不要香菜」——后厨（Python 运行时）未必照做，但骑手/你（人/工具）看得到、能据此判断。
- 像函数头的「说明书标签」：贴着「输入：整数」，方便接手的人不踩坑。

## 设计时怎么用（反推思维）
> 做「多人协作的后端服务 / 对外 SDK」系统时，我会用 **类型标注** 解决「接口契约靠口口相传、改一处崩一片」的问题——给每个公开函数标 `@mypy` 可检查的类型，CI 里跑静态检查，新人接手一眼看懂入参出参，IDE 自动补全，少一半低级传参 bug。

## 典型应用 / 我在哪见过
