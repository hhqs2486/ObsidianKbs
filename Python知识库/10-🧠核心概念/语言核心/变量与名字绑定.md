# 变量与名字绑定

## 一句话定义
> Python 的变量不是「装值的盒子」，而是「贴到对象上的名字标签」——赋值就是一次**名字→对象**的绑定（引用），对象本身不带变量名。

## 它解决什么问题 / 为什么存在
- 解释 Python 为什么不用像 C/Java 那样先声明类型：因为类型属于对象，不属于名字。
- 统一理解动态类型、共享引用、`==` 与 `is` 的区别、以及垃圾回收的触发时机。

## 核心原理（大二能懂的水平）
- **没有类型声明**：`a = 3` 创建 int 对象 `3`，把名字 `a` 绑定到它；`a = 'spam'` 只是把标签挪到字符串对象上。
- **共享引用**：`b = a` 让 `b` 和 `a` 指向同一个对象，不是复制。
- **垃圾回收**：对象没人引用（引用计数归零）就被回收；小整数/短字符串有缓存，解释器复用同一对象。
- **相等 vs 身份**：`==` 比较两个对象的值；`is` 判断是不是同一个对象（比内存地址）。

## 关键参数 / 易错点
- **共享引用 + 可变对象最危险**：列表/字典/集合被多个名字引用时，一处原地修改，所有名字都看得到变化。
- `==` 和 `is` 别混：小整数缓存会让 `256 is 256` 为 True、`257 is 257` 可能为 False，永远用 `==` 比值。
- 不可变对象（数字、字符串、元组）被「改」时其实是生成新对象，所以共享也安全。

## 类比（帮助理解）
- 便利贴贴水杯模型：变量是便利贴，对象是水杯。多张便利贴可同时贴同一个水杯；有人往杯里加水（改可变对象），所有贴纸主人看到的水位都变。

## 设计时怎么用（反推思维）
> 函数传参本质就是「把实参对象绑定到形参名字」——所以是传引用。若想函数内部改了不影响外部，传入前先拷贝，或传入不可变对象。需要跨调用保留状态时，用 [[闭包]] 的 nonlocal 或类属性，而不是全局可变变量。

## 典型应用 / 我在哪见过
- 函数参数传递（见 [[函数(参数与返回值)]]）：默认「传对象引用」。
- 「可变默认参数陷阱」「浅拷贝/深拷贝」都源于此模型。
