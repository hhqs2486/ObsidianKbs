# 元类

## 一句话定义
> 元类是「创建类的类」——普通类用来创建实例，元类（默认是内置 `type`）用来创建类本身，能在类定义阶段拦截并改写类的生成。

## 它解决什么问题 / 为什么存在
- 常规手段（装饰器、描述符、`__new__`）已经能改「实例」和「属性」，但如果你想在「类被定义出来那一刻」就统一改造它（比如自动注册子类、强制某套 API、改写属性顺序），就需要元类。
- 它把「类的创建过程」也变成可编程的对象，是 Python 元编程的最强武器。

## 核心原理（大二能懂的水平）
- Python 中「类也是对象」，而创建类的那个对象就叫元类。所有类的默认元类是 `type`。
- `type(name, bases, namespace)` 三个参数 = 类名 / 父类元组 / 类体命名空间(dict)，动态 `class` 语句就是它的语法糖。
- 用 `class Foo(metaclass=MyMeta):` 指定自定义元类（Python 2 写法 `__metaclass__ =`，不兼容）。
- 自定义元类通常继承 `type`，可重写四个钩子：
  - `__prepare__`：创建空的命名空间对象（可返回有序 dict，用来记录类体里属性的定义顺序）。
  - `__new__(mcs, name, bases, ns)`：真正「造出类对象」的地方。
  - `__init__(cls, name, bases, ns)`：类造好后再做初始化（每个子类都会调用；类装饰器则不会被子类调用，这是两者区别）。
  - `__call__(cls, *a, **kw)`：拦截「用这个类 new 实例」的过程。
- `__new__` 在这里相当于「更高一层的 `__new__`」——在类定义层面思考。

## 关键参数 / 易错点
- `mcs` / `cls` 命名约定：`__new__` 里第一个参数是元类自身（通常叫 `mcs`），`__init__` 里第一个参数是已经造好的类（叫 `cls`）。
- 能用装饰器/描述符/`__new__` 解决的，就别上元类——元类可读性差、调试难，是「最后手段」。
- 类装饰器 vs 元类：`__init__` 在元类中对每个子类都触发，类装饰器只对直接装饰的类触发。
- 跨版本（Py2/Py3）元类语法不兼容，需用 `six.with_metaclass` 这类桥接。

## 类比（帮助理解）
- 类像是「做饼干的模具」，实例是饼干；元类就是「造模具的工厂」——你不常需要它，但想统一所有模具的规格时它是唯一的抓手。
- 像学校的「教务处」：老师（类）制定课程，教务处（元类）在老师上岗前审核、登记、统一规范。

## 设计时怎么用（反推思维）
> 做「插件/子类自动注册框架」系统时，我会用 **元类** 解决「每新增一个 Handler 子类都要手动 import 并登记」的麻烦——在元类 `__init__` 里把每个子类自动塞进注册表，业务方只管继承，框架启动时遍历注册表即可发现全部实现。
