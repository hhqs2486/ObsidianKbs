# 推导式

## 一句话定义
> 推导式（comprehension）是一行「从一个可迭代对象推导出新容器」的语法糖：`[表达式 for 变量 in 可迭代对象 if 条件]`，有列表/集合/字典三种形态，外加惰性求值的生成器表达式。

## 它解决什么问题 / 为什么存在
- 取代「建空容器 → 写 for 循环 → 往里 append」的样板代码，更短、更易读、通常更快。
- 源自集合表示法，把「对每个元素做变换+筛选」表达成一句话。

## 核心原理（大二能懂的水平）
- 列表推导：`[row[1] for row in M]` 取矩阵第 2 列；`[x for x in range(10) if x % 2 == 0]` 取偶数。
- 集合推导：`{x for x in lines}` 直接去重。
- 字典推导：`{k: v for k, v in zip(keys, vals)}`。
- 生成器表达式：`(x*x for x in range(10))` 用圆括号，惰性逐个产生，省内存。
- 可嵌套多个 `for`、可加 `if` 过滤。

## 关键参数 / 易错点
- **别写太复杂**：三四层嵌套的推导式可读性极差，不如拆成普通循环。
- 推导式里的变量名会「泄漏」到外层（列表推导在 3.X 里作用域隔离，生成器/集合/字典推导则隔离）——别依赖这个细节。
- 与 `map()`/`filter()` 取舍：推导式通常更直观；超简单映射可用 `map`。
- 生成器表达式惰性，遍历一次就用完，不能重复索引。

## 类比（帮助理解）
- 像一条流水线：原材料（可迭代对象）逐个过检（if）和加工（表达式），成品落进筐（新容器），全程一句话描述完。

## 设计时怎么用（反推思维）
> 数据清洗、提取矩阵某行某列、把一列 ID 去重、把两个列表拼成字典时，先想能不能一行推导式搞定。需要「边算边给、不全存内存」（如读大文件），用生成器表达式。

## 典型应用 / 我在哪见过
- 矩阵列提取：`col2 = [row[1] for row in M]`。
- 配合 [[函数(参数与返回值)]] 做数据变换；结果常喂给 [[列表]] [[集合]] [[字典]]。
