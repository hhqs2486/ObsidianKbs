# 作用域与命名空间(LEGB)

## 一句话定义
> 名字按 **L→E→G→B**（Local 局部 → Enclosing 嵌套外层 → Global 全局 → Built-in 内置）的顺序查找；一次赋值决定这个名字属于哪个作用域。

## 它解决什么问题 / 为什么存在
- 避免大型程序里名字互相打架（命名冲突）。
- 让你清楚「某个变量在哪儿可见」「函数里改的到底是哪一层变量」。

## 核心原理（大二能懂的水平）
- 变量可在三处被赋值，对应三个作用域：
  - 在 `def` 内赋值 → **局部（Local）**
  - 在包裹它的外层 `def` 内赋值 → **嵌套外层（Enclosing）**
  - 在所有 `def` 之外赋值 → **全局（Global）**
  - 再加上解释器自带的 **内置（Built-in）** 名（如 `len`、`print`）。
- 查找顺序就是 LEGB：先自己函数局部，再一层层往外到全局，最后到内置。
- 想改**全局**变量要写 `global x`；想改**嵌套外层**函数的变量要写 `nonlocal x`（3.X 引入）。
- 这是**词法作用域**：作用域由代码书写位置决定，而非调用位置。

## 关键参数 / 易错点
- 函数内「赋值」默认创建**局部**变量；想改全局忘了 `global`，会悄悄建一个同名局部变量，全局没变（经典的「UnboundLocalError」来源）。
- 嵌套函数改外层变量忘了 `nonlocal`，同样会建局部副本。
- 别给变量起和内建名一样的名字（如 `list = [...]`），会遮蔽内置 `list()`。
- `global/nonlocal` 声明的是「要改哪层」，不是「声明类型」。

## 类比（帮助理解）
- 找文件：先翻自己抽屉（Local）→ 再翻部门柜（Enclosing）→ 再翻公司档案室（Global）→ 最后查公共图书馆（Built-in）。翻到就拿走，不会继续往外找。

## 设计时怎么用（反推思维）
> 模块级常量放心用全局；需要「跨多次调用记住状态」又不想污染全局，用嵌套函数 + `nonlocal`（这正是 [[闭包]] 的底层机制）。写库时尽量少用全局可变状态，降低耦合。

## 典型应用 / 我在哪见过
- 计数器、缓存（闭包 + nonlocal）。
- 与 [[函数(参数与返回值)]] 一体两面；与 [[模块与包]] 衔接：模块文件本身就是一层全局命名空间。
