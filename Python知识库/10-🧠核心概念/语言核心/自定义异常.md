# 自定义异常

## 一句话定义
> 自定义异常就是“自己写一个继承自 `Exception`（或其子类）的类”，用来表达**你的程序特有的、内置异常表达不了的错误语义**，让调用方能精准 `except` 到这种错。

## 它解决什么问题 / 为什么存在
- 内置异常（`ValueError`/`IOError`…）太通用：同一个 `ValueError` 可能来自“参数非法”，也可能来自“配置文件缺字段”，调用方没法区分。自定义异常让错误**自带业务含义**。
- 书里把异常当“带信息的对象”：自定义类可以携带额外字段（错误码、上下文数据），比单纯抛个字符串强。
- 库/框架作者尤其需要：给使用者一套**清晰的异常层级**，而不是让所有人去猜 `except Exception`。

## 核心原理（大二能懂的水平）
- **必须继承 `Exception`**（或其子类，如 `RuntimeError`）：否则 `except Exception` 兜底抓不到，也不符合 Python 约定。
- **构造即传消息**：`class MyError(Exception): pass`，然后 `raise MyError("出错了")`；`except MyError as e: print(e)` 能拿到消息。
- **加字段**：`class ApiError(Exception): def __init__(self, msg, code): super().__init__(msg); self.code = code`，抛出时 `raise ApiError("超时", 504)`，调用方可读 `e.code`。
- **建层级**：`class NetworkError(Exception): pass` → `class TimeoutError(NetworkError): pass`，调用方 `except NetworkError` 可一把抓所有网络子类错（注意别和内建 `TimeoutError` 重名，建议起独特名字）。
- **`raise ... from ...`**：在 except 里转抛自定义错时，用 `raise MyError(...) from orig` 保留原始异常链，调试更清楚。

## 关键参数 / 易错点
- **务必继承 `Exception`**：继承 `BaseException`（如 `KeyboardInterrupt` 那一支）会让它无法被常规兜底捕获，属反模式。
- **别用内建异常名当类名**：自己写 `TimeoutError` 会遮蔽内置类，造成混淆；起业务化名字（如 `DbTimeoutError`）。
- **异常不是流程控制**：能用 `if`/`return` 正常表达的别靠 raise 走通，否则代码难读。
- **别吞掉上下文**：转抛时优先 `raise NewError(...) from e`，保留 `e.__cause__` 便于排查。

## 类比（帮助理解）
- 自定义异常像「公司专用错误工单分类」：通用工单（ValueError）谁都看不懂哪出了问题；你自定义一张“支付失败-余额不足”工单，客服（except）一眼就能精准处理。
- 异常层级像「组织架构」：抓“网络部所有故障”（`except NetworkError`）能覆盖下面“超时”“断连”等子类，不用一个个列。

> 做 XX 系统时，我会用它能解决 YY：
> 做「第三方支付 SDK」时，我会反推“哪些失败是调用方必须区分处理的”：定义 `PaymentError` 基类 + `InsufficientBalanceError`/`GatewayTimeoutError` 子类；网关超时原始是网络层异常，我在封装层 `raise GatewayTimeoutError(...) from e` 转成业务异常，调用方只需 `except GatewayTimeoutError` 做重试。一句话：**先列‘业务里有哪些可预见的、需要被分别处理的失败’→ 每种建一个语义清晰的异常类，挂在统一基类下，别滥用通用内置异常**。

## 典型应用 / 我在哪见过
- 与[[异常处理]]的关系：自定义异常是 `raise/except` 的对象，是异常机制的“扩展点”。
- 与[[类与对象]]的关系：自定义异常就是普通的类，可加字段、可继承。
- 与[[模块与包]]的关系：异常通常定义在模块顶层，供包外 `from pkg import XError` 引用。
