# 函数式编程

## 一句话定义
> 函数式编程（functional programming）是一种「把计算看成函数求值、避免可变状态和副作用」的编程风格；在 Python 里体现为：高阶函数、`lambda`、闭包、迭代器链与不可变数据。

## 它解决什么问题 / 为什么存在
- 命令式代码常用「改来改去的变量 + 大循环」解决序列处理，既慢又难读、还易出 bug。
- 函数式风格把「对每个元素做什么」拆成小而纯的函数，再用 `map/filter`、生成器管道串起来，代码更短、更可组合、更易推理（给定输入必得同一输出）。
- 本书在讲「缓存装饰器（memoize）」时明确点出：这种「相同参数→同一结果」的写法正是函数式编程的特点。

## 核心原理（大二能懂的水平）
- **高阶函数**：函数能接收/返回函数（`decorator` 就是典型，见 [[装饰器]]）。
- **`lambda`**：匿名小函数，如 `lambda x: x*2`；常用于排序 `key=`、一次性回调。
- **闭包（closure）**：内层函数捕获了外层变量，装饰器、参数化装饰器都靠它保存状态。
- **纯函数 + 不可变**：不修改外部变量，输出只由输入决定——这样结果才能安全缓存（memoize）。
- **迭代器管道**：把多个「转换函数」串成处理链，每个函数一次处理一个元素（见 [[高级迭代器]] 的生成器），实时反馈、内存友好。
- 内置工具：`map`、`filter`、`functools.reduce`、`functools.partial`、`itertools` 系列。

## 关键参数 / 易错点
- `lambda` 不能出现在装饰器位置（`@` 后必须是命名可调用，不能用 lambda）。
- 闭包捕获的是「变量」不是「值」——循环里用闭包要小心 late binding（常见坑：循环里 `lambda` 取到最后一个 `i`）。
- 函数式 ≠ 全都用 `map/filter`；Python 里列表推导/`for` 往往更 Pythonic、可读性更好。
- 要可缓存，函数必须是「确定性」的（同输入同输出），否则 memoize 会返回过期结果。

## 类比（帮助理解）
- 像工厂流水线：每个工位（纯函数）只做一种转换，零件（数据）流过整条线，彼此不互相改动。
- 像数学函数 `f(x)`：你不会说「`f` 把 x 改了」，而是「`f(x)` 算出一个新值」。

## 设计时怎么用（反推思维）
> 做「日志/数据清洗 ETL」系统时，我会用 **函数式编程** 解决「一大坨 if-else 的脏数据处理、难以单测」的问题——把清洗拆成 `trim → 去重 → 校验` 几个纯函数，用生成器管道串起来，每个函数单独测、随意组合，新增规则不动主干。

## 典型应用 / 我在哪见过
- 装饰器缓存（memoize）、`sorted(key=lambda ...)`、数据分析里的 `map/filter` 链、`itertools` 组合。
- 本卷书 ch02/第2章：高阶函数、lambda、闭包、缓存装饰器（「这种编程风格是函数式编程的特点」）。
