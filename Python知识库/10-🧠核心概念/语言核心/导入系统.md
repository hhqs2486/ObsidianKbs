# 导入系统

## 一句话定义
> `import` / `from` 把其他模块的名字引入当前命名空间；Python 按「模块搜索路径」找到源文件、编译成字节码并加载，从而复用代码、组织大项目。

## 它解决什么问题 / 为什么存在
- 让代码可复用、可分层：标准库、第三方包、自己写的模块都能即插即用。
- 模块是「自带命名空间」的代码包，天然避免跨文件命名冲突。

## 核心原理（大二能懂的水平）
- 两种基本形式：`import module`（用 `module.name` 访问）；`from module import name`（直接拿 `name`，可 `as` 改名）。
- **搜索路径**由这几部分拼接成 `sys.path`：① 程序主目录 → ② `PYTHONPATH` 环境变量目录 → ③ 标准库目录 → ④ `.pth` 文件内容 → ⑤ 第三方扩展的 `site-packages`。
- 找到源文件后，必要时编译成 `.pyc` 字节码缓存（按修改时间判断是否需要重编）。
- **包**：带 `__init__.py` 的目录（3.3+ 也可无 `__init__` 的「命名空间包」）。包内可用相对导入 `from . import x`；`__all__` 控制 `from pkg import *` 导出什么。
- `import` 语句里**不能带路径和扩展名**；包导入用点号分隔（`import pkg.mod`）。

## 关键参数 / 易错点
- **循环导入**：A 导入 B、B 又导入 A，可能拿到未初始化完的模块——用函数内延迟导入或重组代码解决。
- `from x import *` 会污染当前命名空间，大项目慎用，最好显式导入。
- 相对导入只能在包内使用，且不能作为主程序直接运行。
- 想扩展搜索范围，就改 `sys.path` 或设 `PYTHONPATH`，而不是在 import 里写绝对路径。

## 类比（帮助理解）
- 像图书馆借书：按「本馆→分馆(PYTHONPATH)→总书库(标准库)→特约书商(site-packages)」的顺序找书；借来（import）才能用里面的内容，且每本书自带目录（命名空间）互不打架。

## 设计时怎么用（反推思维）
> 项目一大就用「包」按功能分层（如 `utils/`、`models/`），用 `__init__.py`/`__all__` 收敛对外接口。发布给别人用时，靠 [[包管理pip]] 装进 `site-packages`，import 就能用。

## 典型应用 / 我在哪见过
- `import os, sys, json` 标准库；`from collections import defaultdict`。
- 与 [[模块与包]] 是同一主题的两面（那张偏「模块/包是什么」，这张偏「怎么被找到和加载」）。
