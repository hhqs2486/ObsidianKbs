# 异常处理

## 一句话定义
> 异常是 Python 用「对象」表示的“出错了”状态；`try/except` 让你**捕获并处理**错误而不是让程序崩溃，`raise` 让你主动抛错，`finally` 保证清理（关文件/关连接）一定执行。

## 它解决什么问题 / 为什么存在
- 书里 8.1：如果用 `if` 在每个除法前查除数是否为 0，又臭又长还漏情况。异常把“正常流程”和“出错处理”分开，主代码清爽。
- 异常会**沿调用栈向上传播**：函数里 raise，没处理就传到调用方，再没处理才崩溃报 traceback。所以你能在一个地方统一兜底（书里 `faulty→ignore_exception→handle_exception` 演示）。
- 核心哲学（书里 8.5 引 Grace Hopper）：“请求宽恕比获得许可更容易”——直接做，出错再 `except`，通常比事前写一堆 `if` 检查更自然、更 Pythonic。

## 核心原理（大二能懂的水平）
- **异常是类实例**：`ZeroDivisionError`、`TypeError`、`ValueError`、`KeyError`、`IndexError`、`NameError`、`OSError` 等都是 `Exception` 的子类（书里表 8-1）。
- **`raise` 主动抛错**：`raise Exception('消息')`；可抛内置类或自定义类（自定义必须继承 `Exception`，如 `class HyperdriveError(Exception): pass`）。
- **`try/except` 捕获**：
  - 多分支：`except ZeroDivisionError: ... except TypeError: ...` 不同错不同处理。
  - 一箭双雕：`except (ZeroDivisionError, TypeError): ...`（注意元组要括号）。
  - 拿异常对象：`except Exception as e:` 然后 `print(e)` 看原因。
  - 全捕获 `except:` 危险（会吃掉 Ctrl+C、sys.exit），更稳妥用 `except Exception as e`。
- **`else` 子句**：`try` 没出错才执行，常配合 `while True: try:... except:... else: break` 做“输入对了才退出循环”。
- **`finally` 子句**：无论出不出错都执行，适合关文件/关 socket（见[[文件IO]]）。`try/except/else/finally` 可组合。
- **`raise` 空调用**：在 except 里 `raise` 不传参 = 原样继续向上传播（书里 MuffledCalculator 按需“抑制或外抛”）；`raise ... from ...` 可指定异常上下文。
- **异常与函数**：函数引发的异常传播到调用处；`with` 语句的 `__exit__` 也是借异常机制关资源。
- **`warnings`**：只想警告不致命，用 `warnings.warn(...)`，可调 `filterwarnings("error"/"ignore")` 升级/忽略。

## 关键参数 / 易错点
- **裸 `except:` 别乱用**：会吞掉 `KeyboardInterrupt`，调试时按 Ctrl+C 都停不下来；优先 `except Exception as e`。
- **`except (A, B)` 括号别漏**：写成 `except A, B` 是旧式语法陷阱。
- **自定义异常要继承 Exception**：否则 `except Exception` 抓不到。
- **`finally` 里别再抛新错**：会掩盖原异常，定位困难。
- **“请求宽恕”不等于不处理**：`try: person['occupation']` 比先 `if 'occupation' in person` 少一次查找，但前提是真可能没这个键；纯逻辑分支还是用 `if` 更清晰。

## 类比（帮助理解）
- 异常像「流水线上的红色急停灯」：正常时没人理它，一旦某工位出错，灯亮（raise），沿着流水线往回传，直到有人接手处理（except）；`finally` 是“不管灯亮没亮，下班都要拉闸断电”。
- `try/except` 像「买保险」：你正常开车（try），出事了保险公司赔（except），没出事保险也不赔你钱但流程照走（else）。

## 设计时怎么用（反推思维）
> 做 XX 系统时，我会用它能解决 YY：
> 做「串口通信上位机」时，我会反推“哪里必崩、哪里要兜底”：打开串口包 `try: ser=open(...) except OSError as e: 提示‘端口被占/不存在’并退出`；读一帧数据 `try: frame=ser.read(n) except (TimeoutError, ValueError) as e: 记日志并 continue 跳过这一帧` 而不是整程序挂掉；整个 `with` 块外确保端口在 `finally`/`with` 里关闭（结合[[文件IO]]）。一句话：**先列‘哪些操作是外部环境决定的（网络/文件/用户输入）’→ 给它们加 try/except 兜底，把‘正常逻辑’和‘错误处理’分开写，而不是到处 if 预判**。

## 典型应用 / 我在哪见过
- 书里：除零计算器、多次要求输入正确数字（try/except/else 循环）、`MuffledCalculator` 抑制/外抛、`describe_person` 用 try 替代 if 查键。
- 与[[函数基础]]的关系：函数内 raise 的异常向上传播；与[[文件IO]]的关系：用 try/finally 或 with 保证文件关闭。
