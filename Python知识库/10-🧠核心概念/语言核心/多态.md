# 多态

## 一句话定义
> 多态（polymorphism）指对象可以「不关心具体类型」地通过它们**共同的属性和动作**来被操作与访问——同一操作作用于不同对象，产生不同行为。

## 它解决什么问题 / 为什么存在
- 若不用多态，要针对每种类型写 `if type == A: ... elif type == B: ...`，代码僵硬、难扩展。
- 多态让调用方只依赖「接口/动作」，新增类型时不必改动调用方，符合开闭原则。

## 核心原理（大二能懂的水平）
- 多态依赖**动态（运行时）绑定**：在运行时才确定调用哪个方法，并做类型确定与验证。
- Python 用**鸭子类型（duck typing）**实现多态：「走起来像鸭子、叫起来像鸭子，就是鸭子」——只要对象有某个方法/属性，就能调，不检查它属于哪个类。
- 典型例子：`'abc'.count('a')` 与 `[1,2,'a'].count('a')` 都能用；运算符 `+` 在 `1+2` 与 `'a'+'b'` 上都成立（运算符本身也是多态，见 [[运算符重载]]）。
- 尽量别用 `type`/`isinstance` 做类型检查来破坏多态（只有配合 [[抽象基类]] 时才推荐）。

## 关键参数 / 易错点
- 过度使用 `isinstance`/`type` 判断会破坏多态，丧失扩展性与鸭子类型的灵活。
- 多态建立在「对象确实有该方法」之上——若调用方假定有某方法而对象没有，运行期才报 `AttributeError`。

## 类比（帮助理解）
- 像「所有电器都有插头，插上就能用」：你只管调用 `device.power_on()`，不用管它是电视还是冰箱。
- 像「收银台对所有商品只喊一声『结账』」：商品各自实现自己的计价逻辑，收银台不关心它是苹果还是笔记本。

## 设计时怎么用（反推思维）
> 做「报表导出系统」时，我会用 **多态** 解决「要支持 PDF/Excel/CSV 多种格式但调用方不想写分支」的问题——定义 `export()` 接口，每种格式是一个子类各自实现 `export()`，调用方只写 `report.export()`，新增格式加一个子类即可，主流程一行不改。
