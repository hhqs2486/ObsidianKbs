# 装饰器

## 一句话定义
> 装饰器是一种「接受函数/类、返回一个增强后的函数/类」的语法糖（`@xxx`），本质是把「包装逻辑」从业务代码里抽出来复用。

## 它解决什么问题 / 为什么存在
- 在没有装饰器之前，要把一个函数「变成类方法 / 静态方法」或「加上日志、鉴权、缓存」，得在函数定义后手写 `func = wrapper(func)`，既啰嗦又难读。
- 装饰器把这种「横切关注点」（日志、计时、权限、缓存、上下文）集中到一处，让被装饰的函数保持干净。
- 它是 Python 元编程（metaprogramming）里最易用的一环：运行时修改/增强函数与类，而不动原函数源码。

## 核心原理（大二能懂的水平）
- `@decorator` 写在 `def f():` 上方，等价于 `f = decorator(f)`——纯粹是语法糖。
- 最简单的装饰器是一个「返回内部函数」的函数：
  ```python
  def mydecorator(function):
      def wrapped(*args, **kwargs):
          # 调用前做点事
          result = function(*args, **kwargs)
          # 调用后做点事
          return result
      return wrapped
  ```
- 类也能当装饰器（只要实现 `__call__`），适合需要保存状态或复杂参数化的场景。
- 参数化装饰器需要「三层嵌套」：`def deco(arg): def actual(func): def wrapped(...): ... return wrapped; return actual`。
- 常见四类用法：参数检查、缓存（memoize）、代理（权限）、上下文提供者（但上下文更常用 `with`，见 [[上下文管理器]]）。
- ⚠️ 易错点：装饰器会覆盖原函数的 `__name__` 和 `__doc__`，调试困难。用 `functools.wraps` 保存元数据。
  ```python
  from functools import wraps
  def preserving(function):
      @wraps(function)
      def wrapped(*a, **kw): ...
      return wrapped
  ```

## 关键参数 / 易错点
- `*args, **kwargs`：装饰器要「透明」地透传任意参数，否则会破坏函数签名。
- 装饰器不必返回可调用对象（语法允许返回任意东西，但调用时通常报错）——别滥用。
- 参数化装饰器即使有默认值也必须加括号：`@repeat()`，否则会把函数当参数传进去而报错。
- 类装饰器用闭包创建子类时，会丢掉原类的 `__name__`，且 `functools.wraps` 救不了它（见 [[元类]] 的替代方案）。

## 类比（帮助理解）
- 像给手机套壳：手机（原函数）本体不变，套上壳（装饰器）后多了防摔/支架功能，随时可换壳。
- 像餐厅的「前置安检 + 后置送客」：客人（参数）进门前检查、吃完后送客，餐厅核心（做菜）不动。

## 设计时怎么用（反推思维）
> 做「带登录鉴权的后台接口」系统时，我会用 **装饰器** 解决「每个接口都要判断当前用户角色」的重复代码问题——写一个 `@protect('admin')` 装饰器统一拦截，业务函数只管干活，新增接口时一行 `@protect` 即可，绝不复制粘贴鉴权逻辑。

## 典型应用 / 我在哪见过
- Flask 的 `@app.route('/')`、Django 的 `@login_required`、单元测试的 `@unittest.skip`、计时 `@timeit`。
