# Python对象模型

## 一句话定义
> Python 里「一切皆对象」：数字、字符串、函数、模块、类本身都是带「类型头 + 引用计数」的对象，变量只是贴在对象上的名字标签，而非装值的盒子。

## 它解决什么问题 / 为什么存在
- 给所有数据类型一套统一的心智模型，让你理解「赋值、参数传递、相等判断、垃圾回收」这些行为的共同底层逻辑。
- 解释为什么 Python 不用声明变量类型，以及为什么 `a = 3; a = "spam"` 是合法的。

## 核心原理（大二能懂的水平）
- 每个对象在内存里有两部分元数据：一个是**类型**（决定它能做什么），一个是**引用计数**（记录有几个名字指向它，到 0 就回收）。
- 变量本身没有类型，只有对象有类型。表达式的写法决定创建什么类型的对象：`3` → int，`'x'` → str，`[1,2]` → list。
- 「赋值」`a = 3` 的真实含义是：创建 int 对象 `3`，把名字 `a` 绑定（贴标签）到它上面。后续 `a = 'spam'` 只是把标签挪到新对象上，旧对象没人引用就被回收。

## 关键参数 / 易错点
- `==` 比值（对象内容），`is` 比身份（是否为同一个对象）。小整数（-5~256）和短字符串会被解释器缓存复用，导致 `is` 偶尔返回 True，别依赖它，比较值用 `==`。
- 多个名字可以指向同一个**可变**对象（列表/字典/集合），其中一处原地修改，所有引用都能看到——这就是「共享引用」的坑。
- 没有类型声明，所以同一个名字可以先后指向不同类型对象（动态类型）。

## 类比（帮助理解）
- 对象像一个个水杯，变量像便利贴。便利贴可以今天贴在水杯 A 上，明天揭下来贴在水杯 B 上；水杯本身不关心贴了谁。
- 「共享引用」：好几张便利贴同时贴在同一个水杯上，有人往杯里加了水，所有贴纸的主人看到的水位都变了。

## 设计时怎么用（反推思维）
> 做数据处理系统时，如果要把一份配置/列表传给多个函数，先想清楚是要「共享同一份（改一处全变）」还是「各自一份（互不影响）」。需要互不影响时，显式拷贝，而不是图省事传引用。

## 典型应用 / 我在哪见过
- 函数参数传递（见 [[变量与名字绑定]] [[函数(参数与返回值)]]）：默认都是传对象引用。
- 「可变默认参数陷阱」本质就是共享引用 + 对象模型没理解透。
