# 闭包

## 一句话定义
> 闭包（closure）是一个「内部函数」加上它**捕获的外部作用域变量（自由变量）**的组合——函数带着它定义时所处的环境一起被传递。

## 它解决什么问题 / 为什么存在
- 在 GUI、事件驱动、数据库回调等场景里，经常需要「带一点私有状态的函数」（回调函数）。如果为了保存这点状态去专门写一个类，太重了。
- 闭包让你在不定义类的前提下，让函数「随身携带」外部变量，从而写出轻量、小巧的回调。

## 核心原理（大二能懂的水平）
- 在 Python 的静态嵌套作用域规则下，如果一个**内部函数**引用了**外部函数作用域（非全局）**里的变量，这个内部函数就被称为闭包。
- 被内部函数引用/使用的外部变量叫**自由变量（free variable）**。闭包把「内部函数的代码+作用域」和「外部函数的作用域」绑在一起；这些词法变量既不属于全局、也不属于局部，而属于「另一个名字空间」。
- 书里的计数器例子：用列表 `count = [start_at]`（Python 中 int 不可变，故裹进列表）保存状态，`incr()` 内部修改并返回 `count[0]`，最后 `counter()` 把 `incr` 这个可调用对象返回——调用 `counter(5)()` 的表现和「实例化一个 Counter 对象再执行」非常相似。
- 闭包与**偏函数应用（PFA）**相似但不同：PFA 更像 currying（和函数调用相关），闭包关注的是「使用定义在其他作用域的变量」。
- 可用函数的 `func_closure` 属性追踪自由变量（本书基于 Python 2.x）。

## 关键参数 / 易错点
- 不可变对象（int/str）若在闭包里想被修改，必须包成列表/字典等容器，否则只是创建了新的局部变量（书的 counter 用 `[count]` 正是这个原因）。
- 闭包变量活在「函数的名字空间和作用域」，和对象的实例名字空间不同——别混淆两者。
- Python 2.1 之前作用域规则不同，旧代码可能踩坑；现代 Python（2.2+）已统一。

## 类比（帮助理解）
- 像带「私人笔记本」的外卖员：外卖员（内部函数）每次接单都带着自己的小本子（外部变量），不依赖公司大黑板（全局），也不依赖当前餐厅（局部）。
- 像「会自带调料的厨师」：你只调用 `cook()`，但厨师已经把自己习惯的调料包（自由变量）背在身上了。

## 设计时怎么用（反推思维）
> 做「GUI 按钮点击回调 / 事件驱动处理」系统时，我会用 **闭包** 解决「每个回调都要记住自己属于哪个窗口、哪条数据」的问题——把上下文变量直接包进闭包，比给每个回调单独写一个类更轻；只有当回调变复杂、需要保存很多状态时，才退而用类。

## 典型应用 / 我在哪见过
- 回调函数、事件驱动编程（GUI）、数据库行获取与处理。
- 装饰器（见 [[装饰器]]）底层就是闭包——`@decorator` 返回的内部函数带着被装饰函数的引用。
