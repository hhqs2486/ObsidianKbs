# 高级迭代器

## 一句话定义
> 高级迭代器指 Python 里「按需产出元素、不一次性占满内存」的两件套：**迭代器（iterator，实现 `__iter__`/`__next__`）** 与 **生成器（generator，用 `yield` 暂停的函数）**，外加 `itertools` 等工具。

## 它解决什么问题 / 为什么存在
- 列表推导、`for` 循环都能遍历，但当数据「无穷（斐波那契）」或「巨大（大文件/流）」时，一次性生成全部元素会爆内存、还慢。
- 迭代器/生成器让你「要一个给一个」，边算边给、用多少算多少；还能把多个转换函数拼成处理管道（见 [[函数式编程]]）。

## 核心原理（大二能懂的水平）
- **迭代器协议**：`__iter__()` 返回自身，`__next__()` 返回下一个元素，遍历完抛 `StopIteration`。自定义类实现这俩就是迭代器。
- **生成器**：含 `yield` 的函数调用后返回一个 generator 对象；每次 `next()` 跑到 `yield` 暂停、返回中间值，下次从暂停处续跑，自动保存上下文。
  ```python
  def fibonacci():
      a, b = 0, 1
      while True:
          yield b
          a, b = b, a + b
  ```
- 进阶：`yield` 还能「接收值」——`recv = yield` 配合 `.send(x)` 让生成器与外部双向通信；`.throw()`/`.close()` 抛异常/收尾。
- 生成器是协程、异步并发的基础（见 [[并发编程]] 的 `async/await`，语法与生成器同源）。
- `contextlib.contextmanager` 也是用 `yield` 把 `__enter__`/`__exit__` 写在一个函数里（见 [[上下文管理器]]）。
- `itertools`：`count/cycle/islice/chain/groupby` 等高效迭代工具。

## 关键参数 / 易错点
- 生成器「一次性消费」：遍历完就没了，想再用得重新调用函数生成新的。
- `yield` 表达式赋值要写在右边：`x = yield v`，外面用 `.send(x)` 传值，单纯的 `yield v` 收不到。
- 迭代器和生成器是「底层特性」，日常可不直接写类，多用生成器函数 + 推导式即可。
- 社区里生成器「不够常用」只是因为思维习惯，遇到流/大序列应优先考虑它。

## 类比（帮助理解）
- 像点唱机：你按一次出一首歌（next），不会一次性把整张碟倒出来；想重听得重新点播（重新生成）。
- 像自来水龙头：拧开（next）才出水，关上就停，不用先把一池子水全蓄好。

## 设计时怎么用（反推思维）
> 做「大文件/日志流处理」或「实时数据流」系统时，我会用 **高级迭代器** 解决「一次性读入撑爆内存、且要支持暂停/恢复」的问题——用生成器逐行 `yield`，上层 `for` 逐条处理，配合 `tokenize` 这类「边读边产 token」的管道，十万行日志也能稳定跑、随时停。
