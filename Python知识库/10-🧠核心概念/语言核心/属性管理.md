# 属性管理

## 一句话定义
> 属性管理（property）用内置 `property()`（或 `@property` 装饰器）把「读/写方法」伪装成「普通属性访问」，让你在 `obj.x = 1` 这种看似简单的赋值背后，悄悄插入校验、计算或懒加载逻辑。

## 它解决什么问题 / 为什么存在
- 直接暴露 `obj.x = 1` 无法做校验（比如年龄不能是负数）；手写 `get_x()/set_x()` 又啰嗦、且调用方写法不一致。
- property 让你「对外是属性、对内是方法」——接口保持简单，逻辑却能受控（书里把 `property()` 列为新式类的高级特性 / 内建函数之一）。

## 核心原理（大二能懂的水平）
- `property(fget, fset, fdel, doc)` 把 getter/setter/deleter 三个方法绑成一个描述符对象，赋给类属性后，`obj.x` 实际走 `fget`，`obj.x = v` 实际走 `fset`。
- 更常用写法：`@property` 定义 getter，`@x.setter` 定义 setter（注意名字要一致）。
- property 本质是**内置的描述符**（见 [[描述符]]）——它只是「现成的描述符类型」，自定义描述符能做的事多得多（如类型校验、懒加载）。
- 属于「新式类高级特性」：Python 2.2 统一类型与类后才有完整的 property 能力，因此被归入新式类体系。

## 关键参数 / 易错点
- 子类想覆写父类的 property 时，**必须整段重写 property**（因为 property 在类定义时实时绑定 fget/fset），只重写其中一个访问器会用到父类的方法。
- 只定义 getter、不定义 setter 的属性是只读的，`obj.x = v` 会抛 `AttributeError`。
- property 不等于「字段」：它每次访问都走方法，别在里面放昂贵计算而不加缓存。
- 需要更复杂的属性逻辑（类型校验、越界拦截、依赖触发）时，应直接用 [[描述符]] 而非简单 property。

## 类比（帮助理解）
- 像「看着是普通开关，背后连着一整套电路」：你 `obj.size = (150,100)` 以为只是设值，其实触发了 setter 里的计算。
- 像「银行柜员的窗口」：你只说「存 100」，窗口背后柜员做校验、记账——你感知不到那些步骤。

## 设计时怎么用（反推思维）
> 做「配置对象 / ORM 模型」时，我会用 **属性管理** 解决「字段既要像普通属性一样读写，又要在赋值时做类型/范围校验」的问题——把 `age` 写成 `@property` + `@age.setter`，在 setter 里 `if value < 0: raise ValueError`，调用方仍写 `user.age = 20`，干净且安全。需要跨字段联动或懒加载时再升级到 [[描述符]]。
