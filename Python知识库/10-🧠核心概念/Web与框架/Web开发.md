# Web开发

## 一句话定义
> Web 开发指构建能通过浏览器访问的网站/Web 应用的整个过程，涵盖需求、设计、编码、测试、部署；在 Flask 语境下是一套"路由+模板+数据库+表单"协作的套路。

## 它解决什么问题 / 为什么存在
- 把"用户想要一个能在线干 XX 的网站"这种模糊需求，落成可运行、可维护的系统。它提供一套通用流程和方法论，避免想到哪写到哪。

## 核心原理（大二能懂的水平）
- Web 程序遵循 **MVC** 思路：视图函数≈控制器(Controller，处理请求逻辑)、Jinja2 模板≈视图(View，负责展示)、SQLAlchemy 模型≈模型(Model，管数据)。
- 标准流程：需求分析 → 设计(路由/数据模型/页面) → 开发(用 Flask 搭骨架、分蓝本) → 测试 → 部署(WSGI 服务器)。
- 本书留言板案例正是"用包组织 + 配置分离 + 工厂模式"这一套。

## 关键参数 / 易错点
- 别一上来就写代码，先想清"有哪些页面(路由)、要存什么数据(模型)、怎么交互(表单)"。
- 大项目用程序工厂 + 蓝本 + 实例文件夹分配置。
- 配置(SECRET_KEY/数据库URI)与代码分离。
- 开发用调试模式、上线用 WSGI 服务器 + 关闭调试。
- 易错：把所有东西写进一个文件、把密钥提交到代码库。

## 类比（帮助理解）
- 像盖房子：先画图纸(需求/设计) → 搭框架(Flask 骨架) → 砌墙装修(模板/页面) → 通水电(数据库/表单) → 验收交付(测试/部署)。Flask 是工具箱，MVC 是户型图。

## 设计时怎么用（反推思维）
> 接到"做个在线请假系统"的需求时，我会反推：需要登录([[用户认证Web]]) + 请假表单([[Web表单]]) + 请假记录库([[数据库集成Flask]]) + 列表页([[模板引擎Jinja2]]) + 按模块拆([[蓝本Blueprint]])，用 Flask 把这些拼起来，而不是直接堆代码。

## 典型应用 / 我在哪见过
- 内容站、SaaS、内部系统、API 服务；本书留言板/个人博客即范例。
- 开发流程参考：本书第7章留言板"需求→设计→开发→测试→部署"完整走一遍。
