# 静态文件

## 一句话定义
> 静态文件是服务器**直接返回、不动态生成**的文件：CSS、JavaScript、图片、字体、下载附件等。

## 它解决什么问题 / 为什么存在
- 这些文件内容固定，每次都让 Python 现算一遍是浪费；应由服务器高效、带缓存地直接发给浏览器，甚至不让 Python 参与。

## 核心原理（大二能懂的水平）
- 框架提供静态目录与路由：[[Flask]] 默认从 `/static` 取（`url_for('static', filename=...)`），[[Django框架]] 用 `STATIC_URL` + `STATICFILES_DIRS`。
- 开发模式下框架顺手帮你发；**生产环境**一般把静态文件交给 Nginx 直接托管，根本不经过 Python（见 [[Web部署]]）。

## 关键参数 / 易错点
- 开发方便 ≠ 生产可用：框架发静态文件性能差，扛流量必须用 Nginx/对象存储。
- 路径与 URL 配置易错（`STATIC_URL`、`STATIC_ROOT`、收集命令 `collectstatic`）。
- **缓存破坏**：文件更新后浏览器还用旧的，常见做法给文件名加 hash 或加版本查询参数。

## 类比（帮助理解）
- 像快餐店里的"固定套餐窗口"：直接递给你（不用现做），和"现点现做的菜品"（动态请求经由视图计算）走不同通道，效率更高。

## 设计时怎么用（反推思维）
> 做站点时，我会把 CSS/JS/图片当静态资源，开发用框架目录、上线交给 Nginx/CDN，并在 [[Web部署]] 里专门配置静态路由与缓存。

## 典型应用 / 我在哪见过
- 网站样式与脚本、用户上传的头像/附件、前端打包产物（dist/）。
