# 路由(Web)

## 一句话定义
> 路由是"URL 规则 → 视图函数"的映射表；在 Flask 里用 `@app.route('/路径')` 装饰器把某个函数注册成某个网址的处理器。

## 它解决什么问题 / 为什么存在
- 一个网站有几十个页面（/、/about、/user/123），你需要决定"用户访问某个网址时该跑哪段代码、返回什么"。路由机制自动按 URL 分发，你只管写处理函数。

## 核心原理（大二能懂的水平）
- 你写的 `@app.route('/user/<int:uid>') def user(uid): ...` 会被 Flask 登记进 `app.url_map`。
- 当请求进来，Flask 拿请求路径去 url_map 里匹配规则，提取 URL 变量（如 uid=123），转换成对应类型后传给你函数。
- 端点（endpoint）是规则的内部名字，默认是视图函数名（可用 `endpoint=` 覆盖）。

## 关键参数 / 易错点
- 转换器 `<string>/<int>/<float>/<path>/<any>/<uuid>` 决定变量类型，写错类型匹配不上会 404。
- 同一个函数可绑多个 `@app.route`；`methods=['GET','POST']` 限定允许的方法，默认只 GET。
- `url_for('函数名', uid=123)` 反向生成 URL，比硬编码字符串更稳（改路由不用全局改链接）。
- 忘了设 `methods` 就 POST 会返回 405 Method Not Allowed。

## 类比（帮助理解）
- 像公司前台的分机转接表：电话号码（URL）→ 对应部门（函数）。拨 123 转技术部，拨 456 转人事部。

## 设计时怎么用（反推思维）
> 做带用户中心的系统时，我会用 `<int:uid>` 动态路由做"个人主页"，一个函数通吃所有用户，URL 里的数字自动变成函数参数，省去手动解析查询字符串。

## 典型应用 / 我在哪见过
- 博客文章页 `/post/<int:id>`、用户主页、RESTful 资源路径。
- 本书：`flask routes` 命令可查看当前所有路由规则。
