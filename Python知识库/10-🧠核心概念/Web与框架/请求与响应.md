# 请求与响应

## 一句话定义
> 请求与响应是 Web 通信的基本循环：浏览器发"请求(request)"给服务器，服务器处理后回"响应(response)"，Flask 用 request 对象和 Response 对象分别代表这两头。

## 它解决什么问题 / 为什么存在
- 你写的 Web 程序本质是"收信→读信→写信回"的循环。Flask 把这些原始 HTTP 报文封装成好用的对象，让你用 `request.args`、`request.form` 取数据，用 `return`/重定向/`jsonify` 回数据，不用自己拆字节流。

## 核心原理（大二能懂的水平）
- HTTP 请求报文含 请求行(方法+URL+版本)、请求头、请求体；Flask 解析后放进 `request` 对象：`request.method`(GET/POST…)、`request.args`(URL查询)、`request.form`(表单)、`request.files`、`request.cookies`。
- 响应则是 状态码+响应头+响应体；视图函数返回值会被 Flask 自动包成 Response。
- Flask 用"上下文"把 request/session 变成"当前请求内全局可访问"的对象：程序上下文 `current_app`、请求上下文 `request`+`session`。

## 关键参数 / 易错点
- GET 参数在 `request.args`，POST 表单在 `request.form`，弄混取不到值。
- `request` 只能在"请求上下文激活时"用（视图函数内），在脚本顶层用会报错。
- `redirect()` 做跳转、`abort(404)` 抛错误、`make_response()` 自定义、`jsonify()` 回 JSON（设了正确 MIME）。
- `session` 是加密 Cookie（需 `SECRET_KEY`），别存敏感明文；Cookie 用 `response.set_cookie()`。

## 类比（帮助理解）
- 像快递：你(浏览器)填好寄件单(请求:地址=URL，方法=寄/取，包裹=body)交给驿站(服务器)，驿站打包回执(响应:状态码=是否成功，回执内容=body)给你。

## 设计时怎么用（反推思维）
> 做登录功能时，我会用 `request.form` 取账号密码、校验后用 `session['user_id']=...` 记登录态、`redirect()` 跳回首页——一个完整的"收请求→处理→回响应"闭环。

## 典型应用 / 我在哪见过
- 处理表单提交、返回 API 的 JSON、文件上传、登录态保持、自定义错误页。
- 本书：`before_request`/`after_request` 等请求钩子可在请求前后统一插逻辑。
