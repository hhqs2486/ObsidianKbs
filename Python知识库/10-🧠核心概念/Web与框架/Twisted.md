# Twisted

## 一句话定义
> Twisted 是一个成熟的**异步网络编程框架**（不止 Web），基于事件驱动的 reactor 模式，一套异步模型支持 HTTP、TCP、SSH、SMTP 等几十种协议。

## 它解决什么问题 / 为什么存在
- 用同步阻塞方式写多协议网络服务，每种协议、每个连接都占资源，难以扩展；Twisted 用统一的事件循环 + 回调链，让你用一套异步范式写各种网络协议。

## 核心原理（大二能懂的水平）
- `reactor` 是总事件循环，负责监听和分发事件（"只 run 一次"）。
- `Deferred` 管理异步结果：把"成功时做什么、失败时做什么"的回调先挂上，结果到了再依次执行（避免层层嵌套的回调地狱）。
- `Protocol`/`Factory` 描述连接怎么处理（收到数据、断开连接）。
- Web 只是它的一部分（twisted.web），更多用在底层网络服务。

## 关键参数 / 易错点
- `reactor.run()` 只能调用一次，且是阻塞的"主循环"。
- 在回调里写阻塞代码会拖垮整个 reactor。
- 学习曲线陡：Deferred、Protocol 概念多，调试异步链较难。

## 类比（帮助理解）
- 像"总调度中心"（reactor）：不同专线（HTTP/TCP/SSH）打进来的电话，按协议转给对应的接线员（Protocol），Deferred 就是"先记下来、结果到了再回拨"的待办单。

## 设计时怎么用（反推思维）
> 当需求不是普通网站，而是"多种网络协议的服务端/客户端"（如自定义 TCP 服务、代理、IRC 机器人）时，我会选 Twisted——它把网络层的异步细节封装好了。

## 典型应用 / 我在哪见过
- 自定义协议服务器、网络代理、IM 后端、爬虫调度、SSH/Telnet 服务。
- 本书中 Twisted 作为四大框架之一，侧重其底层网络编程能力。
