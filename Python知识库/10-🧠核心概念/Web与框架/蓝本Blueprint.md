# 蓝本Blueprint

## 一句话定义
> 蓝本（Blueprint）是 Flask 里用来"分模块组织路由和视图"的机制，把一大堆功能拆成多个可插拔的子单元，再统一注册到主程序。

## 它解决什么问题 / 为什么存在
- 小项目所有路由写在一个文件还行；但大项目有用户模块、博客模块、API 模块，全堆一起会爆炸、难协作。蓝本让每个模块自带自己的路由/模板/静态文件，像积木一样拼进主程序。

## 核心原理（大二能懂的水平）
- 用 `bp = Blueprint('auth', __name__)` 建一个蓝本，像普通 `@app.route` 那样写 `@bp.route('/login')`。
- 最后在程序工厂里 `app.register_blueprint(bp, url_prefix='/auth')` 把它挂上去，`url_prefix` 给该模块所有路由加统一前缀。
- 书上原理章指出：蓝本本质是一组"待注册"的操作记录，注册时才真正绑进 app 的 url_map。

## 关键参数 / 易错点
- `url_prefix` 控制前缀（如 /auth，注意别写重复斜杠）。
- 蓝本间 `url_for('auth.login')` 要带蓝本名作端点前缀。
- 蓝本自己的模板/静态文件放在 `blueprints/auth/templates` 子目录。
- 视图里用 `current_app` 而非全局 `app`（配合工厂模式）。
- 易错：在蓝本定义阶段就调用需要 app 的配置（应在注册/请求时取）。

## 类比（帮助理解）
- 像乐高分装包——"动力组""外观组"各自拼好，最后按说明书拼成整车；也像公司按"部门"分楼层，每个部门有自己的门牌规则。

## 设计时怎么用（反推思维）
> 做含前台+后台+API 的博客时，我会拆成 `blog`/`admin`/`api` 三个蓝本，各自管自己的路由和模板，`url_prefix` 分别设 `/`、`/admin`、`/api`——多人并行开发互不打架。

## 典型应用 / 我在哪见过
- 多模块大型 Flask 项目、插件式功能、前后台分离、REST API 版本管理。
- 本书留言板用"程序包 sayhello"组织（`__init__.py` 构造文件 + settings.py 配置）。
