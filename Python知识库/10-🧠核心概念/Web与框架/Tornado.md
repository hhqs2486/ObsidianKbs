# Tornado

## 一句话定义
> Tornado 是一个 Python Web 框架 + 自带异步 Web 服务器，核心是**事件循环 + 非阻塞 I/O**，天生适合长连接、高并发（聊天室、WebSocket、实时推送）。

## 它解决什么问题 / 为什么存在
- 传统同步框架（如早期 WSGI 框架）每来一个连接就占一个线程/进程，连接多了线程爆满（C10K 问题）。Tornado 用单线程事件循环同时照看成千上万连接，空闲时绝不阻塞。

## 核心原理（大二能懂的水平）
- 自带 `IOLoop` 事件循环：谁的数据就绪就处理谁，不用等。
- 视图用 `@gen.coroutine`/`yield` 或 `async def` 写异步；耗时 IO 用非阻塞客户端（如 `AsyncHTTPClient`）。
- 它**自己实现了 HTTP 服务器**，可以不依赖 WSGI 直接 `app.listen(8000)` 跑起来。

## 关键参数 / 易错点
- **最大坑**：在 handler 里写同步阻塞调用（慢查询、requests.get、time.sleep）会卡死整个事件循环——必须全部异步化。
- 与 WSGI 生态不通用（它有自己的接口），要接 WSGI 中间件需适配层。
- 协程写法、异常处理要小心（异常吃掉会静默失败）。

## 类比（帮助理解）
- 像一个服务员同时照看多桌：哪桌举菜单（IO 就绪）就去哪桌点单，而不是一桌配一个专属服务员（每连接一线程）。

## 设计时怎么用（反推思维）
> 做实时聊天、消息推送、WebSocket、长轮询这类"大量连接挂着等事件"的系统时，我会用 Tornado——它不靠堆线程，而是靠事件循环扛并发。

## 典型应用 / 我在哪见过
- 实时聊天室、在线协作白板、行情推送、长连接 API。
- 本书中 Tornado 作为四大框架之一，重点演示异步非阻塞开发。
