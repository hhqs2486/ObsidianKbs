# Flask

## 一句话定义
> Flask 是一个用 Python 写的轻量级 Web 微框架，核心只提供最小可用的 Web 程序骨架，其余功能靠扩展按需添加。

## 它解决什么问题 / 为什么存在
- 从零用 Python 写一个能接收 HTTP 请求、返回网页的程序非常繁琐（要自己解析请求、写路由、拼响应）。Flask 把"最小可用"标准化，让你几行代码就能起一个网站，又不会用一堆默认约定绑死你。

## 核心原理（大二能懂的水平）
- Flask 程序是一个 Flask 类的实例 `app = Flask(__name__)`。
- 它内部用 **Werkzeug**（WSGI 工具集）来真正和 Web 服务器打交道、解析请求；用 **Jinja2** 来渲染 HTML 模板。
- 你在视图函数里 `return '...'`，Flask 帮你包成合法的 HTTP 响应。
- 哲学是"微"：核心小，所有进阶能力（数据库、表单、登录）都是可选扩展，需要时 `pip install` 再 `foo = Foo(app)` 初始化即可。

## 关键参数 / 易错点
- `Flask(__name__)` 的 `__name__` 决定静态文件/模板的相对查找路径，乱改会找不到模板。
- `flask run` 前必须设 `FLASK_APP` 告诉它程序入口文件。
- 调试模式（新版 `flask --debug run`）才开自动重载和交互调试器，但**绝不能上生产**。
- `SECRET_KEY` 不设置则 session/Cookie 签名不可用。

## 类比（帮助理解）
- 像买一辆裸车（发动机+轮子=核心），想要空调、倒车雷达自己后装。对比 Django 像"精装房"，拎包入住但改动受限。

## 设计时怎么用（反推思维）
> 做个人博客 / 内部工具 / API 这类中小型系统时，我会用 Flask 当骨架——因为它够轻、依赖少、我能完全控制目录结构和每一个中间件，而不被大框架的约定束缚。

## 典型应用 / 我在哪见过
- 个人博客、留言板、REST API、原型验证、公司内部小工具。
- 本书最小程序：`app = Flask(__name__)` + `@app.route('/')` 返回 `<h1>Hello, Flask!</h1>`。
