# 中间件

## 一句话定义
> 中间件（Middleware）是夹在"请求进来"和"响应出去"之间的一层**可插拔处理管线**，对每个请求/响应统一做加工，而不必写进每个视图。

## 它解决什么问题 / 为什么存在
- 登录校验、访问日志、CORS、Gzip 压缩、限流、防 CSRF 这些"横切关注点"如果塞进每个视图会重复到崩溃。中间件把它们抽出来，统一拦截所有流量。

## 核心原理（大二能懂的水平）
- 请求先依次穿过中间件链 → 到达视图（View）→ 响应再逆序穿过中间件链返回浏览器。
- 每个中间件可以：读/改 `request`、读/改 `response`，甚至**直接短路返回**（如未登录直接返回 403，不再往后走）。
- [[Django框架]] 中间件是类、`settings.MIDDLEWARE` 列表按顺序加载；[[Flask]] 用 `@app.before_request` / `after_request` 或 WSGI 中间件。

## 关键参数 / 易错点
- **顺序敏感**：认证中间件要在日志/路由之前还是之后，影响行为；顺序错会出诡异 bug。
- 中间件里别做重 IO / 阻塞操作，会拖慢所有请求。
- [[Tornado]]/[[ASGI]] 异步体系里，中间件也要写成异步，否则卡事件循环。

## 类比（帮助理解）
- 像小区门禁 + 快递柜 + 监控：每个包裹（请求）进出都要过几道统一关卡检查，而不是每个住户自己装一套。

## 设计时怎么用（反推思维）
> 做"所有请求都要做"的事（鉴权、记日志、跨域、限流）时，我会写中间件统一处理，而不是在几十个视图里复制粘贴。

## 典型应用 / 我在哪见过
- 登录态校验、请求日志、CORS 头、HTTPS 重定向、API 限流、CSRF 防护。
