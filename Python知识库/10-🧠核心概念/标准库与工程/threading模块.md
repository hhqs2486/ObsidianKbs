# threading 模块

## 一句话定义
> threading 让程序「同时跑多个线程」：在单个进程内并发执行任务，适合 I/O 等待密集型场景。

## 它解决什么问题 / 为什么存在
- 单线程下，等网络/磁盘时 CPU 干瞪眼。多线程让一个线程等 I/O 时别的线程继续跑。
- 注意：受 [[GIL影响]]（全局解释器锁）限制，CPU 密集型计算无法靠它真正并行加速。

## 核心原理（大二能懂的水平）
- **类比**：一个厨房（进程）里多个厨师（线程）共用灶台和冰箱。切菜（I/O 等待）时另一个厨师炒菜——协作提速；但同一时刻只有一个厨师能用灶台（GIL）。
- `Thread(target=func, args=(...)).start()` 启动；`t.join()` 等它结束。

## 关键参数 / 易错点
- 共享变量要加锁：`lock = threading.Lock(); with lock:` 保护临界区，否则数据竞争。
- `daemon=True` 的线程随主线程退出而强制结束。
- 易错：线程间共享状态要同步，否则结果随机错；CPU 密集任务用 [[multiprocessing模块]] 而非 threading。
- `queue.Queue` 是线程安全的任务队列，比手搓锁更稳。

## 设计时怎么用（反推思维）
> 做「爬虫/网络请求」这种大量等待 I/O 的任务时，我会用 threading + Queue 并发抓取，避开 GIL 无关瓶颈。

## 典型应用 / 我在哪见过
- 并发下载多个文件。
- 后台定时任务线程。
