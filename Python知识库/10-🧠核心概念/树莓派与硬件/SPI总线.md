# SPI总线

## 一句话定义
> SPI（Serial Peripheral Interface，串行外设接口）是一种「全双工、四线制、主从式」的高速串行总线，用单独的「片选线」来指定和哪个从设备通信，适合树莓派与屏幕、Flash、高速 ADC 等打交道的场景。

## 它解决什么问题 / 为什么存在
- I2C 两根线省引脚但慢、且一主多从靠地址轮流喊；SPI 用更多线换来更高速度、更简单协议、全双工同时收发，适合数据量大或对时延敏感的器件（显示屏、存储器、射频模块）。

## 核心原理（大二能懂的水平）
- **四根信号线**：
  - SCLK 时钟（主发）
  - MOSI 主发从收（Master Out Slave In）
  - MISO 主收从发（Master In Slave Out）
  - SS/CS 片选（每挂一个从设备就多一根，拉低表示「选你」）
- **全双工**：时钟驱动下，主从同时各发一位，一个字节来回就传完，所以比 I2C 快得多（可达几十 MHz）。
- **无地址、靠片选**：不像 I2C 用地址点名，SPI 用专用片选线「物理点名」每个从设备。

## 关键参数 / 易错点
- **引脚开销**：每多一个从设备就多一根片选线，设备多了引脚紧张（这是它和 I2C 的取舍）。
- **模式配置**：由 CPOL（时钟极性）和 CPHA（采样相位）组合成 4 种模式，主从必须一致否则数据错乱。
- **无硬件应答**：SPI 本身没有「收到没」的确认机制，可靠性靠上层协议保证。
- **电平/速率匹配**：高速下走线、干扰、电平不匹配都会出问题。

## 类比（帮助理解）
- SPI 像多个独立窗口的银行柜台：每个柜员（从设备）有专属叫号灯（片选线），灯亮才为你服务；你和柜员同时递单收单（全双工），比排队喊号（I2C）快。

## 设计时怎么用（反推思维）
> 做「树莓派驱动 TFT 彩屏 / 读高速 ADC / 接 SPI Flash」这类要吞吐量的系统时，我会选 SPI 而非 I2C；在 Python 里配置好正确的模式(CPOL/CPHA)与时钟分频，用 spidev 按片选逐设备通信。

## 典型应用 / 我在哪见过
- 液晶屏/OLED 驱动、SD 卡（SPI 模式）、SPI Flash、RF 无线模块、高速 ADC。
