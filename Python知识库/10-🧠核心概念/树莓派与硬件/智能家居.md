# 智能家居

## 一句话定义
> 智能家居是把照明、门锁、温控、安防等家用设备通过嵌入式硬件（如树莓派）联网、并用软件统一感知与控制的系统，是物联网在「家庭」场景的落地形态。

## 它解决什么问题 / 为什么存在
- 传统家电各自为政、无法联动。智能家居让设备互通：人离家自动关灯断电、温度异常自动报警、语音一句话控制全屋——把「单点功能」升级为「场景化体验」。
- 对学习者而言，它是把 [[传感器]]、[[GPIO]]、[[物联网MQTT]]、云端服务串成完整系统的绝佳综合项目。

## 核心原理（大二能懂的水平）
- **感知层**：用 [[传感器]]（温湿度、人体红外、门磁）采集家庭状态。
- **控制层**：树莓派通过 [[GPIO]]/继电器/[[电机驱动]] 控制灯、窗帘、锁、阀门。
- **连接层**：设备经 [[物联网MQTT]] 或 HTTP 与家庭网关/云端通信。
- **应用层**：手机 App / 语音助手发指令，规则引擎做「如果…就…」的自动化（如温度>28℃ 且 有人 → 开空调）。
- 常见开源中枢：Home Assistant、OpenHAB，树莓派常作本地网关。

## 关键参数 / 易错点
- **可靠性优先**：家里网络一抖就不能开灯会很糟，关键链路尽量本地化、不依赖外网。
- **安全与隐私**：摄像头/门锁数据极敏感，必须加密 + 鉴权，别明文上云。
- **供电与散热**：7×24 运行的树莓派要注意电源稳定与散热。
- **状态一致性**：设备离线后重连，要用 MQTT 保留消息/遗嘱保证状态不「假在线」。

## 类比（帮助理解）
- 智能家居像给房子装了「神经系统」：传感器是感觉神经（知道冷热处理），树莓派是脊髓（本地反应），云端是大脑（远程思考与记忆）。

## 设计时怎么用（反推思维）
> 做「家庭自动化」系统时，我会以树莓派做本地网关：传感器数据经 MQTT 上报，自动化规则在网关或云端判定后下发控制指令到执行器；核心设备本地闭环，保证断网也能用。

## 典型应用 / 我在哪见过
- 灯光/窗帘联动、温湿度自动调节、门磁安防报警、语音控制。
