# 串口UART

## 一句话定义
> UART（Universal Asynchronous Receiver/Transmitter，通用异步收发器）是一种「两根线（TX 发 / RX 收）、不带时钟、靠双方事先约定波特率」的串行通信方式；在 Linux 下它表现为一个设备文件（如 `/dev/ttyAMA0`），用起来像读写 [[文件IO]]。

## 它解决什么问题 / 为什么存在
- 很多模块（GPS、蓝牙、某些传感器、Arduino）只会「说串口」。UART 是最古老也最通用的「两个芯片之间一根线对一根线」对话方式，不需要共享时钟线，接线极简。
- 也常作为树莓派与另一个单片机（如 Arduino/STM32）之间的「调试 + 数据」通道。

## 核心原理（大二能懂的水平）
- **异步**：双方没有公共时钟线，靠「都说好每秒传多少位（波特率，如 9600/115200）」来对齐。发方在数据前后加起始位、停止位，收方据此切分字节。
- **交叉连接**：A 的 TX 接 B 的 RX，A 的 RX 接 B 的 TX——像两人对讲，你的嘴对着对方的耳。
- **在 Linux 即文件**：树莓派把串口暴露成 `/dev/tty*` 设备文件，Python 用 `pyserial` 打开它、`read/write` 就像操作文件流，所以和 [[文件IO]] 思路一致。
- 电平可能是 3.3V TTL，也可能是老式 RS-232（±12V），二者不能直接互连，需转换芯片。

## 关键参数 / 易错点
- **波特率必须一致**：双方波特率不同会读到乱码，是最常见故障。
- **TX/RX 别接反**：接反了双方都「听」不到对方。
- **电平标准**：TTL(3.3V) 与 RS-232 不可直连，需 MAX3232 之类转换。
- **阻塞读取**：串口 `read` 可能一直等数据，需设超时或放在 [[并发编程]] 的任务里，避免卡死主线程。

## 类比（帮助理解）
- UART 像两个约定好语速的人用对讲机：没时钟打拍子，但都按「每秒说 N 个字」同步；你说（TX）我听（RX），交叉着来。

## 设计时怎么用（反推思维）
> 做「树莓派 + GPS/蓝牙/下位机」通信系统时，我会用 `pyserial` 以设备文件方式打开串口，固定波特率与超时，把解析放在独立线程/协程里（参考 [[并发编程]]），避免阻塞主逻辑。
