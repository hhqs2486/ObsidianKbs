# 嵌入式Python

## 一句话定义
> 嵌入式 Python 是指在资源受限的嵌入式硬件（微控制器、树莓派等）上运行 Python 来操控硬件、处理数据的开发方式，让开发者用高级语言直接读写引脚、跑算法，而不必写底层 C。

## 它解决什么问题 / 为什么存在
- 传统嵌入式开发要精通 C/汇编、寄存器、交叉编译，门槛高。嵌入式 Python（树莓派上的 CPython、MCU 上的 MicroPython）把「控制硬件」这件事变得和写普通 Python 一样简单，大幅降低物联网/机器人原型开发成本。

## 核心原理（大二能懂的水平）
- **两种形态**：
  - **树莓派等 Linux 板**：跑完整 CPython，直接 `import RPi.GPIO` 操作 [[GPIO]]，还能用 pip 装海量库（见 [[包管理pip]]），本质是一台小电脑。
  - **微控制器（MicroPython）**：把 Python 解释器烧进 MCU（如 ESP32），用 `machine.Pin` 等统一 API 操作硬件，无需操作系统。
- **统一硬件抽象**：不同板子用相近的 Python API 表达「点灯/读脚/定时」，代码可移植。
- **和通用 Python 的差别**：要注意内存小、无硬盘、实时性弱、IO 直接连物理世界（见 [[文件IO]]、[[并发编程]] 做异步采集）。

## 关键参数 / 易错点
- **资源限制**：MCU 上 RAM/Flash 很小，避免大对象、频繁 GC；树莓派虽强也要注意 7×24 稳定性。
- **实时性弱**：CPython 有 GIL 与 GC 停顿，硬实时控制要下沉到 C/单片机或用实时协处理器。
- **阻塞 IO**：读传感器/串口要用非阻塞或 [[并发编程]]/[[协程]]，别让主循环卡死。
- **包管理差异**：MicroPython 用 `upip`/离线拷贝，不是桌面 pip 全量。

## 类比（帮助理解）
- 嵌入式 Python 像给单片机装了个「同声传译」：你用舒服的 Python 说话，它实时翻译成硬件听得懂的电平动作，省去你啃寄存器手册。

## 设计时怎么用（反推思维）
> 做「物联网边缘节点」时，我会按算力选型：要跑视觉/数据库就上树莓派用完整 Python + pip 生态；只要采数+联网就上 MicroPython 省电省成本。两类都用统一 Python 思维，降低开发与维护负担。
