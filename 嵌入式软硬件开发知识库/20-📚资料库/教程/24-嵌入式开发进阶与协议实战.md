# 24-嵌入式开发进阶与协议实战

## 这条教程在解决什么
- 覆盖 ARM 体系结构、QT 开发、嵌入式协议总线（CAN/I²C/SPI/蓝牙）、嵌入式工程实践（代码模板、架构设计、日志系统、问题排查方法、芯片手册阅读）。
- 作为现有 FreeRTOS 教程系列（14-19）和 STM32 教程（04-07）的补充和进阶。

## 关键步骤（我照着做的）

### 1. ARM 体系结构基础
- **ARM 处理器家族**：Cortex-M（MCU，STM32用）、Cortex-A（应用处理器，树莓派/i.MX用）、Cortex-R（实时处理器）
- **工作模式**：User/System/Supervisor/IRQ/FIQ/Undefined/Abort/Monitor（7 种模式，Cortex-A 特有）
- **寄存器**：R0-R12（通用）、R13/SP（栈指针）、R14/LR（链接寄存器，存返回地址）、R15/PC（程序计数器）、CPSR（状态寄存器）
- **异常向量表**：复位（地址0x00）、未定义指令、软中断、预取中止、数据中止、IRQ、FIQ
- 理解 ARM 对阅读启动代码和中断处理非常重要

### 2. 嵌入式通信协议总线
参考 [[CAN]]、[[I²C]]、[[SPI]]、[[UART]]、[[BLE蓝牙]]、[[RS485总线]]：
- **CAN 总线**：差分信号（CAN_H/CAN_L）、多主架构、帧 ID 仲裁、标准帧（11位ID）和扩展帧（29位ID）、滤波器设置
- **I²C**：两线（SCL+SDA）、开漏输出需上拉电阻、7位地址、主从架构、标准模式 100kHz / 快速模式 400kHz
- **SPI**：四线（MOSI/MISO/SCLK/SS）、全双工、无固定协议标准、时钟极性（CPOL）和相位（CPHA）四种模式
- **蓝牙（BLE）**：低功耗、GATT 协议栈、Service/Characteristic 数据模型、AT 命令控制模块

### 3. QT 应用开发
- QT 是 C++ GUI 框架，也广泛用于嵌入式 Linux 图形界面
- **信号与槽（Signal & Slot）**：QT 的核心通信机制，类似回调但更安全。`connect(button, SIGNAL(clicked()), this, SLOT(onClicked()))`
- **QT Creator**：IDE 集成开发环境，支持拖拽式 UI 设计（`.ui` 文件）
- **交叉编译 QT**：在宿主机编译 QT 库 → 交叉编译应用程序 → 部署到嵌入式 Linux
- **QT 开源项目**：GitHub 上有大量嵌入式 QT 项目可参考

### 4. 嵌入式工程实践
**代码模板与架构**：
- 模块化分层：HAL 层（硬件抽象）→ Driver 层（驱动）→ Middleware 层（协议栈/文件系统）→ Application 层
- 每个 `.c` 配一个 `.h`：只在 `.h` 中暴露公开接口，`.c` 中 static 限定内部函数
- 参考 [[C语言编码规范]]

**日志系统**：
- 分级日志（DEBUG/INFO/WARN/ERROR）
- 输出到串口（UART）或文件系统
- 带时间戳和模块名标签：`[2026-07-23 10:30:00] [MQTT] INFO: Connected to broker`

**问题排查方法**：
- 二分法定位：注释掉一半代码看问题是否还在
- 日志打桩：关键路径每步打日志
- 看门狗：软硬件看门狗防止死机，参考 [[看门狗]]
- 常见错误：数组越界、空指针、栈溢出（递归或大局部变量）、堆碎片

**芯片数据手册阅读**：
- 先看 Overview/Features 了解芯片能做什么
- 再看 Pinout 确认引脚功能
- 找到对应外设章节，先看寄存器摘要再看详细描述
- 参考官方示例代码比从零写快得多。参考 [[STM32文档体系]]

**嵌入式开源项目**：
- GitHub 搜索 `stm32 project`、`freertos example`
- 学习项目结构而非只复制代码
- 关注 LICENSE（MIT/Apache 2.0 可商用，GPL 需开源衍生代码）

### 5. AT 命令通信模块
- AT 命令是控制通信模块（WiFi/蓝牙/GPRS/GPS）的标准指令集
- 格式：`AT+<CMD>=<params>\r\n` → 模块响应 `OK` 或 `ERROR`
- 嵌入式中实现 AT 解析器：发送命令 → 串口中断接收 → 环形缓冲区 → 超时判断 → 解析响应字符串
- 状态机设计：IDLE → SENDING → WAITING → PROCESSING → IDLE

### 6. STM32 知识增强
参考 [[STM32F103]]、[[FreeRTOS]]：
- 结合已有教程 [[04-STM32F103HAL库开发]]：
  - GPIO / EXTI 外部中断配置
  - 定时器：基本定时器（时基）、通用定时器（PWM/输入捕获）、高级定时器（互补输出+死区）
  - ADC：单次/连续/扫描模式，DMA 传输

## 我卡住/没懂的地方
- CAN 总线的仲裁机制初学时很难理解"ID 越小优先级越高"的原理 — 因为 CAN 总线是"线与"逻辑，显性位（0）会覆盖隐性位（1），ID 位逐位比较，谁先输出显性位谁赢。
- QT 的信号槽机制和回调区别：信号槽是**松耦合**的（发送者不知道接收者是谁），回调和函数指针是**紧耦合**的。
- 芯片手册动辄上千页，初学不要试图读完，学会"查"而非"读"。

## 它背后的原理（别只记操作）
- ARM 的 7 种工作模式设计是为了**权限分层**：User 模式受限（不能访问系统资源），Supervisor/IRQ 模式有特权。这是实现操作系统内核/用户态隔离的硬件基础。
- CAN 总线是**多主架构**，没有"主机"概念，所有节点平等。冲突时通过 ID 仲裁而非 CSMA/CD（以太网的做法）。
- AT 命令模块的状态机设计体现了嵌入式中的**异步通信处理**：不能阻塞等待回复，要用状态机 + 超时机制。

## 我能复用/改编的点
> 代码模板的分层架构可以从 STM32 项目直接迁移到任何 MCU 平台（GD32/ESP32/nRF52），只需换 HAL 层。
> AT 命令解析器的状态机可以适配任何通信模块，把命令表改成 JSON 配置文件即可移植。
