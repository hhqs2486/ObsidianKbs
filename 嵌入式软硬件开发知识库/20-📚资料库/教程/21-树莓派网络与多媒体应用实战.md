# 21-树莓派网络与多媒体应用实战

## 这条教程在解决什么
- 在树莓派 Linux 上完成 8 个完整的小项目：FTP 云盘、Socket 多线程聊天室、libcurl 人脸/车牌识别、MJPG-Streamer 视频流、SDL2 多媒体播放、智能家居 Android APP、贪吃蛇游戏、ncurses TUI 界面。
- 每个项目都是独立的可运行 Demo，适合从零开始参考代码结构和编译流程。

## 关键步骤（我照着做的）

### 1. FTP 云盘项目
参考 [[网络Socket编程]]：
- 实现 FTP 客户端和服务器，支持文件上传、下载、目录浏览
- 基于 TCP Socket，多线程处理并发连接
- 用 `fork()` 或 `pthread_create()` 为每个客户端创建独立进程/线程

### 2. Socket 多线程聊天室
参考 [[网络Socket编程]] 和 [[嵌入式数据库SQLite]]：
- **架构**：TCP Server（主线程 `accept` → 子线程 `recv/send`）+ 多客户端
- **数据加密**：使用常见的加密算法（AES/DES/Base64 编码）对消息内容加密后传输
- **SQLite 存储**：聊天记录存 SQLite 数据库（CREATE TABLE messages...），支持历史消息查询和用户登录验证
- **编译脚本**：`gcc.sh` 批量编译全部源文件

### 3. libcurl 库实现人脸/车牌识别
参考 [[网络Socket编程]]：
- libcurl 是 C 语言 HTTP 客户端库，支持 GET/POST/HTTPS/文件上传
- 调用百度 AI / 讯飞等云端 API：POST 上传图片 Base64 数据 → 解析 JSON 返回结果
- 关键步骤：`curl_easy_init()` → `curl_easy_setopt(URL/POSTFIELDS/TIMEOUT)` → `curl_easy_perform()`
- 车牌识别同理，换 API 地址和参数即可

### 4. MJPG-Streamer 视频流 + SDL2 播放
- **MJPG-Streamer** 类似于 Linux 管道：`cat /dev/videoX | encode to JPG | http_server`
  - 采集摄像头数据（V4L2 接口）→ JPEG 编码 → HTTP 服务器推流
  - 浏览器访问 `http://树莓派IP:8080/?action=stream` 看实时画面
- **SDL2 多媒体库**：用于本地显示和音频播放
  - `SDL_Init()` → `SDL_CreateWindow()` → 创建 Surface/Texture 渲染
  - 可以接收 MJPG-Streamer 的 JPEG 流，在本地窗口显示

### 5. 树莓派摄像头使用
- CSI 接口摄像头：`raspistill -o image.jpg`（拍照）、`raspivid -o video.h264`（录视频）
- USB 摄像头：通过 `/dev/video0` 和 V4L2 API 控制
- 语音识别模块：通过 USB 麦克风 + 云端 API 实现离线/在线语音识别

### 6. 智能家居 Android APP 开发
- Java + Android SDK 开发：`.xml` 布局文件 + `.java` Activity 逻辑
- 树莓派端做 TCP/HTTP Server，APP 通过 WiFi 连接控制继电器、读取传感器
- 开发经验：AndroidManifest.xml 权限声明、Activity 生命周期、网络请求必须异步（AsyncTask）

### 7. 贪吃蛇游戏（链表实战）
参考 [[链表]]：
- 用**链表**存储蛇身节点（每个节点是一节身体坐标）
- 蛇移动 = 在头部插入新节点 + 删除尾部节点（不吃食物时）
- 吃食物 = 只插入不删除；碰撞检测：穿墙/撞自己
- 三种模式：Easy（慢+可穿墙）、Hard（快+不可穿墙）、Auto（自动寻路）
- 控制：键盘方向键，`kbhit()+getch()` 无阻塞读取

### 8. ncurses 库 TUI 界面开发
- ncurses 是 Linux 下终端图形界面库（Text User Interface）
- 基本流程：`initscr()` → `printw()/mvprintw()` 在指定位置打印 → `refresh()` → `endwin()`
- 可用于开发终端版文件管理器、系统监控面板、贪吃蛇/俄罗斯方块等终端游戏
- 颜色支持：`start_color()` → `init_pair()` → `attron(COLOR_PAIR(n))`

## 我卡住/没懂的地方
- Socket 编程最容易卡的是**粘包/半包**：TCP 是流协议，`send("Hello")` + `send("World")` 可能被对方一次 `recv` 收到 "HelloWorld"。解决：定义应用层协议（长度前缀或特殊分隔符）。
- libcurl 的 HTTPS 需要 ca-certificates，树莓派上需 `apt install ca-certificates`。
- ncurses 编译需要链接 `-lncurses`，头文件 `#include <ncurses.h>`。

## 它背后的原理（别只记操作）
- FTP 协议（RFC 959）使用**双通道**：控制连接（21 端口，发命令）+ 数据连接（20 端口，传文件）。主动模式和被动模式的区别在于谁发起数据连接。
- Socket `accept()` 返回的新 fd 和监听 fd 是不同的描述符，这是理解服务端架构的关键。[[Linux文件IO与系统调用]]
- MJPG-Streamer 本质是 **生产者-消费者模式**：摄像头采集线程（生产者）→ JPEG 缓冲区 → HTTP 发送线程（消费者）。
- libcurl 内部使用**状态机**管理 HTTP 协议交互，封装了 DNS 解析、TCP 连接、TLS 握手、HTTP 请求/响应解析。

## 我能复用/改编的点
> Socket 聊天室的服务器架构可以直接改成物联网数据采集网关：每个传感器连接作为一个 Socket 客户端上报数据，服务端聚合并入库 SQLite。
> libcurl + API 的模式可以套用到任何云端 AI 服务（语音识别、OCR、图像分类），只需换 URL 和请求参数。
> ncurses 界面非常适合做嵌入式的本地调试终端或设备配置界面。
