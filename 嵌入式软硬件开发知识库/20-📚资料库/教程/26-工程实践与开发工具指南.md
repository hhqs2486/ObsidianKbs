# 26-工程实践与开发工具指南

## 这条教程在解决什么
- 覆盖嵌入式开发者的日常工具箱和工作习惯：从开源项目代码阅读方法论、GDB 调试、个人技术博客搭建，到 Markdown 写作、IDE 配置、文档注释规范、常见问题排查。
- 面向"不只写代码，还要能高效协作和专业输出"的进阶开发者。

## 关键步骤（我照着做的）

### 1. 小型 C 语言开源项目：Triggerhappy
Triggerhappy 是一个 Linux 下热键守护进程，代码量小、可读性好，是学习 C 语言工程实践的优秀范例：
- **阅读方法**：先看 README 和目录结构 → 从 `main()` 函数入口追踪调用链 → 理解核心数据结构 → 画出模块交互图
- **学什么**：命令行参数解析（`getopt`）、守护进程化（`daemon()`）、信号处理（`signal()`）、配置文件解析、`fork()` 子进程管理
- **阅读开源代码的三层递进**：
  1. 会编译运行，知道功能
  2. 能画出模块间调用关系
  3. 能指出设计的优点和不足，提出改进方案

### 2. GDB 调试实战
参考 [[GDB调试器]]：
- **段错误（Segmentation Fault）**：`gdb ./program core` → `backtrace` 直接看到崩溃位置
- **条件断点**：`break main.c:100 if x > 10`（只在条件满足时中断）
- **观察点**：`watch var`（var 值被修改时自动中断，排查"谁改了不该改的变量"神器）
- **信号捕获**：`handle SIGSEGV stop`（段错误时 GDB 接管而非直接崩溃）

### 3. 个人技术网站搭建
- 静态网站方案：Hexo/Hugo + GitHub Pages，免费托管
- 使用 Markdown 写文章，主题模板一键发布
- 建议内容：项目笔记、踩坑记录、技术总结 — 符合 [[C语言编码规范]] 的代码示例
- 价值：面试加分、知识归档、写作锻炼

### 4. 开发工具与效率
**MobaXterm / SecureCRT**：Windows 端 SSH/串口终端工具
- MobaXterm：内置 X Server（可在 Windows 显示 Linux GUI 程序）、SFTP 文件传输
- SecureCRT：稳定、支持录制脚本（自动化重复操作）

**Source Insight**：Windows 端 C/C++ 代码阅读神器
- 符号跳转、函数调用图、全局搜索速度快
- 配置步骤：新建工程 → 添加源码目录 → 同步文件 → 开始阅读

**VSCode**：跨平台通用编辑器
- 必备插件：C/C++（IntelliSense）、GitLens（git 可视化）、Remote SSH（远程开发）
- `.vscode/tasks.json` 配置编译任务，`launch.json` 配置 GDB 调试
- 嵌入式开发终极方案：VSCode Remote SSH 连接 Linux 开发机，所有代码和编译都在远端

### 5. 文档规范
**Markdown 语法**：
```markdown
# 一级标题
## 二级标题
**加粗** *斜体* `代码`
- 无序列表
1. 有序列表
> 引用
[链接文本](URL)
![图片描述](图片路径)
```

**代码注释**：
- `/* */` 用于文件头注释和多行注释
- `//` 用于单行注释
- 函数注释：描述功能、参数、返回值、注意事项
- 参考 Doxygen 格式：`@param` `@return` `@note` 可以自动生成 HTML 文档

### 6. 日常知识管理
**快捷方式汇总**：
- 文本编辑：`Ctrl+A` 全选、`Ctrl+Shift+箭头` 按单词选中、`Ctrl+D` 选中下一个相同词
- 终端：`Ctrl+L` 清屏、`Ctrl+R` 历史搜索、`Ctrl+C` 终止程序、`Ctrl+Z` 挂起
- 浏览器：`Ctrl+T` 新标签、`Ctrl+W` 关标签、`Ctrl+Shift+T` 恢复关闭的标签

**问题收集习惯**：
- 每个项目维护一个 `PROBLEMS.md` 记录踩坑
- 格式：现象 → 原因 → 解决方案 → 相关链接
- 参考 [[C语言高效编程技巧]]

### 7. 技术提升方向
- **T 型人才模型**：一竖（嵌入式 Linux 深耕）+ 一横（了解 Web/数据库/算法）
- **进阶路线**：裸机 MCU → RTOS → 嵌入式 Linux → Linux 驱动 → 系统架构
- **不可替代的能力**：系统级调试能力（不是调 API 而是调内核/驱动）、从需求到架构的设计能力
- **AI 辅助开发**：在嵌入式 C/C++ 项目中，AI 可以帮助理解旧代码、生成 HAL 配置、编写测试用例。参考 [[现代边缘AI推理引擎]]

## 我卡住/没懂的地方
- 开源项目阅读最怕"不知道从哪看起"。方法是：先 `grep main` 找到入口，再 `grep` 关键数据结构的定义和使用位置，逐步构建认知地图。
- VSCode 的 Remote SSH 配置有时候连不上，常见原因：远端 `~/.vscode-server` 目录权限问题，或远端 glibc 版本过低。

## 它背后的原理（别只记操作）
- Source Insight 的符号数据库原理：它解析所有源文件的语法树，建立符号→定义位置的索引。这和编译器的前端工作类似（词法分析+语法分析），只是不做代码生成。
- GitLens 的 blame 信息来自 `git blame` 命令，它可以精确到每一行是谁在哪个 commit 改的，是排查"这行代码为什么这么写"的最快方法。

## 我能复用/改编的点
> 个人网站/博客模板可以做成团队知识库，用 Markdown 统一格式，Git 管理版本。
> VSCode Remote SSH + Linux 开发机的模式推荐给所有嵌入式开发者，告别 Windows 虚拟机里慢悠悠的图形界面。
> 问题收集的 `PROBLEMS.md` 习惯应该从第一个项目就开始培养，比内存更可靠。
