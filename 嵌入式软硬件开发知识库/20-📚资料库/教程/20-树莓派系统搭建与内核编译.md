# 20-树莓派系统搭建与内核编译

## 这条教程在解决什么
- 从零开始在 Ubuntu 宿主机上为树莓派搭建交叉编译环境、编译定制化 Linux 内核、使用 wiringPi 库控制 GPIO、理解 Linux 动态库/静态库的制作和使用。
- 覆盖树莓派 3B/4B 两种型号的 32 位和 64 位编译配置。

## 关键步骤（我照着做的）

### 1. 树莓派交叉编译环境搭建
参考 [[交叉编译与根文件系统]] 和 [[编译工具链]]：
- 从 [raspberrypi/tools](https://github.com/raspberrypi/tools) 获取交叉编译工具链
- 解压后把 `arm-bcm2708/gcc-linaro-arm-linux-gnueabihf-raspbian-x64/bin` 加入 PATH
- 永久生效：在 `~/.bashrc` 末尾加 `export PATH=...`，然后 `source ~/.bashrc`
- 验证：`arm-linux-gnueabihf-gcc -v`

**编译 Linux 内核时使用的环境变量**：
```
ARCH=arm CROSS_COMPILE=arm-linux-gnueabihf- KERNEL=kernel7
```
- `ARCH=arm` — 目标架构（32位）
- `CROSS_COMPILE` — 交叉编译工具链前缀
- `KERNEL=kernel7` — 树莓派 2/3 用 kernel7，Pi 4 用 kernel7l，Pi 1/Zero 用 kernel

### 2. 树莓派 Linux 内核编译
**获取源码**：
```bash
git clone --depth=1 https://github.com/raspberrypi/linux
```

**配置内核**：
- 方式 1（推荐）：从运行中的树莓派获取配置 — `scp pi@[IP]:/proc/config.gz .` → `zcat config.gz > .config`
- 方式 2：用源码自带默认配置 — `make bcm2709_defconfig`（Pi 2/3）、`make bcm2711_defconfig`（Pi 4）
- 方式 3：`make menuconfig` 手动调整

**编译**：
```bash
make -j4 zImage modules dtbs 2>&1 | tee build.log
# -j4: 4 核并行  zImage: 内核镜像  modules: 驱动模块  dtbs: 设备树
```

**安装到 TF 卡**：
```bash
# 安装驱动模块
sudo make INSTALL_MOD_PATH=[ext4挂载点] modules_install
# 复制内核镜像
cp kernel_new.img [fat挂载点]/
# 复制设备树
cp arch/arm/boot/dts/*.dtb [fat挂载点]/
cp arch/arm/boot/dts/overlays/*.dtb* [fat挂载点]/overlays/
```

**本地编译（直接在树莓派上）**：只需设 `KERNEL=kernel7`，不需要 CROSS_COMPILE。速度慢（约 2 小时），适合小改动。

### 3. 静态库与动态库的制作
参考 [[编译工具链]]：
- **静态库** `.a`：编译时链接进可执行文件，体积大但独立运行。`ar cr libxxx.a file1.o file2.o`
- **动态库** `.so`：运行时加载，多个程序共享，节省空间。`gcc -shared -fPIC -o libxxx.so file.c`
- 树莓派交叉编译时，动态库需一同拷贝到目标板或放在标准库路径。

### 4. wiringPi GPIO 库开发
参考 [[wiringPi]] 和 [[GPIO]]：
- 安装：`git clone https://github.com/WiringPi/WiringPi` → `./build`
- 查看引脚映射：`gpio readall`（最关键命令，确认 wPi/BCM/物理编号对应关系）
- 基本操作：
  ```c
  #include <wiringPi.h>
  wiringPiSetup();           // 初始化 wiringPi 编号
  pinMode(0, OUTPUT);        // wPi 编号 0 设为输出
  digitalWrite(0, HIGH);     // 输出高电平
  int val = digitalRead(1);  // 读取输入
  ```
- 中断支持：`wiringPiISR(pin, INT_EDGE_RISING, &callback)` — 边沿触发调用 [[回调函数]]

### 5. 树莓派驱动开发入门
基于 Linux 内核驱动模型，参考 [[Linux驱动与内核模块]]：
- 写简单的字符设备驱动：`file_operations` 结构体注册 `open/read/write/ioctl`
- 模块编译 Makefile：
  ```makefile
  obj-m += mydriver.o
  all: make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules
  ```
- `insmod mydriver.ko` 加载 → `dmesg | tail` 查看日志 → `rmmod mydriver` 卸载

## 我卡住/没懂的地方
- 内核 .config 有几千个选项，第一次用 `menuconfig` 时完全不知道该选什么。解决方案：先用树莓派运行中的 `/proc/config.gz` 做 baseline，后续只改需要改的。
- 交叉编译工具链的 `arm-linux-gnueabihf-`（32位）和 `aarch64-linux-gnu-`（64位）不能混用，必须和目标内核版本完全匹配。

## 它背后的原理（别只记操作）
- 交叉编译的核心是"宿主机 CPU 架构 ≠ 目标机 CPU 架构"：宿主机 x86_64 用交叉编译器生成 ARM 机器码。[[编译工具链]]
- Linux 内核编译之所以要指明 `ARCH` 和 `CROSS_COMPILE`，是因为内核 Makefile 需要根据目标架构选择不同的启动代码（arch/arm/kernel/head.S）、内存模型、设备树解析逻辑。
- TF 卡的两个分区：FAT 放 bootloader/内核镜像（FAT 是树莓派 GPU 固件唯一能识别的文件系统），ext4 放根文件系统和驱动模块。这与 [[Bootloader]] 的"引导区 + 数据区"架构一致。

## 我能复用/改编的点
> 这套交叉编译流程（获取源码→配置→编译→安装到目标介质）是几乎所有嵌入式 Linux 平台（i.MX6ULL、全志、RK）的通用套路，只要换对应的交叉编译器、defconfig 和设备树即可。
> wiringPi 的 Linux 用户态 GPIO 控制思路也可以迁移到其他 SBC（如 Rockchip 的 libgpiod）。
