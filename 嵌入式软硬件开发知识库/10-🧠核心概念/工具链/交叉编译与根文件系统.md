# 交叉编译与根文件系统

## 一句话定义
- **交叉编译**：在 x86 PC 上用 `arm-linux-gnueabihf-gcc` 编译出能在 ARM 板子上跑的程序（板子太弱，不能原生编译）。
- **根文件系统 rootfs**：内核挂载后用户空间的"地基"——提供命令、C 库、配置文件、第一个进程 `/sbin/init`。

## 它解决什么问题 / 为什么存在
板子 CPU 弱、内存小，跑不了编译器；且应用程序依赖 C 库（glibc）和一堆系统文件，这些必须提前打包成"根文件系统"让内核挂载。没有 rootfs，内核起来也寸步难行（"kernel panic: no init found"）。

## 核心原理（大二能懂的水平）
**交叉工具链**：
- 前缀 `arm-linux-gnueabihf-`（gnueabihf = 硬浮点 ABI）；注意别和裸机 `arm-none-eabi-gcc`（无 OS、newlib）搞混（见 [[编译工具链]]）。
- 自带 **sysroot**（一套目标板的头文件 + 库），编译时链接的是目标板的 glibc。
- 编译四步（预处理→编译→汇编→链接）与 PC 相同，只是编译器换成交叉前缀；靠 Makefile / 构建系统管理。

**根文件系统组成**：
- `/bin`、`/sbin`：命令（`ls`、`ifconfig`…），常用 **busybox** 提供
- `/lib`：C 库等动态库（程序运行要找得到）
- `/etc`：配置文件（init 脚本、网络配置）
- `/dev`：设备节点
- `/sbin/init`：内核启动后运行的**第一个用户进程**，它读配置拉起其他程序

**调试**：开发阶段常用 **NFS** 把 PC 目录挂成板子根文件系统，改完程序不用重烧。uboot 的 `bootargs` 里 `root=/dev/nfs` 指定网络根文件系统。

## 关键参数 / 易错点
- 工具链 **ABI 不匹配**（gnueabihf vs gnueabi）→ 一运行就 Illegal instruction / 段错误。
- sysroot 库版本与板子不一致 → 运行时缺符号。
- rootfs 缺 `/lib` 的 C 库 → 程序起不来；缺 `/sbin/init` → kernel panic。
- 用 NFS 调试时 PC 防火墙/权限挡了挂载。

## 类比（帮助理解）
交叉编译像"在总厂（PC）按分厂（板子）的规格预制零件"；根文件系统像"板子开工后要的水电粮油库"，没它工人（进程）没法干活。

## 设计时怎么用（反推思维）
- 反推"程序为什么在板子上跑不起来"→ 八成是工具链 ABI 或 rootfs 缺库。
- 反推"怎么快速迭代"→ NFS 挂载 rootfs，PC 上改 PC 上编，板子直接跑。

## 典型应用
所有 ARM-Linux 开发：编译 app、制作固件镜像、部署到开发板。
