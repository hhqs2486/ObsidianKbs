# 功能框图

## 一句话定义
把需求拆解出的功能，画成「MCU / 电源 / 传感 / 执行 / 通信 / 人机交互」几大模块，并标清模块之间用什么信号、什么协议连——原理图的前置蓝图。

## 它解决什么问题 / 为什么存在
不画框图直接画原理图，容易漏模块（忘了电平转换、忘了复位电路）、信号流向混乱。框图让"谁和谁说话"先定下来，原理图只是把框图翻译成器件。

## 核心原理（大二能懂的水平）
1. 主控居中：MCU/MPU 是大脑，其他模块围绕它。
2. 六大类分区：
   - 电源：怎么把输入变成各路电压（[[线性电源LDO]] / [[开关电源DCDC]]）
   - 传感：采什么信号（[[ADC]]、[[I²C]] 传感器、[[SPI]] 器件）
   - 执行：驱动什么（[[直流电机驱动]]、继电器）
   - 通信：对外的口（[[UART]] / [[USB]] / 无线）
   - 人机：按键/屏/灯（[[GPIO]]）
3. 标连线类型：电源线(粗)、数字信号、模拟信号、通信协议名。
4. 标谁主控：I²C 谁是 Master、SPI 谁是 CS 选中的 Slave。

## 关键参数 / 易错点
- **易错**：框图不标协议 → 原理图时才发现 MCU 没有对应外设（如要 CAN 但选的型号没 CAN）。
- **易错**：忘了电平域 → MCU 是 3.3V，传感器是 5V，框图阶段就该标 [[电平转换]]。
- **易错**：模拟/数字不分区 → 后面布线串扰（见 [[布局与布线]]）。

## 类比（帮助理解）
像装修平面图：先定哪间是卧室(模块)、门开在哪(接口)、水电走哪(电源/地)，再买材料(器件)。

## 设计时怎么用（反推思维）
需求拆解的 MUST 列表 → 每项映射到一块模块 → 画框图标协议 → 检查 MCU 外设够不够（倒推 [[芯片选型]]）→ 框图定了才进 [[原理图推导思维]]。

## 典型应用
STM32 最小系统板、传感器节点、带屏网关。
