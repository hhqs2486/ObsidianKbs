# 硬件设计检查清单

## 一句话定义
打样前一张逐条打钩的核对表，覆盖 DRC / 电源时序 / 去耦 / 上电顺序 / 未用引脚 / 丝印 / BOM 一致性——把"返工"挡在工厂之前。

## 它解决什么问题 / 为什么存在
原理图画完肉眼很难发现所有坑：丝印反了、BOM 少料、电源没时序。清单把经验变成可复用的流程，每次打样前过一遍，成本远低于一次报废。

## 核心原理（大二能懂的水平）
打样前至少过这几类：
1. **DRC**：[[DRC设计规则]] 全过，无未连接网络、无间距违例。
2. **电源**：各路电压值对、[[去耦电容]] 齐全且靠脚、[[电源分割]] 无短路、上电顺序满足（内核先于 IO）。
3. **信号**：晶振包地、复位走线短、[[差分对与等长]] 满足（高速时）、[[阻抗控制]] 对（如 USB 90Ω）。
4. **引脚**：未用引脚按手册处理（拉高/拉低/输入禁用），boot 引脚电平正确。
5. **丝印**：位号朝向可读、极性/引脚1 标记清楚（[[丝印与位号]]）。
6. **BOM**：与原理图一致，封装名对（[[封装Footprint]]），关键料有替代。

## 关键参数 / 易错点
- **易错**：只过 DRC 不过电源时序 → 上电瞬间 IO 先于内核，可能闩锁。
- **易错**：丝印镜像 → 贴片反、调试找错脚。
- **易错**：BOM 封装写错（如 0603 写成 0805）→ 工厂贴不上或虚焊。

## 类比（帮助理解）
像考试交卷前检查：姓名写了没、选择题填涂对没、计算题单位对没。

## 设计时怎么用（反推思维）
清单从需求倒推：需求要"一次打样成功" → 清单必须覆盖每类已知故障 → 每次踩的坑都加进清单（养 [[40-🐞问题排查]] 笔记）。

## 典型应用
每次嘉立创打样前；企业级见 [[2026-OTA智能控制终端]] 的检查清单段。
