# CAN过滤器

## 一句话定义
bxCAN 外设里的"硬件筛子"——只让 ID 匹配的帧进接收 FIFO，挡掉不关心的帧，省 CPU 中断。

## 它解决什么问题 / 为什么存在
CAN 总线上帧很多，若全进中断 MCU 会被刷爆。过滤器在硬件层就过滤，软件只收"该收的"。**无数初学者倒在了没配过滤器→收不到任何帧。**

## 核心原理（大二能懂的水平）
- bxCAN 有 **14 个过滤器组**(bank 13~0)，互联型 28 个。每组 = 2 个 32 位寄存器 `CAN_FxR1`/`CAN_FxR2`，可配 **16 位或 32 位**宽。
- 两种模式：
  - **屏蔽位模式(mask)**：`FxR1`=期望 ID，`FxR2`=屏蔽字。屏蔽位=1→收到的该位必须与 ID 一致；=0→不关心。可实现一个 ID、一段 ID 区间(0x310~0x317)、或全收(0x000~0x7FF)。
  - **标识符列表模式(list)**：`FxR1`/`FxR2` 都当 ID，收到的帧必须和其中之一完全相同才收——只能收 2 种 ID(32位)或 4 种(16位)。
  - 16 位模式 = 把两个 32 位寄存器拆成 4 个 16 位，原理同 32 位。
- 发送：`CanTxMsg`(StdId/ExtId/IDE/RTR/DLC/Data[8])；接收：`CanRxMsg`(多一个 `FMI`=命中的过滤器编号)。

## 关键参数 / 易错点
- **最大坑**："过滤器里的 ID" 和"你发出去帧的 ID" 是两个不同寄存器、两回事——`FxR1` 是"防守"用的，发送 `StdId` 是"进攻"用的。
- 标准帧 ID 11 位(0~0x7FF)，扩展帧 29 位(0~0x1FFFFFFF)。
- 过滤器必须配置并激活，否则默认全关 → 收不到任何帧。
- 双 CAN 时要决定过滤器组分配给 CAN1 还是 CAN2。

## 类比（帮助理解）
像公司前台——只放行工牌号在白名单(列表模式)或符合某规则前缀(屏蔽模式)的访客。

## 设计时怎么用（反推思维）
需求(只收 0x317 控制帧) → 选 32 位屏蔽模式，`FxR1`=0x317 对齐位，`FxR2` 对应位=1 → HAL：`CAN_FilterInitTypeDef` 配 `FilterIdHigh/Low`、`MaskIdHigh/Low` + `FilterMode=CAN_FILTERMODE_IDMASK` + `FilterScale=CAN_FILTERSCALE_32BIT`。

## 典型应用
多节点网络中只处理发给自己的命令帧；网关按 ID 区间分拣。
