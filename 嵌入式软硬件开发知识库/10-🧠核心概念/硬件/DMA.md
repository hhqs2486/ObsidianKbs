# DMA

## 一句话定义
DMA（Direct Memory Access，直接存储器访问）让**外设和内存之间直接搬数据，不经过 CPU**，从而把 CPU 从大量数据搬运里解放出来。

## 它解决什么问题 / 为什么存在
ADC 连续采样、SPI/UART 收发大块数据、刷 LCD 等，数据量很大。若每字节都靠 CPU 读/写，CPU 几乎被搬运占满，没法做别的。DMA 在总线空闲时自动搬运。

## 核心原理（大二能懂的水平）
- 一个 **DMA 控制器** 接管总线，按"源地址→目的地址"批量搬字节/半字/字。
- STM32 上：每个通道(Channel)/流(Stream)绑定一个外设请求（如 ADC1、SPI2_RX、USARTx_TX）。
- 模式：单次 / **循环**（搬完自动从头，适合持续采样）；可配源/目的地址是否递增。
- 搬完触发**传输完成中断**，CPU 才介入处理。

## 关键参数 / 易错点
- 缓冲区长度、地址递增方向要配对（外设寄存器通常不递增，内存递增）。
- 数据宽度（8/16/32 位）两端要一致。
- 带 Cache 的内核（如 M7）要注意**缓存一致性**（F1/F4 基本无此问题）。
- 传输进行中别改源/目的缓冲区内容。

## 类比（帮助理解）
像公司里的快递员：货从仓库(外设)直接搬上车(内存)，不用每件都让你经手签字，搬完快递员喊你一声(中断)"好了"。

## 设计时怎么用（反推思维）
- 需求：持续采 N 路 ADC、或串口收一整帧、或 SPI 读大块 Flash → 开 DMA。
- 套路：`HAL_ADC_Start_DMA`（循环采样到数组）、UART 用 DMA+IDLE 中断收变长帧、SPI 用 DMA 收发。
- CPU 只在"搬完"时处理数据，平时去跑控制逻辑。

## 典型应用
多通道 ADC 采集、音频流、屏幕刷图、高速串口透传。

## 关联
- 前置知识：[[ADC]]、[[SPI]]、[[UART]]
- 相关：[[中断NVIC]]（完成中断）
- 反例/误区：以为 DMA 完全不占 CPU——配置和完成中断仍要 CPU，只是"搬运"不用。
