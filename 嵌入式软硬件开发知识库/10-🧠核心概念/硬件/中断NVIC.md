# 中断NVIC

## 一句话定义
NVIC（Nested Vectored Interrupt Controller，嵌套向量中断控制器）是 Cortex-M3 管理"外部/内部突发事件"的硬件模块；中断就是 CPU 暂停当前 `while(1)`，转去执行 ISR（中断服务函数），完了再回来。

## 它解决什么问题 / 为什么存在
没有中断，CPU 只能不断"轮询"按键有没有按，浪费算力且响应慢。中断让硬件事件主动"敲门"，CPU 平时该干啥干啥，事件来了立刻处理——这是实时性的来源。

## 核心原理（大二能懂的水平）
Cortex-M3 有一张"中断向量表"（存在 0 地址），表里每个中断对应一个函数入口。事件触发 → NVIC 硬件自动：保存现场 → 跳到对应 ISR → 执行 → 恢复现场。NVIC 支持优先级（0~15，数字越小越高）和嵌套（高优先级可打断低优先级）。EXTI 把 GPIO 边沿变成中断信号送进 NVIC。

## 关键参数 / 易错点
- HAL 用 `HAL_NVIC_SetPriorityGrouping(NVIC_PRIORITYGROUP_4)` 把 4 位全给抢占优先级。
- 按键中断必须消抖：在回调里用 `uwTick` 判断"距上次 >200ms"再处理。
- `HAL_Delay` 靠 SysTick，若在低优先级 ISR 里调用且 SysTick 优先级更低，会卡死——"中断里慎用 HAL_Delay"。

## 类比（帮助理解）
像你写作业时门铃响了（中断）去开门（ISR），开完继续写（恢复现场）；快递员（高优先级）能打断你跟朋友的闲聊（低优先级嵌套）。

## 设计时怎么用（反推思维）
- 需求反推：按键/传感器边沿触发、UART 收数据、定时器到时 → 用中断。
- CubeMX：引脚设 GPIO_EXTIx → NVIC 里勾 Enable 并设优先级。
- HAL：在 `HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)` 里按 `GPIO_Pin` 分支处理。

## 典型应用
按键唤醒、编码器计数、串口接收、定时器周期性采样。
