# CAN

## 一句话定义
CAN（Controller Area Network，控制器局域网）是一种**差分、多主、带优先级仲裁**的串行总线，抗干扰极强，专为汽车/工业里多节点可靠通信设计。

## 它解决什么问题 / 为什么存在
多个 ECU/传感器要在一根总线上互传数据，且环境电磁干扰大、不能丢关键帧。CAN 用差分信号抗共模干扰，用"非破坏性仲裁"让高优先级消息先发、不互相冲突。

## 核心原理（大二能懂的水平）
- 两线 `CANH`/`CANL` 差分传输，显性(0)/隐性(1)靠驱动能力决定。
- **仲裁**：每个帧带 11 位(ID)或 29 位扩展 ID，ID 越小优先级越高；多节点同时发时，低 ID 赢，失败方自动退出发送（不破坏已发数据）。
- 帧含：起始位、仲裁场、控制、数据(0~8B)、CRC、ACK、帧尾。靠 ACK 确认、CRC 检错。
- 位时序由 `波特率 = 时钟 / 分频 / (BS1+BS2+SJW)` 配置，需各节点一致。

## 关键参数 / 易错点
- **两端必须 120Ω 终端电阻**，否则信号反射、通信失败（最常见坑）。
- 收发器（如 TJA1050）供电 5V，与 3.3V MCU 间注意电平。
- CAN 只传"带 ID 的数据帧"，不含节点地址——靠 ID 过滤决定收不收。
- 高速 CAN(1Mbps)/容错 CAN 速率与走线要求不同。

## 类比（帮助理解）
像会议室抢话：谁的事更急（ID 小）谁先说，且边说边听，一旦发现自己优先级低就立刻闭嘴让别人说，谁都没白说。

## 设计时怎么用（反推思维）
- 需求：多个节点（电机/传感器/网关）要稳定联网 → 选 CAN，而非 UART 点对点。
- STM32 用 **bxCAN** 外设 + 外部收发器；CubeMX 配波特率与过滤器；HAL 用 `HAL_CAN_Start` / `HAL_CAN_AddTxMessage` / `HAL_CAN_GetRxMessage`。
- 总线两端各放 120Ω；节点中间不放。

## 典型应用
汽车 ECU 网联、工业控制总线、医疗器械多模块通信。
