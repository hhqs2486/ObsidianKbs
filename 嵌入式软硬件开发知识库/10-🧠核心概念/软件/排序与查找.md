# 排序与查找

## 一句话定义
查找：在一堆数据里按关键字定位目标（顺序 / 折半 / 哈希 / 树查找）。排序：把一组数据按规则排好序（冒泡 / 选择 / 插入 / 希尔 / 堆 / 归并 / 快排）。两者是数据处理最高频的两类操作。

## 它解决什么问题 / 为什么存在
无序数据查找只能逐个比（慢）。先排序或建索引，查找能从 O(n) 降到 O(log n) 甚至 O(1)。选对算法直接决定程序卡不卡——嵌入式里尤其明显。

## 核心原理（大二能懂的水平）
- 查找：
  - 顺序查找：从头比到尾，O(n)，无序也能用。
  - 折半查找：对有序 [[数组与字符串]] 取中点砍半，O(log n)；但链表不能随机访问，不适用。
  - 哈希查找：用哈希函数算位置直接定位，O(1)；冲突时用 [[链表]] / 红黑树 挂在同一格。
  - 树查找：BST / AVL / 红黑树，O(log n)，支持动态增删。
- 排序（时间复杂度）：
  - O(n²)：冒泡（相邻交换冒泡）、选择（每轮选最值）、插入（像理牌插到已排好部分）。简单但慢。
  - O(nlog n)：希尔（分组插入）、堆（完全二叉树）、归并（分治合并，稳定，需 O(n) 额外空间）、快排（选枢轴 partition，平均最快，最坏 O(n²)）。

## 关键参数 / 易错点
- 稳定性：相等元素相对顺序不变（归并稳定，快排 / 堆不稳定）。
- 折半必须先有序；哈希要处理冲突与扩容。
- 快排必须有合理的枢轴与递归终止（见 [[递归]]），否则最坏 O(n²) 或爆栈。

## 类比（帮助理解）
查找像从书架上找书：乱放只能一本本翻（顺序），按拼音排好就能折半（二分），每本书贴编号直接抽（哈希）。排序像整理手牌。

## 设计时怎么用（反推思维）
小数据 / 教学 → 简单 O(n²)；大数据通用 → 快排或归并；要稳定 → 归并；查得多、增删少 → 先排序再用折半；海量 → 哈希 / B+ 树。

## 典型应用
成绩排名、数据库索引（[[树]]）、字典、日志去重、串口数据排序显示。
