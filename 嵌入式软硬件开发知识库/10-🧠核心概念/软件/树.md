# 树

## 一句话定义
树是一种"非线性、层次化"的结构：一个根节点，每个节点有零到多个子节点，除根外每个节点有且只有一个父节点。二叉树是最常见的特例——每个节点最多两个子（左 / 右）。

## 它解决什么问题 / 为什么存在
线性表一对一、图多对多，树填补"一对多、有层次"的中间地带：目录、族谱、决策、索引天然是树。它让"查找 / 插入 / 删除"能从 O(n) 降到 O(log n)。

## 核心原理（大二能懂的水平）
- 术语：根、父、子、叶子、深度（到根距离）、高度（到叶最长路径）、子树。
- 遍历（深度优先，靠 [[递归]]）：前序 根→左→右、中序 左→根→右、后序 左→右→根；层序是广度优先。
- 二叉排序树（BST）：左子树值 < 根 < 右子树值，中序遍历得到有序序列，查找 O(log n)；但若插入有序会退化成链表 O(n)。
- 平衡二叉树（AVL / 红黑树）：左右子树高度差 ≤1，保住 O(log n)。
- 哈夫曼树：带权路径最短的二叉树，用于数据压缩（哈夫曼编码）。

## 关键参数 / 易错点
- 中序遍历对 BST 才有"有序"性质，别套到其他树。
- 递归遍历必须有终止条件，否则爆栈（见 [[递归]]）。
- 完全二叉树适合用 [[数组与字符串]] 顺序存（下标 2i、2i+1）；非完全树用链式（节点含 lchild/rchild 指针）更省。

## 类比（帮助理解）
现实中的树：根在最上，分支往下长；叶子是没有子节点的末端。

## 设计时怎么用（反推思维）
要"快速查找 + 动态增删"→ BST / 平衡树（数据库索引）；要压缩 → 哈夫曼；要表示层级菜单 → 普通树。嵌入式里文件系统目录、路由表常用。

## 典型应用
二叉排序树、AVL / 红黑树（[[排序与查找]] 的哈希冲突也可用红黑树）、哈夫曼压缩、XML/JSON 解析。
