# 计数型信号量

## 一句话定义
> 计数型信号量（Counting Semaphore）是 FreeRTOS 中维护一个**计数值**的同步原语，记录可用资源的数量，每次 Give 计数 +1、Take 计数 -1，底层是一个长度为 MaxCount 的特殊队列。

## 它解决什么问题 / 为什么存在
- 二值信号量只能表示"有/没有"，无法表示"有几个"
- 需要管理固定数量的资源池（如 5 个网络连接句柄、10 个内存块）
- 需要累计事件数量（如"按键被按了 3 次"）
- 生产者和消费者速度不匹配时，计数充当缓冲

## 核心原理（大二能懂的水平）
- 底层 = 队列长度为 `MaxCount`、每项大小为 0 的特殊队列（每项只占位置，不存数据）
- `uxMessagesWaiting` 成员记录当前计数值（队列中非空项的数量）
- 创建时指定两个参数：`uxMaxCount`（上限）和 `uxInitialCount`（初始值，通常为 0）
- Give：计数值 +1，达到 MaxCount 时再 Give 会失败
- Take：计数值 -1，为 0 时再 Take 会阻塞（等别人 Give）
- `uxSemaphoreGetCount()` = 读取当前计数值（不修改）

## 关键参数 / 易错点
- **MaxCount 决定 RAM 开销**：底层队列长度为 MaxCount，每个槽位虽有 0 字节数据但占用队列管理结构，MaxCount 设太大会浪费 RAM
- **初始值 ≤ MaxCount**：`xSemaphoreCreateCounting(100, 101)` → 返回 NULL 创建失败
- **Give 超上限无效**：计数值 = MaxCount 时 `xSemaphoreGive` 返回失败
- **中断里必须用 `FromISR`**：同所有 FreeRTOS API，ISR 中用 `xSemaphoreGiveFromISR`
- 需要先在 `FreeRTOSConfig.h` 中 `#define configUSE_COUNTING_SEMAPHORES 1`

## 类比（帮助理解）
- 停车场计数牌：MaxCount=100（总车位），计数值=剩余车位数；进来一辆 -1（Take），出去一辆 +1（Give），数字到 0 时"车位已满"灯亮（Take 阻塞）

## 设计时怎么用（反推思维）
> 如果这条知识能用于「从需求到设计」，在这里写一句：做 XX 设计时，我会用它能解决 YY。
- 做 N 个网络连接池设计时：MaxCount=N，初始化 Give N 个（全部可用），每次建立连接 Take 一个，断开 Give 一个——优雅管理连接数
- 做事件批量处理设计时：ISR 中每次事件 Give，处理任务批量 Take 处理——实现流量整形

## 典型应用 / 我在哪见过
- 连接池管理（TCP 连接/蓝牙连接数量限制）
- 内存块池管理（固定大小的内存块分配与回收）
- 流量控制（令牌桶算法：MaxCount=速率，定时器每秒 Give 一次，发送前 Take）
- 生产者-消费者缓冲计数
