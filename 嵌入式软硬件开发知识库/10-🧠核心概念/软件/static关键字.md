# static 关键字

## 一句话定义
static 在 C 里有**三种用法**，核心都是"限制作用域 / 延长生命周期"：
1. **函数内的局部 static**：只初始化一次，生命周期贯穿整个程序，值在函数调用间保留。
2. **文件内的全局 static**：作用域限定在**本 .c 文件**（内部链接），不暴露给其他文件。
3. **static 函数**：同上，文件内私有函数，避免多文件命名冲突。

## 它解决什么问题 / 为什么存在
- 局部 static：需要"跨调用保留状态"又不想用全局变量（如计数器、单例）。
- 全局/函数 static：大型工程多文件，避免不同 .c 里的同名全局变量/函数互相冲突（内部链接）。

## 核心原理（大二能懂的水平）
- **为什么只初始化一次**：局部 static 变量存在**静态存储区**（`.data`/`.bss`），不在栈上；程序启动时初始化一次，函数返回不销毁，下次进来直接沿用。（对比普通局部变量在栈上，每次调用重新创建。）
- 全局 static / static 函数：链接阶段只在本编译单元可见，其他文件 `extern` 不到。

## 关键参数 / 易错点
- 局部 static **不是线程安全的**（多线程序列化访问需加锁，见 [[互斥与信号量]]）。
- 别以为 static 变量在堆或栈——它在静态区。
- 头文件里定义 static 变量 → 每个包含它的 .c 各有一份副本（常是坑）。

## 类比（帮助理解）
普通局部变量像临时便签（用完就扔）；局部 static 像你抽屉里的私人物品（一直在，下次接着用）；文件 static 像只给你部门用的内部编号（别的部门查不到）。

## 设计时怎么用（反推思维）
- 反推"函数要记住上次的计数/状态，又不想污染全局"→ 局部 static。
- 反推"这个辅助函数/全局只在本文件用"→ 加 static 避免命名冲突。

## 典型应用
状态机计数器、单例、模块私有函数、驱动内部缓冲。
