# 哈希表

## 一句话定义
哈希表（散列表，Hash Table）= 用**散列函数 h(key)** 直接把关键字算成存储位置，理想情况下查找 / 插入 / 删除都是 **O(1)**。是 [[排序与查找]] 里最快的查找方式。

## 它解决什么问题 / 为什么存在
顺序查找 O(n)、折半查找 O(log n)——再快也摆脱不了「比大小」。哈希表干脆不比了，用函数算位置直接定位，把查找打到 O(1)。适合**海量数据、查多增删少**的场景（字典、缓存、去重、索引）。

## 核心原理（大二能懂的水平）
- **散列函数**（把 key 映射成桶下标）：
  - 直接定址、数字分析法、平方取中、折叠法、**除留余数法** `h(key)=key % p`（p 取质数最稳）。
- **冲突**（不同 key 算到同一桶，必然发生——鸽巢原理）：
  - **开放定址法**：线性探测 / 二次探测 / 再散列，往后找空桶。
  - **链地址法**：同桶的元素挂成一条 [[链表]]（最常用，简单且不怕堆积）。
- **装载因子** α = 已存元素数 / 桶数。α 越大冲突越密，需**扩容 rehash**（桶数翻倍、重新散列）。

## 关键参数 / 易错点
- 冲突**必然存在**，重点在「怎么处理」而非「怎么避免」。
- 除留余数法模数取**质数**，分布更均匀；链地址法最稳。
- 忘了扩容 → α 过高 → 退化成接近 O(n)。
- 哈希函数太简单（如只取末位）→ 大量冲突。

## 类比（帮助理解）
就像储物柜：钥匙（key）插进算法立刻告诉你「第几号柜」（h(key)），不用挨个找。两个人的钥匙凑巧指向同柜（冲突）→ 要么旁边找个空柜（开放定址），要么这柜里挂个清单都放着（链地址）。

## 设计时怎么用（反推思维）
> 要做「按 key 快速存取」——字典 / 缓存 / 集合去重 / 快速索引 → 上哈希表。嵌入式里 RAM 小，桶数别开太大，链地址法控内存更稳。

## 典型应用 / 我在哪见过
- 字典、对象存储、路由表缓存、日志去重、符号表（编译器）。
- 与 [[排序与查找]] 互补：查找需求极致性能时选它。
