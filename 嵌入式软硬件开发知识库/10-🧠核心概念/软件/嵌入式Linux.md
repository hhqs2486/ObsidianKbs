# 嵌入式Linux

## 一句话定义
在带 **MMU** 的应用处理器（如 ARM Cortex-A9/A53）上运行的 Linux 系统；它由 **bootloader + 内核 + 驱动 + 根文件系统** 四大件组成，区别于裸机 MCU 和 RTOS。

## 它解决什么问题 / 为什么存在
复杂嵌入式设备（网关、工控、摄像头、车载）需要多任务、网络协议栈、文件系统、成熟生态。自己写裸机或 RTOS 难以cover；Linux 开源、驱动/协议栈/工具链生态庞大，能极大提高开发效率与系统稳定性。

## 核心原理（大二能懂的水平）
嵌入式 Linux 系统 = 四大块：
1. **bootloader**（对应 PC 的 BIOS）：上电先跑，初始化硬件、把内核从 Flash 读到内存、启动内核并传参。
2. **内核 kernel**：管理进程调度、内存、文件系统、中断、网络；启动后挂载根文件系统。
3. **驱动 driver**：让内核认识并操作具体硬件（Flash/网卡/USB/LCD…），= 硬件操作 + 驱动框架。
4. **根文件系统 rootfs**：内核挂载后用户空间的"地基"，提供 `/bin`、`/lib`、C 库、`/sbin/init`（第一个用户进程）。

学习三阶段（循序渐进，别跳）：**应用开发 → 系统/移植 → 驱动开发**。

## 关键参数 / 易错点
- 与 MCU 裸机/RTOS 的本质区别：Linux 有 **MMU + 虚拟内存 + 多进程**；RTOS（[[FreeRTOS]]）无 MMU、确定性强、资源占用小。
- 常见学习误区：① 死磕桌面/服务器版 Linux 使用（那只当开发工具，1~2 天会用命令即可）；② 零基础直接读内核源码（以卵击石）。
- 切入点：先在现成开发板上做**应用编程**（文件 IO、多进程多线程、网络），再下沉到内核与驱动。

## 类比（帮助理解）
裸机 = 你一个人住毛坯房自己管一切；RTOS = 有个极简物业但只管几件事；嵌入式 Linux = 一整套精装小区（物业/水电/门禁/网络都齐），你只要写"住户应用"或"物业规则（驱动）"。

## 设计时怎么用（反推思维）
- 反推"为什么选 Linux"→ 功能复杂、要联网/跑算法/要文件系统 → 上 Linux；简单控制 → MCU 裸机/RTOS 更省。
- 想"自己搭一套平台"→ 必须吃透 bootloader、内核移植、根文件系统、驱动四块。
- 工程师思维：先定需求（应用/系统/驱动），再决定学到哪一层，别盲目啃内核。

## 典型应用
网关、IPC 摄像头、车载终端、工业 HMI、物联网边缘节点（见 [[物联网终端]]）。
