# Linux内核并发控制

## 一句话定义
Linux 内核并发控制是管理多 CPU、多中断、多进程同时访问共享资源的机制，包括自旋锁、互斥锁、原子操作、RCU 等。

## 它解决什么问题 / 为什么存在
裸机程序单线程运行不用考虑并发。Linux 内核随时可能被中断打断、被其他 CPU 同时执行、被进程抢占。如果两个执行流同时修改同一数据结构，会导致数据损坏。内核提供多种同步原语适配不同场景。

## 核心原理（大二能懂的水平）
核心同步原语：
1. 自旋锁(spinlock)：忙等，不可睡眠，用于中断上下文或持有时间极短的场景。spin_lock_irqsave() 禁中断并加锁
2. 互斥锁(mutex)：睡眠等待，可睡眠，用于长时间持有。mutex_lock() / mutex_unlock()
3. 信号量(semaphore)：可睡眠，可计数。down() / up()
4. 原子操作：atomic_inc() / atomic_read()，无需锁
5. RCU(Read-Copy-Update)：读端无锁，写端复制后替换。适合读多写少
6. 完成量(completion)：等待某事件完成。wait_for_completion() / complete()

选择原则：中断上下文->自旋锁；进程上下文短临界区->自旋锁；进程上下文长临界区->mutex；读多写少->RCU；简单计数->原子操作

## 关键参数 / 易错点
- 自旋锁持有期间绝对不能睡眠（不能 mutex、不能 kmalloc(GFP_KERNEL)）
- spin_lock_irqsave 比 spin_lock 安全：同时禁了本 CPU 中断
- 死锁：持有锁 A 再请求锁 A；持有锁 A 再请求锁 B，另一路径持有 B 请求 A
- RCU 读端无开销但写端复杂，不要滥用
- 优先用 devm_ 和已封装的高级接口

## 类比（帮助理解）
并发控制像公共卫生间：自旋锁=有人就在门口等（忙等），mutex=拿号排队去干别的（睡眠），原子操作=只有一个坑位自动开关门，RCU=读不排队写时复制副本。

## 设计时怎么用（反推思维）
反推：驱动有共享数据被中断和进程同时访问 -> 自旋锁 irqsave；被多个进程访问且操作耗时 -> mutex；简单计数器 -> 原子操作。

## 典型应用
所有多核/多中断/多进程场景的 Linux 驱动开发。
