# 动态任务创建

## 一句话定义
> 动态任务创建是 FreeRTOS 提供的一种在**运行时**从堆内存中分配任务栈和 TCB 来创建任务的方式，通过 `xTaskCreate()` API 实现。

## 它解决什么问题 / 为什么存在
- 裸机用 `while(1)` + 中断的方式无法清晰分离不同功能模块
- 需要在运行时根据条件动态增删任务（如"收到指令后启动新任务"）
- 让开发者不必在编译时确定所有任务的数量和内存布局

## 核心原理（大二能懂的水平）
- `xTaskCreate()` 做了三件事：①从 heap 分配一块内存给 TCB（任务控制块，记录任务的姓名/优先级/状态）②从 heap 分配一块内存给栈（独立栈空间，切换时保存现场）③把任务函数地址和初始参数压入栈，加到就绪链表
- 调度器启动后，按优先级抢占运行
- 删除任务时（`vTaskDelete`），TCB 和栈被标记删除，由空闲任务（Idle Task）真正回收内存
- 栈深度参数单位是**字**不是字节！`128` = 128×4 = 512 字节（32 位 MCU 上一个字 4 字节）

## 关键参数 / 易错点
- **栈深度单位是字**：初学者最常犯的错——把 128 当 128 字节用，结果栈溢出导致 HardFault
- **栈溢出检测**：用 `uxTaskGetStackHighWaterMark()` 看剩余栈最少值；接近 0 就危险了
- **堆大小要够**：`configTOTAL_HEAP_SIZE` 必须 >= 所有任务的 (TCB + 栈) 之和 + 队列/信号量的开销
- **不要频繁创建/删除**：heap_2 会碎片化（建议用 heap_4）
- **中断里不能创建任务**：创建涉及堆分配，不能在 ISR 中调用
- 优先级：数值越大越高（0 最低），`configMAX_PRIORITIES` 限制最大层级数

## 类比（帮助理解）
- 就像开饭店：裸机是老板一个人在灶台前（while(1)）又要炒菜又要接电话又要算账；动态任务创建就像"随时雇临时工"——来了大单就多叫一个厨师（新任务），忙完就让人走（删除任务），每个人的工位（栈）自己负责

## 设计时怎么用（反推思维）
> 如果这条知识能用于「从需求到设计」，在这里写一句：做 XX 设计时，我会用它能解决 YY。
- 做"按键触发临时测量任务"设计时：按键中断通知后台任务 → 后台任务 `xTaskCreate` 创建一个测量任务 → 测量完成 `vTaskDelete(NULL)` 自删除
- 做 OTA 升级设计时：升级完成后创建新任务跑新版固件验证，验证通过删旧任务

## 典型应用 / 我在哪见过
- OTA 智能终端中动态创建通信和处理任务
- 多传感器网关中根据传感器接入数量动态增加采集任务
- 人机界面中临时弹窗任务
