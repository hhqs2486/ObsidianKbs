# 贪心算法

## 一句话定义
> 贪心算法（Greedy Algorithm）是一种在每一步都做出当前看起来最优的选择，期望通过局部最优决策的累积达到全局最优解的算法策略。

## 它解决什么问题 / 为什么存在
- 某些问题具有"贪心选择性质" — 局部最优就能推出全局最优，不需要像 DP 那样存储和回溯所有子问题。
- 贪心算法通常比 DP 更高效（O(n) 或 O(n log n) vs DP 的 O(n^2)），代码也简单。
- 在嵌入式实时场景中（如任务调度、资源分配），贪心思路因响应快、计算轻而实用。

## 核心原理（大二能懂的水平）
- **贪心选择性质**：问题的最优解可以由一系列局部最优选择构成，每次选择后不再回溯（无后效性）。
- **典型流程**：把问题分解成多步 → 每步按某规则选最优 → 选完后问题规模缩小 → 继续直到完成。
- 经典例子：
  - 找零钱（币值 1/5/10/20/50/100）：每次选最大面额不超过剩余金额的
  - 活动选择问题：按结束时间排序，每次选最早结束且不冲突的
  - Huffman 编码：每次合并两个最小频率的节点
  - Kruskal 最小生成树：每次选最短的不构成环的边

## 关键参数 / 易错点
- **必须证明贪心正确**：贪心策略看起来正确 ≠ 真的正确。如背包问题，贪心选单位价值最高的物品能装满，但不一定是全局最优（此时需 DP）。
- **排序开销**：很多贪心需要先排序（O(n log n)），如果 n 很小，贪心可能不如简单 DP 省事。
- **与 DP 的边界**：能用贪心则一定不用 DP（更高效），但不能用贪心时必须回退到 DP。

## 类比（帮助理解）
- 爬山时每一步都朝最陡的方向走（局部最优）— 在小山坡上能到达山顶（全局最优），但在复杂地形可能只是局部最高点而非真正的顶峰。

## 设计时怎么用（反推思维）
> 做嵌入式任务调度时，如果任务集满足"按优先级调度即最优"，直接用贪心（OSSched），无需 DP 枚举所有排列。做传感器采样时，贪心选当前最优的采样率分配功耗预算。

## 典型应用 / 我在哪见过
- FreeRTOS 调度器 — 基于优先级的抢占调度本质上是一种贪心（选最高优先级就绪任务）
- 网络路由 — 距离矢量路由（如 RIP）每跳选最短路径
- 数据压缩 — Huffman 编码、LZ77 都是贪心策略
- 活动安排 — 会议室/CPU 时间片分配
