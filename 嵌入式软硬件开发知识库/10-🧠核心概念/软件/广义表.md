# 广义表

## 一句话定义
广义表（Lists）是**元素可以是「原子」也可以是「子表」**的有序序列，记作 `LS = (a1, a2, ..., an)`。它是 [[线性表]] 的推广——线性表要求元素同型，广义表允许「表中有表」。

## 它解决什么问题 / 为什么存在
表达**带层次 / 递归**的数据：多项式、目录树、Lisp 的 S 表达式、JSON 之类的嵌套结构。普通线性表装不下这种「一层套一层」的东西。

## 核心原理（大二能懂的水平）
- **表头 Head(LS) = a1**（第一个元素）；**表尾 Tail(LS) = (a2, ..., an)**（**剩余元素组成的子表**，注意是子表不是单个元素）。
- **长度** = 最外层元素个数；**深度** = 括号嵌套层数（原子深度 0，空表深度 1）。
- 递归结构，常用 [[链表]] 实现：每个节点要么是原子，要么指向一个子表。
- 特殊：非空广义表可拆成「表头 + 表尾」——这是很多递归算法的切入点。

## 关键参数 / 易错点
- **表尾是子表**，不是第二个元素！`Tail((a,b,c)) = (b,c)` 而不是 `b`。这是最常错的点。
- 深度 = 括号层数，空表深度记为 1（约定）。
- 求长度只看最外层，不递归进子表。

## 类比（帮助理解）
像俄罗斯套娃的清单：清单里有的格子放单个娃娃（原子），有的格子放「另一个小清单」（子表）。表头是清单第一个格子，表尾是「剩下的格子组成的新清单」。

## 设计时怎么用（反推思维）
> 数据天然嵌套（文件系统目录、配置树、表达式树）→ 用广义表 / 递归结构表达，配 [[递归]] 遍历。别硬塞进扁平 [[数组与字符串]]。

## 典型应用 / 我在哪见过
- 多项式表示、目录结构、Lisp/Scheme 数据、JSON/XML 解析的底层模型。
- 与 [[树]] 相通（广义表能表示树）。
