# 静态任务创建

## 一句话定义
> 静态任务创建是 FreeRTOS 中使用**用户预先分配的内存**（而非堆分配）来创建任务的方式，通过 `xTaskCreateStatic()` API 实现，内存占用在编译时完全确定。

## 它解决什么问题 / 为什么存在
- 动态分配有内存碎片风险，长时间运行的系统可能因碎片导致创建失败
- 安全关键型应用（汽车/医疗）不允许动态内存分配（MISRA C 规范要求）
- 资源极度受限的 MCU 上，静态分配让开发者精确掌控每一字节

## 核心原理（大二能懂的水平）
- 用户预先声明两个 `static` 数组：一个 `StaticTask_t`（TCB）和一个 `StackType_t[]`（栈）
- 把这两个数组的地址传给 `xTaskCreateStatic()`，内核直接用你给的内存，不从堆拿
- 任务删除时只修改状态，**内存不释放**（因为是 static 变量，生命周期 = 程序全周期）
- 必须实现两个回调函数告诉内核空闲任务和定时器任务的内存放在哪：`vApplicationGetIdleTaskMemory()` 和 `vApplicationGetTimerTaskMemory()`
- 在 `FreeRTOSConfig.h` 中打开 `configSUPPORT_STATIC_ALLOCATION = 1`

## 关键参数 / 易错点
- **栈大小估算**：先用动态创建跑通，用 `uxTaskGetStackHighWaterMark()` 测实际栈用量，再设静态栈大小（留 30% 安全余量）
- **别忘记空闲任务回调**：`configSUPPORT_STATIC_ALLOCATION` 打开后不实现 `vApplicationGetIdleTaskMemory` → 编译错或 HardFault
- **static 数组不能跨文件**：如果任务函数在不同 .c 文件，TCB 和栈必须放在能访问到的作用域
- 静态创建的任务被删除后不能"重建"（内存已经被 static 声明固定了），除非预留多个 TCB + 栈
- 同动态创建：栈深度单位是**字**（32 位 MCU 上 1 字 = 4 字节）

## 类比（帮助理解）
- 动态创建像去饭馆现点菜（现做现吃），静态创建像自己带盒饭（提前装好，不用等，量也固定）
- 动态分配像租房（随时换，但房东可能没房了），静态分配像买房（固定不变，但最可靠）

## 设计时怎么用（反推思维）
> 如果这条知识能用于「从需求到设计」，在这里写一句：做 XX 设计时，我会用它能解决 YY。
- 做心电监测设备设计时：所有任务用静态创建，确保 7×24 小时运行不因内存碎片死机
- 做安全认证级产品时：静态创建使内存占用完全可审计，满足安全标准

## 典型应用 / 我在哪见过
- 汽车 ECU 固件（ISO 26262 功能安全要求）
- 医疗设备固件（IEC 62304）
- 资源极小的 MCU（如只有 8KB SRAM 的 STM32F030）
