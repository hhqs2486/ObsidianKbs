# TCP 三次握手与四次挥手

## 一句话定义
TCP 是**面向连接、可靠**的传输层协议。建立连接用**三次握手**，释放连接用**四次挥手**。

## 它解决什么问题 / 为什么存在
可靠通信前必须先确认"双方收发能力都正常"，并协商初始序号；关闭时要双向都关干净（TCP 全双工）。

## 核心原理（大二能懂的水平）
**三次握手（建立）**：
1. 客户端 → 服务器：`SYN`, seq=x（请求连接）
2. 服务器 → 客户端：`SYN+ACK`, seq=y, ack=x+1（同意+确认）
3. 客户端 → 服务器：`ACK`, ack=y+1（再确认）→ 进入 `ESTABLISHED`

**四次挥手（释放）**：
1. 客户端 → 服务器：`FIN`, seq=u（我要关）
2. 服务器 → 客户端：`ACK`, ack=u+1（知道你要关，这方向先半关）
3. 服务器 → 客户端：`FIN`, seq=w（我也关）
4. 客户端 → 服务器：`ACK`, ack=w+1 → `TIME_WAIT` 等 2MSL 后 `CLOSED`

**关键状态**：`SYN_SENT`/`SYN_RCVD`/`ESTABLISHED`/`FIN_WAIT_1`/`FIN_WAIT_2`/`TIME_WAIT`/`CLOSE_WAIT`/`LAST_ACK`。

**为什么挥手要 4 次**：TCP 全双工，关闭时被动方收到 FIN 只能先 ACK（可能还有数据要发），等自己发完再发 FIN——所以 ACK 与 FIN 分开，成了 4 次。

**TIME_WAIT 作用**：确保最后 ACK 到达对方；让本连接残留报文在网络中消散（2MSL），避免影响新连接。

## 关键参数 / 易错点
- 为什么不是 2 次握手：无法确认服务器收能力，且防历史连接报文乱入。
- TIME_WAIT 过多 → 端口耗尽（可调 `tcp_tw_reuse`）。
- TCP 有拥塞控制、按序到达；对比 UDP（见 [[通信协议设计]]）无连接、不可靠、首部小。

## 类比（帮助理解）
握手像打电话："喂？"(SYN)→"听得到，你呢？"(SYN+ACK)→"听得到！"(ACK)；挥手像挂电话：你说"先挂了"→"好，等我说完这句"→"我说完了"→"拜拜"。

## 设计时怎么用（反推思维）
- 反推"物联网设备怎么连服务器"→ socket + TCP 三次握手建立（见 [[物联网终端]]、[[嵌入式Linux]]）。
- 调试连接不上 → 先看哪一端卡在 SYN_SENT / TIME_WAIT。

## 典型应用
所有可靠网络通信：HTTP/MQTT/FTP、设备连云。
