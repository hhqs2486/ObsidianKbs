# 进程与线程（Linux）

## 一句话定义
- **进程 process**：资源分配的最小单位，拥有**独立的虚拟地址空间**（靠 MMU 映射）。
- **线程 thread**：CPU 调度的最小单位，同进程内的线程**共享地址空间**（全局/堆），各有独立栈。
- Linux 用同一个 `task_struct` 描述二者，靠 `clone()` flags 区分"共享多少"。

## 它解决什么问题 / 为什么存在
多任务需要并发：进程提供强隔离（一个崩不影响别的），线程提供低开销共享（通信不用跨地址空间拷贝）。

## 核心原理（大二能懂的水平）
- **进程**：`fork()` 创建子进程（写时复制 COW，效率高）；`exec()` 替换进程映像；`wait()` 回收防僵尸进程。
- **线程**：`pthread_create()` 建线程，共享全局/堆，独有栈、寄存器、TLS。
- **进程间通信 IPC**：管道/共享内存/消息队列/信号/套接字（见 [[互斥与信号量]]、[[通信协议设计]]）。
- **与 RTOS 对比**：[[任务与调度]](FreeRTOS) **无 MMU、无虚拟地址**、所有任务共享同一地址空间、确定性调度；Linux 进程有 MMU 隔离、调度更复杂（SCHED 调度类、时间片）。

## 关键参数 / 易错点
- 线程共享变量**无同步 → 竞态**，必须加锁（见 [[互斥与信号量]]，spinlock/mutex）。
- `fork()` 后父子**共享文件描述符**（小心重复 close / 双写）。
- 不 `wait` 子进程 → 僵尸进程占 PID；不回收线程 → 资源泄漏。
- 嵌入式 MCU 大多跑 RTOS/裸机，没有 Linux 这套进程模型（见 [[嵌入式Linux]]）。

## 类比（帮助理解）
进程像独立办公室（各有人事/财务，隔离）；线程像同办公室里的多个员工（共享文件柜，但要排队用打印机=锁）。

## 设计时怎么用（反推思维）
- 反推"功能模块要隔离还是共享"→ 隔离用进程(IPC 通信)，共享用线程(加锁)。
- 嵌入式里轻量并发优先 RTOS 任务；要跑 Linux 应用才用进程/线程。

## 典型应用
Linux 嵌入式应用：数据采集进程 + 网络上传线程、GUI 与主逻辑分离。
