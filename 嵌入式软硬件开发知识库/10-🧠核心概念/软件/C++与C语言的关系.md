# C++与C语言的关系

## 一句话定义
C++ 在 C 的基础上扩展出"面向对象 + 泛型 + 标准库"，**对绝大多数 C 代码向后兼容**——可以理解为"C with classes"。本卡串起资料包里的 `14本C++书籍`。

## 为什么存在
C 贴近硬件、确定性强，是嵌入式主力；C++ 在桌面/服务端/上层算法更顺手。理解二者关系，能决定"项目用 C 还是 C++"、以及"C++ 怎么调 C 写的底层库"。

## 核心区别（大二能懂）
| 维度 | C | C++ |
|---|---|---|
| 范式 | 面向过程 | 多范式（过程+面向对象+泛型） |
| 函数 | 自由函数 | 类成员函数、函数重载 |
| 数据封装 | struct（全公开） | class（public/private/protected） |
| 内存 | malloc/free | new/delete + 构造函数/析构函数(RAII) |
| 复用 | 宏/函数 | 模板、STL（vector/string/map…） |
| 引用 | 无（只有指针） | 有引用 `int& r=x` |
| 命名 | 全局扁平 | 命名空间 `namespace` |
| 异常 | 无 | 有 try/catch（嵌入式常禁用） |

## 嵌入式里怎么选
- **裸机/RTOS 底层、驱动、协议栈**：多用 C（确定性强、无异常/虚表开销、栈可控）；见 [[C语言]] [[FreeRTOS]]。
- **上层算法、GUI、测试工具**：可用 C++（STL/类提升开发效率）。
- **C++ 调 C 库**：用 `extern "C" { #include "foo.h" }` 关掉 C++ 的名字改编（name mangling），让链接器找到 C 函数。

## 设计时怎么用（反推思维）
- 学 C 打底（指针/内存模型），再上 C++ 才不虚；
- 资料包 `14本C++书籍` 是深入学习入口（见 [[C语言资料包索引]]）；
- 与 [[C语言编码规范]] 的命名/头文件规则一致，C++ 同样适用。
