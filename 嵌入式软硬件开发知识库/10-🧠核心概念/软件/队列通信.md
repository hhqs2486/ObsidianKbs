# 队列通信

## 一句话定义
> 队列（Queue）是 FreeRTOS 中**任务间传递数据**的核心机制，本质是一个线程安全的环形缓冲区，支持数据按值复制、FIFO 顺序、阻塞等待。

## 它解决什么问题 / 为什么存在
- 多个任务之间需要传递数据（传感器读数、命令、状态），直接用全局变量会竞态（A 写一半 B 读）
- 需要一种"生产者不关心谁消费、消费者不关心谁生产"的解耦通信方式
- 生产者和消费者的速度不匹配时需要缓冲（生产者快→队列暂存；消费者快→队列阻塞等）

## 核心原理（大二能懂的水平）
- 底层是**环形缓冲区** + **两个等待链表**（等着发数据的任务链表 + 等着收数据的任务链表）
- 发送时：数据按值复制（memcpy）到缓冲区，不是传引用——发完可以立即修改原变量不影响队列里的
- 接收时：从缓冲区复制出来，然后该槽位标记为空
- 效率优化——"零拷贝"：如果队列为空但有人等着收，发送方直接把数据 memcpy 给接收方，**不经过队列缓冲区**；反过来也一样（队列满但有等待发送的，接收方直接从发送方拿）
- 阻塞超时：`0` = 不等待立即返回，`portMAX_DELAY` = 无限等，其他值 = 等 N 个 tick

## 关键参数 / 易错点
- **创建队列的两个参数**：`uxQueueLength`（槽位数）+ `uxItemSize`（每个槽字节数，传结构体时用 `sizeof(struct)`）
- **中断里必须用 `FromISR`**：`xQueueSendFromISR()` / `xQueueReceiveFromISR()`，否则 HardFault
- **阻塞只在任务中有效**：ISR 中不能阻塞，即使传 `portMAX_DELAY` 也当 `0` 处理
- 队列满了再发：如果超时=0 则立即返回 `errQUEUE_FULL`；超时=portMAX_DELAY 则任务阻塞等有空位
- 队列空了再收：同理，要么返回失败要么阻塞等
- **队列里是复制，不是引用**：大结构体会消耗带宽，可以改传指针（但要确保指针指向的数据在接收方使用时仍然有效）

## 类比（帮助理解）
- 队列就像餐厅的传菜口（FIFO）：厨师（生产者）从一边放盘子，服务员（消费者）从另一边取盘子；传菜口只能放固定数量的盘子（队列深度）；满了厨师就等着（阻塞），空了服务员就等着

## 设计时怎么用（反推思维）
> 如果这条知识能用于「从需求到设计」，在这里写一句：做 XX 设计时，我会用它能解决 YY。
- 做多传感器数据汇聚设计时：每个传感器任务私有队列写入，数据处理任务统一读取——解耦传感器和算法
- 做 UART 接收设计时：UART RX 中断中 `xQueueSendFromISR` 推送字节，解析任务 `xQueueReceive` 拼完整帧

## 典型应用 / 我在哪见过
- ADC 采集任务 → 队列 → 数字滤波器任务
- 按键任务 → 队列（按键事件）→ UI 状态机任务
- UART/SPI/I2C 驱动层 → 队列 → 协议解析层
