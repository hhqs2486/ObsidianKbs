# 大小端字节序

## 一句话定义
多字节数据（如 `int`、`short`）在内存里的**字节排列顺序**：
- **大端 Big-Endian**：高位字节存低地址（和人类书写顺序一致，网络/PowerPC 常用）
- **小端 Little-Endian**：低位字节存低地址（x86、ARM-Linux 默认）

例：`0x12345678` 在内存：大端 = `12 34 56 78`，小端 = `78 56 34 12`。

## 它解决什么问题 / 为什么存在
不同 CPU 架构字节序不同。数据跨架构、跨网络传输时若不考虑字节序，解析出来就是乱码（0x1234 变成 0x3412）。

## 核心原理（大二能懂的水平）
- **判断方法（经典面试题）**：
  ```c
  union { int i; char c; } u;
  u.i = 1;  // 小端：c==1（低地址是 0x01）；大端：c==0
  ```
  或用指针：`*(char*)&x` 看低地址字节。
- **网络字节序 = 大端**：TCP/IP 规定，发前用 `htonl/htons` 转，收后用 `ntohl/ntohs` 转。
- ARM 内核字节序可配，但跑 Linux 时默认小端。
- 结构体跨平台还要注意**内存对齐**（见 [[堆栈与内存布局]]），字节序 + 对齐是双重坑。

## 关键参数 / 易错点
- 串口/网络收到的多字节（如 `uint16_t` 寄存器值）必须按**网络序转主机序**，否则数值错。
- 强转指针读多字节跨越对齐边界 → 某些架构直接总线错误（bus error）。
- 不要假设"本机就是小端"——写协议/驱动时显式处理。

## 类比（帮助理解）
书从左到右写 vs 从右到左写，同一串数字两种排法；双方约定好顺序才能读懂。

## 设计时怎么用（反推思维）
- 反推"为什么读到的寄存器值反了"→ 八成是字节序或位域顺序没处理。
- 写通信协议 → 明确定义字节序（通常大端），收发两侧统一转换函数。

## 典型应用
网络协议栈、Flash 镜像、传感器多字节数据、跨平台数据共享。
