# volatile 与 const 关键字

## 一句话定义
- **volatile**：告诉编译器"这个变量可能被意想不到地改变（硬件/中断/其他线程），别优化掉对它的内存访问，每次都从内存重读"。
- **const**：只读限定，表明"我不想让它被修改"，用于保护变量/参数/指针。

## 它解决什么问题 / 为什么存在
编译器为了效率会"聪明地"把变量缓存进寄存器、删掉"看似无用"的读写。但嵌入式里变量常被外设、中断、其他核改写，缓存会读到过期值 → 诡异 bug。volatile 强制老实访问内存。

## 核心原理（大二能懂的水平）
**volatile 三个经典例子（面试必背）**：
1. **内存映射硬件寄存器**：`volatile uint32_t* status = (uint32_t*)0x40021000;` 状态寄存器被外设改，必须每次读真实值。
2. **中断服务程序(ISR)与 main 共享的全局变量**：main 循环读的标志位，ISR 里改了，不加 volatile 编译器可能一直用寄存器里的旧值。
3. **多线程/多核共享变量**：被另一线程改。

**const 的用法**：
- `const int a = 10;` 变量不可改
- `const int* p;` 指向常量的指针（p 可改，*p 不可改）
- `int* const p;` 常量指针（p 不可改，*p 可改）
- `const int* const p;` 都不可改
- 函数参数 `const char* s`：承诺不修改传入的字符串

**组合 `const volatile`**：只读的硬件状态寄存器——值会变（volatile）但不该被程序写（const）。

## 关键参数 / 易错点
- **volatile 不保证原子性**，也不能替代互斥锁（见 [[互斥与信号量]]）；它只管"别优化掉访问"。
- const 是**编译期**只读约束，不保证运行时不可改（可强转去掉）。
- volatile 用错位置会拖慢性能（每次都访存）；不用则出隐蔽 bug。

## 类比（帮助理解）
volatile = "这个公告栏谁都能改，你每次都要去现场看，别凭记忆"；const = "这张纸钉死不许涂改"。

## 设计时怎么用（反推思维）
- 反推"为什么 main 一直读不到中断改的标志"→ 变量加 volatile。
- 写寄存器/状态位 → `volatile`；接口参数不被改 → `const`。

## 典型应用
裸机寄存器访问、ISR 与主循环通信、RTOS 任务间共享标志、设备驱动。
