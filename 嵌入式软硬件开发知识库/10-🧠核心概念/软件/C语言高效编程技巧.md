# C语言高效编程技巧

## 一句话定义
在"功能正确"之后，进一步追求**运行更快、体积更小、可维护性更高**的 C 代码写法集合——嵌入式里尤其重要，因为 MCU 的 Flash/RAM/主频都紧。

## 为什么存在
嵌入式 MCU 资源有限（几 KB~几百 KB RAM），且常要求实时响应。同样的功能，写法不同可能差几倍时间或几 KB 内存。下面四招来自《C语言高效编程技巧》原文（见 [[C语言资料包索引]] 里的 `C语言高效编程技巧` 目录）。

## 核心技巧（大二能懂）

### 第1招：以空间换时间
矛盾是"空间 vs 时间"。例如字符串赋值：
- 方法A：`memset`+`strcpy` 两次函数调用，灵活但慢；
- 方法B：`const char string2[]="...";` 直接拿指针用，零函数调用、执行最快，代价是多占内存。
> 实时性要求高、内存还宽裕时，用 B。变招：**用宏函数代替小函数**——宏只占空间不占调用时间（见下方 `SET_BITS`）。

```c
// 宏函数（ARM 官方源码，三行覆盖全部位操作）
#define BIT_MASK(__bf) (((1U<<(bw##__bf))-1)<< (bs##__bf))
#define SET_BITS(__dst,__bf,__val) \
  ((__dst)=((__dst)&~(BIT_MASK(__bf)))|(((__val)<<(bs##__bf))&(BIT_MASK(__bf))))
```
> 宏函数没有函数调用的压栈/弹栈开销，但会展开占用代码空间；**频繁调用的小操作**才划算。

### 第2招：数学方法解决问题
求 1~100 和：
- 方法E：`for` 循环 100 次（100 次赋值+判断+加法）；
- 方法F：`I=(100*(1+100))/2`，1 次加法+1 次乘+1 次除。
> 动脑筋找规律（等差数列、查表、位运算替代乘除），效率可差数量级。

### 第3招：使用位操作
- `I=257/8;` → 改 `I=257>>3;`（除以 2 的幂用右移）
- `J=456%32;` → 改 `J=456-(456>>4<<4);`（取模用位运算）
> 除法/取模在 MCU 上很慢（可能调库函数），位运算只需几条汇编。注意**可移植性**：不同 CPU 字长不同，位技巧移植时可能埋坑，进阶后再用。

### 第4招：汇编嵌入（必杀技）
对 memcpy 这类底层操作，ARM 上用内联汇编 `LDMIA/STMIA` 一次搬 8 个字，比 C 循环快得多。代价是**丧失可移植性**，只在确定平台、确实是瓶颈时用。

## 常见错误（来自 `C语言常见错误集合.txt`）
1. 标识符大小写不分（`a` 与 `A` 是两个变量）；
2. 类型不符做非法运算（实型不能 `%` 求余）；
3. 字符常量 `'a'` 与字符串 `"a"` 混淆；
4. `=` 赋值 与 `==` 判断 写错（初学者高频坑）；
5. 语句漏写/多写分号（尤其 `if(...);` 后面多分号导致逻辑错）；
6. `scanf` 输入变量漏写 `&` 取地址符；
7. 输入格式与 `scanf` 要求不符（逗号分隔不被 `%d%d` 接受）；
8. 数组越界、指针未初始化。

## 设计时怎么用（反推思维）
- 先保证**清晰可维护**（见 [[C语言编码规范]]），确定瓶颈再做第1/3/4 招优化；
- 寄存器操作、协议打包用第3招位运算最自然（也见 [[位运算]]）；
