# 时间复杂度

## 一句话定义
时间复杂度描述"算法运行时间随问题规模 n 增长的趋势"，记作 `T(n)=O(f(n))`，叫大 O 记法。它忽略常数和低阶项，只看增长快慢。

## 它解决什么问题 / 为什么存在
同一问题不同算法，n 变大后快慢天差地别。复杂度让我们**不跑程序也能比优劣**，尤其 MCU 主频低、RAM 小，提前估复杂度能避免写出"数据一多就卡死"的代码。

## 核心原理（大二能懂的水平）
把算法里"语句执行次数"写成关于 n 的函数 T(n)，取它的数量级：
1. 所有加法常数用 1 代替；
2. 只保留最高阶项；
3. 去掉最高阶项前的系数。
例：循环 `for(i=0;i<n;i++) sum+=i;` 执行 n 次 → O(n)；两层嵌套 → O(n²)。

常见量级（由快到慢）：
`O(1) < O(log n) < O(n) < O(nlog n) < O(n²) < O(2ⁿ)`
空间复杂度同理，看额外内存随 n 的增长（栈 / 堆占用）。

## 关键参数 / 易错点
- O(1) 不是"只执行一次"，而是"次数与 n 无关"（如三条赋值仍是 O(1)）。
- 别把循环层数当全部：while(count*=2) 是 O(log n)，不是 O(n)。
- 最坏 / 平均 / 最好要分清（如快排平均 O(nlog n)、最坏 O(n²)）。
- 空间复杂度常被忽略：`malloc` 的额外数组要算进去。

## 类比（帮助理解）
搬 100 块砖：O(1) 是叫一台吊车一次吊走；O(n) 是一块块搬；O(2ⁿ) 是每搬一块数量翻倍——指数爆炸，n 稍大就完蛋。

## 设计时怎么用（反推思维）
先问"数据量 n 大概多大、要实时吗"：n 小无所谓 O(n²)；n 大或实时 → 至少 O(nlog n)。要省 RAM → 看空间复杂度，优先原地算法。

## 典型应用
选排序算法（见 [[排序与查找]]）、估查找效率、判断 [[递归]] 深度是否会爆栈。
