# Linux 驱动与内核模块

## 一句话定义
让 Linux 内核识别并操作硬件的代码；常以**可加载内核模块（.ko）**形式动态 `insmod` 进内核，无需重编整个内核。

## 它解决什么问题 / 为什么存在
硬件寄存器、中断只有**内核态**才有权限访问。驱动就是"内核里负责某硬件的那段代码"，把硬件能力以文件接口（`/dev/xxx`）暴露给用户程序。

## 核心原理（大二能懂的水平）
**三大类驱动**：
- 字符设备（按字节流访问：串口、LED、按键、大部分传感器）
- 块设备（按块访问：硬盘/SD/Flash）
- 网络设备（网卡，走协议栈而非文件接口）

**字符设备框架**：
1. 定义 `file_operations` 结构体，挂上 `open/release/read/write/ioctl` 等函数。
2. 分配/初始化 `cdev`，用 `register_chrdev_region` + `cdev_add` 注册，绑定主/次设备号 `dev_t`。
3. `mknod /dev/xxx c 主 次` 创建设备节点；用户态 `open` 它即可调你的函数。

**模块机制**：`module_init`/`module_exit` 宏指定加载/卸载函数；`printk` 打印（用 `dmesg` 看）；`insmod`/`rmmod` 动态装卸。

**驱动 = 硬件操作 + 框架**：硬件操作靠读芯片手册配寄存器/中断；框架是上面那套注册流程。现代还配合 [[设备树DeviceTree]] 从 dts 取地址/中断。

## 关键参数 / 易错点
- **竞态**：驱动里多用 [[互斥与信号量]]（spinlock 中断上下文 / mutex 进程上下文），否则多进程同时访问会乱。
- 用户/内核空间数据不能直拷 → 必须用 `copy_to_user` / `copy_from_user`。
- 卸载时要反注册、释放资源，否则内核内存泄漏或野指针。
- Linux 中断模型与 MCU 的 [[中断NVIC]] 不同（顶半部/底半部、不能睡眠）。

## 类比（帮助理解）
驱动像"硬件的翻译官"：用户程序说"读个温度"，翻译官（驱动）去查寄存器、读 ADC，再把结果翻回给用户。

## 设计时怎么用（反推思维）
- 反推"加个新传感器"→ 先确认它挂在哪条总线(I2C/SPI)，写 dts 节点，再写字符设备驱动框架 + 硬件读写。
- 调试驱动 → `dmesg` 看 `printk`；先保证 `probe` 成功再调读写。

## 典型应用
所有接在 Linux 板上的外设：Flash、网卡、USB、LCD、触摸屏、传感器。
