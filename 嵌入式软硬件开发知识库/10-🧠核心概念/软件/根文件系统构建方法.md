# 根文件系统构建方法

## 一句话定义
根文件系统(rootfs)是内核挂载的第一个文件系统，包含用户空间的基础命令、库、配置和 init 进程。构建方法有 BusyBox、Buildroot、Debian、Ubuntu 等。

## 它解决什么问题 / 为什么存在
内核启动后需要一个文件系统提供 /bin/init、/lib/libc.so、/etc 配置等。不同场景需求不同：资源紧张用 BusyBox（几 MB），需要包管理用 Debian/Ubuntu（几百 MB），自动化构建用 Buildroot。

## 核心原理（大二能懂的水平）
四种主流方法：

1. BusyBox（最小化）：手动编译 BusyBox -> 拷到 rootfs 目录 -> 添加 libc -> 打包 ext4/jffs2。优点：极小约 4MB、可控；缺点：手动管理依赖、无包管理器

2. Buildroot（自动化构建）：make menuconfig 选目标板+组件 -> make -> 输出完整 rootfs。优点：自动处理依赖、可定制；缺点：编译时间长

3. Debian（包管理）：debootstrap 生成基础系统 -> chroot 安装包 -> 打包。优点：apt 包管理、软件丰富；缺点：体积大约 200MB+

4. Ubuntu（桌面级）：类似 Debian，预装更多桌面组件。优点：生态最全；缺点：体积大、启动慢

rootfs 基本结构：/bin /sbin /lib /etc /dev /proc /sys /usr /var /home

## 关键参数 / 易错点
- rootfs 必须有 init 进程（/sbin/init 或 /bin/sh），否则内核 panic
- /lib 下的 libc 和 ld 必须和交叉编译器匹配
- /dev 下设备节点可以手动 mknod 或用 devtmpfs/mdev 自动创建
- rootfs 格式：ext4(SD/eMMC)、jffs2(NOR Flash)、ubifs(NAND Flash)、squashfs(只读压缩)
- bootargs 里 root= 指定的设备必须和实际 rootfs 所在分区一致

## 类比（帮助理解）
rootfs 像毛坯房交付后的装修：BusyBox=极简出租屋（床+灶台），Buildroot=精装公寓（按需配置），Debian/Ubuntu=精装大平层（啥都有但贵）。

## 设计时怎么用（反推思维）
反推：资源紧张的嵌入式设备 -> BusyBox；需要快速出产品 -> Buildroot；需要丰富软件生态 -> Debian；需要桌面 UI -> Ubuntu。

## 典型应用
所有嵌入式 Linux 系统的 rootfs 构建（I.MX6ULL、RK3568、树莓派等）。
