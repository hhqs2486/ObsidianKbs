# 设备树 Device Tree

## 一句话定义
用 **dts（文本）/ dtb（编译后二进制）** 描述板级硬件（CPU、内存、外设、引脚、中断号）的机制；内核启动时读取 dtb 来"认识"这块板子，替代老式的 board 文件硬编码。

## 它解决什么问题 / 为什么存在
同一颗 SoC（如 i.MX6）会用在无数板子上，硬件连接差异巨大。若把硬件描述写死在内核代码里，内核会变得又臃肿又不可移植。设备树把"硬件长什么样"从内核**抽出来**成独立文件，内核本身保持通用——换板子只换 dts。

## 核心原理（大二能懂的水平）
- 流程：`xxx.dts` →（dtc 编译）→ `xxx.dtb`；uboot 把 dtb 和内核一起加载，传给内核。
- 结构：**节点 + 属性**。根节点下挂 `cpu`、`memory`、`serial`、`i2c` 等子节点。
- 关键属性：
  - `compatible = "vendor,device"`：驱动靠它匹配自己（驱动里有 `of_match_table` 比对这个字符串）
  - `reg = <地址 长度>`：寄存器基地址与范围
  - `interrupts`：中断号/触发方式
  - `status = "okay" | "disabled"`：使能/禁用
- 驱动通过 `of_*` 系列 API 从设备树取资源（地址、中断），再 `request_irq`/`ioremap`。

## 关键参数 / 易错点
- `compatible` 字符串写错/拼错 → 驱动匹配不上，设备"消失"。
- `reg` 地址长度与数据手册不符 → 访问错寄存器。
- 节点忘了 `status = "okay"` → 默认可能不使能。
- 资料包偏老（S3C2440 时代用 board 文件），**设备树是现代必学补充**，务必另外练。

## 类比（帮助理解）
设备树像"板子的身份证/户口本"：内核是"通用办事员"，看了户口本（dtb）才知道这家人（板子）有几口人、住哪、电话多少。

## 设计时怎么用（反推思维）
- 反推"怎么让同一内核适配不同板"→ 把硬件描述外置成 dts，内核只认规则不认具体板。
- 加新外设 → 写/改 dts 节点（compatible/reg/中断），再写对应驱动框架代码。

## 典型应用
所有现代 ARM Linux（i.MX / RK / Allwinner / AM335x…）板级描述。
