# 堆栈与内存布局

## 一句话定义
C 程序运行时的典型**五段内存布局**：
- `.text`：代码段（只读、可执行）
- `.data`：已初始化的全局/静态变量
- `.bss`：未初始化的全局/静态变量（启动清 0）
- **堆 heap**：`malloc` 动态分配，向高地址生长，**程序员手动管**
- **栈 stack**：函数调用栈帧、局部变量、参数，向低地址生长，**自动管**

## 它解决什么问题 / 为什么存在
理解内存布局才能解释"为什么会栈溢出""返回局部变量地址为什么危险""malloc 不 free 为什么会泄漏"。

## 核心原理（大二能懂的水平）
**堆 vs 栈**：
| | 栈 stack | 堆 heap |
|---|---|---|
| 生长方向 | 高→低地址 | 低→高地址 |
| 管理 | 编译器自动(进出作用域) | 程序员 malloc/free |
| 速度 | 快(CPU 直接移动 SP) | 慢(需找空闲块/维护空闲链表) |
| 大小 | 受限(默认几 MB，易溢出) | 大(受限于物理内存) |
| 碎片 | 无 | 有(频繁分配释放) |

**内存分配方式**（面试常问）：静态(.data/.bss)、栈(局部)、堆(malloc)、只读(.text/常量)。

## 关键参数 / 易错点
- **返回局部变量地址**：函数返回后栈帧销毁，指针变野指针（经典坑）。
- **栈溢出**：函数内大数组、深递归 → 覆盖相邻内存/崩溃。
- **内存泄漏**：malloc 不 free；**悬空指针**：free 后继续用。
- 局部 static 不在栈上（见 [[static关键字]]），在 .data/.bss。

## 类比（帮助理解）
栈像餐厅一次性餐盘架（用完自动收）；堆像自助仓库（你自己借还，忘了还就丢库存）。

## 设计时怎么用（反推思维）
- 反推"大缓冲放哪"→ 太大别放栈(局部数组)，用堆或全局/静态。
- 反推"为什么返回 &local 崩"→ 别返回栈上地址，改用堆或传出参数。

## 典型应用
嵌入式里栈空间尤其紧张（RTOS 每个任务有独立栈），排布要算清。
