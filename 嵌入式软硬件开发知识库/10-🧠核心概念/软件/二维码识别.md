# 二维码识别（QR Code Decode）

> 让 STM32「扫」二维码：摄像头抓图 → 预处理 → 定位三个角 → 透视校正 → 按版本解码比特流 → 纠错 → 出字符串。项目合集里「基于STM32的二维码识别源码+解码库 lib」给了一套可直接移植的方案。

## 一句话定义
二维码（QR）是二维条码，靠黑白模块排布存数据；识别 = 图像算法把画面里的码还原成文本/URL。

## 为什么存在
设备扫码绑定、产线追溯、APP 快速配网（比手动输 SSID 方便）都要本地识码，不依赖手机。

## 核心原理
1. **图像采集**：OV 系列摄像头 → DCMI 接口（或并口）→ MCU 收灰度图。
2. **预处理**：灰度化 + 二值化（全局/局部阈值，对抗光照不均）+ 几何校正。对应 [[滤波算法]]。
3. **定位**：找三个「回」字形定位角（finder pattern）→ 算透视变换把歪的码拉正。
4. **解码**：按 QR 版本/格式信息读模块 → 数据码字 → **RS 里德-所罗门纠错**（容错 L/M/Q/H）→ 出结果。
5. 开源解码库（如 Quirc / 项目合集合并的 lib）把 2~4 步封装成 `decode(img)` 函数。

## 关键参数·易错点
- 分辨率太低扫不出（码边长建议 ≥ 图像 1/5）；光照不均二值化必翻车 → 用局部自适应阈值。
- MCU RAM 小，大图要分块或降采样；浮点运算多，M4/M7 更稳。
- 纠错等级越高越抗脏，但能存数据越少。

## 类比
像 [[通信协议设计]] 里的「收发」——只不过发送方是打印机、接收方是摄像头+算法，信道是「光」。

## 设计时怎么用（反推思维）
要本地识码 → 要不要上 Linux（OpenCV 现成）还是纯 MCU（用轻量 lib）？实时性要求高就选带 DCMI 的 STM32 + 优化过的 C 解码库。

## 典型应用
扫码配网、物料追溯、门禁、项目合集「二维码识别源码」。
