# 回调函数

## 一句话定义
> 回调函数（Callback）是通过函数指针传递给另一个函数的函数，当特定事件或条件满足时，由被调用方"回调"执行。它是 C 语言实现异步通知和事件驱动架构的核心机制。

## 它解决什么问题 / 为什么存在
- 让调用者注册一段自定义逻辑，由框架/库在合适时机调用，实现**控制反转（IoC）**。
- 在嵌入式中广泛用于：中断服务注册、定时器回调、数据就绪通知、库的扩展点。

## 核心原理（大二能懂的水平）
- C 语言中通过**函数指针**实现：`void (*callback)(int arg)` 声明一个指向"接受 int 参数、无返回值"函数的指针。
- 调用方将函数地址传给框架函数（注册），框架在事件发生时通过该地址调用该函数（回调）。
- 示例模式：
  ```c
  typedef void (*onDataReady)(char* data, int len);
  void sensor_init(onDataReady cb) {
      // 存储 cb，当传感器数据就绪时调用 cb(buf, len)
  }
  ```

## 关键参数 / 易错点
- **函数指针与函数名**：函数名本身即为函数地址，`cb = myHandler` 等价于 `cb = &myHandler`。
- **参数匹配**：回调函数的参数列表必须与声明的函数指针签名完全一致，否则未定义行为。
- **上下文传递**：C 语言回调通常用 `void* userdata` 参数传递上下文（类似 C++ `std::function` + lambda 捕获）。
- **生命周期**：回调执行时被调用方的栈帧可能已销毁，不要依赖局部变量（除非用了 static 或全局）。

## 类比（帮助理解）
- 就像你留了一个电话号码给快递站（注册），包裹到了快递站按这个号码通知你（回调），你不用一直守着（轮询）。

## 设计时怎么用（反推思维）
> 做嵌入式传感器驱动设计时，用回调模式让传感器 ISR 通过回调通知上层应用，避免在 ISR 中做太重处理；上层注册自己的数据处理函数实现解耦。

## 典型应用 / 我在哪见过
- FreeRTOS 定时器回调 `vTimerCallback`
- C 标准库 `qsort()` 的比较函数回调
- STM32 HAL 中断回调 `HAL_UART_RxCpltCallback`
- Linux 信号处理 `signal(SIGINT, handler)`
- 树莓派 wiringPi 中断 `wiringPiISR(pin, edge, callback)`
