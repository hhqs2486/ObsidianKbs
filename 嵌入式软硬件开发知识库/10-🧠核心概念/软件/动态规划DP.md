# 动态规划DP

## 一句话定义
> 动态规划（Dynamic Programming, DP）是一种将复杂问题分解为重叠子问题，通过记忆化存储子问题结果来避免重复计算，最终组合出全局最优解的算法设计范式。

## 它解决什么问题 / 为什么存在
- 递归暴力搜索有大量重复计算，时间复杂度通常是指数级的（如斐波那契 F(n) = F(n-1) + F(n-2) 会重复计算大量子项）。
- DP 通过**空间换时间**，将中间结果存表，把指数复杂度降到多项式复杂度。
- 在嵌入式场景中也是常用思维：如路径规划、资源调度、传感器状态融合。

## 核心原理（大二能懂的水平）
- **两个条件**：问题必须具有（1）最优子结构 — 最优解可由子问题的最优解构成；（2）重叠子问题 — 递归树中有大量重复的子问题。
- **两种实现**：
  - 记忆化搜索（Top-Down）：递归 + 数组/哈希表缓存结果，遇到已算过的直接返回
  - 递推填表（Bottom-Up）：从小到大循环填 DP 表，最终 `dp[n]` 为答案
- 经典例子：斐波那契 `dp[i] = dp[i-1] + dp[i-2]`；背包问题 `dp[i][w] = max(dp[i-1][w], dp[i-1][w-wt[i]] + val[i])`；最长公共子序列

## 关键参数 / 易错点
- **状态定义**：`dp[i]` 或 `dp[i][j]` 代表什么，是 DP 最难也是最关键的一步。定义不清则转移方程必错。
- **边界初始化**：`dp[0]` 或 `dp[i][0]` 需要根据语义正确初始化，否则结果错。
- **空间优化**：很多二维 DP 只需保留上一行，可用滚动数组从 O(n^2) 降到 O(n)。
- **递推顺序**：Bottom-Up 填表必须是子问题的答案已经算好，不能有循环依赖。

## 类比（帮助理解）
- 就像做菜备料：把洋葱切好、胡萝卜切好（子问题），炒菜时直接加进去，不用每炒一道菜重新切（记忆化避免重复计算）。

## 设计时怎么用（反推思维）
> 做嵌入式路径规划（如 AGV 小车走迷宫）时，用 DP 预计算每个格子的最短距离，运行时只需查表不重复计算。做传感器融合时，用 DP 状态转移模型优化多帧之间的估计。

## 典型应用 / 我在哪见过
- 算法竞赛/笔试 — 背包问题、最长递增子序列、编辑距离、股票买卖、打家劫舍
- 路径规划 — Dijkstra（与 DP 思想一致）、Viterbi 算法
- 嵌入式控制 — PID 参数自适应也可用 DP 做离线优化
- 机器人 SLAM — 粒子滤波中的状态转移概率
