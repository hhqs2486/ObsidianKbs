# 端侧大语言模型 (On-Device / Edge LLM, 2024-2026)

## 一句话定义
把 LLM 直接跑在手机/PC/嵌入式设备本地，不依赖云端。动机：隐私（数据不出设备）、延迟（亚 50ms 键盘补全）、离线、规模化成本（千万次/日分类时自托管更省）。神书(2019)写于大模型时代前，完全没有这一层。

## 推理框架（2025-2026 现状）
| 框架 | 定位 | 亮点 |
|------|------|------|
| **llama.cpp** | 跨平台/社区标准 | 纯 C/C++，GGUF 单文件，Q2_K~Q8_0 + IQ 量化；CPU/CUDA/Metal/Vulkan；投机解码 180+ tok/s；~91K stars |
| **Ollama** | 开发者工具 | 包 llama.cpp + REST API + 模型管理 |
| **MLX** | Apple 专属 | 统一内存架构；M2 Ultra ~230 tok/s，M4 Max 达 525 tok/s |
| **ExecuTorch (Meta)** | 生产移动端 | 1.0 GA(2025-10)，50KB 运行时，`.pte`，12+ 后端；Instagram/WhatsApp 在用 |
| **LiteRT** | 跨平台成熟 | 原 TFLite(2024 改名)，已支持 PyTorch/JAX |
| **Core ML** | iOS 专属 | ANE INT4 |
| **MNN-LLM**（阿里） | 移动端最快 | KV cache 溢到 Flash，长上下文 |

## 小模型（端侧友好）
- **Phi-4-mini** (3.8B)：4-bit GGUF ~2.5GB，指令遵循/推理强。
- **Gemma 3** 2B/4B：Google 专为端侧设计。
- **Llama 3.2** 1B/3B：Meta 首批移动优先模型。

## 量化选型（经验）
- 7B：Q4_K_M(~4GB) 一般业务，Q6_K 关键业务，Q3_K_M 极限压缩。
- 70B：Q4_K_M(~40GB)/Q8_0(75GB) 视内存。
- Apple Foundation Models (WWDC 2025)：免费调用本机 Apple Intelligence，支持引导生成/工具调用。

## 硬件现实
- CPU 1-5 tok/s（移动端，非实时）；移动 GPU 5-10x 但易降频；**NPU 生产首选**（Hexagon 图像 TTFT 0.12s，比 CPU 快 100x、比 GPU 省电 35-70%），但需后端专属量化、不跨芯片族。
