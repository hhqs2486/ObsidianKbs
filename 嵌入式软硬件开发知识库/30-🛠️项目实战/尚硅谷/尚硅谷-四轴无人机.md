# 尚硅谷-四轴无人机

> 基于 STM32F103C8T6 的微型四轴飞行器：MPU6050 六轴姿态 + 四元数 [[姿态解算]] + 串级 [[PID控制算法]] 稳姿态，Si24R1（[[NRF24L01]]）2.4G 遥控，[[FreeRTOS]] 做多任务调度，分飞控板与遥控板两套硬件。

## 1. 需求拆解
- 必须实现
  - 姿态自稳：MPU6050 取三轴加速度/角速度，解算横滚/俯仰/偏航三倾角，串级 PID 控制平衡。
  - 2.4G 遥控：遥控板发指令、飞控板回传数据（遥控每 10ms 发一次，2ms 收一次）。
  - 数据显示：电池电压、摇杆量、2.4G 信道实时显示在 OLED。
  - 多任务调度：移植 FreeRTOS 管理姿态、通信、显示任务。
- 可选实现
  - 无（微型四轴已是最简闭环）。
- 硬约束
  - 3.7V / 2000mAh 单芯锂电，需 [[线性电源LDO]] 降到 3.3V 给逻辑。
  - 微型、低成本、X 型布局；采用有刷电机（非无刷）。

## 2. 功能框图
```
飞控板 STM32F103C8T6
  MPU6050 ──I2C1(0x68)──► 姿态(加速度+角速度)
  Si24R1  ──SPI1+CE/IRQ/CSN──⇄ 遥控板(2.4G)
  TIM1/2/3/4 PWM ──► 电机驱动 ──► 有刷电机×4(X布局,正反桨)
  ADC(分压) ──► 电池电压检测
   LED ──► 状态指示

遥控板 STM32F103C8T6
  双摇杆(4通道) ──ADC──► 油门/偏航/横滚/俯仰
  Si24R1 ──SPI1──⇄ 飞控板
  12864 OLED ──SPI/GPIO──► 显示
  按键(微调/对频) ──GPIO
  3.7V 电池 ──LDO──► 3.3V
```

## 4. 原理图推导（逐个模块，讲清为何需要每个元件）
- **STM32F103C8T6 最小系统**：[[复位电路]]、8M 晶振、[[去耦电容]]、[[时钟树]]、SWD 下载。它是飞控和遥控共用的主控，靠内置 I2C/SPI/PWM/ADC 同时吃下姿态、通信、驱动、采集四类外设。
- **MPU6050**：通过 [[I²C]]1（地址 0x68）接 MCU。为何需要：姿态必须同时知道「角速度」和「加速度」，单陀螺仪会漂移、单加速度计不动时判不出角度，六轴互补才能解算三倾角。I2C 只需 2 根线（SDA/SCL 需 [[上拉电阻与下拉电阻]]）。本项目自己读原始六轴做四元数解算，比 MPU 自带 DMP 更准更稳。
- **Si24R1（NRF24L01 国产替代）**：经 [[SPI]]1 通信，外加 CE（收发模式切换）、IRQ（中断通知）、CSN（片选）三个 GPIO。为何需要：遥控与飞控要无线双向、低延迟；2.4G 模块速率够、引脚兼容 NRF24L01，国产 Si24R1 降本。对频就是让双方 RF 频道/地址一致。
- **电机驱动电路**：4 路 PWM（TIM1_CH3 / TIM2_CH2 / TIM3_CH1 / TIM4_CH4）经 [[三极管开关电路]] 或 MOS 放大后驱有刷电机——见 [[直流电机驱动]]。为何需要驱动级：MCU IO 电流小，带不动电机；PWM 占空比 = 转速。X 布局要求 1/3 与 2/4 转向相反，配正反桨抵消反扭矩（偏航原理）。
- **电池电压采集**：电池电压经电阻分压（÷2）后进 ADC，公式 `bat=0.2*(ADC*3300/4095*2)+0.8*bat`，即一阶低通。为何分压：电池满电 > 3.3V，分压后落进 ADC 量程，同时顺带做电量监测。
- **12864 OLED**：遥控板用 SPI 或 GPIO 模拟（CS/DC/RST/SDIN/SCLK）显示。为何需要：现场要实时看到电压、摇杆、信道，不用每次连电脑。
- **双摇杆**：左摇杆=油门(上下)+偏航(左右)，右摇杆=横滚(左右)+俯仰(上下)，4 个电位器进 4 路 ADC；航模通道值 1000~2000（中位 1500）。按键做微调/对频。
- **电源**：3.7V 锂电 → [[线性电源LDO]]（3.3V）给 MCU/传感器；电机直接接电池经驱动级，逻辑地与功率地分离。
- **FreeRTOS 任务划分**：飞控板建 3 个任务——2ms（姿态串级 PID，最频）、4ms、50ms（显示）；遥控板 4ms + 20ms。用 [[任务与调度]] 把「高频控制」与「低频显示/通信」分时，避免裸机大循环卡顿。
- 本项目仅有 HAL 库版（docx V1.0.1），无寄存器对照版。

## 5. 布局布线要点
- 电机是大电流噪声源：电池功率线单独走、与 MCU/通信线隔开；驱动 MOS 靠近电机，逻辑地与功率地单点相连。
- 每片 MCU / MPU6050 / Si24R1 电源就近放 [[去耦电容]]（0.1µF）。
- 2.4G 天线远离电机和金属、避免遮挡与甩线，否则遥控距离骤降。
- 全 3.3V 逻辑；电机驱动级走电池电压，注意驱动级与逻辑间用 [[三极管开关电路]] 隔离。
- MPU6050 远离电机并加减震：振动直接污染加速度计，触发 [[滤波算法]] 也难救，会恶化 [[姿态解算]] 与串级 PID。

## 6. 检查清单
- [ ] STM32F103 最小系统完好
- [ ] MPU6050 I2C 上拉、地址 0x68 可通
- [ ] Si24R1 SPI + CE/IRQ/CSN 接线正确，双方对频（频道/地址一致）
- [ ] 4 路 PWM → 电机驱动 → 电机，X 布局转向/正反桨正确
- [ ] 电池分压电阻接入 ADC，电压公式标定
- [ ] OLED / 双摇杆 / 微调对频按键 接线正确
- [ ] 3.3V LDO 与电机电源分离、单点共地
- [ ] FreeRTOS 任务周期（2/4/50ms）合理，中断优先级不踩内核红线

## 7. 复盘
- 工程师思维贯穿「反推」：微型四轴选 X 布局（稳定性 > 十字）；加速度计受振动 → 把角度放串级 PID 外环、角速度放内环，既抗扰又提响应；自己读 MPU6050 做四元数解算而非依赖 DMP，精度更可控；Si24R1 国产替代降本；电池分压 + 一阶低通做电压监测；FreeRTOS 把姿态(2ms)、通信(4ms)、显示(50ms)分时。这些都是在「性能/成本/稳定」三角里做工程取舍。
