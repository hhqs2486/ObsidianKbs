# 宠物定位器

> 一套"宠物/老人随身定位器 + 主人接收器"组合：定位器用 GPS 取坐标，经 LoRa 或 4G 发给接收器，接收器再经 BLE 推到手机 APP。本项目聚焦嵌入式软件。

## 1. 需求拆解
- 必须实现：
  - 定位器（随身）：STM32F103C8T6 + LoRa + 4G-GPS 模组，定时取 GPS 并外发。
  - 接收器（主人随身）：STM32F103ZET6 + LoRa + 蓝牙，收 GPS 后经 BLE 推手机 APP。
  - 主链路 LoRa 把 GPS 发给接收器；LoRa 失败则 4G 发后台服务器，APP 从互联网取。
  - GPS 坐标格式 `+GPSINFO:<LON>,<LAT>,<ALT>,<SPD>,<UTCtime>`（dd.dddd）。
- 可选实现：
  - 拓展到老人定位等同类需求。
  - 后台服务器 / 手机 APP（本项目不做，由公司专门工程师负责）。
- 硬约束（供电/尺寸/成本/通信）：
  - 通信：LoRa 433M 远距离低功耗；4G 仅兜底；BLE 连手机。
  - 供电：定位器/接收器均便携，4G-GPS 模组 VIN 5–16V。
  - 范围：GPS 需户外搜星（至少 4 颗卫星解算三维坐标+时间）。

## 2. 功能框图

```
  定位器 STM32F103C8T6            接收器 STM32F103ZET6

  │ 4G-GPS 模组        │           │ LoRa E220         │

           ▼                             ▼
      后台服务器 ──互联网──▶ 手机APP ◀────┘
```

## 4. 原理图推导（逐个模块，讲清为何需要每个元件）
- **定位器主控 STM32F103C8T6**：跑 GPS/4G/LoRa 三件套。用 [[CubeMX]] 配时钟、USART、GPIO，[[HAL库结构]] 自动生成驱动层代码。USART2 连 4G-GPS 模组（[[UART]]），USART1 仅调试（printf 经 `fputc` 重定向）。
- **4G-GPS 模组 FS-MCore-F800EG**：把"联网 + 定位"两件麻烦事下沉给模组。为什么？MCU 不必自己跑 TCP/IP 和 NMEA 解析，只发 `adminAT+GPSINFO` 取经纬度。模组 VIN 5–16V，其 TX/RX **已上拉到 3.3V**（[[上拉电阻与下拉电阻]]），与 STM32 3.3V IO 直接兼容，**无需 [[电平转换]]**；PEN 为电源使能、DTR 拉低 3s 恢复出厂。
- **LoRa E220-400M22S（LLCC68）**：433M 把 GPS 发给接收器。为什么用 LoRa？宠物/老人场景要穿墙远距、低功耗，LoRa 比 BLE/WiFi 远得多；背景里讲调制原理（频率越高波长越短、天线越短），LoRa 用 FSK 搬频。移植官方 `ebyte_core` 驱动即可。
- **接收器主控 STM32F103ZET6**：收 LoRa → ESP32 BLE 转手机，资源比 C8T6 富，便于扩展。
- **ESP32-C3 蓝牙（[[BLE蓝牙]]）**：AT 指令建 BLE server + SPP 透传，手机 APP 连上即收 GPS 文本。为什么 BLE 透传？手机原生支持 BLE，无需额外私有协议框架，最省事。
- **兜底链路**：LoRa 失败 → 4G 把 GPS 发后台服务器（Socket TCP）→ APP 从互联网取，体现工程冗余。
- **软件架构**：驱动层（HAL 自动生成）→硬件接口层（GPS/4G、LoRa、ESP32）→应用层（定时取 GPS、外发）。定位器每 5s 取一次；调试靠 [[中断NVIC]] 的 UART 中断 + `printf`，GPS 解析用 [[结构体与位域]] 管理缓冲。

## 5. 布局布线要点
- **双电压域**：4G-GPS 模组 VIN 5–16V，但其逻辑 IO 是 3.3V；模组电源与 MCU 3.3V 域分开，模组侧 [[去耦电容]] 必须足（射频瞬间电流大），否则掉线。
- **LoRa 433M 天线**：天线长度与波长相关（背景讲调制），远离电机/电源噪声，天线座焊接可靠才能远距。
- **ESP32 与 STM32 同 3.3V**：串口直连；上拉已在模组内部，外部勿重复强上拉。
- **恢复出厂**：DTR 拉低 3s 恢复出厂，调试/产线接口要能触发。
- **工程配置锁死**：两板 CubeMX 的时钟树、USART 波特率、中断优先级要固定，烧错直接跑飞。

## 6. 检查清单
- [ ] 定位器 USART2 接 4G-GPS、USART1 仅调试，波特率匹配
- [ ] 4G-GPS 模组 VIN/地、TX/RX（3.3V 上拉）接对，PEN/DTR 可控制
- [ ] LoRa E220 天线焊接可靠、驱动移植成功
- [ ] 接收器 ESP32-C3 AT 固件支持 BLE SPP，广播名已配置
- [ ] 双板 3.3V 域与模组电源域隔离、去耦齐全
- [ ] GPS 冷启动/使能 AT 顺序正确，户外搜星测试通过
- [ ] 兜底：LoRa 不通时 4G 能发后台服务器
- [ ] 定位周期 5s，低功耗与实时性平衡

## 7. 复盘
- **为什么 GPS+4G 用模组而非 MCU 自解**：把 TCP/IP、NMEA、基站注册全下沉，MCU 只发 AT，开发与稳定性双赢（同 [[物联网终端]] 思路）。
- **为什么主链路用 LoRa**：宠物场景要远距、低功耗、穿墙，LoRa 最优；4G 仅兜底，省流量与功耗。
- **为什么蓝牙用 ESP32 透传**：手机原生 BLE，APP 直接读文本，省一套私有协议；[[通信协议设计]] 只需约定 GPS 文本格式。
- **企业分工**：后台/APP 由专门工程师做，本项目只攻嵌入式软件，体现真实协作边界。
