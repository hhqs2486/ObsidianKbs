# STM32数字示波器与DSP

> 一台基于 STM32F4 + uCOS-III + STemWin 的数字存储示波器（DSO）：把模拟信号经前端调理、ADC 等间隔采样进 MCU，再用 CMSIS-DSP 做 FFT 频谱和 FIR 数字滤波，最终在触摸屏上画出波形与频谱。配套安富莱《数字信号处理教程》讲透 FFT/滤波器原理（见 [[数字信号处理DSP]]）。

## 1. 需求拆解
- 必须实现：
  - 模拟输入 → 波形实时显示（时域），支持时基（采样率）与幅值档位切换。
  - 等间隔采样：用定时器触发 [[ADC]] + [[DMA]] 循环缓冲，保证频率轴准确（FFT 的前提）。
  - 数学功能：FFT 频谱（本文用 2048 点实数 FFT）、FIR 低通数字滤波（见 [[滤波算法]]）。
  - 触发与测量：边沿触发、幅值/频率测量值窗口。
- 可选实现：
  - 波形发生器（DAC 输出，源码含 DSO_DacDlg）、文件保存/回读（[[STM32项目合集资料索引]] 中 FatFS 部分）。
  - 触摸 GUI、多档量程自动切换。
- 硬约束（供电/尺寸/成本/通信）：
  - 平台为安富莱 V5 开发板（STM32F4 系列，外接 SDRAM + RGB LCD），资源充足但成本高，属"教学/演示"定位。
  - 实时性靠 uCOS-III 多任务（采集/显示/UI 解耦），见 [[任务与调度]]。

## 2. 功能框图
```
 探头→前端调理               ┌──────────── STM32F4 ────────────┐
 (衰减/增益/耦合)            │  uCOS-III 任务:                │
  运算放大器/模拟开关         │   采集任务: TIM触发ADC+DMA     │
        │ 模拟量             │            → g_usWaveBuf(6144) │
        ▼                    │   显示任务: STemWin GUI 画图    │
   ┌─────────┐  ADC数字量     │   Math任务: CMSIS-DSP          │
   │  ADC1   │ ─────────────▶ │     arm_rfft_fast_f32(2048点) │
   │ (TIM触发)│  DMA2_Stream1 │     → arm_cmplx_mag_f32 幅频   │
   └─────────┘  循环10240点   │     arm_fir_f32 低通滤波       │
        ▲                     └───────┬───────────────┬───────┘
   定时器触发(等间隔)                 │ SPI/FSMC       │ SDIO
                                     ▼                ▼
                                RGB触摸LCD        SD卡(FatFS)
```

## 3. 器件选型
| 模块 | 型号/方案 | 选型理由 | 替代 |
| --- | --- | --- | --- |
| 主控 MCU | STM32F4 系列（安富莱 V5） | F4 带浮点单元、DMA 多流、定时器触发 ADC，跑 RTOS+GUI 够快 | 其它带 FPU 的 F4/F7 |
| 前端调理 | 运算放大器 + 模拟开关/继电器 | 切换衰减/增益与交直流耦合，把 ±数百 V 缩到 ADC 量程（见 [[运算放大器]]） | 专用示波器前端 IC |
| ADC 采样 | 片内 ADC + 定时器触发 + [[DMA]] | 等间隔采样，免 CPU 搬运，循环缓冲 10240 点 | 外置高速 ADC |
| DSP 库 | ARM CMSIS-DSP | 官方优化 FFT/FIR，免去自写算法（见 [[数字信号处理DSP]]） | 自写/Matlab 生成系数 |
| GUI | STemWin | 免费嵌入式 GUI，做菜单/波形/测量窗口 | LVGL |
| 文件 | FatFS | 波形存 SD 卡，掉电不丢 | 片内 Flash |

## 4. 原理图推导（逐个模块，讲清为何需要每个元件）
- **前端调理电路**：示波器要测大信号，探头来的电压远超 ADC 0~3.3V。为什么需要它？——用电阻分压衰减 + [[运算放大器]] 隔离缓冲，再用模拟开关切档（增益/衰减）和电容切交/直流耦合。没有它，要么烧 ADC，要么小信号看不见。
- **ADC + 定时器触发**：为什么用定时器硬件触发而非软件循环读？——保证采样间隔严格相等（Δt 恒定），FFT 的频率分辨率 `f_s/N` 才正确。源码里 `DMA2_Stream1->NDTR` 读当前位置，循环缓冲 10240 点，再取 2048 点做变换。
- **[[DMA]]**：ADC 每采样一次自动搬进内存，CPU 只管"取一帧算一帧"，不阻塞 [[任务与调度]] 里的显示任务。
- **CMSIS-DSP 的 FFT**：`arm_rfft_fast_f32(&S, in, out, 0)` 做 2048 点实数 FFT，`arm_cmplx_mag_f32` 取幅值得到频谱。为什么不直接算 DFT？——FFT 把 N² 降到 N·logN，F4 上百 MHz 主频也要靠它实时出频谱（教程第 26 章专讲示波器 FFT 应用）。
- **FIR 数字滤波**：`arm_fir_f32` 实现低通（源码 DSO_FirFilter_Step1K/10K/100KHz 三档），用来在软件层压掉带外噪声，比模拟滤波更灵活（见 [[滤波算法]]）。
- **STemWin GUI + uCOS-III**：GUI 负责画波形/菜单/测量窗口；RTOS 把"采、算、显"拆成任务，避免互相卡顿。
- **FatFS**：把波形存 SD 卡，属"可回放"的加分项。

## 5. 布局布线要点
- **模拟前端与数字部分分地**：调理/ADC 模拟区单点接数字地，否则数字噪声窜进小信号，底噪飙升（见 [[EMC电磁兼容]]）。
- **[[去耦电容]]**：MCU、运放、ADC 的 VCC 旁每片 0.1µF，ADC 参考电压加储能/滤波电容，参考不稳频谱就漂。
- **ADC 参考与输入保护**：前端加钳位/限幅，避免过压打坏 ADC 输入。
- **采样时钟干净**：定时器触发源用低抖动时钟，采样间隔抖动会让频谱出现"相位噪声"。
- **LCD 总线**：RGB/FMC 走线等长、远离模拟前端，避免屏噪耦合进采集通道。

## 6. 检查清单
- [ ] 前端量程：最大输入电压经衰减后 ≤ ADC 满量程，且不超过运放供电轨
- [ ] 触发：定时器触发 ADC 已使能，采样率 = 定时器频率 / 分频，时基档位计算正确
- [ ] [[DMA]] 缓冲：循环缓冲长度 > 一屏点数，取帧不踩写指针（双缓冲/临界区）
- [ ] FFT：点数 2048 为 2 的幂；输入已去直流；幅频结果做了窗函数补偿（见 [[数字信号处理DSP]] 第 26.7 节窗函数）
- [ ] FIR：系数由 fdatool 生成、Q 格式匹配；群延迟在显示时已对齐
- [ ] GUI：触摸校准、波形与频谱窗口不重叠刷屏撕裂
- [ ] 电源：模拟/数字 [[去耦电容]] 齐套，LDO 纹波够低
- [ ] 文件：FatFS 挂载 SD 成功，存读波形不越界

## 7. 复盘
- **为什么用 CMSIS-DSP 而非自写 FFT**：FFT 是数值密集活，官方库用汇编写好、定点/浮点都优化过，直接调用既快又不易错——把"算法正确性"和"性能"两件事都外包掉。
- **为什么必须定时器触发 + [[DMA]]**：示波器 FFT 的频率轴靠 Δt 恒定，软件轮询读 ADC 会有抖动；硬件触发 + DMA 才保证等间隔，频谱才准。
- **为什么上 RTOS**：采、算、显三件事节奏不同（采要快、显要稳、UI 要响应），拆任务后用 [[任务与调度]] 解耦，比大循环好维护。
