# STM32物联网户外环境监测

> 一台基于 STM32F103 + ESP8266 的户外环境监测终端：STM32 聚合温湿度/光照/PM2.5/气压多路传感器，本地 LCD5110 显示，经 WiFi 模块把数据推到手机 APP，APP 可设阈值、超阈值时本地蜂鸣器+LED 报警。是"端—网—云(手机)"三层物联网架构的入门范本（见 [[物联网终端]]）。

## 1. 需求拆解
- 必须实现：
  - 监测：温湿度（DHT11）、光照强度（光敏电阻）、PM2.5（GP2Y1010AUOF）、大气压强，共 4+ 类环境参数。
  - 本地显示：LCD5110 屏实时显示各参数。
  - 无线远传：STM32 经 WiFi 模块把数据发到手机 APP（Android），APP 可设报警阈值。
  - 报警：数据超阈值时蜂鸣器/语音播报模块 + LED 动作。
- 可选实现：
  - 多节点组网、云端存储、历史曲线（本文聚焦单机+手机直连）。
- 硬约束（供电/尺寸/成本/通信）：
  - 主控 STM32F103C8T6（72MHz、128K Flash、多外设，见 [[STM32F103]]）。
  - 供电 5V（AC-DC 降压），ESP8266 与 MCU 均需 3.3V（见 [[线性电源LDO]]）。
  - 通信：WiFi 模块用 [[UART]] AT 指令接入局域网/互联网，非另跑网络协议栈。

## 2. 功能框图
```
 传感器层                        ┌──── STM32F103C8T6 ────┐
 DHT11(温湿度,单总线)──GPIO      │ 采集+处理+报警判断     │
 光敏电阻(光照)──分压──┐         │                       │
 GP2Y1010(PM2.5,模拟)─┤ADC+DMA  │  ADC-DMA 多路扫描      │
 气压(I2C)─────────I2C│         └───┬─────────┬─────────┘
                      │             │SPI       │UART(AT)
                      ▼             ▼          ▼
                  ADC1(模拟量)   LCD5110    ESP8266(WiFi)
                                 (显示)       │  TCP/无线
                                              ▼
                                          手机APP(Android)
                                         设阈值/看数据
 超阈值 → 蜂鸣器/语音模块 + LED(报警)
 供电: 5V(AC-DC) → 3.3V LDO → MCU / ESP8266
```

## 4. 原理图推导（逐个模块，讲清为何需要每个元件）
- **STM32F103C8T6**：系统大脑，把多路异构传感器（数字/模拟/I2C）统一采集、融合、显示、上报。丰富 USART/I2C/ADC 正对口（见 [[STM32F103]]、[[通信协议设计]]）。
- **ESP8266 WiFi 模块**：把"连云"下沉到模组——它内置 TCP/IP 与 Socket AT 指令，STM32 只需用 [[UART]] 发 `AT+CWJAP`(连路由)、`AT+CIPSTART`(建 TCP) 等，就把数据推到手机。为什么用串口 WiFi 透传？——MCU 不用跑网络栈，开发快、成本低，是物联网终端常用套路（见 [[物联网终端]]）。注意它 3.3V 供电、IO 不耐 5V，与 5V 器件间需 [[电平转换]]。
- **DHT11（温湿度）**：单总线数字传感器，一根 GPIO 按时序读温湿度（见 [[GPIO]]），内部已校准，省外部电路。
- **光敏电阻 + 分压电阻**：无光时阻值大→分压点电压高，光照强→阻值小→电压低，于是"光照"被变成"电压"送 [[ADC]] 量化（见 [[光敏电阻传感器]]、[[无源元件基础]]）。
- **GP2Y1010AUOF（PM2.5）**：内部 LED 发光、光电管收散射光，粉尘越多电压越高，输出模拟量进 [[ADC]]；需 5V 供电并定时点亮 LED。
- **气压传感器（I2C）**：数字气压，走 [[I²C]] 读取，地址化、两根线挂多设备。
- **ADC + [[DMA]]（源码第 4.7 章）**：光敏、PM2.5 等多路模拟量用 ADC 连续扫描 + DMA 搬运，CPU 不轮询、不丢点，适合"持续监测"场景。
- **LCD5110（SPI）**：本地把各参数画出来，断网也能看（见 [[SPI]]）。
- **蜂鸣器/语音模块 + LED**：超阈值时由 [[GPIO]] 经 [[三极管开关电路]] 驱动蜂鸣器/语音芯片并点亮 LED，形成本地闭环报警，不依赖手机在线。
- **电源**：户外 5V（AC-DC）进，再经 3.3V LDO 给 MCU 与 ESP8266（见 [[线性电源LDO]]）；ESP8266 发射瞬时电流大，3.3V 需足够储能/[[去耦电容]]。

## 5. 布局布线要点
- **ESP8266 电源与天线**：3.3V 走线短而粗、旁加 0.1µF + 大电容储能；天线区域净空、远离数字/功率线，否则 WiFi 掉线（见 [[EMC电磁兼容]]）。
- **[[电平转换]]**：ESP8266 IO 仅耐 3.3V，任何 5V 信号进模组前必须降压，否则烧毁。
- **模拟采样**：光敏/PM2.5 的 ADC 走线远离开关电源与 WiFi 射频，加 [[去耦电容]]、走差分/包地减少干扰。
- **[[去耦电容]]**：MCU、传感器、LDO 输出各加 0.1µF；模拟与数字地单点相连。
- **[[看门狗]]**：户外长期无人值守，开独立看门狗防程序跑飞"假死"失联。
- **复位/下载**：SWD 接口留好，便于现场烧录与调试。

## 6. 检查清单
- [ ] 电平：ESP8266 所有信号 ≤3.3V，必要时 [[电平转换]]
- [ ] 电源：5V→3.3V LDO 能力够，ESP8266 发射瞬间压降不垮（储能电容够）
- [ ] WiFi：AT 指令波特率/回车格式与 STM32 一致；连路由/建 TCP 有超时重连
- [ ] 传感器：DHT11 单总线时序；光敏分压中点电压在 ADC 量程内；GP2Y1010 LED 点亮时序
- [ ] [[ADC]]+[[DMA]]：扫描通道顺序、缓冲区长度与解析对应，不串道
- [ ] 报警：阈值比较与蜂鸣器/LED/语音驱动方向正确，不误报漏报
- [ ] [[看门狗]]：喂狗周期 > 主循环最长阻塞，防失联
- [ ] 显示：LCD5110 初始化与 SPI 速率正确

## 7. 复盘
- **为什么 ESP8266 透传而非 MCU 跑网络栈**：把 TCP/IP 下沉到模组，MCU 专注传感与业务逻辑，省资源、降难度——物联网终端的经典分工（见 [[物联网终端]]）。
- **为什么多传感器用单 MCU 聚合**：市场趋势是"系统集成化"，单板同时测温湿度/光照/PM2.5/气压，比多个单功能设备成本低、好维护。
- **为什么 ADC+[[DMA]] 采模拟量**：户外要持续监测多路慢变模拟信号，DMA 连续扫描免 CPU 轮询，既稳又省算力。
- **为什么手机设阈值 + 本地报警闭环**：云端/手机负责"看与设"，本地报警负责"即时响"，即使手机不在线也能现场提醒，可靠性高。
