# STM32数据采集与心率检测

> 一台基于 STM32F411 的便携心率采集仪：用 PulseSensor（光电容积脉搏波 PPG，见 [[心率检测]]）采指尖脉搏，500Hz 采样进 ADC，在定时器中断里实时跑心率算法算出 BPM/IBI，2.2" TFT 画波形，同时经 [[UART]] 把原始数据发给 PC。是"数据采集 + 信号算法"的典型练手项目。

## 1. 需求拆解
- 必须实现：
  - 采集人体脉搏波形（PPG 模拟量）→ [[ADC]] 数字化。
  - 实时心率算法：从波形里找心跳、算 BPM 与 IBI（心率变异性 HRV 指标）。
  - 本地显示：TFT 屏绘波形 + 显示 BPM/IBI。
  - 数据上传：[[UART]] 发原始/计算结果到 PC（Processing 可视化）。
- 可选实现：
  - 多通道数据采集（本工程单通道心率，框架可扩展）。
  - 阈值/报警、历史存储。
- 硬约束（供电/尺寸/成本/通信）：
  - 主控 STM32F411（F4 带 FPU，跑算法轻松）；本工程时钟仅用 HSI 16MHz（PLL 关），TIM3 分频得 500Hz 采样。
  - 通信走 USART2（PA2/PA3，115200），接 PC 串口。

## 2. 功能框图
```
 PulseSensor(PPG)               ┌──────── STM32F411 ────────┐
 指尖光电容积脉搏波              │ TIM3(500Hz)中断:          │
        │ 模拟(0~3.3V)          │   HAL_ADC_GetValue(PA0)   │
        ▼                       │   峰值/谷值/阈值跟踪算法   │
   ┌──────┐  ADC1_CH0(PA0)      │   BPM=60000/IBI(10次均值) │
   │ ADC1 │────────────────────▶│   IBI→HRV                │
   └──────┘  单次转换+重启       └──────┬───────────┬───────┘
        ▲                               │ SPI(模拟)  │ UART(115200)
    TIM3触发(500Hz)                     ▼           ▼
                                  2.2" TFT       PC(Processing)
                                  (PB0~PB5)      原始'S'/BPM'B'/IBI'Q'
                                  PA5 LED 每拍亮
```

## 3. 器件选型
| 模块 | 型号/方案 | 选型理由 | 替代 |
| --- | --- | --- | --- |
| 主控 MCU | STM32F411 | F4 带浮点，算法/中断实时性好 | 其它 F4/F1 |
| 心率传感 | PulseSensor (PPG) | 无创、指尖一贴即测，模拟输出直接进 ADC（见 [[心率检测]]） | 血氧/ECG 模块 |
| ADC 通道 | ADC1_CH0 (PA0) | 单端 10 位，心率信号幅度够用 | 更高分辨率 ADC |
| 定时采样 | TIM3 (Prescaler15, Period1999) | 16M/(16·2000)=500Hz 等间隔触发 | 其它定时器 |
| 显示 | 2.2" 240×320 TFT (SPI/模拟) | 小屏低引脚，软件 SPI 刷波形+汉字 | OLED |
| 上传 | USART2 (115200) | 串口直连 PC，协议简单（见 [[UART]]） | USB 虚拟串口 |

## 4. 原理图推导（逐个模块，讲清为何需要每个元件）
- **PulseSensor（PPG）**：为什么用它而不是 ECG？——PPG 用绿光 LED 照指尖、光敏管收反射光强，血液容积随心跳变化→电压起伏，无创、方便；ECG（见 [[心电ECG采集]]）需贴电极测心电，便携性差。其模拟输出直接接 PA0。
- **ADC1_CH0 (PA0)**：把脉搏模拟电压转数字。本工程用"单次转换 + TIM3 中断里 `HAL_ADC_Start` 重启"的方式（500Hz 下足够轻量）；若采样率更高，更优做法是开 [[DMA]] 双缓冲自动搬运，CPU 零干预。10 位分辨率对心率波形绰绰有余。
- **TIM3（500Hz）**：`Prescaler=15, Period=1999` → 16MHz/(16×2000)=500Hz，每 2ms 进一次中断采一个点。为什么 500Hz？心率波形主频 <10Hz，按采样定理几十 Hz 就够，500Hz 留足余量且算力轻松。
- **心率算法（[[滤波算法]]）**：在 TIM3 中断里实时跟踪波形峰值 P、谷值 T、阈值 thresh（取幅值 50%）。检测到"过阈且静默 3/5 个 IBI 避开二峰噪声"即判为一拍，记 IBI（两拍间隔 ms），对最近 10 次 IBI 滑动平均得 `BPM=60000/均值`；IBI 本身就是 HRV（心率变异性）指标。阈值自适应应对不同人幅度差异。
- **2.2" TFT（SPI 模拟）**：用 PB0~PB5 当 CS/SCK/SDI/DC/REST 软件模拟 SPI，按 ILI9341 类时序初始化（写一堆 0xCB/0xCF… 寄存器）、画点画线。为什么模拟 SPI？小屏刷波形速率要求不高，省下硬件 SPI 资源、布线简单。
- **USART2 (PA2/PA3, 115200)**：`sendDataToProcessing('S',Signal)` 发原始、'B' 发 BPM、'Q' 发 IBI 给 PC 上的 Processing，做更漂亮的波形/曲线存储——这就是"数据采集"的对外出口。
- **PA5 LED**：每检测到一拍置高，心跳可视化指示。

## 5. 布局布线要点
- **PA0 模拟输入保护**：PulseSensor 信号弱，走线远离开关屏线、LED 驱动线，旁边加 [[去耦电容]] 稳参考；传感器本身要遮光避免环境光干扰。
- **电源**：TFT 和 LED 瞬时电流不小，MCU 与屏的 VCC 各加 0.1µF 去耦，屏电源要稳否则花屏。
- **地**：模拟（PA0）与数字地单点相连，减少数字噪声窜入小信号。
- **复位**：屏 REST 脚上电先拉低再拉高（代码里有 20ms 延时），初始化顺序错就点不亮。
- **串口电平**：USART2 是 3.3V TTL，接 PC 需 USB-TTL 模块，注意 [[电平转换]]。

## 6. 检查清单
- [ ] 采样率：TIM3 分频算出的 500Hz 正确；ISR 里先取值再重启 ADC，不丢点
- [ ] 算法：首拍/第二拍种子逻辑正确，IBI 平均窗口不越界；无心跳 2.5s 后阈值复位
- [ ] ADC 量程：PulseSensor 输出 0~3.3V 不削顶；10 位够分辨率
- [ ] TFT：复位时序、寄存器初始化（ gamma/扫描方向）正确，不花屏
- [ ] [[UART]]：波特率 115200 两边一致；'S'/'B'/'Q' 前缀 PC 端能解析
- [ ] 去耦：MCU/屏/传感器旁 0.1µF 齐套，传感器遮光
- [ ] 扩展：如需更高采样率，改 ADC+[[DMA]] 双缓冲（见 [[DMA]]）

## 7. 复盘
- **为什么用 PPG 而非 ECG**：便携、无创、单点接触即可，适合做"人人能用的心率仪"；ECG 更准但需多电极，定位在医疗场景。
- **为什么 500Hz 而不是更高**：心率波形能量集中在 <10Hz，500Hz 已满足采样定理且给算法留余量，再高只是白费算力与带宽。
- **为什么阈值自适应 + 10 次平均**：不同人脉搏幅度差很大，固定阈值会漏拍/误判；滑窗平均抑制单拍抖动，BPM 显示更稳。
- **单定时器中断里"采样+算法"的工程取舍**：500Hz 下足够简单实时；若做多通道或上千 Hz，就该上 [[DMA]] + 双缓冲把搬运和算法解耦。
